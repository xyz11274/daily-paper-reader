## 摘要
全量微调仍然是适配预训练LLM的一种有效方式，但它会更新所有权重且成本高昂。LoRA减少了可训练参数的数量，但并未直接回答在适配过程中哪些预训练组件应被训练、哪些可以冻结。我们提出TopoTuner，一种拓扑引导的微调框架，用于选择性冻结注意力投影矩阵。该方法将每个投影矩阵视为一个行点云，并使用持久性图之间的Wasserstein距离来衡量其在微调过程中拓扑结构的变化。TopoTuner从源数据集中学习一个可重用的冻结配置文件，并将其转移到跨领域数据集上高效微调模型，评估特定任务的拓扑漂移是否在问答和情感分析任务中具有泛化性。在LLaMA-3.1-8B、Mistral-7B-v0.3和Qwen3-8B-Base上，TopoTuner在仅训练1-2%模型参数的情况下与全量微调竞争力相当，并在9个模型-数据集设置中的7个中优于LoRA，该设置可改变高达39.57%的投影参数。除了最小化更新外，TopoTuner相对于全量微调平均减少20.4%的训练时间，相对于LoRA平均减少5.5%。TopoTuner为可重用的冻结配置文件开辟了新方向，在单个数据集上学习到的微调行为可以跨多个任务共享。

## Abstract
Full fine-tuning remains a strong way to adapt pretrained LLMs, but it updates all weights and can be expensive. LoRA reduces the number of trainable parameters, but it does not directly answer which pretrained components should be trained and which can be frozen during adaptation. We introduce TopoTuner, a topology-guided fine-tuning framework for selective freezing of attention projection matrices. \method treats each projection matrix as a row cloud and uses Wasserstein distances between persistence diagrams to measure how its topology changes during fine-tuning.   TopoTuner learns a reusable freezing profile from a source dataset and transfers it to efficiently fine-tune models on out-of-domain datasets, evaluating whether task-specific topological drift generalizes across question answering and sentiment analysis tasks.   Across LLaMA-3.1-8B, Mistral-7B-v0.3, and Qwen3-8B-Base, TopoTuner is competitive with full fine-tuning while training only 1-2\% of the model parameters, and outperforms LoRA in 7 out of 9 model-dataset settings, which can change up to 39.57\% of the projection parameters. Along with minimized updates, TopoTuner reduces training time by 20.4\% relative to full fine-tuning and 5.5\% relative to LoRA on average. TopoTuner opens a new direction for reusable freezing profiles, where fine-tuning behavior learned on one dataset can be shared across multiple tasks.

# TopoTuner: Topological Finetuning of Large Language Models 论文总结

## 1. 核心问题与整体含义

全量微调（Full Fine-tuning）能有效适配预训练大语言模型，但更新所有权重导致高计算成本；LoRA等参数高效微调方法虽减少了可训练参数量，却未指明**哪些预训练组件应被冻结、哪些应被训练**。TopoTuner 从**拓扑数据分析**（持续同调）角度出发，通过量化注意力投影矩阵在微调前后的结构性变化（拓扑漂移），实现**选择性冻结**并生成**可跨任务复用的冻结配置文件**，从而在极低参数更新率下保持竞争力。该方法首次将“微调应控制哪些组件变化”这一结构性问题纳入拓扑框架。

## 2. 方法论

### 核心思想
将每个注意力投影矩阵（K、Q、V、O）的每一行视为高维空间中的一个点，形成“行点云”。利用 Vietoris–Rips 过滤构建持续同调，得到持久性图，再通过 **Wasserstein 距离**度量微调前后持久性图之间的差异，作为该矩阵的结构性变化指标（拓扑漂移）。

### 关键技术细节
- **拓扑漂移定义**：  
  对矩阵 i，定义第 t 轮的拓扑距离 D<sup>(t)</sup><sub>i</sub> = Wasserstein<sub>p</sub>(PD<sub>k</sub>(X<sub>i</sub><sup>(0)</sup>), PD<sub>k</sub>(X<sub>i</sub><sup>(t)</sup>))。  
  归一化 epoch-to-epoch 漂移 Δ<sup>(t)</sup><sub>i</sub> = (D<sup>(t)</sup><sub>i</sub> - D<sup>(t-1)</sup><sub>i</sub>) / D<sup>(1)</sup><sub>i</sub>。

- **两种场景**：
  - **A：可复用冻结配置文件**  
    在源任务（如 QA:GSM8K）上全微调，计算各投影矩阵的 Wasserstein 距离，按距离排序（高漂移或低漂移），选择 top-b 个矩阵冻结。将同一冻结集迁移到目标任务，目标梯度的 Lipschitz 条件保证排序稳定。
  - **B：动态停止**  
    在微调过程中实时监测所选矩阵的归一化 epoch-to-epoch 漂移，当平均漂移低于阈值 η 时提前终止训练。

- **理论保证**：  
  若两个任务的梯度场在预训练初始点附近足够接近，则拓扑漂移排序的差异有上限，且当排序间隔大于该上界时，冻结配置文件可完全复用。

## 6. 主要结论与发现

1. **竞争力强**：TopoTuner 在 9 个模型-数据集迁移设置中，**7 个优于 LoRA**，性能接近全微调，同时仅训练 1-2% 模型参数。  
2. **训练更快**：平均训练时间比全微调减少 20.4%，比 LoRA 减少 5.5%。  
3. **漂移模式具模型依赖性**：LLaMA/Mistral 的高漂移集中在 V/O 投影，Qwen 集中在 K/Q 投影，无法使用统一规则。  
4. **冻结配置文件可迁移**：从 GSM8K 学到的拓扑排序可成功应用于 SST-2、IMDB、MMLU。  
5. **动态停止有效**：多数实验可在 2-3 epoch 后停止，保留接近最终验证集的性能。  
6. **减少过拟合**：高漂移冻结策略的 train-test 泛化差距小于全微调。  
7. **遗忘控制**：在问答、情感分析、信息检索任务上遗忘更少，在生成任务上不如 LoRA。

## 7. 优点

- **新颖的拓扑视角**：首次将持续同洞用于 LLM 微调的组件选择，提供比元素级幅度更丰富的结构化信息。  
- **可复用性**：生成的冻结配置可跨数据集复用，减少重复探索。  
- **效率与性能的平衡**：在极低的参数更新率（<3%）下达到甚至超越 LoRA 的效果。  
- **理论支持**：给出了稳定性定理，为迁移学习提供保证。  
- **鲁棒性**：高漂移冻结策略普遍优于低漂移，且对预算变化不敏感。  

## 8. 不足与局限

- **依赖内部权重访问**：需要模型权重和检查点，对闭源 API 模型（如 GPT-4）不适用。  
- **计算开销**：持久性计算在 CPU 上运行，虽可离线并行，但总时间仍可能成为实践中的瓶颈。  
- **模型尺寸限制**：仅在 7B/8B 级模型上验证，未测试更大模型（如 70B, 180B）。  
- **跨任务迁移范围有限**：仅从 QA:GSM8K 向三个目标迁移，未系统探索不同源任务的影响。  
- **生成任务遗忘评估不理想**：在 CNN/DM、Alpaca、HumanEval 等任务上，TopoTuner 的遗忘控制弱于 LoRA（表15-17）。  
- **模型结构与漂移模式不一致**：不同架构需重新计算拓扑排序，无法直接迁移冻结配置文件。  
- **缺乏消融**：未对比仅使用 H<sub>0</sub> 与使用更高维同调的差异；也未分析不同距离度量（如欧氏距离 vs 余弦距离）的影响。  
- **计算资源未充分说明**：GPU 数量、并行策略、内存消耗等细节缺失。
