## 摘要
大语言模型（LLM）智能体不断拓展的运行能力催生了复杂精密的安全威胁。运行时防御通过将安全机制集成到智能体执行循环中，已成为缓解此类风险的有效方案。然而，现有运行时防御高度依赖人工设计的干预措施，缺乏用于其构建与维护的规范化框架。在本文工作中，我们首先构建了防护层级的运行时防御形式化定义，系统性刻画了防护机制如何支撑防御构建，并从防护视角为现有运行时防御干预提供了统一视图。基于该形式化定义，我们提出了HARD（基于防护的自主运行时防御进化，Harness-based Autonomous Runtime Defense Evolution），这是一个自进化运行时防御框架，可基于观测到的失效轨迹自动识别合适的干预策略，并迭代优化防御构件。HARD将运行时防御开发从人工工程转变为自主进化过程，大量实验表明，相较于现有人工定制防御，该框架在保留良性任务效用的同时提升了安全性能。我们的研究结果表明，自主防御进化是保护已部署LLM智能体极具前景的新范式，可使智能体识别防御弱点并持续改进自身保护机制。

## Abstract
The expanding operational capabilities of large language model (LLM) agents introduce sophisticated security threats. Runtime defenses have emerged as an effective approach to mitigating these risks by integrating security mechanisms into the agent execution loop. However, existing runtime defenses rely heavily on manually designed interventions and lack a principled framework for their construction and maintenance. In this work, we first develop a harness-level formulation of runtime defense that systematically characterizes how harness mechanisms enable defense construction and provides a unified view of existing runtime defense interventions from a harness perspective. Building on this formulation, we propose HARD (Harness-based Autonomous Runtime Defense Evolution), a self-evolving runtime defense framework that automatically identifies appropriate intervention strategies and iteratively improves defense artifacts based on observed failure traces. HARD transforms runtime defense development from manual engineering into an autonomous evolution process, and extensive experiments demonstrate that it improves security performance over existing handcrafted defenses while preserving benign task utility. Our findings highlight autonomous defense evolution as a promising new paradigm for securing deployed LLM agents, enabling agents to identify defense weaknesses and continuously improve their protection mechanisms.

## 1. 核心问题与研究背景
- 背景：LLM智能体已经从被动文本生成演进为能调用工具、维护状态、和外部环境交互的交互式系统，能力提升的同时，安全风险从孤立的文本生成转变为运行时工具介导的执行风险，一次不安全的工具调用就可能引发严重后果，常见威胁包括提示注入、内存投毒、技能投毒等。
- 现有方案的缺陷：
  - 模型级防御需要修改模型参数、重新训练，不适合基于固定闭源模型的已部署智能体，还存在安全-效用的权衡问题。
  - 现有运行时防御都是静态手工设计的，而LLM智能体的失败空间是开放不可穷尽的，自适应攻击会不断演变攻击方式，现有防御依赖人工排查失败、迭代修改防御，成本高、难以规模化。
- 核心研究问题：如何让LLM智能体的运行时防御能够基于观测到的失败自动进化，适配不断涌现的新攻击。

## 2. 提出的方法论
### 核心思想
将运行时防御建模为LLM智能体运行时harness的优化问题，提出自进化框架HARD，基于攻击失败轨迹自动迭代优化防御构件，把防御开发从人工工程转变为自主进化过程。

### 关键技术细节
1. **harness中心的统一形式化定义**
  - 把LLM智能体建模为 `A = (Mθ, H)`，其中$M_\theta$是参数固定的基础大模型，$H$是运行时harness，负责中介模型和外部环境、持久化智能体构件的交互。
  - harness拆分为两个独立可编辑的核心组件：
    - 上下文构建函数$\phi_H$：负责从交互历史、持久化构件中整理出给模型的输入上下文，对应上下文侧防御（管控模型输入）。
    - 动作解释函数$\psi_H$：负责把模型输出转换为可执行动作，做解析、校验、拦截，对应动作侧防御（管控模型输出执行）。
  - 将运行时防御形式化为带约束的优化问题，目标是在harness空间中最大化安全性能和任务效用的加权和，平衡安全与可用性。

2. **HARD自进化框架流程**
  整体是迭代的失败驱动进化循环，每一轮流程如下：
  1. **失败轨迹收集**：基于当前harness，采样攻击任务，收集执行轨迹，筛选出安全或效用不达标的失败轨迹。
  2. **失败轨迹路由**：用LLM作为路由器，分析每个失败轨迹，将其分配给对应负责的防御构件（上下文侧安全策略/动作侧执行规则），按构件分组得到专属的失败反馈集。
  3. **分构件防御进化**：
    - 上下文策略进化器：从分组失败中提取通用可泛化的安全不变量，合并、优化现有策略，避免过拟合特定攻击样本，同时保证不影响合法任务的执行。
    - 动作规则进化器：从分组失败中提取低误报、可复用的执行匹配规则，仅新增针对新失败的规则，保留原有有效规则。
  4. 组装优化后的构件得到新一代harness，进入下一轮进化循环。

- **数据集与场景**：
  - 主基准：AgentCanary，额外加入AgentHazard数据集，统一转换为AgentCanary格式保证评估一致性。
  - 攻击场景：覆盖4类静态攻击（直接提示注入DPI、间接提示注入IPI、内存污染MC、技能投毒SP），2类自适应攻击（动态攻击进化DAE、长时渐进攻击LPA）。

## 6. 主要结论与发现
- 静态攻击场景下，HARD-Both在四类攻击上都取得了远优于手工防御的安全性能，攻击成功率分别降至15.4%（DPI）、1.0%（IPI）、6.7%（MC）、10.2%，而手工防御的攻击成功率范围为13%~66%；同时HARD保留了很高的良性任务效用（BU在91.9%~95%之间），还大幅提升了攻击下的任务效用，例如内存投毒场景UA从56%提升至86%，技能投毒场景UA从52%提升至92%。
- 自适应攻击场景下，HARD依然保持显著优势，动态攻击进化下HARD-Both的ASR为26.5%，优于最强手工防御的30.1%；长时渐进攻击下HARD-Policy的ASR降至4.8%，远低于最强手工防御的24.1%。
- 消融实验发现：静态攻击下联合进化两个构件效果最优；自适应攻击下，上下文策略进化的泛化能力优于动作规则进化。所有主流大模型作为进化backbone都能实现防御提升，但backbone的能力会影响最终的安全-效用权衡。
- 核心结论：自主防御进化是保护已部署LLM智能体极具前景的新范式，能够让防御自动识别弱点、持续优化防护机制。

## 7. 优点
- 思路创新：首次提出LLM智能体运行时防御的自进化范式，解决了传统手工静态防御难以适配不断演化的攻击的痛点，开辟了LLM智能体安全的新研究方向。
- 理论贡献：提出了harness中心的统一形式化框架，将现有各类运行时防御统一归到上下文构建、动作解释两个干预接口，为该领域后续研究提供了清晰的分析框架。
- 框架设计合理：通过失败路由机制实现分构件针对性优化，针对语义类失败进化泛化性强的安全策略，针对有明确执行模式的失败生成高效拦截规则，兼顾了防御效果和泛化能力。
- 实验设计严谨：覆盖静态、自适应多类攻击场景，做了充分的消融实验，控制变量严格，结论可信。

## 8. 不足与局限
- 联合进化在长周期自适应攻击场景下存在缺陷：大量有明确模式的失败被路由到动作侧，会导致上下文策略获得的进化机会不足，泛化能力弱于单独进化策略，不同防御构件的交互会带来性能损失。
- 动作侧执行规则容易过拟合已观测的攻击模式，对未见过的变形攻击泛化性较差。
- 防御进化效果依赖进化backbone的能力，部分backbone可能生成过于保守的规则，额外损失任务效用。
- 未验证大规模长期部署下的进化稳定性，多轮进化后是否会出现规则累积、防御效率下降、误报率上升等问题还不明确，也未充分验证在不同架构LLM智能体上的通用性。
- 未披露进化的实际成本，多次调用大模型做进化的算力开销还有待评估。
