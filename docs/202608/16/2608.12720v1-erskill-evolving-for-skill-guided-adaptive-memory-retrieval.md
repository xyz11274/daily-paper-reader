## 摘要
尽管大语言模型（LLM）智能体越来越依赖长期记忆实现持续交互，但管控该记忆的检索机制极少被视为可进化组件。这种静态方法限制了模型在异构记忆查询上的性能，而这类查询通常需要多样化的证据构建策略。为解决这一问题，我们提出了**ERSkill**，这是一个以检索为核心的自进化、技能引导式记忆访问框架。ERSkill将交互历史编译为结构化记忆库，将检索行为表示为由基础基元构成的可执行技能。推理阶段，训练完成的路由模块会为每个查询动态匹配最优技能，构建适配答案生成的定制化证据。为实现持续改进，ERSkill在训练过程中对技能集合与路由模块进行共同进化。它采用经验前缀树高效记录已探索的检索路径，并搭配双边界机制，安全地将新技能能力的扩展与面向路由的稳定部署解耦。在多个智能体记忆基准上开展的实验表明，ERSkill显著优于性能强劲的非进化与自进化基线方法。值得注意的是，使用Qwen3-Next-80B-A3B-Instruct时，该方法在F1、BLEU-1和LLM评判得分上的整体平均提升了31.3%，使用GPT-5.4-nano时提升了28.1%。

## Abstract
While Large Language Model (LLM) agents increasingly rely on long-term memory for persistent interactions, the retrieval mechanisms governing this memory are rarely treated as evolvable components. This static approach limits performance on heterogeneous memory queries, which often demand diverse evidence construction strategies. To address this, we introduce \textbf{ERSkill}, a retrieval-centric framework for self-evolving, skill-guided memory access. ERSkill compiles interaction histories into a structured memory store and represents retrieval behaviors as executable skills composed of fundamental primitives. At inference time, a trained router dynamically matches each query to the optimal skill to construct tailored evidence for answer generation. To enable continuous improvement, ERSkill co-evolves the skill set and the router during training. It employs an experience trie to efficiently record explored retrieval paths, alongside a double-frontier mechanism that safely decouples the expansion of new skill capabilities from stable, router-facing deployment. Experiments across multiple agent memory benchmarks demonstrate that ERSkill substantially outperforms strong non-evolving and self-evolving baselines. Notably, it improves the overall average across F1, BLEU-1, and LLM-judge scores by 31.3\% with Qwen3-Next-80B-A3B-Instruct and by 28.1\% with GPT-5.4-nano.

# 论文详细总结
## 1. 核心问题与研究背景
- 当前大语言模型智能体需要依托长期记忆支撑持续交互，现有工作大多聚焦于优化记忆内容构建、推理经验进化，**检索机制本身始终被设计为静态固定组件
- 异构记忆查询对证据构建有完全不同的需求：例如查找特定礼物只需要检索单个事件，而分析行程取消原因需要关联多段事件构建因果链，静态检索无法适配这种多样化需求
- 核心研究问题：如何让大语言模型智能体自主进化出组合检索动作的能力，让检索行为适配不同查询的异构信息需求

## 2. 提出的方法论
### 核心思想
将记忆访问建模为技能引导的证据构建过程，对检索技能集和技能路由模块共同进化，实现针对不同查询的自适应检索，同时保障进化过程的稳定性和效率。

### 关键技术细节
1. **结构化记忆与检索原语库**
   - 将原始交互历史切分为原子记忆单元，构建包含搜索索引和原子关系图，形成面向检索的结构化记忆存储
   - 定义固定的三类基础检索原语：搜索原语（实体搜索、词法BM25搜索、稠密相似度搜索）、扩展原语（时序扩展、相似扩展、关系扩展）、处理原语（LLM查询改写/证据过滤等控制操作），所有技能通过组合原语形成
2. **推理流程**
   - 每个检索技能是一段可执行的原语序列，附带技能描述和信息偏好
   - 训练好的技能路由器对查询和所有技能编码，计算匹配概率，选择匹配度最高的技能执行
   - 执行选定技能得到查询专属的证据集合，输入大语言模型生成最终答案
3. **技能-路由器共同进化机制**
   - 双前沿设计：**能力前沿**保留所有已探索中最优的检索技能，跟踪最大可达到的检索能力；**部署前沿**只保留经过路由器验证、能够被稳定选中的技能，将能力探索和稳定部署解耦，避免路由器错选不稳定的新技能
   - 经验前缀树（Experience Trie）：记录所有已经探索过的原语路径，避免重复生成相同技能，提升进化效率，复用历史探索经验
   - 进化流程：从3个单原语种子技能开始，每轮迭代：
     1. 对当前能力前沿的技能做滚动评估，收集性能数据
     2. 编辑现有技能生成新候选技能，过滤掉已经探索过的重复路径
     3. 剪枝冗余技能更新能力前沿，仅保留能带来独特性能增益的技能
     4. 基于历史滚动结果用软标签交叉熵更新路由器参数
     5. 仅当候选部署前沿能提升路由性能或更紧凑时，才更新部署前沿
   - 理论保证：该机制保证两个前沿的Oracle覆盖度始终不下降，进化过程不会出现性能退化
