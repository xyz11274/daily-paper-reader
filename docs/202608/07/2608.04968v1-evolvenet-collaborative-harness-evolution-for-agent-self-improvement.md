## 摘要
LLM智能体的能力不仅取决于其模型，还取决于执行框架：即可执行程序，它负责构建上下文、调用工具、验证结果并从失败中恢复。最近的研究表明，演化执行框架可以在不更新模型权重的情况下带来持续改进。然而，现有方法假设所有执行经验都可以路由到一个单一的优化器，该优化器沿着一条串行轨迹演化单个执行框架。真实的智能体生态系统违背了这一假设：用户、组织和环境产生无法汇集的孤立经验流，因此最值得学习的经验恰恰是无法直接集中的经验。我们提出了EvolveNet，一种协作式执行框架演化范式，它将经验提取迁移到数据端。一个共享的执行框架被广播到数据本地的智能体部署中，每个部署都在自身的工作负载上演化它。只有最终形成的程序调整被组合进更新后的共享执行框架并重新分发，从而使每个参与的智能体都能继承其他智能体发现的操作经验。通过将聚合边界从原始工作负载转移到学到的调整，EvolveNet保持了工作负载的本地性，并允许多个演化搜索并发进行，同时降低了串行深度。由于独立修改的程序不能像模型参数那样被平均，并且组合时可能产生冲突，EvolveNet引入了作用域类型化、证据引导的程序聚合。在涵盖文本转SQL、数据科学编码、竞争性编程、软件工程和智能体工作流的五个场景中，EvolveNet在全部五个场景中均提升了共享执行框架，其中在异质工作负载下收益最大；消融实验将这种提升归因于来自不同智能体的调整的组合，而非在它们之间进行选择。

## Abstract
The capabilities of an LLM agent depend not only on its model but on the harness: the executable program that constructs context, invokes tools, verifies results, and recovers from failure. Recent work shows that evolving the harness yields persistent improvements without updating model weights. Existing approaches, however, assume that all execution experience can be routed to a single optimizer, which evolves one harness along a sequential trajectory. Real agent ecosystems violate that assumption: users, organizations, and environments generate isolated streams of experience that cannot be pooled, so the experience most worth learning from is exactly the experience that cannot be directly centralized. We introduce EvolveNet, a paradigm of collaborative harness evolution that moves experience extraction to the data. A shared harness is broadcast to data-local agent deployments, each of which evolves it on its own workload. Only the resulting program adaptations are composed into an updated shared harness and redistributed, so that every participating agent inherits operational experience discovered by the others. By shifting the aggregation boundary from raw workloads to learned adaptations, EvolveNet keeps workloads local and allows multiple evolutionary searches to proceed concurrently with reduced serial depth. Because independently modified programs cannot be averaged like model parameters and may conflict when composed, EvolveNet introduces scope-typed, evidence-guided program aggregation. Across five settings spanning text-to-SQL, data-science coding, competitive programming, software engineering, and agentic workflows, EvolveNet improves the shared harness in all five, with the largest gains under heterogeneous workloads, and ablations attribute the improvement to composition of adaptations from different agents rather than to selecting among them.

## 论文核心问题与整体含义

- **研究动机**：LLM 智能体的能力不仅取决于模型权重，还取决于其“执行框架”（harness）——即构建上下文、调用工具、验证结果、处理失败的可执行程序。已有工作（如 TTHE、MOSS 等）证明，演化 harness 可以在不更新模型权重的情况下带来持续的智能体行为改进。
- **核心问题**：现有 harness 演化方法普遍采用“集中式”范式，即先把所有工作负载、执行轨迹和反馈汇集到单一优化器，再沿一条串行轨迹演化一个 harness。但真实智能体生态中，用户、组织、环境产生的经验流是相互隔离、无法池化的；最值得学习的经验恰恰无法被直接集中。
- **整体含义**：论文提出 **EvolveNet**——一种协作式 harness 演化范式，将“经验提取”从集中优化器迁移到数据本地，只聚合“学到的程序适配”，而不是聚合产生这些经验的原始工作负载。这样既能保持数据本地性，又能让多个演化搜索并发进行、降低串行深度，使分布式经验在共享 harness 中持续累积，形成“本地演化-聚合-再分发”的自改进闭环。

## 方法论

- **核心思想**：将传统“先聚合数据再演化”的流程，逆转为“先本地演化再聚合适配”。共享 harness 被广播到多个数据本地客户端；每个客户端在自己的工作负载上独立演化出一个“专家程序”；服务器仅将这些程序相对于公共基线的增量（delta）与行为证据组合成新的共享 harness，再重新广播。
- **关键流程（每轮循环）**：
  1. 服务器广播共享 harness \( h^{(t)} \) 给所有客户端；
  2. 客户端 k 在本地数据 \( D_k^{tr} \) 上执行局部演化，得到专家程序 \( h_k^{(t)} = E(h^{(t)}, D_k^{tr}) \)，并计算与基线的 diff \( \Delta_k^{(t)} \) 和行为变化证据 \( e_k^{(t)} = (F_k^{(t)}, B_k^{(t)}) \)（新解决/新失败的数据项集合）；
  3. 服务器执行**证据引导、作用域类型化的程序聚合**（Eq. 11），得到候选共享 harness \( \tilde{h}^{(t+1)} \)；
  4. 在验证集 \( D^{val} \) 上比较候选与旧共享 harness 的行为翻转（Eq. 15-16），若 \( |F_{val}| \ge |B_{val}| \)（Eq. 17）则提交为新共享 harness；否则允许一次修订，再失败则回滚至旧 harness。
- **程序聚合的四项原则**：
  - **公共基线的程序 delta**：所有客户端从同一 harness 出发，delta 可直接比较，避免拼接完整程序导致的失控增长；
  - **行为证据**：每个 delta 附带“解决了哪些项/破坏了哪些项”的逐项证据，约束聚合器对修改意图的解读；
  - **作用域类型化**：每个候选机制被赋予 `GLOBAL`（跨域证据充分、普遍适用）或 `HOME(d_k)`（证据仅来自单一客户端域）或 `⊥`（单条目的怪癖，拒绝）；HOME 机制以条件分支方式仅在归属域激活，从而将许多冲突转化为“条件组合”而非“二选一”（命题 1、2 给出隔离条件）；
  - **行为提交与回滚**：组合后的程序必须通过逐项验证门（Eq. 17），保证“修复数 ≥ 破坏数”才提交，否则回滚，避免回归损害共享基线。
- **聚合的近似求解**：由于 Eq. 12 的目标函数无法可分离、不可单调枚举，EvolveNet 将聚合拆分为“LLM 单轮启发式提案”和“精确可行性检查”两步：提案步骤由 LLM 依据证据和作用域规则一次生成；验证门则通过执行程序精确判断是否满足约束。
- **串行深度分析**：EvolveNet 的每轮串行深度为 \( \max_k C_k^{(t)} + C_A^{(t)} + C_{val}^{(t)} \)，而串行演化为 \( \sum_k C_k^{(t)} + \dots \)，因此并行分支降低了串行深度，使多轨迹并发搜索成为可能。
- **保留共享基线的机制**：聚合器在共享 harness 上原地修改、保留已有提示规则、尽量以局部扩展方式加入新机制，并设置增长预算，减少无关行为的改动。

## 实验设计

- **五个评估场景**（每个场景的“客户端”对应一种自然的分片轴）：

  - **LiveCodeBench（LCB）**（竞赛编程）：客户端按难度档位分片，K=3；

  - **ClawEval**（智能体工作流）：客户端按任务族分片，K=5，分数为连续 judge 评分。
- **对比方法与消融**：
  - **Unevolved harness**（初始共享 harness）；
  - **Select-best**：服务器不聚合，直接选验证分数最高的客户端程序；
  - **Delegation**：保留全部 K 个客户端程序，按域调度（routing-only）；
  - **GLOBAL-only**：EvolveNet 聚合器禁用域条件，只允许全局机制；
  - **集中式基线**：两种预算（等串行深度 / 等总预算）的集中式演化；
  - **跨模型鲁棒性**：用 MiMo-V2.5 替换 deepseek-v4-flash 重复完整 BIRD 流程；
  - **K 消融**：BIRD 上的 K=1/2/5/7 配置对比；

## 主要结论与发现

- **共享 harness 稳步改进**：在全部五个场景上，EvolveNet 均显著优于未演化的 harness（BIRD +13.4, DS-1000 +13.0, LCB +33.4, SWE-V +20.0, ClawEval +8.3），且都通过 Holm 校正后的配对检验。
- **组合优于选择/路由**：在 DS-1000 上，EvolveNet（68.5%）高于 Delegation（64.0%）和 GLOBAL-only（66.5%），且远高于 select-best（59.5%）；说明收益主要来自“把不同客户端的机制组合进同一程序”，而不是简单保留专家并按域调度。
- **跨智能体的经验确实累积**：DS-1000 上客户端新增能力的保留率达 90%（20 项中保留 18 项）；其中多项能力仅存在于单一客户端，且合并 harness 还解决了没有任何单一客户端解决的两个项，即组合产生了新行为；对无客户端训练过的 Pytorch 域也有提升，说明存在跨域迁移。
- **集中式演化对比**：等预算下 EvolveNet（70.7%）优于集中式种群（67.3%）和每轮集中优化器（68.7%）；集中式容易出现停滞或回滚，EvolveNet 借助分工与并行避免。
- **模型无关性**：换用 MiMo-V2.5 后，EvolveNet 依然优于 select-best 和未演化 harness，定性的“接受增益、拒绝回归、最终优于基线”行为完全复现。
- **并行加速**：K=5 时客户端阶段比串行快 3.96×；端到端 T=3 的 BIRD 在 K=5 下 6110 秒，且精度不低于 K=1。
- **聚合行为具体可解释**：合并报告中展现了“将 hard-coded 的探测泛化、把另一个客户端的方言修复逐字纳入、拒绝 4 条破坏性的分片提示规则”等可读性强的实例，说明聚合依赖逐项证据而非盲目合并。

## 优点

- **范式创新**：将“聚合边界”从原始工作负载移动到“学到的程序适配”，从根本上解决了集中式演化的数据池化约束，使数据本地与协作改进可兼得。
- **方法设计严谨**：对程序聚合这一非算术问题给出明确的形式化（Eq. 8-17）、作用域隔离命题（Prop.1、2）和“提案 + 精确门”的求解结构，把不可枚举的搜索问题转化为可实现的启发式 + 可验证的约束。
- **实验设计注重公平与可归因**：配对评估协议、同一快照上重放不同聚合规则、门规则重放、跨模型复现等设计，能较好地区分“聚合规则本身”和“随机性/客户端质量”的贡献。
- **工程细节扎实**：冻结 solver 缓存、固定 hash seed、gold 审计与冻结时间线、无 gold 泄漏的静态审计器等，提升了结果的可靠性和可重复性。
- **可解释性**：不仅报告最终分数，还分析机制保留率、库级表现、合并报告中的具体操作，让读者能看到“聚合到底做了什么”。

## 不足与局限

- **隐私与泄漏风险**：数据本地性 ≠ 隐私；程序编辑本身可能编码客户端信息（如 hard-code 的 schema 探测），文中未量化此类泄漏，且没有威胁模型。
- **验证数据假设较强**：方法要求服务器有带标签且能代表部署分布的验证集，这比参数空间联邦学习通常的要求更严格。
- **作用域依赖可观察键**：HOME 机制的调度键必须在推理时可观测（数据库、库、仓库等可以；LiveCodeBench 的难度元数据较受限）。
- **程序规模单调增长**：三轮后 BIRD harness 从 14 行增至 253 行、DS-1000 从 17 增至 409 行；当前门不对行数增长进行惩罚，长期累积可能导致臃肿甚至性能下降。作者指出严格 tie-rejecting 门会损失效果（DS-1000 少 14 项、LCB 少 5 项），但真正的“机制退役/规模感知门”尚缺。
- **评估范围有限**：T≤3、K≤7；每轮仅一次局部生成；聚合规则对比只在一个快照上完成；无人工盲审（BIRD gold audit 为 LLM 审计）；所有结论建立在特定模型栈（deepseek-v4-flash）上，跨模型仅验证了单一场景。
- **监督需求**：方法依赖训练分片标签与验证标签，属于有监督协作适应，与无标签的 test-time 类 prior work 不可比。
- **gold 噪声**：BIRD 的 40 个 hard 项中存在 9 项 gold 不唯一（保留以兼容 prior work），会限制可达到的上限分数。
