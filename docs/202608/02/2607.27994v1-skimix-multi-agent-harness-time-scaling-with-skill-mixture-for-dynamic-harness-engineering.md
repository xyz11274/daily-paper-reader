## 摘要
AI智能体日益依赖大型技能库，但选择、组合和维护技能仍然困难。我们提出SKIMIX，一个多智能体框架，其中拥有不同技能组合的智能体通过迭代细化进行协作。SKIMIX结合了基于嵌入的技能检索、子模抗稀释路由和自适应技能进化。在六个推理基准上，多智能体协作显著改善了开放式数学推理，但在多项选择任务上带来的收益有限或为负。智能体数量的扩展是非单调的，且大部分改进出现在第一轮细化中。这些结果表明，任务特征决定了技能级集成是否有帮助，并为可扩展智能体设计提供了实用指导。

## Abstract
AI agents increasingly rely on large skill libraries, but selecting, combining, and maintaining skills remains difficult. We propose SKIMIX, a multi-agent framework in which agents with different skill portfolios collaborate through iterative refinement. SKIMIX combines embedding-based skill retrieval, submodular anti-dilution routing, and adaptive skill evolution. Across six reasoning benchmarks, multi-agent collaboration substantially improves open-ended mathematical reasoning but offers limited or negative gains on multiple-choice tasks. Agent-count scaling is non-monotonic, and most improvements arise during the first refinement round. These results show that task characteristics determine whether skill-level ensembles help and provide practical guidance for scalable agent design.

### 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现代AI智能体（Agent）越来越依赖大型技能库（Skill Libraries），但面临两大根本性挑战：
  - **技能组合难**：对任意查询，无人知晓最佳技能组合；查询不会显式表明所需技能，而技能组合空间太大无法穷举搜索。现有系统要么使用单一固定管道，要么依赖用户手动挑选技能，导致大部分技能库未被充分利用。
  - **技能稀释（Skill Dilution）**：随着技能库增长，冗余技能增加噪声、加大路由难度、拉低集成性能。
- **整体含义**：论文主张不要将所有技能打包给单个智能体，也不应固定单一管道，而是通过多智能体并行、每个智能体配备不同技能组合、并让其迭代共享与细化答案的方式，来系统性地解决技能组合与技能维护问题。这是首次系统性地研究“技能级集成”（skill-level ensemble）在不同任务类型上的扩展规律。

### 2. 方法论：核心思想、关键技术细节与公式

#### 2.1 核心思想
SKIMIX 源自于测试时扩展方法（Test-Time Scaling），借鉴 Mixture-of-Agents（MoA）和 Tool-Use Mixture（TUMIX）的思想，但将重点从模型多样性/工具多样性转向**技能组合多样性**——因为技能比模型/工具更廉价、更易混合、与任务表现更直接相关。系统通过多智能体、多技能组合的并行与迭代细化来提升推理性能。

#### 2.2 三大核心机制
1. **动态技能注册表（Dynamic Skill Registry, DSR）**
   - 每个技能 sᵢ 在嵌入空间中被编码为稠密向量 eᵢ ∈ Rᵈ，编码了能力概况、调用模式和成功率统计。
   - 嵌入通过句子编码初始化，并通过使用反馈在线更新：eᵢ⁽ᵗ⁺¹⁾ = eᵢ⁽ᵗ⁾ + η · ∇_{eᵢ} L_align(q, eᵢ, y)。
   - 支持新技能注册（k-NN索引）、相似度检索（top-k余弦相似度）、技能进化（过时技能标记弃用或再生）。

2. **抗稀释路由（Anti-Dilution Routing, ADR）**
   - 将技能路由建模为**子模最大化**问题，目标函数同时考虑相关性和多样性：
     P\* = arg max_{P⊆S, |P|≤k} Σ_{s∈P} rel(s,q) + γ · log det(I + K_P)
   - 其中 rel(s,q) 为嵌入相似度（相关性），log det(I + K_P) 为基于技能相似性核的行列式项（多样性）。
   - 贪心求解获得 (1−1/e) 近似保证；边际增益 Δ(s|P) < τ_min 的技能被排除或归档，从而在稀释发生前就阻止它。

3. **自适应技能进化（Adaptive Skill Evolution, ASE）**
   - 持续评估技能近期表现，过时技能被弃用；当使用模式暴露空白时，从观测到的推理轨迹中合成新技能。

#### 2.3 系统框架与流程
- 全局技能注册表 S = {s₁, ..., s_K}，技能组合 Pⱼ ⊆ S 分配给智能体 j。
- 策略 π 按轮决定：(i) 激活哪些技能组合、(ii) 通信图、(iii) 停止规则、(iv) 聚合规则。
- 优化目标：max_π P{âπ = a⋆} − λ · Cost(π)，即在计算预算与准确率之间做权衡。
- 默认使用 **15 个预设计技能组合**，分为五大类：
  - 推理类（Base, CoT, StructuredReason, Memory, Planning）
  - 代码类（CoTcode, Code, Code+）
  - 搜索类（三个不同后端的 Search）
  - 混合类（DualMode, Guided, Guided+）
  - 专业领域类（Analysis, Verification, MultiModal）
- 每轮中每个智能体同时考虑原始查询和上一轮所有智能体的解答，生成新解答（类似消息传递）；最终经多数投票选出答案。
- 终止策略采用 LLM-as-Judge 评估边际收益 Δᵣ = E[Aᵣ₊₁ − Aᵣ]，当边际收益≤边际成本则停止，最少运行 2 轮。

### 6. 主要结论与发现

#### 6.1 发现一：**任务类型决定多智能体的价值**
- **开放式推理（AIME、MATH-500）**：多智能体 SKIMIX 大幅优于单智能体自我细化。
  - AIME：Base 0.0% → Self-Refine 40.0% → SKIMIX-3 73.3%（相对提升+83%）；SKIMIX-15 达到 76.7%（相对单次基线提升76.7个百分点）。
  - MATH-500：SKIMIX-5 达 72.0%，比 Self-Refine（61.0%）高 11 个百分点。
- **多项选择（GPQA、MMLU-Pro、BBH）**：多智能体带来有限甚至负收益。
  - GPQA 上 Self-Refine 最优（88.0%），而 SKIMIX-3 = 78.0%（−10.0%）、SKIMIX-5 = 74.0%、SKIMIX-15 = 72.0%，随智能体增加单调下降。
  - MMLU-Pro 上方法差异极小（±3 点）。
  - BBH 上 SKIMIX 有中等增益（+12.0%，50.7%→62.7%）。
- **混合型（HLE）**：增益小但单调（43.0%→51.0%）。
- **解释**：开放题存在多解路径，多样性提升覆盖率；而选择题具有单一答案“地形”，多样推理引入冲突信号反而扰乱聚合步骤。

#### 6.2 发现二：**智能体数量扩展非单调**
- AIME 上 3 个智能体（73.3%）优于 5 个（70.0%），15 个才恢复到 76.7%（但需 5 倍智能体，仅多 3.3 点）。
- GPQA 上单调递减（88% > 78% > 74% > 72%），每增加一个智能体都使性能下降。
- MMLU-Pro 上 3 智能体（49%）低于 Self-Refine（51%），但 5 智能体（52%）又恢复。
- 结论：“更多智能体 = 更好性能”的默认假设不成立，最优 agent 数量须按任务实证确定。

#### 6.3 发现三：**第二轮细化贡献最大**
- 在全部基准和全部方法上，最大精度增益发生在 Round 1→2 之间。例如 AIME 上 SKIMIX-3 从 Round1 的 10.0% 跳到 Round2 的 62.2%；GPQA 上 Self-Refine 从 66.0%→74.0%。
- Round 3 收益递减甚至为负（如 GPQA 的 SKIMIX-15 从 Round2 的 82.8% 降至 Round3 的 74.5%），说明过度细化可能丢弃正确答案。

#### 6.4 发现四：**覆盖率显著高于最终准确率**
- 覆盖率与最终准确率之间存在持续差距。例如：AIME 上 SKIMIX-3 Round2 覆盖率为 76.7% 但最终准确率 73.3%；HLE 上 SKIMIX-15 Round2 覆盖率 72.0% 但最终准确率仅 51.0%（差距 21 点）。
- 说明当前瓶颈在于**答案聚合**而非候选生成，多数投票并非最优方案，未来可探索基于置信度或可靠性的聚合方法。
