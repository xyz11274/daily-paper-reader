## 摘要
大语言模型智能体发展迅速，但进展在领域、能力、任务难度和交互设置上仍然碎片化。我们将其定义为全场景智能体规模化，并提出AgentOmnia，这是一个协调任务空间定义、数据合成、后训练、评估和改进的框架，覆盖面向消费者（ToC）、面向企业（ToB）和面向员工（ToE）的应用。一个可扩展的“领域×能力×原子难度”分类法将这些阶段对齐，并通过OmniaBench实现细粒度诊断。AgentOmnia将双向环境-任务合成与工具依赖、程序结构和基于求解器的流水线相结合，构建了5,018个有状态环境，包含255,375个工具和52,361个任务。程序、求解器和验证器提供正确性信号，而监督微调、在线智能体强化学习和回滚课程支持后训练。评估失败转化为产品需求文档（PRD），用于有针对性的自我进化。从Qwen3-30B-A3B-Thinking-2507开始，AgentOmnia将OmniaBench挑战子集的通过率从9.16%提升至37.11%，并将OmniaBench、τ²-Bench、DeepPlanning和VitaBench上的宏平均值从22.86%提升至41.69%。在统一协议下，它在OmniaBench上领先于所评估的智能体后训练基线，并保持了最高的四项基准宏平均值。它还在所有四项基准上超越了Qwen3-235B-A22B-Thinking-2507，并在宏平均值上超过了Qwen3.5-35B-A3B。提升涵盖了三个应用划分、十个能力维度、八个原子难度因素以及90个一级领域中的76个，表明这是广泛的而非特定类别的改进。一项单轮研究为PRD引导的自我进化提供了初步证据，激励在更大规模和工业环境中进行验证。

## Abstract
Large language model agents have advanced rapidly, yet progress remains fragmented across domains, capabilities, task difficulty, and interaction settings. We frame this as full-scenario agentic scaling and present AgentOmnia, a framework coordinating task-space definition, data synthesis, post-training, evaluation, and improvement across To-Consumer (ToC), To-Business (ToB), and To-Employee (ToE) applications. An extensible Domain x Capability x Atomic Difficulty taxonomy aligns these stages and enables fine-grained diagnosis with OmniaBench. AgentOmnia combines bidirectional environment-task synthesis with tool-dependency, program-structured, and solver-based pipelines, constructing 5,018 stateful environments with 255,375 tools and 52,361 tasks. Programs, solvers, and verifiers provide correctness signals, while supervised fine-tuning, online agentic reinforcement learning, and a rollback curriculum support post-training. Evaluation failures translate into Product Requirement Documents (PRDs) for targeted self-evolution. Starting from Qwen3-30B-A3B-Thinking-2507, AgentOmnia raises the pass rate on the OmniaBench challenging subset from 9.16% to 37.11% and the macro-average across OmniaBench, $τ^2$-Bench, DeepPlanning, and VitaBench from 22.86% to 41.69%. Under a unified protocol,it leads the evaluated agentic post-trained baselines on OmniaBench and retains the highest four-benchmark macro-average. It also surpasses Qwen3-235B-A22B-Thinking-2507 on all four benchmarks and exceeds Qwen3.5-35B-A3B on the macro-average. Gains span three application splits, ten capability dimensions, eight atomic-difficulty factors, and 76 of 90 level-1 domains, indicating broad rather than category-specific improvement. A one-round study provides initial evidence for PRD-guided self-evolution, motivating validation at larger scales and in industrial settings.

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 总体框架

AgentOmnia 由四个模块构成闭环开发流程：

1. **全场景分类法（Full-Scenario Taxonomy）**：以“领域（Domain）× 能力（Capability）× 原子难度（Atomic Difficulty）”三维坐标统一任务空间，支撑数据合成、后训练、评估与诊断；
2. **可扩展数据合成（Scalable Data Synthesis）**：双向合成可执行环境与任务；
3. **弱到强合成与后训练（Weak-to-Strong Synthesis & Post-Training）**：模型生成候选，程序/求解器/验证器提供正确性信号；
4. **PRD 引导的自我进化（PRD-Guided Self-Evolution）**：将评估失败转化为结构化产品需求文档，引导下一轮数据合成与训练。

### 2.2 三维分类法

- **领域轴**：ToC（22 个 L1/101 个 L2 域）、ToB（38 个 L1/186 个 L2 域）、ToE（30 个 L1/67 个 L2 域），共 90 个 L1、354 个 L2 域。每个 L2 域需保证可落地到可执行、有状态的环境；
- **能力轴**：10 个能力维度——任务理解、信息收集、规划与决策、状态管理、工具使用、代码与程序化操作、数据分析、办公与文档处理、交互协作、可靠性与安全；
- **原子难度轴**：8 个原子难度因素——模糊目标与上下文约束、工具与参数接地、结构化信息复杂度、长上下文与多工件证据、动态多步规划、多源不一致、渐进披露与状态演化、风险/可靠性与澄清。任务可复合多个难度因素，并指定一个主难度。

每个任务由坐标 Z = (D, C, δ) 索引，支持细粒度覆盖统计与失败诊断。

### 2.3 数据合成框架

**环境合成（四阶段流水线）**：
- 环境种子挖掘：从查询种子（197K）、技能定义（20K）、MCP 规范（2.3K）、API 种子（1.3K）中筛选候选环境，按实用性和真实感评分；
- 状态空间构建：LLM 生成高召回实体/属性/关系/约束，编译为可执行 Python 状态容器；
- 工具集合成：生成、验证、归一化、多样化的可执行工具，引入多分支、多参数约束、结构化输出以及语义重叠但逻辑不同的工具；
- 可执行性验证：初始化级、工具级、环境级三级修正，不可修复者丢弃。

最终获得 **5,018 个环境、255,375 个工具**，平均每个环境 50.9 个工具、13.3 个实体、77.3 个属性。

**任务合成（三条互补流水线）**：
- **DAG 基合成**：构建工具依赖图，采样拓扑感知工具组，插入虚拟工具形成增强 DAG，生成可执行任务并验证任务-轨迹-状态一致性。产出 43,851 个 DAG-Standard 与 2,004 个 DAG-Challenge 任务；
- **程序基合成**：联合合成任务规格与参考程序，涵盖循环、分支、状态依赖控制流；通过执行接地调试、公共查询改写（去除工具名、API 签名等泄漏，防止模型走捷径）和验证与筛选。产出 2,204 个任务；
- **求解器基合成**：面向选择、分配、调度、规划等含资源约束或显式优化目标的任务。两种策略——
  - **隐式求解器引导（Implicit Solver-Guided）**：通过求解器感知的领域模式与任务蓝图，由 LLM 依据给定验证模式进行求解与评估，不执行真实求解器；
  - **显式求解器锚定（Explicit Solver-Anchored）**：执行真实求解器，用求解器验证的最优结果锚定任务构建与评估。产出 1,848 个隐式 + 2,454 个显式任务。

三个流水线共合成 **52,361 个任务**。

**轨迹合成**：
- 用户交互建模：通过人物卡片（persona）模拟真实用户的请求粒度、信息完整性、不一致/误导性细节；
- 能力感知特权引导：根据教师模型的失败类型提供两类引导——
  - 面向规划的引导（planning-oriented）：给出高层分解策略与执行启发式；
  - 面向结果的引导（outcome-oriented）：给出期望完成标准、约束、目标状态与验证要求；
- 轨迹质量验证：推理连续性、逻辑一致性、证据接地性三重检测，确保特权信息不泄漏到最终监督数据中。特权引导使 DAG-challenge 的验证 Pass@3 提升 28.0 个百分点、Solver 提升 22.1、Program 提升 12.6；证据接地性保持高位。

### 2.4 后训练：SFT + RCRL

- **SFT 冷启动**：53K 训练实例，包括格式验证、基于收敛需求的样本预算分配（不同轨迹源按各自学习难度分配监督预算）、上下文对齐（多轮轨迹仅保留最终用户查询对应的推理过程）；
- **强化学习（RCRL，Rollback-based Curriculum RL）**：
  - 基于 GRPO，去掉 KL 正则；
  - 用推理引擎的原始行为策略替代 PPO 中的近端策略，解决训练-推理分布失配；
  - 采用非对称裁剪（ε_low=0.2, ε_high=0.28）；
  - **动态回滚课程**：当一组 rollout 全零奖励时，强制延长黄金前缀并重新 rollout；每轮结束后根据组平均奖励自适应地增减前缀长度（奖励过高则缩短前缀、过低则延长），并采用混合目标：
    - L_RCRL(θ) = λ_CE · L_SFT(golden-prefix) + λ_RL · L_GRPO(on-policy exploration)；
  - 奖励系统：规则基+标准基（rubric）混合，路由与安全机制，异步 judge 服务，五维奖励模型校准（rubric 可靠性、Kendall tau-b 排序保持、优势方向可靠性、优势幅度一致性、重复评分一致性）；
  - 训练稳定技术：动态过滤、绕开 KL/熵正则、token 级训练-推理对齐、routing replay 等；
  - **Rollout 轨迹分析系统**：识别失败模式、归因奖励黑客（reward hacking）、发现能力缺口，指导奖励函数细化和下一轮数据合成。

### 2.5 PRD 引导的自我进化

- 诊断报告：任务级分析（单任务失败原因）→ 能力级分析（跨任务聚合出能力缺口）；
- PRD 生成：将诊断结果与外部需求规范化为结构化 PRD，包含目标场景、功能需求、失败证据、合成指导（环境合成+任务合成）；按失败频率与严重程度排序；
- 迭代训练循环：SFT 冷启动 + RL 微调，PRD 数据针对诊断出的弱点，基础分布数据保留既有能力；
- 产品端扩展：支持产品经理/领域专家直接输入 PRD，将部署后的交互日志与反馈纳入后续循环。

## 3. 实验设计与基准

### 3.1 评估基准

- **OmniaBench**：自主发布的配套诊断基准，共 1,431 个任务，挑战子集 644 个任务，任务已与训练语料去重，并按三维分类法标注，支持细粒度诊断；
- **τ²-Bench**：工具-智能体-用户交互，覆盖航空、零售、电信；
- **DeepPlanning**：购物与旅行场景的长时程规划；
- **VitaBench**：跨域、配送、店内、OTA 生活服务任务。

### 3.2 对比方法（四组）

- **专有通用模型**：GPT-5.5 (xhigh)、Claude Opus 4.7、Gemini 3.5 Flash、Qwen3.7-Max；
- **开源通用模型**：DeepSeek-V4-Pro-Max、Qwen3-30B-A3B-Thinking-2507（基座）、Qwen3-235B-A22B-Thinking-2507、Qwen3.5-35B-A3B、Qwen3.6-35B-A3B；
- **开源智能体后训练模型**：MUA-RL、Toucan、Nex-N1 变体、AgentSkiller、Arctic-AWM、EnvScaler、Nex-N2-Mini、Agents-A1；

## 5. 实验数量与充分性

**实验规模较充分，主要包含：**

1. **主实验**：4 个基准 × 20+ 个模型（含专有、开源通用、开源智能体后训练、来源报告），统一评估协议；
2. **细粒度诊断**：
   - 90 个 L1 领域的通过率对比（76 个提升、12 个持平、2 个下降）；
   - 10 个能力维度逐项对比（提升 25.00–36.77 个百分点）；
   - 8 个原子难度逐项对比（提升 21.43–47.73 个百分点）；
   - ToC/ToB/ToE 三分组对比（+28.37/+28.17/+26.42）；
3. **消融/分析实验**：
   - 特权引导 vs 无特权引导的轨迹合成 Pass@3 对比；
   - 特权引导下轨迹证据接地性检测（表 7）；
4. **单轮 PRD 自我进化实验**：诊断基准（OmniaBench）从 37.11% → 38.49%，外部基准平均从 43.22% → 44.14%。

**充分性评价**：
- 优点：统一评估协议下横向对比多个基线，覆盖多基准、多维度，能够证明改进的广泛性而非单一基准特化；OmniaBench 任务与训练语料去重，降低数据泄漏风险；外部基准独立开发，验证泛化性；
- 不足：
  - 与 Qwen3.5 系基线（Agents-A1、Nex-N2-Mini）基础模型代差不同，DeepPlanning 上仍落后，公平性受基础模型差异影响；
  - 自我进化实验仅一轮、804 个任务，作者自述为“初步证据”，细粒度指标有升有降；
  - 未给出多轮进化、更大规模数据下的收益曲线与稳定性分析；
  - 与专有前沿模型差距仍大（宏平均落后 DeepSeek-V4-Pro-Max 约 19.4 分、GPT-5.5 约 26.9 分），表明框架价值虽被验证但规模化空间尚存。

## 6. 主要结论与发现

- AgentOmnia 从 Qwen3-30B-A3B-Thinking-2507 出发，将 OmniaBench 挑战子集通过率从 **9.16% 提升至 37.11%**，四基准宏平均从 **22.86% 提升至 41.69%**；
- 在同类 30B 级智能体后训练模型中取得最强 OmniaBench 成绩和最高四基准宏平均，微弱领先 Agents-A1（41.69 vs 41.52）、明显领先 Nex-N2-Mini（40.06）；
- 全面超越更大的 Qwen3-235B-A22B-Thinking-2507（34.17），并超过 Qwen3.5-35B-A3B 的宏平均（36.92）；
- 改进是**广泛的而非类别特化**的：覆盖 76/90 个 L1 域、全部 10 个能力维度、全部 8 个原子难度因素；
- 特权引导能显著提升困难任务的轨迹合成效率且不牺牲监督数据的证据接地性；
- KL 散度对比表明 PRD 引导合成数据与失败分布更对齐（0.196 vs 0.603），单轮训练带来正向收益和外部迁移效果；
- PRD 引导的自我进化具有初步可行性，但多轮稳定性与工业规模收益仍需验证。

## 7. 优点与亮点

1. **统一的分类学坐标系统**：三维分类法贯穿数据合成、训练、评估、诊断全流程，使“改进什么”有据可依，而不是只看总分；
2. **双向环境-任务合成**：环境导向（环境覆盖驱动任务）与任务导向（任务需求驱动环境构造）结合，提升覆盖与难度控制的灵活性；
3. **三种互补任务流水线**：DAG（顺序/长时程）、程序（分支/循环/数据依赖）、求解器（全局约束下的规划与优化），拓宽了任务的推理结构类型；
4. **弱到强合成范式**：模型生成候选，程序、求解器、状态转换检查与结构化验证器提供正确性信号；特权引导只用于教师模型生成，不进入最终监督数据，兼顾“困难轨迹可生成”与“监督数据可信”；
5. **回滚课程强化学习**：针对 all-fail 任务，从黄金轨迹前缀出发渐进探索，解决了传统组相对 RL 在困难样本上无学习信号的问题；混合目标同时保证前缀复现能力与 on-policy 探索；
6. **奖励模型五维校准**：超越简单准确率，直接度量排序保持、优势符号、优势幅度与重复评分一致性等与组相对 RL 训练质量强相关的指标；
7. **轨迹分析系统**：将奖励黑客、工具调用异常等行为模式转化为可操作的奖励细化与数据合成建议，形成闭环；
8. **PRD 作为可解释进化接口**：连接评估证据、利益相关者需求与数据合成，兼顾内外部反馈路径，实践意义强；
9. **工程系统完备**：环境沙箱（集群调度、运行时隔离、统一 API）、训练-推理对齐（路由重放、top-p=1、TI/TO token 对齐）等技术细节完善；
10. **评测严谨性**：OmniaBench 与训练语料去重、统一评估协议、外部基准独立验证、消融实验设计较完整。

## 8. 不足与局限

1. **基础模型代差带来的比较公平性偏差**：Agents-A1 和 Nex-N2-Mini 基于更新的 Qwen3.5 基础模型，DeepPlanning 上的落后很可能部分来自基础模型规划能力差异而非后训练方法的不足；作者也承认 13.16 分的 DeepPlanning 差距与基础模型推理/规划强度相关；
2. **自我进化证据不足**：仅一轮、804 个任务的小规模实验，增益 1.38 个百分点属“初步证据”，多轮进化的收益累积、稳定性、过拟合风险尚未验证；
3. **数据泄漏风险未完全消除**：尽管 OmniaBench 与训练语料去重，但其任务构造方法与合成方法论部分同源，Author 也承认 OmniaBench 的大幅提升需在“分类法对齐和部分方法论复用”的背景下解读；
4. **合成环境与真实应用存在差距**：代码驱动合成环境虽可扩展，但真实 API 的偶然性、权限复杂性、外部系统交互等未必完全模拟，工业环境中的实际部署表现尚待验证；
5. **细粒度弱点仍突出**：Ambiguous Goal 与 Contextual Constraints 的绝对分数仍低（37.04%），Multi-source Inconsistency 提升最小（+21.43），说明模糊目标理解与多源冲突处理仍是短板；
6. **算力与工程成本未披露**：无法评估训练成本、复现难度，有工程门槛（环境合成、验证、RL 基础设施

6. **算力与工程成本未披露**：无法评估训练成本与复现难度，完整复现需重建环境合成、验证器、RL 基础设施等全套系统工程，技术门槛较高。

7. **评估基准各自为政**：论文依赖多个外部基准（τ²-Bench、DeepPlanning、VitaBench），各基准的任务分布、交互协议与难度定义差异较大，宏平均的解读受基准构成影响；OmniaBench 虽提供统一诊断，但其任务规模（1,431 个）相对 52K 训练任务仍偏小，细粒度统计的稳定性有限。

8. **能力覆盖存在偏置**：分类法虽宣称 ToC/ToB/ToE 三分，但实际数据合成以可模拟、可验证的 API/工具生态为主，对多模态交互、物理世界操作、多人协作等场景覆盖不足；10 个能力维度中"交互协作与可靠安全"的验证主要依赖模拟用户与沙箱，与真实部署仍有距离。

9. **RL 训练稳定性依赖启发式**：回滚课程、动态前缀调整、奖励校准等虽有效，但超参数（ε_low/ε_high、前缀长度调整幅度、混合目标权重）缺乏系统敏感性分析，方法的可迁移性尚不明确。

## 9. 结论与展望

AgentOmnia 的核心贡献在于给出了一个**"分类学驱动的全场景智能体规模化"范式**：以三维分类法为坐标系，将环境合成、任务合成、弱到强监督、后训练与 PRD 引导的自我进化统一在同一个可诊断、可迭代的闭环中。实验结果表明，该范式能从单一的开源基座模型出发，在 30B 级参数规模下取得与更强基座模型后训练相当甚至更优的综合表现，且改进覆盖大部分领域、能力维度和难度因素，具有较强的泛化性与工程可行性。

从研究意义上讲，这项工作与单纯堆数据、堆算力或设计更强提示策略的路线形成鲜明对比，其真正价值在于：

- **将"智能体能力提升"从黑盒分数追逐转变为可定位、可归因、可迭代的工程-科学问题**；
- **验证了弱到强合成+程序/求解器校验的可扩展性**，为在缺乏真实环境 API 时构建高质量训练数据提供了可复制的通用路径；
- **示范了"评估失败→结构化 PRD→针对性数据合成→再训练"的自我进化闭环**，虽然目前仅有一轮初步证据，但方向明确，具备进一步发展的潜力。

未来的关键方向包括：多轮自我进化的稳定性与过拟合控制；更强基座（如 Qwen3.5 及以上代际）上的方法迁移；跨模态与真实物理/多人协作场景的覆盖；将 PRD 接口与更广泛的产品反馈（日志、用户投诉、业务指标）做端到端打通；以及在公开算力预算下对框架各组件进行更精细的成本-收益分析。

总体而言，AgentOmnia 是一篇工程系统性强、方法论完整、评测规范的高质量工作，在智能体数据合成与后训练领域具有明确的参考价值。但其结论仍需在更多代际基座、更多外部基准和更长期的自进化循环中得到进一步验证。
