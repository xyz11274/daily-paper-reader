## 摘要
大语言模型智能体日益在动态环境中运行，其中工具接口、API和用户需求在部署后发生变化。现有的自进化方法主要遵循两种范式：基于外部机制的方法，将反馈外化为可编辑的记忆或技能以实现快速适应；以及基于参数的方法，将经验内化为模型参数以进行更深层次的能力提升。然而，单独使用任何一种机制都会在灵活性和性能之间产生权衡。本文探讨智能体如何协调这两种渠道以实现稳健的自进化。我们提出了COVE，一个统一的智能体自进化框架，通过任务感知路由、阶段感知调度和知识优化，将基于外部机制的学习与基于参数的学习相结合。通过这种设计，COVE将自进化视为一个协调过程，而非对经验不加区分地积累，该过程将任务和知识类型与适当的学习机制相匹配。跨多个任务类别的实验表明，COVE优于单通道进化策略，在变化的环境下展现出更稳健和高效的改进。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

### 1. 论文的核心问题与整体含义

- **背景**：大语言模型（LLM）智能体越来越多地被部署在动态环境中，工具接口、API、数据库模式、用户需求在部署后会持续变化。要让智能体长期保持高性能，需要频繁重新配置或重训练，成本高昂（人力+算力）。智能体自进化（Agent Self-Evolution）通过把任务执行过程中的环境反馈转化为可复用经验，让智能体持续适应新任务与新环境。
- **现有两大范式及其矛盾**：
  - **基于外部机制（Harness-based）**：如 Evo-Memory、Reflexion、Voyager，把反馈总结为外部记忆/技能，推理时检索注入。优点是快速、灵活、易增改，但基础模型能力不足时可能产生误导性经验，且对深层推理能力提升有限。
  - **基于参数（Parameter-based）**：如 WizardLM、Self-Challenging，通过 SFT/RL 更新模型权重。优点是可内化稳定推理模式，但训练成本高、适应慢，且对表面接口变化（如 API 改名）脆性很大。
- **核心问题**：两类方法的局限互补，但单独使用任一通道都无法兼顾灵活性与性能。**关键问题是：何时该"记住"（存外部记忆）、何时该"内化"（写入参数）、以及两者如何协调？**
- **整体含义**：论文主张自进化不应是经验的 indiscriminate accumulation（不加区分地积累），而应是一个"任务和知识类型——学习机制"相互匹配的协调过程，由此提出统一框架 **COVE**。

### 2. 论文提出的方法论

#### 2.1 核心思想
COVE（Channel Orchestrated Volatility-aware Evolution）将自进化建模为"双通道协调"：外部知识库（Harness）与模型参数（Parameter）不是二选一，而是通过三类机制协同工作，并依据**任务类型、学习阶段、知识波动性（volatility）**三个维度动态决策。

#### 2.2 三个关键组件

**（1）任务感知路由（Task-aware Routing）**
- 将路由建模为"反馈条件化的决策策略"，而非手工打分函数。
- 给定任务描述 τᵢ 与执行反馈 fᵢ（含结果状态、标量分数、诊断信息），由约束法官（constrained judge）输出结构化决策记录 dᵢ=(mᵢ, sᵢ, rᵢ)，其中 mᵢ 为通道选择，sᵢ 为任务语义描述（如 `dynamic_tool`、`logical_rigor`），rᵢ 为一句理由。
- 通道分三类：`harness_only`（波动性或上下文知识导致失败）、`parametric_candidate`（需内化能力）、`hybrid`（两者兼有）。

**（2）阶段感知调度（Stage-aware Scheduling）**
- 通过可复现的触发条件动态决定何时切换通道，而非固定顺序：
  - **性能平台期（Plateau）**：最近 w 轮的成功率/平均奖励提升低于阈值 ε；
  - **数据充分性（DataSufficient）**：高质量轨迹数 |D_q| ≥ N；
  - **冷启动失败（ColdStartFailure）**：任务族前 k 个任务成功率低于阈值 τ_c，说明 harness 无法自举，需先做参数训练建立最低能力基线。
- 触发逻辑：`Trigger = Plateau ∨ DataSufficient ∨ ColdStartFailure`。
- 覆盖两种路径：常规的"先 harness 探索、再参数内化"路径，以及冷启动领域"先参数训练建立能力地板、再 harness 进化"的反向路径。

**（3）KnowledgePO：双模态知识优化**
- 核心是对知识条目做**波动性标注**：ℓ ∈ {volatile（波动）, stable（稳定）, strategic（策略）}；反复修订的非波动条目会被提升为 volatile。
- **记忆辅助参数训练（Harness-assisted Parametric）**：训练前进行 memory-aware rollout，检索 top-k 记忆注入上下文，提高轨迹质量；volatile 条目用 `<volatile>...</volatile>` 显式标记。
  - **抗背诵奖励（Anti-Recitation Reward）**：训练前将 volatile 条目中的名字随机重命名，若模型调用过时或未观察到的旧名称则惩罚：
    - R = R_task − λ·I[使用了过时或未观察到的 volatile 名称]
    - 目的是让模型学会"读当前条目再行动"而非"记住并重复"。stable 知识不惩罚，允许内化。
- **参数辅助记忆释放（Parametric-assisted Harness, Memory Release）**：训练后在 held-out 子集上做 A/B 评估，若稳定记忆在训练后不再显著提升效果（Δⱼ 低于阈值），则标记为已内化并从在线检索集中释放（可保留在归档库）。volatile 记忆永不释放。

#### 2.3 整体目标函数
最大化累计任务效用，同时惩罚推理 token 成本与参数训练计算成本：
max Σᵢ Rᵢ − α·Σᵢ C_tokⁱ − β·Σₘ C_trainᵐ

#### 2.4 算法流程（Algorithm 1）
检索记忆 → harness 推理 → 收集反馈 → 提取并标注候选知识 → 更新知识库 → 路由决策 → 按 Trigger 判断是否切换参数训练 → 训练时注入记忆并施加抗背诵惩罚 → 训练后评估稳定记忆释放/丢弃/保留 → 恢复 harness 交互。

### 6. 论文的主要结论与发现

1. **单一通道均不充分**：harness 记忆无法解决能力瓶颈（Lean 上记忆积累几乎不提升成功率），参数学习在接口变化时严重脆化（API 改名致成功率下降 59.3%）。
2. **通道选择须按任务分层**：波动性任务（如动态 API）需要可编辑的 harness 适应；能力受限任务（如形式化证明）需要参数学习。
3. **切换时机是独立决策变量**：平台期触发的参数更新优于"全程参数训练"与"仅 harness"；冷启动场景则需反向（先参数后 memory）。
4. **知识应差异化处理**：波动性（volatile）、稳定性（stable）、策略性（strategic）三类知识的存储机制应不同；频率高不等于可内化，高频接口知识恰恰最危险。
5. **抗背诵机制有效**：防内化 volatile 表面形式能显著提升接口变化下的鲁棒性，且不损害同分布性能。
6. **自进化的本质**：应视为"反馈是异质知识，其存储与更新机制须匹配稳定性与复用模式"的协调过程。

### 7. 优点

- **问题定位精准**：清晰诊断了两类方法的互补瓶颈，并用两套诊断实验（Lean 平台期、API 改名）给出量化证据，而非空谈。
- **框架统一且模块化**：路由、调度、知识优化三组件解耦清晰，各自的消融接口干净（可单独去掉 Trigger 或 Router 做对照）。
- **知识波动性（volatility）标准有洞见**：反对"高频=值得内化"的直觉，指出高频接口知识是最危险的，这一视角有较强的学术启发价值。
- **抗背诵奖励设计巧妙**：通过训练前随机改名 + 惩罚失忆调用的方式，把"防止记忆化表面形式"转化为可优化的奖励信号；注意力分析进一步佐证其机制。
- **效率意识强**：以"性能/token"为优化目标，86% 的 token 缩减是有说服力的实际收益。
- **路由过程可解释**：约束法官输出通道 + 语义描述 + 一句理由，且跨三个骨干模型 >95% 一致性，增强了可信度。

### 8. 不足与局限

- **实验覆盖有限**：主实验只用 Qwen3-8B 一个 8B 规模模型，未验证在更大模型（如 70B+）或更小模型上的可扩展性与结论稳定性；跨骨干测试仅覆盖路由模块。

- **Router 依赖 LLM 判断**：约束法官本身可能引入判断偏差或成本，论文未详细分析路由器判断错误的代价与容错机制。

- **未报告关键训练细节**：缺乏训练轮数、总时长、收敛曲线等，复现门槛较高。
- **无真实部署验证**：所有实验均为离线 benchmark，未在真实 Agent 持续运行环境中评估长期自进化的稳定性与安全性。
