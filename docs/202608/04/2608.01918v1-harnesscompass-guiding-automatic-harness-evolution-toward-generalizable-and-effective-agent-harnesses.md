## 摘要
Harness设计通过塑造大型语言模型（LLMs）在可执行环境中感知、推理和行动的方式，对智能体性能起着关键作用。近期工作提出了自动harness演化，通过智能体-环境交互迭代改进harness。然而，现有方法常常过度适应演化任务，仅依赖轨迹衍生的信号，并联合优化harness组件，导致组件间相互干扰。我们提出HarnessCompass，一种新颖的自动harness演化框架，围绕约束演化、主动反馈和组件级优化构建。HarnessCompass首先对演化施加全局约束，将修改限制在与任务无关的harness变化上，从而超越演化任务进行泛化。然后，它利用来自智能体关于harness使用的主动第一人称反馈来增强轨迹衍生证据，为演化提供更丰富的信号。最后，它将不同harness组件的优化解耦，再整合为一个统一的harness，在减少跨组件干扰的同时保留组件协同作用。在GPT-5.4上的SWE-bench Verified中，HarnessCompass仅用5次演化迭代即将Pass@1从54%提升至66%，在有效性和演化效率上均优于AHE。此外，演化后的harness能有效迁移到保留任务和其他模型，展现出比先前自动harness演化方法更强的泛化能力。

## Abstract
Harness design plays a critical role in agent performance by shaping how large language models (LLMs) perceive, reason over, and act within executable environments. Recent work has proposed automatic harness evolution, which iteratively improves the harness from agent--environment interactions. However, existing methods often overfit to the evolution tasks, rely exclusively on trajectory-derived signals, and optimize harness components jointly, causing interference across components. We propose HarnessCompass, a novel automatic harness evolution framework built around constrained evolution, proactive feedback, and component-wise optimization. HarnessCompass first enforces global constraints on evolution, restricting modifications to task-agnostic harness changes that generalize beyond the evolution tasks. It then augments trajectory-derived evidence with proactive first-person feedback from the agent about harness usage, yielding richer signals for evolution. Finally, it decouples the optimization of different harness components before consolidating them into a unified harness, reducing cross-component interference while preserving component synergy. On SWE-bench Verified with GPT-5.4, HarnessCompass improves Pass@1 from 54\% to 66\% in only 5 evolution iterations, outperforming AHE in both effectiveness and evolution efficiency. In addition, the evolved harness transfers effectively to held-out tasks and other models, demonstrating substantially stronger generalization than prior automatic harness evolution methods.

## 1. 论文的核心问题与整体含义

### 研究背景
- **Harness（外壳/脚手架）** 是连接大语言模型（LLM）与可执行环境的软件层，涵盖提示词、工具、中间件、记忆和验证例程等组件，它决定了智能体如何感知状态、推理和行动。
- 即使固定基础模型不变，仅设计不同的 Harness 就能显著改变智能体的性能，因此 Harness 设计是提升智能体能力的重要杠杆。
- 由于最优 Harness 因模型而异，且基础模型迭代速度快，手工调优难以跟上，学界提出了**自动 Harness 演化**（automatic harness evolution）：由元智能体（meta-agent）基于智能体-环境交互轨迹，迭代地提出、评估并改进 Harness 修改。

### 现有方法的三大局限
论文识别出现有自动 Harness 演化方法的三项关键缺陷：

1. **过拟合搜索任务**：元智能体可自由修改 Harness 以迎合固定任务集的验证信号，容易把任务特定的"捷径"编码进 Harness，导致在保留任务上泛化能力差。
2. **仅依赖轨迹信号**：元智能体只能从外部观察任务失败的位置和结果，却无法得知智能体为何觉得 Harness 难用，容易产生归因错误（例如将 Harness 摩擦误判为智能体错误）。

3. **联合优化组件**：提示词、工具、中间件、记忆等组件在同一轮中被同时修改，各编辑之间相互干扰，孤立的增益难以叠加。

### 核心论点
- 问题的根源不在于 Harness 演化本身，而在于**演化过程缺乏结构和纪律**——无约束的编辑招致过拟合、仅结果导向的证据招致误归因、同步编辑招致干扰。
- 有效的 Harness 应来自一个有纪律的演化过程：约束"能改什么"、为元智能体提供更丰富的证据、在合并前隔离各修改。

## 2. 方法论：HarnessCompass 框架

### 总体框架与算法流程
HarnessCompass 沿用"评估→分析→改进"的迭代闭环，但以三项原则施加纪律。完整演化流程见算法（Algorithm 1），每轮迭代的核心步骤：

1. 在当前 Harness 下对搜索任务集进行 k 次 rollout，收集轨迹；
2. 从轨迹中蒸馏证据（trajectory-based evidence）；
3. 收集智能体的第一人称反馈并做轨迹接地验证（grounding）；
4. 在**结构（structural）** 和**指导（guidance）** 两个轨道上**并行**运行受限演化，各自产生一个 Harness 变体；
5. 分别评估两个变体，选出胜者；
6. 通过 **R³合并** 将败者的有益编辑整合进胜者，得到本轮最终 Harness；
7. 仅当胜者优于当前最优时接受新 Harness。

### 原则一：约束演化（Constrained Evolution）
- 动机：防止过拟合搜索任务。
- 实现方式：设置一个覆盖全部七类组件的**全局泛化门（Generalization Gate）**，对每次候选编辑施加两项要求：
  - **内容要求**：禁止提及特定任务实例、测试函数、私有符号、任务专属关键词匹配分支等；只允许"可复用决策准则 + 可评估的适用性条件"，确保编辑经验可在未见任务上被独立评估。
  - **位置要求**：将编辑分为两类并指定其允许的落点——
    - **能力编辑（capability edits）**：新增可执行功能（如运行测试、安装缺失依赖），必须放在中间件、工具或子智能体中，以确定性代码实现；
    - **指导编辑（guidance edits）**：仅提供行为指导，必须放在系统提示词或记忆中，禁止写成可执行逻辑，以免指导被无差别触发或失效。

### 原则二：主动反馈（Proactive Feedback）
- 动机：轨迹只能显示"失败在哪"，不能揭示"为什么 Harness 难用"；第一人称反馈能暴露使用摩擦与缺失能力。
- 实现流程（四阶段）：
  1. **盲报告（blind report）**：向生成轨迹的智能体展示轨迹但**不透露验证结果**，让其报告 Harness 阻碍点与期望的缺失能力，避免事后合理化（hindsight bias）；
  2. **事后报告（hindsight report）**：透露验证结果，让智能体将失败归因于四种原因（Harness、自身推理、任务歧义、环境），从而过滤掉 Harness 无法修复的失败；
  3. **协调（reconciliation）**：合并两份报告为统一反馈项，记录其一致程度；
  4. **轨迹接地（grounding）**：仅保留轨迹能直接支持的反馈——已有组件的抱怨须有轨迹证据，新能力请求须对应轨迹中确实存在的缺口；凡不支持的反馈一律丢弃。
- 聚合与使用：按组件分组、以确定性程序计算置信度（依据报告间一致性、受影响任务数、盲/事后报告吻合度），注入元智能体的演化查询中，作为轨迹证据的补充而非替代。

### 原则三：组件级优化（Component-wise Optimization）
- 动机：同时修改所有组件会造成相互干扰。
- 实现方式：
  1. **双轨道并行演化**：每轮并行运行两个 Harness 变体——结构变体仅修改中间件、工具实现、子智能体；指导变体仅修改系统提示词、技能、工具描述、记忆。两变体编辑不相交的文件，互不干扰；
  2. **R³合并**：以胜者为基座，分三步整合败者的有益编辑——
     - **Revision（修订）**：逐条审查败者编辑，仅保留独立有益、不与胜者重复或冲突的修改，丢弃回归、任务特定规则与不确定修改；
     - **Recombination（重组）**：将保留的编辑应用到胜者基座上，文件级冲突时胜者优先；
     - **Refinement（精简）**：主动寻找并删除功能重复的冗余编辑，保留更确定性的实现。

### 初始 Harness
- 刻意从极简 Harness（H0）起步：仅一个 shell 命令工具 + 简短系统提示词，无中间件、技能、子智能体或长期记忆。这样确保后来 Harness 的每个组件都是演化循环自身引入并度量过的。

## 6. 主要结论与发现

1. **有效性**：HarnessCompass 在 SWE-bench Verified 上将 GPT-5.4 的 Pass@1 从 54.0% 提升至 66.0%，仅需 5 次迭代，最终性能和演化效率均超越 AHE（63.0%，20 次迭代）。
2. **泛化性**：在 450 个未见任务上，HarnessCompass 达到 60.4%，显著高于 AHE 的 54.7%（差距 5.7 点，比演化集上的 3.0 点差距更大），说明其改进是任务无关的设计原则而非任务特定捷径。
3. **跨模型迁移**：冻结 GPT-5.4 演化的 Harness 后，Claude-Sonnet-4.6 的总 Pass@1 从 70.0% 提升至 73.8%，证明学到的是可复用工程改进而非模型特定修复。
4. **三项原则互补**：泛化门提升可迁移性；主动反馈扩大优化信号；R³ 在保持增益的同时恢复泛化并大幅减少迭代次数。
5. **收益分布**：性能提升广泛分布在大型仓库（django +10.8 点、sphinx +22.8 点、pytest +15.8 点），且集中在种子 Harness 较弱的"Harness 敏感"仓库。
6. **机制验证**：案例研究表明，无门演化的记忆积累的是任务特定配方（类似"答案簿"），而有门演化的记忆沉淀为带适用条件的跨任务决策准则。
