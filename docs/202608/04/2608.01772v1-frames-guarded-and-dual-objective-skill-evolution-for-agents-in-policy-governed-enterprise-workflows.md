## 摘要
LLM 智能体越来越多地运行受策略约束的企业工作流，例如文档审计，在这些工作流中，它们必须一致地应用规则、验证每个数值，并保持可审计性。改进这些智能体很困难：运营反馈稀疏且未标记，对一条规则的编辑可能导致无关案例的回归，而且必须在不增加推理成本或失去可审计性的情况下提高准确性。我们提出了 FRAMES，一个闭环框架，它从现有资产中冷启动可部署的技能，然后通过基于共识的变异、基于准确性和成本的 Pareto 选择以及防回归保证来进化这些技能，同时保持可审计性。在我们内部生产系统上的部署表明，FRAMES 在基线中实现了最佳的准确性-成本权衡，并且在 tau-bench 上复现了相同的收益。

## Abstract
LLM agents increasingly run policy-bound enterprise workflows such as document auditing, where they must apply rules consistently, ground every value, and stay auditable. Improving these agents is hard: operational feedback is sparse and unlabeled, edits to one rule can regress unrelated cases, and accuracy must improve without inflating inference cost or losing auditability. We present FRAMES, a closed-loop framework that cold-starts deployable skills from existing assets and then evolves them through consensus-based mutation, Pareto selection over accuracy and cost, and an anti-regression guarantee, all while preserving auditability. Deployed on our internal production system, FRAMES attains the best accuracy-cost trade-off among baselines, with the same gains reproduced on tau-bench.

# FRAMES：策略治理企业工作流中智能体的受保护与双目标技能进化

## 1. 核心问题与研究动机

### 研究背景与问题
- 大型语言模型（LLM）智能体越来越多地被部署于**受策略约束的企业工作流**（如金融文档审计、案件验证、客户服务），这类场景要求智能体必须：
  - **一致性**地应用企业规则；
  - 对每个数值进行**可溯源（grounding）**验证；
  - 全程保持**可审计性**（auditability）。
- 然而，改进这类生产环境中的智能体面临三重核心困难：
  - **反馈稀疏且未标记**：运营反馈来自过往案例结果、审核人批注或失败日志，规模小且缺乏标签，难以直接用于监督学习。
  - **规则修改易致回归**：对一条规则的编辑可能破坏与之交互的其他规则，导致无关案例表现下降（即“修复一个，破坏另一个”）。
  - **成本与可审计性约束**：高吞吐场景下推理成本与准确率同等重要；任何变更必须可审查、可回滚，且需免重建部署。
- 现有技能进化方法（如 AutoSkill、EvoSkill、SkillRL 等）均未针对受监管企业环境设计：要么不处理冷启动问题，要么缺乏逐类别防回归机制，要么未将成本作为目标函数，要么不满足审计生命周期需求。

### 论文目标
- 提出 **FRAMES**（Feedback-driven Reasoning with Adaptive Mutation and Evolution of Skills），一个**闭环技能进化框架**，在受监管企业工作流的治理约束下持续改进智能体的技能库（Skill Bank），同时保证可审计性、防回归和成本可控。

## 2. 方法论

### 2.1 问题形式化
- 将技能进化建模为**双目标优化**问题：

> max_S ( PR(S), −Cost(S) )
>
> s.t. PR_c(S) ≥ PR_c(S₀), ∀c ∈ C

其中：
- S 为技能库；
- PR(S) 为通过率（pass@k），Cost(S) 为平均每案例的 LLM 推理 token 消耗；
- C 为运营类别集合（不同业务风险级别）；
- S₀ 为进化起始技能库，约束确保**逐类别不回归**。

### 2.2 两阶段框架

#### 阶段一：冷启动（Cold Start）
- **策略到技能生成**：LLM 将企业策略文档按程序边界切分，并将每段重写为自包含的 SKILL.md 技能，附带描述字段与策略回链（policy back-link），确保每次智能体行为可追溯到源策略条款。
- **反馈分流与引导**：
  - 从策略文档合成基线案例集（未覆盖策略条款 → 案例）；
  - 若存在原始运营反馈，通过 LLM 分类器区分为**经验性知识**（不可执行建议，追加至技能附加上下文）与**可执行反馈**（转为结构化案例 (mᵢ, tᵢ)）——mᵢ 为诊断记录，tᵢ 为带评分标准（rubric）的可执行评估任务。
- **持续反馈摄入**：后续通过三个渠道持续吸收新案例——人工审核、自动化轨迹分析、策略更新，各渠道均有专门的 LLM 转换器。

#### 阶段二：进化循环（Evolution Loop）
- **技能检索与基准锚定**：基于案例诊断记录对技能库进行语义–词汇混合检索，选出 top-k 技能构成工作范围 P₀，并在当前案例集上评测获得基线 E₀，作为防回归门锚点和 Pareto 前沿种子。
- **受保护变异（Guarded Mutation）**——每轮迭代生成候选的四个步骤：
  1. **父代选择**：对当前前沿成员进行**轮询式非贪婪选择**，避免搜索坍缩到单一准确率–成本折中端。
  2. **分布式诊断**：将诊断记录划分为 N 个不相交批次（每轮重新洗牌），每批由一个独立 LLM 诊断器分析，输出提议 δᵢ = (targets, root_cause, plans)。批处理实现类似 bagging 的多样性；跨迭代重洗牌让相关失败以新组合共现，暴露隐藏的根因。
  3. **共识整合**：整合器先进行投票过滤（默认按技能投票，低于 q 个诊断器同意的编辑被丢弃），再由 LLM 将保留提议合并为统一编辑计划。
  4. **技能重写**：对每个目标技能，从回归池检索锚定案例（anchor cases）作为行为约束，防止灾难性遗忘；LLM 重写技能（保留未触及技能不变）。每次编辑都是自然语言 readable diff，可版本化、可审计。
- **评分与准入（Scoring & Admission）**：
  - 候选在“当前案例集 + 回归池采样子集（大小为当前评估集的 50%）”上评估；
  - **逐类别防回归门**：

> PR_c(P′) ≥ (1 − ε) · PR_c(P₀), ∀c ∈ C

  ε 为容差（默认 5%）以吸收评估噪声；锚定在 P₀ 而非当前父代，防止质量下限随迭代次数的指数衰减（(1−ε)ᵗ）。
- **双目标前沿（Dual-Objective Frontier）**：
  - 通过 Pareto 支配关系维护非支配候选集合：

> a ≻ b ⟺ o(a) ≥ o(b) ∧ o(a) ≠ o(b)，其中 o = (PR, −Cost)

  - 构成覆盖准确率–成本权衡的**部署菜单**，运营商可按工作负载的风险与预算选择操作点；
  - 连续 τ 代无新成员晋入即停止，选定最优 P* 提交回技能库，其解决的案例并入回归池。

## 6. 主要结论与发现

1. **FRAMES 在全部三个场景的一致领先**：
   - FinDAS 测试集上 FRAMES 总通过率达 0.80（[0.74, 0.85]），每类别均领先最强基线 B5 0.07–0.11（McNemar p=0.0026）；
   - τ-bench 零售域 FRAMES 以最低成本并列最佳总质量（0.98），是唯一在 general 类达到 1.00 的方法；
   - τ-bench 航空域 FRAMES 总质量最高（0.96），hallucination 类达 1.00（最强基线仅 0.86）。
2. **准确率–成本双目标有效**：FRAMES 在最优准确率的同时保持输出成本最低（FinDAS 4.06k vs. B5 的 6.48k token/案例），不存在以更高推理花费换取准确率的隐性偏差。
3. **所有消融替代配置均未超越默认设置**：默认配置在 pass@k 上保持领先，验证了 Pareto 前沿搜索、共识变异过滤和逐类别防回归门各自的价值。
4. **消融揭示关键敏感度**：批大小是最敏感的超参数——过细批处理使进化成本增加 4.7 倍，过粗批处理带来最高推理输入成本；不同共识过滤模式和回归容差均导致总体性能下降。
5. **方法泛化性**：在公共 τ-bench 上的收益复现验证了 FRAMES 不仅适用于内部金融领域。

## 7. 优点

- **逐类别防回归门是核心亮点**：以每类别的质量下限（锚定于 P₀ 而非当前父代）为安全过滤器，避免了“全局精度掩盖少数类别回归”的遮蔽效应（masking effect），这对业务风险不对称的监管场景至关重要。
- **双目标 Pareto 前沿设计务实**：将准确率和成本置于同一优化面，产出可配置部署菜单而非单一升级选项，支撑不同风险–预算画像的工作负载。
- **共识变异机制针对稀疏噪声反馈设计**：多诊断器批处理 + 跨迭代重洗牌 + 投票过滤，有效抑制单诊断器噪声编辑，在花费评估预算前即过滤不可靠变更。
- **冷启动能力完整**：无需种子技能或标注数据，直接从企业策略文档生成技能库和初始案例集，满足真实企业部署条件。
- **可审计性贯穿全链路**：每次修改均为可读的自然语言 diff、带版本记录、回链到源策略条款，合规官员可逐项审查批准；不涉及模型权重更新，回滚简单。
- **回归池的终身记忆设计**：已解决案例成为永久回归测试，重写时注入锚定案例作为行为约束——在“提出阶段”防止遗忘而非仅在“评估阶段”拒绝。
- **实验统计严谨**：采用配对检验（McNemar）而非简单区间比较，揭示了边际置信区间重叠下仍存在显著差异的细节。

## 8. 不足与局限

- **基准稀缺限制了外部效度**：当前无公共基准能完整测试 FRAMES 的目标（策略治理 + 工具调用执行 + 生产反馈生命周期），τ-bench 为改适后的最接近选择，但其案例数少（航空仅 50 例），类别级准确率估计粗糙。
- **依赖运营反馈质量**：FRAMES 的学习收益直接受反馈质量制约——反馈稀疏或噪声大时（如 τ-bench 零售域），改进幅度有限；共识过滤和防回归门在保证安全性同时降低了编辑接受率，导致收敛较慢。
- **不进行模型微调**：由于冻结底层模型，FRAMES 无法为智能体添加基础模型不具备的新能力，这是为可审计性和部署实用性所做的刻意取舍，但也是一项能力天花板。
- **评估成本占循环主导地位**：候选需在完整智能体运行中多次重评分，评估成本比其他模块高 1–2 个数量级，目前限制了循环能处理的案例规模（数百量级）；论文承认这是当前最主要的扩展瓶颈。
- **生产数据约束**：FinDAS 案例须经匿名化和合规审查方可使用，限制了数据规模和共享可能性。
- **消融覆盖面有限**：实验仅在单一默认配置周围做局部扰动，未探索更广泛的超参数空间；且消融集缩减至 40 例，信号稀疏度变化可能与超参数效应相互影响。
