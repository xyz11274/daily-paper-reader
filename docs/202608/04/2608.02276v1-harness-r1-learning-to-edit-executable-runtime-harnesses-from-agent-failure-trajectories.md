## 摘要
基于大型语言模型的智能体在部署过程中会不断积累交互轨迹，但其行为通常保持不变。除了更新模型权重外，这些轨迹还可以改进智能体环境（harness），该环境负责构建上下文、协调工具、验证动作以及恢复执行。我们提出了Harness-R1，据我们所知，这是第一种将现有可执行运行时的基于失败条件的全生命周期编辑视为一种可学习能力的方法。它使用在线强化学习对专门的“环境工程师”（harness engineer）进行后训练，使其编辑针对实际任务成功进行优化，而非由固定编辑器提出。一个独立的9B工程师将批量的目标智能体失败转化为经过验证的可执行补丁；冻结目标模型在同一批次中的重新运行提供结果奖励，因此训练仅更新工程师。冷启动的监督微调初始化该编辑策略，随后使用组相对策略优化（GRPO）进行在线训练。在WebShop、ALFWorld和DBBench上，Harness-R1将标准Qwen3.5-9B的成功率从44.3%提升至53.6%（+9.3个百分点）。在对目标智能体进行直接微调后，特定目标的工程师将平均成功率进一步从59.2%提升至64.2%（+5.0个百分点）；由于这些增益在目标微调前后均保持，Harness-R1指向了环境工程师与目标智能体共同进化的方向。

## Abstract
Agents built around large language models continually accumulate interaction trajectories during deployment, yet their behavior typically remains fixed. Beyond updating model weights, these trajectories can improve the agent harness that constructs context, mediates tools, validates actions, and recovers execution. We introduce Harness-R1, the first method, to our knowledge, that makes failure-conditioned, lifecycle-wide editing of an existing executable runtime a learned capability. It post-trains a dedicated harness engineer with online reinforcement learning so that its edits are optimized for the realized task success they produce, rather than proposed by a fixed editor. A separate 9B engineer converts batches of target-agent failures into validated executable patches; fresh same-batch reruns of the frozen target provide outcome rewards, so training updates only the engineer. Cold-start supervised fine-tuning initializes this editing policy, which is then trained online with group-relative policy optimization. Across WebShop, ALFWorld, and DBBench, Harness-R1 raises vanilla Qwen3.5-9B success from 44.3% to 53.6% (+9.3 percentage points). After direct target-agent fine-tuning, a target-specific engineer raises the average further from 59.2% to 64.2% (+5.0 points); because these gains hold both before and after fine-tuning the target, Harness-R1 points toward co-evolving the harness engineer and the target agent.

# Harness-R1 论文中文总结

## 1. 核心问题与整体含义

- **背景**：基于大语言模型的智能体在部署后会持续产生交互轨迹，但智能体行为通常固定不变。这些轨迹既能用于更新模型权重，也能用于改进智能体外围的“运行时环境”（harness）——即负责上下文构建、工具中介、动作验证和恢复执行的系统组件。
- **现有局限**：传统方法要么直接微调模型权重，要么依赖固定提示规则（如 Self-Refine、ReAct）或提示大型前沿模型来编辑 harness。但这些方法不可靠：固定规则会降低性能，固定编辑模型只优化“补丁看起来合理”而非“任务真正成功”，且无法根据实际失败动态调整。
- **核心问题**：能否把“从目标智能体失败轨迹出发、对现有可执行运行时进行全生命周期编辑”这一能力本身，变成一种可学习的技能？
- **整体含义**：Harness-R1 证明了 harness 编辑可以被训练为一个独立于目标模型的学习任务，且编辑效果基于真实重跑结果反馈。该能力与目标模型微调可以协同，指向“harness 工程师”和“目标智能体”共同进化的方向。

## 2. 方法论

- **核心思想**：训练一个专门的“harness 工程师”模型（9B），它读取一批目标智能体的失败轨迹，生成可执行补丁，作用在目标模型外部的运行时钩子上；目标模型权重保持冻结，补丁带来的实际任务成功率变化作为奖励，用于训练工程师。
- **可编辑生命周期钩子**（4 个位置）：
  1. `on_init`（回合初始化）：设置初始上下文、技能提示。
  2. `make_pre_hint`（决策前）：注入状态相关的指导信息。
  3. `on_before_action`（动作前）：规范化、改写或拦截待执行动作。
  4. `on_post_step`（反馈后）：检查环境反馈并触发恢复逻辑。
- **奖励公式**：
  - 对一批任务 \(B=\{x_i\}\)，原始奖励为 \(R_i^0\)，安装补丁后重跑得到 \(R_i^P\)。
  - 全批性能差异：\(\Delta_B(P)=\frac{1}{n}\sum_i(R_i^P - R_i^0)\)
  - 工程师奖励：\(r(B,P)=\Delta_B(P)\)（仅当补丁有效且完整），否则为 0。
- **两阶段训练**：
  - **冷启动 SFT**：用 GPT-5.5 教师基于失败包生成补丁示例，在冻结目标上验证后筛选出约 877 个可执行、非负收益的示例，进行监督微调。
  - **在线 GRPO**：对每个失败包采样 K=8 个候选补丁，逐一验证并重新运行冻结目标，得到奖励；在组内做均值-方差归一化得到优势，用裁剪的 token 级代理目标更新工程师参数，不加 KL 损失或格式奖励。
- **算法流程**：缓存基线轨迹、奖励和失败包 → 循环采样补丁 → 验证 → 独立安装并重跑 → 计算奖励 → 归一化优势 → 仅更新工程师参数。
- **关键设计**：目标模型始终冻结，补丁通过结构化执行效果被宿主运行时解释，工程师不直接与环境交互；同一批任务重跑保证奖励 grounded，但也是转导目标，可能过拟合到同批任务。

## 3. 实验设计

- **基准环境**（3 个）：
  - **WebShop**：网络购物任务，需要搜索、比价、选择商品属性并购买。
  - **ALFWorld**：文本化具身环境，需要多步导航、物体操作、状态追踪和恢复。
  - **DBBench**（来自 AgentBench）：数据库交互任务，需要 schema 检查、SQL 查询、数据修改和结果验证。
- **测试规模**：WebShop 500 任务、ALFWorld 500 任务、DBBench 300 任务；成功率作为主指标，WebShop 额外报告 shaped score。
- **对比方法**：
  - 提示式智能体策略：ReAct、Self-Refine、Reflection（后者按 success@2 协议单独报告）。
  - 前沿模型作为工程师：Qwen3.5-397B、GLM-5.2、Kimi-K2.6、DeepSeek-V4-Pro、Gemini-3.5-Flash、GPT-5.5。
  - 仅监督训练的工程师、Harness-R1（监督+在线 RL）。
- **主要目标模型**：Qwen3.5-9B；另有一个直接 SFT 微调后的目标模型用于协同进化实验。
- **额外实验**：
  - 跨目标模型泛化：21 个不同规模/家族的模型（Llama、Gemma、Qwen 系列），每个目标用自身失败轨迹生成专属补丁。
  - 留出任务泛化：每个基准只观察 10 条失败轨迹，生成补丁后应用于其余任务（共 1270 个留出任务，3 个种子）。
  - 生命周期消融：固定补丁，逐一去掉某个钩子，测量成功率变化。
  - 定性案例研究：WebShop、ALFWorld、DBBench 各一个批次，含失败模式、补丁内容和运行轨迹对比。

## 4. 资源与算力

- 文中明确说明：SFT、在线 GRPO、直接目标 SFT 均在**单节点 8 张 NVIDIA H800 GPU** 上运行。
- 训练规模：冷启动 SFT 约 877 个示例；在线 GRPO 约 1500 个失败包；目标 SFT 使用 2515 条成功且去重轨迹。
- 超参数：GRPO 候选数 K=8、学习率 1e-6、rollout 温度 0.7、上下文长度 32k 等。
- **训练时长未在论文中说明**，这是资源信息的一个缺口。

- **实验数量**：主实验 3 个基准 × 多种对比方法；跨目标泛化覆盖 21 个模型 × 3 个基准；留出任务泛化重复 3 个种子；生命周期消融 6 个配置 × 3 次重复；3 个定性案例批次。实验规模较大。

## 6. 主要结论与发现

- Harness-R1 将 vanilla Qwen3.5-9B 在三个基准上的平均成功率从 44.3% 提升到 53.6%（+9.3 个百分点），比仅监督训练的工程师高 7.1 点。
- 在直接对目标模型进行 SFT 后，重新训练的 target-specific Harness-R1 工程师将其平均成功率从 59.2% 提升到 64.2%（+5.0 点），说明 harness 编辑能力与目标模型微调可以叠加，二者可协同进化。
- 相比固定前沿模型（最优 GLM-5.2 为 48.8%），训练过的 9B 工程师表现更好（53.6%），证明“从真实重跑结果学习”比单纯扩大提示模型规模更有效。
- 跨 20 个未见目标模型：平均提升 7.06 个百分点，56/63 组合提升，4 个不变，3 个微小回归；全部目标平均值均为正。
- 从 10 条失败轨迹生成的补丁能在 1270 个留出任务上平均提升 8.9±1.5 个百分点，且 3 个种子均为正；对比前沿工程师则平均为负或接近零且波动大。
- 生命周期消融显示：pre-action 动作中介和 post-feedback 恢复机制贡献最大（移除后分别损失 3.9 和 3.3 点），但主导位置因环境而异：WebShop 主要靠 pre-action，ALFWorld 主要靠 post-feedback。

## 7. 优点

- **新颖性**：首次将“失败条件下、生命周期级、可执行运行时编辑”建模为独立工程师的在线强化学习问题，目标模型冻结，奖励来自实际任务结果。
- **方法设计严谨**：SFT 冷启动提供有效先验，GRPO 在线优化真实效用；补丁必须可执行、有效、完整才算有效，否则零奖励；工程师不接触环境，角色隔离清晰。
- **泛化能力强**：单次训练得到的编辑策略可转移到多个未见模型，且对留出任务也有收益；训练流程无需逐目标调参。
- **实验充分且分析深入**：主实验、跨模型、留出任务、消融、定性案例相互印证；定性分析区分“生成了代码”与“实际执行了干预”，避免虚假归因。
- **写作清晰**：奖励公式、算法伪代码、生命周期接口、数据划分细节完整，可复现性好。

## 8. 不足与局限

- **单次适应 vs 多轮协同进化**：论文只研究 vanilla 目标微调一次后的再训练场景，没有探索工程师和目标交替更新的多轮演化过程，收敛性和复合增益未知。
- **奖励过拟合风险**：奖励来自同批任务重跑，是转导目标，可能让补丁过度适应失败批次而牺牲留出任务表现（虽然实验显示留出表现好，但训练目标本身未显式优化留出性能）。
- **缺少推理成本项**：补丁可能通过增加大量提示或动作拦截提升成功率，但论文没有考虑运行时开销；作者也承认未来可加入效率项。
- **跨模型泛化存在小回归**：少数目标（如 Llama-3.1-70B、Qwen2.5-72B、Gemma-4-31B-it）在部分基准上轻微下降，说明编辑策略并非对所有基座模型都无损。
- **可编辑表面有限**：DBBench 环境不支持 SQL 改写或强制提交，只能软指导和拦截；不同环境的钩子能力不对称，可能限制方法在更复杂环境中的适用性。
- **训练资源未完全披露**：未给出 SFT 和 GRPO 的具体训练时长，无法准确评估算力成本。
- **对比实验的潜在偏差**：前沿工程师模型仅通过提示使用，未经任务反馈优化，这种比较虽合理但可能低估其潜力；Reflection 的协议差异也使其不完全可比。
