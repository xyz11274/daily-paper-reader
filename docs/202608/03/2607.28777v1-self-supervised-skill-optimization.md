## 摘要
代理技能为冻结的大型语言模型（LLM）代理提供可重用的程序性指导，近期研究表明，此类技能可以通过真实标签（GT）反馈进行优化。然而，许多应用缺乏GT标签、任务分数、奖励或可靠的特定任务评估器。因此，我们引入了自监督技能优化（SSO），这是一种仅从未标记任务实例中学习可重用技能的比较框架。在每一步中，SSO在未标记批次上运行当前技能，使用一部分执行结果生成完整的技能探针，并在同一批次上运行这些探针。LLM裁判比较生成的答案、轨迹、工件或终态。独立的行为提取器在不参考裁判决策的情况下识别行为差异。SSO利用这些决策汇聚跨实例支持或反对所观察行为的证据，然后根据得到的证据对行为进行排序，并从排名最高的行为中生成新的完整技能。仅当新技能在未标记验证集上优于当前技能时，更新才会被接受。在封闭式和开放式任务上，SSO均优于现有的无GT提示优化器。在封闭式基准测试中，其性能接近甚至有时超过最强的基于GT的技能优化器，且无需使用任何GT反馈。

## Abstract
Agent skills provide frozen large language model (LLM) agents with reusable procedural guidance, and recent work shows that such skills can be optimized with ground-truth (GT) feedback. Many applications, however, lack GT labels, task scores, rewards, or reliable task-specific evaluators. We therefore introduce Self-Supervised Skill Optimization (SSO), a comparative framework that learns a reusable skill from unlabeled task instances alone. At each step, SSO runs the current skill on an unlabeled batch, uses a subset of the resulting executions to generate complete skill probes, and runs the probes on the same batch. An LLM judge compares the resulting answers, trajectories, artifacts, or terminal states. A separate behavior extractor identifies behavioral differences without seeing the judge's decisions. SSO uses these decisions to aggregate evidence for and against the observed behaviors across instances. It then ranks the behaviors by the resulting evidence and renders a new complete skill from the highest-ranked behaviors. The update is accepted only if the new skill outperforms the current one on an unlabeled validation set. SSO outperforms existing GT-free prompt optimizers on both closed-ended and open-ended tasks. On closed-ended benchmarks, it approaches and sometimes exceeds the strongest GT-based skill optimizer without using any GT feedback.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **研究背景**：大型语言模型（LLM）代理通过多步推理、工具调用和环境交互来解决复杂任务，而"代理技能"（Agent Skills）以自然语言文档的形式为冻结的LLM提供可复用的程序性指导。这类技能文档可以检查、编辑和跨任务复用，因而成为优化目标。
- **现有工作的局限**：已有技能优化方法（如SkillOpt等）依赖真实标签（GT）、任务分数、奖励或任务特定评估器来指导更新方向和接受决策。但在实际应用中，开放式任务往往没有参考答案，企业任务可能只暴露源文档和执行痕迹，交互或工件生成任务也缺乏可靠评估器，导致GT反馈不可获得。
- **核心问题**：能否仅从未标注的任务实例出发，优化一个可复用的代理技能？作者将此定义为 **GT-free技能优化** 问题。
- **整体含义**：该研究探索了不依赖任何外部监督信号、仅通过比较可观察执行结果来迭代优化技能的可能性，拓展了技能优化的适用场景，降低了将冻结代理适配到新任务所需的标注成本。

## 2. 论文提出的方法论（核心思想与技术细节）

### 核心思想
SSO是一个比较式（comparative）优化框架，核心思路是：**不直接选择最佳候选技能，而是在行为级别（behavior-level）聚合跨探针和任务的证据，从而渲染出一个全新的完整技能**。

### 算法流程（以步骤 t 为例）

1. **探针生成与锚定比较（Probe Generation and Anchored Comparison）**
   - 从未标注训练集选取批次 Xₜ，用当前技能 Sₜ 执行得到锚定执行 rₒᵢ。
   - 基于当前技能和历史执行子集，LLM生成器 f_gen 联合生成 K 个完整技能探针 {Pₖ}，每个探针是完整技能文档而非局部编辑，且彼此不同。
   - 用每个探针在同一训练批次上执行，得到替代执行 rₖᵢ。
   - 固定LLM裁判 f_judge 对每个探针执行与锚定执行进行两两比较，输出 yₖᵢ ∈ {−1, 0, +1}（偏好探针、偏好锚定、平局）。通过随机化呈现顺序缓解位置偏差。

2. **行为提取与聚类（Behavior Extraction and Clustering）**
   - 对每个存在非平局比较的任务，行为提取器 f_beh 接收任务、当前执行和所有探针执行（**不看到裁判决策**），输出一组行为记录 {(βᵢⱼ, αᵢⱼ)}，其中 βᵢⱼ 是行为描述，αᵢⱼ 为激活映射（1=存在、0=不存在、⊥=不明确）。
   - 聚类器 f_cluster 仅根据行为描述（不接收激活状态或决策）将语义等价的行为分组到簇中，簇用原始描述作为代表。

3. **证据聚合与排序（Evidence Aggregation and Ranking）**
   - 对每个比较 (i, k)，确定行为簇集合 Aₖᵢ（该集合中的行为在探针与锚定执行间有明显激活差异）。
   - 为每个簇 c 计算证据：eₖᵢc = yₖᵢ · dₖᵢc / |Aₖᵢ|，其中 dₖᵢc = αᵢc(rₖᵢ) − αᵢc(rₒᵢ) ∈ {−1, +1}。
   - 每个决定性比较的总绝对证据归一化为1，避免涉及多个行为的比较产生更大影响。
   - 聚合得 Qc（净方向）和 Ec（总证据量），由 sign(Qc) 决定行为意图（鼓励/抑制/中性），Qc=0 的簇被丢弃。
   - 按 |Qc| 降序排列，辅以 Ec 和贡献任务数作为决胜条件，保留最多 U 个行为单元。

4. **整体技能渲染与无标注验证（Whole-Skill Rendering and Unlabeled Validation）**
   - 渲染器 f_render 基于当前技能和选中的行为单元生成候选技能 S̃ₜ₊₁，可融合不同探针中的受支持行为。
   - 在无标注验证集 Vₜ 上执行当前技能与候选技能，由同一LLM裁判比较，统计胜局数 Wₜ 和败局数 Lₜ。
   - **只有 Wₜ > Lₜ 时才接受更新**，否则保持当前技能不变。

### 关键设计特点
- 探针仅用于暴露替代行为，**永远不会被直接接受**。
- 行为提取器与裁判决策解耦，避免比较结果偏差影响行为描述的客观性。
- 证据归一化使得每次比较的影响力一致。

1. **SSO是最强的GT-free技能优化方法**：在封闭式任务中，SSO在全部6个基准和3个目标模型上均超过所有GT-free基线。与No skill相比，平均提升 20.4（GPT-5.5）、16.6（GPT-5.4-mini）、14.2（Qwen3.5-4B）个百分点。
2. **接近甚至超过GT-based最强方法**：在GPT-5.5上恢复 SkillOpt 增益的 86.8%；在GPT-5.4-mini上超过SkillOpt 1.2个百分点；在Codex框架下仅落后SkillOpt 1.9个百分点。
3. **开放式任务上全面占优**：SSO对No skill的加权平均胜率62.4%，对SPO为63.6%，对PDO为62.5%，所有对比均超过50%。
4. **行为级聚合优于候选级选择**：直接选择最佳探针相比完整SSO平均下降8.5个百分点，表明跨探针聚合行为证据并渲染新技能是有效策略。
5. **验证门控有效**：去除验证门控导致性能下降，说明无标注验证集上的比较式接受决策起到必要的保护作用。
6. **迭代优化过程稳定**：渲染候选始终优于事后最优探针，验证门控能拒绝退化更新。

## 7. 优点

- **问题设定新颖且实用**：将GT-free技能优化形式化，回应了实际部署中标注稀缺这一真实痛点。
- **行为级证据聚合的创新性**：不同于现有GT-free优化器在候选层面进行选择，SSO在行为层面聚合跨探针和任务的证据，可组合出超越任何单个候选的技能。
- **模块化解耦设计**：行为提取器不接触裁判决策、聚类器不接触激活状态，有效避免反馈偏差污染行为描述。
- **完整的验证机制**：尽管没有GT反馈，仍以比较方式在无标注验证集上实现更新接受决策，增强优化稳定性。
- **实验覆盖面广**：6个封闭式 + 3个开放式任务 × 3个目标模型 + 额外Codex框架验证，展示了较好的跨任务、跨模型泛化能力。
- **超参数鲁棒性**：默认配置在敏感性分析中达到最优，为实际使用提供了合理默认值。

## 8. 不足与局限

- **对LLM裁判质量的高度依赖**：整个优化过程（训练比较和验证接受）都依赖单一LLM裁判（GPT-5.5），若裁判存在系统偏差或对某些行为不够敏感，会直接影响优化质量和公平性。
- **对优化器模型的依赖**：所有优化侧模块均使用GPT-5.5，未检验使用较弱或不的开源模型作为优化器时的表现，限制了方法的可复现性和可移植性。
- **未报告统计显著性**：缺少多次运行的标准差、置信区间或显著性检验，难以判断不同方法间的差异是否在统计上稳健。
- **计算成本未量化**：每步需要执行当前技能+ K个探针（K=3）在训练批次和验证批次上的全部运行，每个模块都调用LLM，迭代8~40步，总推理开销可能较大，但论文未给出具体计算资源数据。
- **代码和提示词未在正文公开**：虽然补充材料可能提供，但正文引用不充分，复现门槛较高。
- **开放式评估覆盖有限**：仅使用MT-Bench-101中3个对话任务，未覆盖更广泛的开放式场景（长文档写作、代码生成、工具调用的开放式完成等）。
- **GT-based对比的不对称性**：SSO与SkillOpt等GT-based方法对比时，基线结果引自原文，而GT-free基线由作者复现，可能引入环境不一致的偏差。
- **行为提取质量未独立评估**：行为提取器产生的行为记录质量和覆盖率没有被独立验证，可能影响证据聚合的完整性（例如某些影响性能的行为未被提取到）。
