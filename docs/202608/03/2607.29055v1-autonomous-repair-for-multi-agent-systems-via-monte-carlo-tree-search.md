## 摘要
多智能体系统（MAS）日益被部署用于解决复杂任务。当输出不正确或不令人满意时，用户必须通过检查智能体轨迹（即失败归因）来手动定位智能体错误，并提供反馈以改进输出（即修复）。尽管最近在MAS失败归因方面有一些工作，但自动化的错误恢复机制在很大程度上仍未得到探索。为弥补这一差距，我们提出了MARS，一个基于搜索的框架，将MAS修复形式化为蒙特卡洛树搜索（MCTS）过程，并通过诊断引导的扩展和基于分类法的评估在巨大的潜在修复空间中进行导航。与标准MCTS通过完整 rollout 评估完整模拟不同，MARS使用部分 rollout 评估智能体轨迹以减少 token 消耗。此外，我们引入了StateMAS，一个大规模MAS修复基准，包含1,310条可重放的多智能体失败轨迹，涵盖四种智能体架构和四个LLM骨干网络。在StateMAS上的实验表明，MARS在所有设置中持续优于最先进的方法，实现3.0%到12.1%的绝对改进，同时保持可比的token消耗成本。消融研究进一步证实，基于分类法的评估和诊断引导的扩展是取得这些性能提升的关键。

## Abstract
Multi-agent systems (MAS) are increasingly deployed to solve complex tasks. In case of incorrect or unsatisfactory outputs, users have to manually locate agent mistakes by inspecting agent trajectories (i.e., {\em failure attribution}) and provide feedback to refine the outputs (i.e., {\em repair}). Despite some recent work in MAS failure attribution, automated mechanisms to recover from such mistakes remain largely unexplored. To bridge this gap, we propose MARS, a search-based framework that formulates MAS repair as a Monte Carlo Tree Search (MCTS) process and navigates the vast space of potential repairs via diagnosis-guided expansion with taxonomy-augmented evaluation. Unlike standard MCTS, which evaluates a complete simulation via full rollout, MARS evaluates the agent trajectory using partial rollout to reduce token consumption. Furthermore, we introduce StateMAS, a large-scale MAS repair benchmark with 1,310 replayable multi-agent failure trajectories spanning four types of agent architectures and four LLM backbones. Experiments on StateMAS demonstrate that MARS consistently outperforms state-of-the-art methods, achieving an absolute improvement from 3.0\% to 12.1\% across all settings, while maintaining a comparable token consumption cost. The ablation study further confirms that taxonomy-augmented evaluation and diagnosis-guided expansion are critical to achieving these performance gains.

### 1. 核心问题与整体含义（研究动机与背景）
- **研究背景**：多智能体系统（MAS）在复杂任务中应用日益广泛，但由于智能体协同的复杂性，其输出经常出错或不符合预期。现有研究已针对"失败归因"（failure attribution，即定位哪个智能体在哪一步出错）展开了探索，但"失败后的自动修复"（repair）几乎未得到系统研究。
- **核心问题**：当 MAS 运行失败时，用户仍需手动检查轨迹、定位错误并提供反馈来引导重新生成，整个过程繁琐且耗时，迫切需要自动化的修复机制。
- **现有工作局限**：作者指出，已有的唯一自动修复系统 DoVer 存在两个主要问题：(1) 采用顺序搜索策略，修复空间探索有限且 token 开销大；(2) 修复操作仅局限于中心化编排器（orchestrator），无法适用于无中心化控制的 MAS 架构。此外，现有 MAS 失败归因基准只提供静态的、不可重放的日志，无法支撑修复实验。
- **论文整体意义**：本文首次将自动 MAS 修复形式化为蒙特卡洛树搜索（MCTS）问题，兼顾修复质量与 token 效率，并发布大规模可重放修复基准 StateMAS，填补了该研究方向的空白。

### 2. 方法论
- **核心思想**：将修复视为一个在 MAS 状态空间上的搜索问题，通过 MCTS 迭代地选择修复干预序列 Δ* = {δ₁, δ₂, ...}，逐步修复轨迹中的多处错误，直到获得满意输出或达到预算上限。每个修复干预 δ = (t, φ) 包括回滚步骤 t 和修复操作 φ。
- **MARS 框架的四个阶段**（对应标准 MCTS 流程）：
  - **选择（Selection）**：使用 UCT 启发式从根节点出发选择可扩展节点，公式为 UCT(c) = Q(c)/N(c) + C·√(ln N(p)/N(c))，平衡探索与利用。
  - **扩展（Expansion）**：由 LLM 动作选择器根据节点存储的诊断反馈决定采取何种修复动作。
  - **评估（Evaluation）**：利用 LLM-as-a-Judge 对部分轨迹进行打分和诊断。
  - **回溯（Backpropagation）**：将评分沿选择路径传播回根节点，更新各节点累计奖励与访问次数。
- **三类专门设计的修复动作（Action Space）**：
  - **Rollback（回滚）**：在错误步骤 t 处截断轨迹，丢弃后续错误步骤，保留有效前缀。回滚与修复解耦，避免归因不准时重复执行不必要的代码。
  - **Guided Repair（引导修复）**：将诊断出的失败原因转化为具体修复建议 φ（如"避免之前的错误 X..."），注入到下一智能体轮次的提示中，再执行 L 步。
  - **Continuation（继续）**：不加修复指导，从当前状态继续执行 L 步，用于探索有潜力的部分轨迹。
- **部分展开（Partial Rollout）**：不同于标准 MCTS 的完整展开（full rollout），MARS 只执行至多 L 步（实验中 L=4），显著降低 token 开销，并允许逐步构建更长的轨迹。
- **Taxonomy 增强评估与诊断**：
  - 基于 MAST 分类法（对 150 条失败轨迹分析得出），整理了 14 种失败模式，分为三类：智能体执行问题（如步骤重复、违反系统角色、不服从任务规范）、智能体间协作失调（如忽略其他智能体输入、信息隐瞒、任务偏移）、验证问题（如过早终止、验证不完整）。
  - LLM 评估器会先诊断轨迹中是否存在上述失败模式，输出诊断反馈 f；然后按照 5 级粒度评分标准给出得分 r ∈ [0, 1]：1.0（已验证完成）、0.8-0.9（强进展）、0.5-0.7（中等进展）、0.2-0.4（有限进展）、0.0-0.1（失败/偏离）。
  - 评估强调"辅助证据"要求：仅当最终答案由工具输出（如网络搜索、文件读取、代码执行结果）直接支持，并且评估器能从引用的工具输出中独立推导出相同答案时，才能判定为"已验证完成"；否则可能被判定为"幻觉"。
- **诊断引导的节点扩展（Diagnosis-guided Node Expansion）**：动作选择器在每次扩展前先检查节点存储的诊断反馈 f 与实际轨迹是否一致，如发现诊断有误则可选择不同动作。这一机制提升了搜索对误判的鲁棒性，类似于 Self-Refine 中的自我纠错。
- **搜索终止条件**：当评估器给出 r=1（已验证完成）或达到最大迭代预算 N_iter（实验中为 75）时终止，返回得分最高的轨迹。若预算耗尽仍未得到正确答案，则视为修复失败。

- **基准数据集（StateMAS）**：作者新构建了大规模 MAS 修复基准，包含 **1,310 条可重放失败轨迹**，覆盖：

  - **AssistantBench**：全部 33 个 AssistantBench 验证任务，中心化架构，共 132 条轨迹。
- **四种智能体架构**：中心化（Centralized）、顺序（Sequential）、去中心化（Decentralized）、并发（Concurrent），使用统一的 Magentic-One 五智能体团队以隔离架构影响。

### 6. 主要结论与发现
- **修复有效性**：MARS 在所有对比设置中均取得最高的修复后通过率：
  - 相比最强基线（ReAct 或 DoVer），GAIA 上绝对提升 7.8%-9.7%，AssistantBench 上提升 6.1%-9.1%。
  - 在不同 MAS 架构下，相对最强基线的绝对提升为 3.0%-12.1%，最大增益出现在 Qwen3.5-9B + 去中心化架构下（34.8% vs 22.7%）。
- **Token 效率**：MARS 的 token 消耗与最经济的基线（ReAct/DoVer）相当（相比 ReAct 增加 14.0%-38.7%，相比 DoVer 增加 1.1%-42.2%），但性能相对提升幅度（56.2%-92.5%）远高于 token 增加比例；相比 Reflexion 减少了 1.6%-54.7% 的 token。
- **消融结论**：三类设计均发挥关键作用——树搜索（K>1）比线性搜索提升效果显著；部分展开相对完整展开节省约 73% 的 token 且不损效果；Taxonomy 增强评估可额外提升 4.5 个百分点的通过率。
- **搜索超参发现**：中等分支因子（K=3 或 4）、中等 rollout 长度（L=4 或 6）和更大的迭代预算（75-90）效果最佳，过宽、过短或过长均会降低性能。

### 7. 优点
- **问题选择新颖且实用**：MAS 自动修复是尚未被充分研究的真实痛点，论文抓住了"归因已有研究、修复仍然空白"的切入点。
- **方法设计有针对性**：
  - 将修复解耦为 Rollback、Guided Repair、Continuation 三类动作，既避免重复执行有效前缀，又支持精细控制。
  - 部分 rollout 以较低 token 开销完成搜索，解决了将 MCTS 应用于 MAS 的核心成本瓶颈。
  - 利用成熟失败分类法（MAST 的 14 种失败模式）指导 LLM 评估器，解决了部分轨迹无最终结果可评估的难题。
  - 诊断反馈在评估器与动作选择器之间流转，形成"诊断 → 决策 → 执行 → 再诊断"的闭环。
- **基准贡献大**：StateMAS 是首个大规模可重放 MAS 修复基准，保存了每一步系统状态，支持确定性回放和任意点干预，覆盖多架构、多模型，可复现性强。
- **评估严格**：验证了随机性波动（方差在 3.0% 以内），做了敏感性分析，并使用同一 LLM 保持修复公平，结论较为可信。
- **成本透明**：详细报告了 token 消耗，坦诚展示了相对某些基线的开销增加，并论证性能提升的性价比。

### 8. 不足与局限
- **框架绑定**：StateMAS 基于 Microsoft Agentic Framework（MAF）构建，其检查点与重放机制对其他 MAS 框架的移植性有限。
- **任务场景单一**：基准任务仅覆盖 GAIA（通用助手）和 AssistantBench（网页导航）两类通用场景，缺乏领域特定任务（如编程、医疗、金融等）的验证，泛化性有待考证。
- **架构覆盖不完整**：受限于计算与 API 成本，GAIA-Comm 和 AssistantBench 仅评估了中心化架构，未覆盖全部 16 种模型-架构组合；消融与敏感性实验仅在一个模型上验证。
- **搜素成本仍有优化空间**：虽然性能提升大于 token 开销增加，MARS 在部分设置下（如并发架构 + Qwen3.5-9B 上消耗 419 万 token）开销仍然较大；DoVer 在部分设置下 token 更少，也表明成本控制仍有改进余地。
- **依赖 LLM 评判可靠性**：评估器与动作选择器本身是 LLM，存在误判或幻觉风险；虽然设计了交叉验证环节缓解，但并没有从根本消除该偏差。
- **无 oracle 假设的严格性**：虽然论文声称不假设可查询的 oracle，但"Verified Completion"的判定实际上依赖工具证据和 LLM 独立验证，在工具返回误导性结果时仍可能给出错误评分。
