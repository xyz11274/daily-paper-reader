## 摘要
个性化AI智能体通常可配置，但用户无法控制决定其未来行为的工件。我们提出OurArk，一种以智能体自有软件体为中心的持久化个人智能体架构：该软件体是一个具有身份、可检查、可版本化且由人类保管的工件。该软件体包含行为定义代码、提示词、工具、技能、策略、测试和进化机制。记忆和凭据保持为私有实例状态，而模型推理被视为可替换的外部服务。OurArk定义了在同一软件体上的受治理自进化和递归后代演化。自进化产生孤立的候选变更，这些变更在人类控制下经过验证、审查并合并，从而实现人类与智能体对智能体软件体的协同开发。后代演化创建具有独立版本的后代，拥有独特的身份、使命、历史和全新的私有状态边界；兼容的后代自身也可以繁衍进一步的后代。分化后，可直接检查父代变更和同类技能，以进行选择性局部适配。我们在开源Genesis创建引擎和Enoch参考智能体中实现了该架构。一个包含四个智能体、三次后代演化的线性世系和可执行回归测试演示了递归创建、继承的验证契约、隔离的软件体变更、人类控制的审查以及失败更新恢复。OurArk为个人智能体提供了具体的基础，使人们能够拥有、治理、定制并随时间演化这些智能体。

## Abstract
Personalized AI agents are often configurable without giving users control over the artifacts that determine their future behavior. We present OurArk, an architecture for persistent personal agents centered on an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state, while model inference is treated as a replaceable external service. OurArk defines governed self-evolution and recursive descent over the same body. Self-evolution produces isolated candidate changes that are validated, reviewed, and merged under human control, enabling human-agent co-development of the agent's software body. Descent creates an independently versioned descendant with a distinct identity, mission, history, and fresh private-state boundary; compatible descendants can themselves source further descent. After divergence, direct-parent changes and peer skills can be inspected for selective local adaptation. We implement the architecture in the open-source Genesis creation engine and Enoch reference agent. A four-agent, three-descent linear lineage and executable regression tests demonstrate recursive creation, inherited validation contracts, isolated body changes, human-controlled review, and failed-update recovery. OurArk provides a concrete substrate for personal agents that people can possess, govern, specialize, and evolve over time.

### 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：当前个性化 AI 智能体虽然可配置，但用户无法真正掌控决定其未来行为的“工件”（artifacts）。平台方往往控制着智能体的组装与修改过程，用户只能进行表面化的定制，却无法拥有、检查或治理决定智能体长期演化的底层载体。
- **整体含义**：论文提出，一个长期存在的个人智能体应拥有一个**带身份的软件体（identity-bearing software body）**，该软件体受人类保管，可被检查、版本化并持续演化。由此，个人计算范式将从“人人有电脑”推进到“人人有属于自己的、可传承和演化的 AI 智能体”。
- **设计论断**：代码、工具、技能、策略、测试和进化机制属于智能体的“身体”（body）；记忆、凭证和实例历史属于私有状态（private state）；模型推理则是可替换的外部服务。智能体拥有其身体的生命周期角色，而人类保管者保留最终权力。

### 2. 论文提出的方法论

- **核心架构**：OurArk 将智能体实例定义为四元组关系，即处于人类保管者 H 之下的智能体 A = (B, S, R)：
  - **B（Body）**：版本化的软件体仓库，包含身份声明、使命、代码、提示词、工具、技能、策略、测试及进化机制；
  - **S（Private State）**：凭据、记忆、日志、队列等私有实例状态，不可继承；
  - **R（External Reasoner）**：可替换的外部模型推理服务，不是身份的持久载体；
  - **H（Human Custodian）**：持有身体和私有状态，并控制向权威身体的合并提升（promotion）。
- **三个核心操作**：
  1. **evolve(B, c) → B′**：根据上下文或压力 c 产生候选身体变更，只有通过配置的验证与提升流程后才成为权威版本；
  2. **descend(B, m) → (B_d, S_d)**：以独立身份、使命 m 和版本历史创建后代身体，并初始化全新的私有状态边界；
  3. **transfer(B_p, B_d, Δ) → B′_d**：后代可从亲代或同辈处检查并局部适配选定的变更 Δ，而无需放弃自身的独立历史。
- **六个设计原则**：保管与连续性、身体级个性化、可复现后代、独立专业化、可问责变更、人类治理。
- **Genesis 创建引擎**：实现后代创建的具体流程——验证源仓库干净性、记录完整提交 ID、复制并转换身份相关工件、写入新身份与使命、解析依赖、运行继承的测试套件，验证通过后才创建“出生提交”（birth commit）。任何兼容的后代都可以继续作为下一代的来源，实现**递归后代**。
- **受治理的自进化**：进化来源有六种（用户请求、人类反馈、联合工作经验、直系亲代继承、跨智能体学习、LLM 头脑风暴）。变更在隔离的工作树（worktree）中实现，经验证后发布为可审查的 Pull Request，由人类决定是否合并；失败的更新会回滚到先前版本。
- **继承 vs 学习**：继承是选择性的、拉取式的，仅限直系亲代；学习则可从任意可信智能体获取技能，属于横向适配。这与面向对象继承不同——后代只在出生时获得一次身体副本，之后可自主选择是否适配亲代的后期变更。

### 6. 论文的主要结论与发现

- **主要结论**：OurArk 提供了一个具体的载体，使个人智能体能够被人类拥有、治理、专业化并长期演化。将“进化”和“后代”应用于同一个身份化的软件体上，使得一个种子智能体可以成为独立专业化谱系的根。
- **关键发现**：
  1. 身体/状态/推理器的边界划分是可行的——记忆等私有状态可与可继承的身体分离；
  2. 递归后代是可实现的——兼容的后代可以继续创建下一代，无需依赖中心模板；
  3. 人类治理与自进化可以共存——智能体负责提议、实现和验证，人类掌握合并权；
  4. 分化后的选择性转移（继承与学习）在架构上是清晰且可执行的；
  5. 版本化仓库（Git）作为身体载体，能为智能体提供身份、可审计性和回滚能力。

### 7. 优点

- **概念清晰**：身体/私有状态/外部推理器/人类保管者的四元边界简洁而有力，解决了“用户真正拥有智能体”这一核心问题。
- **架构优雅**：进化与后代作用于同一个身体，赋予身体双重角色（可演化与可繁殖），形成自洽的生命周期模型。
- **人类治理落到了实处**：通过 Git 分支、工作树、Pull Request、受保护分支实现人工合并权，而非停留在口号层面。
- **失败恢复机制**：软件更新失败时回滚到上一个健康版本，保证系统鲁棒性。
- **可复现性**：提供冻结的版本快照和可执行的复现命令（含依赖哈希校验），方便他人验证。
- **诚实与克制**：论文在 Limitations 中坦诚区分了“demonstrated”与“partial”的证据，不夸大其贡献。

### 8. 不足与局限

- **谱系规模有限**：仅有一个开发团队创建的线性谱系，无兄弟分支交叉或群体规模评估，难以验证多样化场景下的行为。
- **测试多为模拟**：大部分测试使用 mock 服务，未验证长期运行的可靠性、并发或多租户场景。
- **语义安全性未验证**：行为连续性跨推理器替换的稳定性、演化出的代码的语义正确性均未系统评估。Genesis 使用边界感知的字符串替换而非语言解析器，可能引入语义错误。
