## 摘要
随着大型语言模型（LLM）演变为自主智能体，传统的静态评估无法捕捉多步决策过程。我们提出了AgenticAI-Supervisor，这是一个由API和UI驱动的强化学习Gym环境，将环境创建与可扩展执行解耦。通过转向可验证的执行结果，该平台生成高保真轨迹并应用多维奖励塑造。关键的是，我们的框架通过严格的内部状态验证和测试来缓解奖励破解。本文通过一个客户支持智能体案例研究，初步展示了我们平台的核心能力，该案例展示了模型优化的一致闭环反馈。未来工作将聚焦于高级功能，如计算机使用、工具使用、自动“卡住”和边缘案例生成。

## Abstract
As Large Language Models (LLMs) evolve into autonomous agents, traditional static evaluation fails to capture multi-step decision-making. We introduce AgenticAI-Supervisor, an API and UI-driven RL Gym environment that decouples environment creation from scalable execution. By moving to verifiable execution outcomes, the platform generates high-fidelity traces and applies multi-dimensional reward shaping. Critically, our framework mitigates reward hacking through rigorous internal state validation and testing. This work provides a first look at our platform's core capabilities through a Customer Support Agent case study demonstrating a consistent closed-loop feedback for model optimization. Future work will focus on advanced features such as Computer Use, Tool Use, automated "stumping", and edge-case generation.

## 2. 论文提出的方法论

- **核心思想**：采用“Run-to-Verify”范式，将环境创建与**大规模并发执行解耦**。环境提供可验证的确定性状态变化，智能体执行后根据真实环境状态而非文本启发式生成奖励信号，从而抑制奖励欺骗。
- **关键技术细节**：
  - **高保真环境搭建**：包含三个核心组件
    - *Agentic Workflows*：领域驱动执行路径，包含标准操作、故意失败状态、缺失数据、模糊工具响应，以测试智能体韧性。
    - *Base Tool Simulator*：可复用基础设施，模拟有状态的后端 API 和基于 Web 的 GUI（通过 Model Context Protocol (MCP) 标准化工具接口）。
    - *Dataset Connectors*：状态管理层，将测试用例绑定特定环境上下文，确保初始化和每轮 rollouts 的一致性。
  - **可扩展执行引擎**：*Test Run Engine* 在隔离、无状态 sandbox 中并行执行数千条 rollouts。*Rollout Handler* 管理容器化实例生命周期，防止状态泄露；*Agent Runtime* 编排 LLM 提示、动作解析（工具调用与 GUI 交互）、观察检索；所有事件以结构化 *Spans* 记录，聚合形成 *Traces*。
  - **多维奖励塑造**（核心贡献，公式/算法描述如下）：
    - **Outcome Reward（终端奖励）**：将终端环境状态与金标准答案进行多集归一化动作键比较，同时检查资源预算约束。稀疏二进制信号。
    - **Constraint Adherence（约束遵守）**：额外验证（1）禁止字段值（负检查）；（2）记录数量是否异常（检测奖励欺骗）；（3）输出事实性（交叉引用工具 API 响应）。有效缓解奖励欺骗（文中发现仅靠结果奖励时约 40% 的奖励正向轨迹违反约束，约 3.8% 存在编造）。
    - **Trajectory Efficiency Reward（轨迹效率奖励）**：连续密度信号，包含五个子分量：
      - *Tool Correctness*：有效工具调用比例减去禁止动作惩罚。
      - *Redundant Call Penalty*：惩罚重复调用相同工具且参数不变。
      - *Validation Error Penalty*：惩罚返回错误的工具调用比例。
      - *Min-Tool Coverage Score*：确保必要工具被调用，欠调用或过度调用均受罚，通过非线性函数结合后经 sigmoid 聚合。
      - *Step-Penalized Efficiency Modifier*：根据实际步数与金标准步数差异缩放奖励，惩罚不必要的长轨迹。
    - **评估模态**：
      - *Verifiable Rewards*：确定性、基于状态的检查（如匹配金标准、验证约束、跨引用标识符），无需推理成本。
      - *LLM-as-a-Judge*：对响应连贯性、推理质量等定性维度使用结构化评分标准，集成评判以减少方差。
    - 整体奖励通过配置校准，适应不同环境需求。
