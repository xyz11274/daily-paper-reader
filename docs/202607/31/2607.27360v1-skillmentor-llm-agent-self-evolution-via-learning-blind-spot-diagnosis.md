## 摘要
智能体自我进化主要关注学习如何行动，而忽略了同样重要的能力：学习发现智能体自身不知道什么。现有方法通常假设失败发现是给定的，侧重于一旦识别出失败如何修复。我们提出疑问：盲点诊断本身是否可以学习。因此，我们将诊断作为一种与执行分离的智能体能力来研究，并排除两个替代性的进展来源：执行器适应和人工监督。在这些约束下，性能无法通过执行器更新或标注示例来提升，迫使所有改进都源于学到的诊断能力。我们提出了SkillMentor，通过强化学习训练一个导师策略，以生成诊断任务、识别反复出现的失败模式，并将其整理为可复用的纠正性技能。在AppWorld和BFCLv3上，SkillMentor平均将执行器性能提升了44.2%。这些结果表明，盲点诊断是一种可学习的能力，使得在不更新执行器权重或依赖人工策划数据的情况下实现自我进化成为可能。

## Abstract
Agent self-evolution has primarily focused on learning how to act, while overlooking an equally important capability: learning to discover what an agent does not know. Existing approaches typically assume that failure discovery is given, focusing on how to repair failures once they are identified. We ask whether blind-spot diagnosis itself can be learned. We thus study diagnosis as an agent capability separate from execution, and exclude two alternative sources of progress: executor adaptation and human supervision. Under these constraints, performance cannot improve through executor updates or annotated examples, forcing all improvements to originate from the learned diagnostic capability. We propose SkillMentor, which trains a Mentor policy via reinforcement learning to generate diagnostic tasks, identify recurrent failure modes, and curate them into reusable corrective skills. Across AppWorld and BFCLv3, SkillMentor improves executor performance by an average of 44.2%. These results suggest that blind-spot diagnosis is a learnable capability, enabling self-evolution without updating executor weights or relying on human-curated data.

## 2. 方法论

### 2.1 核心思想

SkillMentor 训练一个 **Mentor 策略（πθ）**，通过强化学习（RL）主动发现执行器的盲点并生成纠正性技能。它将诊断建模为序列决策问题，采用“发现 — 评估 — 整理”三阶段闭环，形成自我进化的正反馈循环。

### 2.2 关键技术细节

- **问题形式化**：盲点定义为二元组 b = (T, c)，其中 T 为执行器持续表现不佳的任务，c 为可缓解失败的纠正技能。目标函数为最大化累计发现奖励与整理奖励之和：
  \[
  \max_\theta \mathbb{E}_{\pi_\theta}\left[\sum_t \left( r_{\text{disc}}(q_t) + r_{\text{curate}}(c_t) \right)\right]
  \]

- **阶段 A — 盲点发现（Blind-Spot Discovery）**：
  - Mentor 在无预定义目标的环境中自由探索，生成探索轨迹；
  - 维护多样性缓冲区（Diversity Buffer），惩罚使状态分布坍缩的动作；
  - 从轨迹中综合生成 G=8 个候选诊断任务。

- **阶段 B — 差距评估（Gap Evaluation）**：
  - 对每个候选任务 qi，使用强参考模型 M 生成参考轨迹并打分（sᴹ），同时让冻结执行器作答并打分（sᴱ）；
  - 诊断差距定义为 δ = max(0, sᴹ − sᴱ)；
  - 选择差距最大的任务进入技能整理阶段；
  - 采用 **线性衰减阈值调度**（从 0.5 降至 0.2，每步减少 0.002），以适配技能积累导致的差距分布自然收缩。

- **阶段 C — 技能整理（Skill Curation）**：
  - Mentor 通过三种操作生成候选技能：**ADD**（新增）、**UPDATE**（更新）、**MERGE**（合并）；
  - 双重验证：**语法有效性**（符合预定义 Markdown schema）与 **执行器接地效用**（重新让执行器作答，验证 Δ = sᶜ − sᴱ > 0.5 才允许入库）；
  - 整理奖励：r_curate = 0.3·f(c) + 0.7·Δ；
  - 采用轻量级 **DELETE 机制**：技能检索成功率低于 0.05 即被淘汰。

- **训练目标**：使用 **GRPO** 联合优化发现奖励与整理奖励，二者共享策略网络参数，形成“发现更好的盲点 → 整理更好的技能 → 技能改变能力边界 → 暴露新的盲点”的正反馈闭环。

### 2.3 推理流程

- 推理时执行器根据任务描述检索相关技能并前置到提示中，技能库既是诊断的产物，也是进化的引擎；
- 训练阶段使用强模型作为“裁判”（LLM Judge），推理/部署阶段完全移除强模型依赖。

## 6. 主要结论与发现

1. **诊断是可以学习的**：RL 训练的 4B Mentor 在 AppWorld 和 BFCLv3 上均显著优于所有 prompt-based Mentor（平均相对提升 44.2%）；
2. **学习胜过规模**：4B 的 RL 训练 Mentor 持续超越 DeepSeek-V4-Flash（远大于 4B 的强模型），说明诊断能力不是模型规模的副产品，而是训练的产物；
3. **弱执行器受益更大**：DeepSeek-R1-7B（最弱）提升 46.6%，Qwen3.5-9B（更强）提升 36.7%，与“弱执行器暴露更多盲点”的假设一致；
4. **发现与整理必须联合优化**：分开训练或去掉任一奖励都显著降低性能（0.351 → 0.292/0.303/0.336），验证共享表征的正反馈循环；
5. **技能具有可迁移性**：弱执行器学到的技能迁移到强执行器效果显著（有时甚至超过强执行器自训练结果）；而强→弱的迁移效果有限（强执行器的训练暴露盲点较少）；
6. **盲点具有非平稳性**：技能积累使原有盲点逐渐修复、新盲点不断涌现，需要动态衰减阈值持续探索；
7. **技能库是可解释的诊断输出**：技能以人类可读的 Markdown 格式存储，可以按类别（API 调用、参数处理、状态跟踪等）展示执行器的能力边界，且不同执行器呈现不同的盲点分布。

## 8. 不足与局限

- **评估范围有限**：只用了 AppWorld 和 BFCLv3 两个基准，二者的任务分布相对偏向 API 调用与流程操作，未覆盖更广泛的开放式任务（如网页操作、多智能体协作、长对话等）；
