## 摘要
大型语言模型驱动的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题求解能力。然而，现有系统通常将通信拓扑视为固定设计选择或离线优化目标。我们提出MANTA，一个多智能体网络拓扑自适应框架，使得通信结构能够在推理时自我演化。在执行前，MANTA根据先前的结构经验初始化任务条件化拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在五个基准上评估MANTA，涵盖信息检索、工具使用、规划、工作流执行和数学推理，与代表性的单智能体和多智能体基线进行比较。MANTA达到最高平均分74.0，比最强基线高出5.8个百分点，并在PlanCraft上获得最佳结果。这些结果表明，推理时自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

## 2. 论文提出的方法论

### 2.1 核心思想
MANTA 采用两层嵌套架构：底层是解决任务的目标多智能体系统，上层是负责规划、审计、控制和学习的编排层。核心思想是：**先根据任务特点和积累的经验规划一个初始拓扑，在执行过程中监控协作轨迹，当当前组织结构不足时施加一次有界（bounded）的结构性突变，并将每次运行的经验跨任务传递下去**。

### 2.2 拓扑表示
- 每个智能体具有**结构角色**（如协调者、工人、验证者、辩论者、投票者）和**阶段角色**（工人或评论家）。
- 智能体属于具有预定义交互结构的**模式组**（pattern groups），组可以嵌套，支持代理将工作委派给子组并综合其报告。
- 每个**上下文策略**控制智能体可以访问的消息、发送者、共享证据，以及消息传播范围和报告摘要程度。
- 执行前会进行结构验证（组成员资格、附件循环、角色、智能体预算），无效提案被拒绝。

### 2.3 编排循环（Orchestration Loop）
1. **查询条件化规划**：顶层规划器（Topology Planner）接收任务和经验记忆，分析任务需求与潜在过程风险，输出紧凑计划（交互模式、智能体数量、可选验证器或嵌套组），确定性代码将其扩展为完整拓扑并验证所有结构约束。
2. **回合执行**：每个协作回合按组结构递归执行拓扑。智能体通过结构化的中继包（relay packets）通信（总结答案、证据、置信度、未解决问题），而非原始对话记录。共享上下文控制器强制实施每个智能体的可见性策略，重复工具调用被去重，追加式证据账本保存跨分支的声明和支持证据。
3. **轨迹审计与修复**：每回合后，审计器（Trace Auditor）扫描结构化产物、工具记录、中继包和证据可见性，报告可观察的**过程风险**（而非答案正确性）。若审计建议修复（至少一个可修复的中等/高严重性标志），则控制器允许一次有界修复和最终回合。修复由规划器输出最多3个操作（添加/扩展智能体、更改组模式、编辑通信边、更改信息可见性），确定性代码应用并验证。

### 2.4 双时间尺度记忆（Two-Horizon Playbook Memory）
- **短期剧本（Short-term playbook）**：记录当前运行的每个回合的拓扑、过程标志、推荐修复和控制器决策，使规划器看到已尝试的结构及其产生的异常。
- **长期剧本（Long-term playbook）**：跨运行累积一般性原则，将任务特征和过程风险映射到拓扑选择。技能反射器（Skill Reflector）每隔N次运行重写经验教训。该学习回路**仅使用过程信号**（如程序是否干净运行、是否达成决策级共识），从不接触基准测试的正确性标签或真实结果。

### 2.5 关键设计特点
- 智能体是无状态的，所有对话状态存储在共享运行状态中（包存储、证据账本、候选列表），拓扑突变时仅需将上下文控制器重新指向新规范，实现无损且廉价的拓扑变更。
- 每次运行最多一次拓扑突变（mutation），每次突变最多3个操作。
- 最终答案通过时间候选投票机制选择，较好的前序候选不会被更差的突变结果覆盖。

## 6. 论文的主要结论与发现

- **主结果**：MANTA在5个基准的平均得分**74.0**，比最强基线（ADAS的68.2）高出**5.8个百分点**，并在PlanCraft上获得最佳结果。MANTA在单智能体基线的所有基准上均有提升。
- **消融分析**：初始拓扑规划贡献最大（移除后从71.7降至57.5），拓扑修复次之（降至60.8），长期剧本更新提供额外但较小的收益。这验证了“任务条件化规划”和“执行时修复”是核心贡献。
- **突变预算**：增加突变预算可扩展可解决任务集合，第一个突变机会提供了最大的平均增益，后续突变提供较小但正向的增益。
- **经验迁移**：MANTA的长时程剧本在域内和跨域转移中均产生正收益（平均+3.3），而ADAS、AgentSquare、MASS的跨域转移为中性或负值（MASS平均-58.3）。MANTA的剧本保留可继承的结构性知识，而非针对预定义任务的最优固定工作流。
- **Token效率**：MANTA是评估的多智能体系统中总token消耗最低的，其元级操作仅占推理预算的约12%，表明目标明确的拓扑规划与修复不会引入显著开销。
- **拓扑演化的本质**：有效的拓扑演化不一定是让系统更大——只有分支扩展增加了规模，序列化改变执行顺序，重连改变通信关系，插入评论者赋予新智能体检查角色而非求解角色。修复由执行轨迹中可见的结构性失败决定，而非系统规模。
- **审计信号的有效性**：无修复标志的运行83.2%正确，有标志的运行仅62.5%正确（20.7个百分点差距），表明轨迹质量提供了有意义的可靠性信号。审计在WorkBench达到F1 0.78。修复后60.9%的运行过程标志数量减少，59.6%的命名修复目标在下一次审计中消失。

## 7. 优点

- **问题新颖性**：首次系统性地将通信拓扑定义为推理时可自我改进的对象，提出“拓扑级自我改进”的新问题层次，与现有仅改进输出、提示、记忆或角色层面的方法形成鲜明区分。
- **方法设计优雅**：采用“规划→执行→审计→修复→记忆”的闭环，结构清晰；确定性代码与LLM组件分离（LLM负责规划、审计与反思，确定性代码负责展开、验证、执行与强制执行可见性策略），兼顾灵活性与可靠性。
- **过程信号而非正确性信号**：审计和长期学习仅使用可观察的协作过程信号（如工具失败级联、分支崩溃、过早共识），不接触基准测试真值，实现了不依赖监督标签的自演化，具有更强的泛化潜力。
- **有界突变与保守修复**：每次运行最多一次突变、每次最多3个操作，避免了系统性动荡；无效提案被拒绝，使用保守修复编译器兜底，体现了工程上的审慎。
- **Token效率**：在所有多智能体系统中总token消耗最低，且元级开销仅占12%，说明自适应不必然以计算开销为代价。
- **丰富的实验验证**：除了主实验，还包含消融研究、突变预算分析、跨域迁移实验、审计质量统计、修复细节分析和算子使用频率统计，多层次验证了方法的有效性。
- **深刻的定性洞察**：案例分析（分支扩展、验证与执行顺序修复、重连通信、插入评论者）表明拓扑修复是精细的结构操作，而非简单的规模扩展。

## 8. 不足与局限

- **评估规模有限**：每个基准仅30题（3次运行），样本量小，且某些结果的标准差较大（例如PlanCraft上的CoT为±12.6，ADAS为±13.4），统计显著性未经过正式检验。
- **模型泛化性未验证**：所有实验仅使用Gemma 4 31B一个骨干模型，未测试在不同规模、不同家族模型上的表现，限制了结论的一般性。
- **MATH基准表现一般**：MANTA在MATH上（91.1）低于Self-Refine（96.7）和多个静态工作流（最高94.4），说明拓扑自适应对纯推理任务的增益有限甚至略微负面，可能引入了不必要的协调开销。
- **WorkBench表现低于自适应基线**：在WorkBench上，MANTA（43.3）低于ADAS（66.7）和AgentSquare（62.2），暗示在特定工作流密集型任务上，预算受限的在线修复可能不如离线搜索得到的最优工作流。
- **硬件资源信息缺失**：论文未报告GPU型号、数量和训练/推理的实际算力消耗，仅提供了token使用量，可复现性和资源评估的透明度不足。
- **审计作为正确性代理的局限**：审计标志与答案正确性的关联仅基于“过程信号”的近似（如无标志的运行83.2%正确），并非因果保证。论文承认“智能体可能无可观察异常地达成一致的错误答案”。表8显示在BrowseComp和StableToolBench上审计的代理精度很低（0.25和0.21），高FPR意味着大量正确运行被不必要地标记和修复。
- **修复上限限制**：每次运行仅允许一次修复（最多3个操作），某些复杂任务可能需要多次迭代修复，单次修复可能无法充分应对多重并发结构缺陷。
- **跨域迁移验证不充分**：仅测试了PlanCraft ↔ WorkBench两个规划/工作流基准，未测试其他能力类别（如检索、推理）间的迁移，结论的普适性有限。
- **时间合理性存疑**：文中引用了大量2025-2026年的文献（如Gemma 4、GEPA等），arXiv编号为2607.28527（2026年7月），在当前时间点（2025年）看来这些时间信息不合理，需要在实际环境中验证论文的真实性和时效性。
