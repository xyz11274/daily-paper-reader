## 摘要
自演化智能体可通过交互经验改进未来行为，但现有评估通常在固定执行条件下优化，不对条件改变后的恢复能力进行测试。为填补这一空白，我们提出PACE-Bench（基于代码演化的物理适应性，Physics Adaptation via Code Evolution），这是一个基于模拟器的基准，包含跨六个物理域的144组源-目标适应对。每组适应对将源环境与拥有相同目标和接口的变异目标环境相关联。在源环境中有效的代码驱动设计会在目标环境中失效，智能体必须在有限的尝试次数预算内，利用诊断沙箱反馈迭代将其适配为可在目标环境正常工作的设计。我们比较了来自四种范式的十种自演化方法。该基准远未饱和：Reflexion + Qwen3-14B仅在全基准35.9%的测试对上取得成功，而GPT-5.5在全尝试预算下解决了静力学（Statics）子集66.7%的问题。这些结果共同表明，基于模拟器的反思比未验证的自我修正更可靠，记忆会将智能体锚定在早期设计，宽树搜索可进行探索但无法收敛。即便是告知精确的物理变化也无法提升性能上限，这说明核心瓶颈是机制重新设计而非参数推断。数据和代码已公开于https://github.com/thunlp/PACE-Bench。

## Abstract
Self-evolving agents improve future behavior from interaction experience, yet existing evaluations typically optimize under fixed execution conditions and do not test recovery after those conditions change. To address this gap, we introduce PACE-Bench (Physics Adaptation via Code Evolution), a simulator-grounded benchmark of 144 source-to-target adaptation pairs across six physics domains. Each pair links a source environment to a mutated target environment with the same goal and interface. A code-driven design that succeeds in the source fails in the target, where agents must iteratively adapt it into a working target design using diagnostic sandbox feedback within a limited attempt budget. We compare ten self-evolving methods from four paradigms. The benchmark remains far from saturated: Reflexion + Qwen3-14B succeeds on only 35.9\% of full-benchmark pairs, while GPT-5.5 solves 66.7\% of the Statics subset under the full budget. Together, these results show that simulator-grounded reflection is more reliable than unverified self-revision, while memory anchors agents to early designs and broad tree search explores without converging. Even revealing exact physical changes does not raise the performance ceiling, pointing to mechanism redesign rather than parameter inference as the central bottleneck. Data and code are available at https://github.com/thunlp/PACE-Bench.

## 1. 核心问题与研究背景
- 自演化智能体可以通过交互经验自动改进自身行为，减少人工重复设计，支持终身智能体系统，是当前大模型agent领域的重要研究方向
- 现有自进化智能体的评估存在明显缺口：大多在固定执行条件下优化，仅测试任务流上的长期性能或跨任务/环境的泛化能力，没有测试**环境物理条件发生变化、原有可工作设计失效后，智能体能否自主修改适配原有设计**的能力
- 现有物理相关基准要么在固定环境下测试设计能力，要么仅改变物理环境但不要求智能体自进化重设计，因此该能力一直缺乏标准化的测试平台

## 2. 提出的方法论（PACE-Bench基准设计）
### 核心思想
构建一个基于模拟器的标准化基准，专门测试动态环境物理变化后，自进化智能体通过代码迭代修改原有设计，适配新物理条件完成相同目标的能力。
### 关键设计细节
1. **任务定义**
   - 每个基础任务包含固定上下文模板（目标描述、约束、成功标准、可用API）+ 5个物理环境：1个源环境$E_0$、4个递增难度的变异目标环境$E_1-E_4$，所有环境共享目标和接口，仅物理参数（地形、摩擦、重力、材料强度等）发生改变
   - 核心测试单元为源-目标适应对，要求满足：源设计可在源环境通过、但在目标环境一定失效，且目标环境一定存在可验证的可行解，保证任务非平凡可解
   - 智能体最多拥有20次尝试机会，每次提交修改后的Python设计代码（定义结构组装和控制逻辑），沙箱执行后返回结构化诊断反馈（包含约束满足率、任务得分、失败位置/幅度信息），仅报告失败不提供修正建议，智能体需基于反馈迭代修改。
2. **基准构建流程**
   - 阶段1：任务生成：共定义6个物理领域，每个领域6个基础任务，每个基础任务生成4个源-目标对，共得到144个测试对，难度从Stage1到Stage4逐步递增。6个领域分别为：静力学平衡、运动学连杆设计、动力学能量、颗粒流体交互、控制论控制、奇异物理。
   - 阶段2：架构与参考解生成：采用模块化隔离架构，人工+LLM辅助生成每个环境的参考解，验证满足源设计失效、目标可解的要求。
   - 阶段3：验证校准：先进行自动化一致性审计，再经过三轮人工审核，最后用Qwen3-4B校准难度：调整参数直到Qwen3-4B两次独立运行都无法通过，但目标仍保持可解，保证基准难度合适。

## 3. 实验设计
- **测试基准与指标**：使用PACE-Bench的144组源-目标对作为测试集，核心指标为`Pass@2`（至少一次运行成功的比例）、`Score@2`（两次运行最优得分的平均值）。
- **对比方法**：覆盖当前四类主流自进化范式共10种方法，加上Vanilla迭代基线：
  - 上下文修正类：Reflexion、Self-Refine
  - 记忆增强类：ACE、ExpeL、ReasoningBank
  - 推理时搜索类：Tree-of-Thoughts(ToT)、CodeEvolve
  - 参数测试时学习类：SEAL、RAGEN、TTT-Discover
- **模型设置**：
  - 全基准测试：使用Qwen3 4B/8B/14B三个尺寸，测试所有对比方法
  - 大模型缩放测试：在静力学24对子集上，额外测试Qwen3-32B、DeepSeek-V4-Pro、GPT-5.5
  - 前沿模型对比：在5次尝试预算下，额外对比GPT-5.5、Gemini-3.1-Pro、Claude-Opus-4.7等6个闭源前沿模型
- **额外分析实验**：参数披露消融（对比不告诉变化/告诉精确变化）、VLM视频增强反馈消融、错误分类分析、代码相似性失败模式分析、成本归一化效率分析、从零生成设计难度测试等。

  - 覆盖了当前所有主流自进化范式、不同参数量的开源模型、多个前沿闭源模型，维度齐全

  - 整体实验设计充分、客观、公平，能够有效区分不同方法和模型的能力差异。

## 6. 主要结论与发现
1. 基准远未饱和：最强开源配置`Reflexion + Qwen3-14B`仅解决全基准35.9%的测试对，GPT-5.5在20次尝试预算下也仅解决静力学子集66.7%的问题，仍有很大提升空间
2. 范式层面规律：基于模拟器的带验证反思（Reflexion）性能最好，远优于无验证的自修正（Self-Refine，无验证内循环会累积错误）；记忆增强方法会让智能体锚定在早期设计，对强能力大模型反而会产生性能拖累；宽树搜索可以有效探索但很难在20次尝试预算内收敛；所有参数类方法整体性能都不如Vanilla基线
3. 失败模式：智能体普遍存在两类问题：要么设计固着（仅修改原有设计的细节，不改变整体框架），要么盲目探索无法收敛；领域难度差异大，动力学是最难的领域，奇异物理最容易，模型缩放对推理能力的提升远大于组合搜索能力
4. 核心瓶颈：哪怕直接告诉智能体精确的物理参数变化，也无法提升性能上限，说明**机制重新设计（知道如何修改结构逻辑）比参数推断（知道什么发生了变化）是更核心的瓶颈**
5. 额外发现：VLM视频反馈可以帮助记忆类方法降低设计固着、提升性能，但会分散上下文类方法的注意力，反而降低性能。

## 7. 优点
- 首次填补了自进化智能体评估的空白，瞄准真实部署中非常常见但未被标准化测试的「环境变化后原有设计适配」场景
- 基准构建流程严谨，通过自动化审计+三轮人工审核+科学难度校准，保证所有任务满足非平凡、可复现的要求，代码和数据完全公开
- 实验设计系统全面，覆盖了当前所有主流自进化范式，多维度分析揭示了不同方法的优缺点、失败模式和核心瓶颈，对后续研究有很强的指导价值

- 所有任务都是合成物理任务，尚未覆盖真实工程设计场景。
