# AgentSLABench: Evaluating and Benchmarking Agentic Systems Under Resource Constraints 

Meher Bhaskar Madiraju 

meherbhaskar.madiraju@gatech.edu 

Meher Sai Preetam Madiraju 

mehersaipreetam@gatech.edu 

Abstract — We present A GENT SLAB ENCH , a resource-aware evaluation framework for autonomous AI agents that measures correctness alongside latency, cost, compute, memory, and net-work usage under declared resource budgets. Unlike standard benchmarks that report only accuracy, AGENT SLAB ENCH 

produces a multi-dimensional profile per agent per task — the same way systems profilers ( perf , pprof , cProfile )measure resource consumption of code, but extended with task correctness as a first-class dimension. A GENT SLAB ENCH 

provides 16 task environments across 6 categories (5 core: multi-hop QA, retail substitution, code generation, web shopping, travel planning; 11 extended) with isolated Docker containers, declared CPU/memory/time/network budgets, sealed test sets with SHA256 hashes, and a standardized profiling protocol. We profile 5 general-purpose baseline agents (ReAct, PlanAndSolve, Reflexion, CoT, Random) plus 4 task-specialized agents, finding that specialized agents achieve 100% success on 3/5 core tasks (fact_qa, web_shopping, travel_planning) and 66.7–83.3% on retail and code_gen, while general baselines fail entirely on 4/5 domain tasks. Crucially, we report the Efficiency-Adjusted Suc-cess Rate (EASR) — success weighted by resource consumption relative to declared budgets — revealing that high accuracy at unbounded cost is not production-viable. We release the full infrastructure, sealed test sets, and profiling results to enable reproducible, resource-aware agent evaluation. 

Keywords: Agent Evaluation, Resource-Aware Profiling, Benchmark, Autonomous Agents, Production Constraints, Efficiency Metrics. I. I NTRODUCTION 

Autonomous agents powered by large language models (LLMs) are transitioning rapidly from research prototypes to production systems — deployed in customer support, software engineering, financial analysis, and enterprise au-tomation. Yet the evaluation methodologies remain stuck in a pre-production mindset: “Did it succeed?” dominates leaderboards and papers, while “Can it run in production?” 

is systematically ignored. An agent achieving 90% task accuracy but costing $50/query and taking 5 minutes is useless for real-time retail substitution where decisions must complete in < 200 ms at 

< $0 .01 . Similarly, an agent that solves coding tasks but requires 32GB GPU memory and 10 API calls per step cannot be deployed in cost-sensitive environments. Standard benchmarks (WebShop [1], ALFWorld [2], SWE-bench [3], GAIA [4], AgentBench [5], ToolBench [6]) measure task ac-curacy in unconstrained environments with effectively unlim-ited compute, memory, and API budgets. Systems profilers (perf , pprof , cProfile , nsys , VTune) measure CPU, memory, cache, and GPU utilization of code functions but have no notion of task correctness. No existing framework measures both task success and resource consumption under production-realistic constraints. 

This gap is not merely academic. Production deployment of LLM agents faces hard constraints that current evaluations ignore:  

> •

Latency SLAs: Often < 500 ms for user-facing, < 2sfor backend workflows  

> •

Cost budgets: Cents per query, not dollars (e.g., $0.01– $0.10 per resolution)  

> •

Memory limits: Container quotas (typically 2–8GB for CPU workloads)  

> •

Rate limits: External API throttling (e.g., 60 req/min on search APIs)  

> •

Safety/compliance: PII leakage, unauthorized tool calls, budget overruns An evaluation that ignores these dimensions produces “leaderboard champions” that fail in deployment. Industry surveys confirm this: teams report that agents passing accu-racy benchmarks routinely violate latency and cost SLAs in staging, requiring costly re-engineering [7]. Consider a concrete example: a retail substitution agent deployed at a major e-commerce platform must recommend alternative products when items go out of stock. The produc-tion SLA requires P99 latency < 200 ms, cost < $0 .005 per request, and memory < 512 MB. A ReAct-based agent using GPT-4 achieves 78% substitution accuracy in unconstrained evaluation but averages 3.2s latency, $0.12 cost, and 1.2GB memory — violating all three SLAs. A specialized RetailA-gent using a smaller model with cached product embeddings achieves 83% accuracy at 142ms, $0.002, and 180MB — meeting all constraints. Current benchmarks would report only the 78% vs 83% accuracy, missing the critical deploy-ment reality. We introduce agent profiling : extending systems profiling to autonomous agents with correctness as a measured dimen-sion alongside latency, cost, compute, memory, and network .The output of A GENT SLAB ENCH is not a scalar “score” but a profile — a structured record of (success, latency, cost, peak memory, CPU time, network calls, safety violations) per episode, under declared resource budgets. This mirrors how systems engineers profile code: they do not ask “is this function correct?” but rather “what is its performance profile?” — then optimize within constraints.

II. R ELATED WORK 

Agent Benchmarks. WebShop [1] evaluates web nav-igation and shopping; ALFWorld [2] measures embodied instruction following; SWE-bench [3] tests software engi-neering issue resolution; GAIA [4] assesses general assis-tant capabilities across browsing, tool use, and reasoning; AgentBench [5] provides a unified benchmark across 8environments; ToolBench [6] focuses on tool learning with 16,000 APIs. All report accuracy metrics (success rate, exact match, pass@k) without resource constraints. Recent work on agent evaluation (AgentEval [8], AutoGenBench [9]) introduces multi-dimensional scoring but still lacks enforced resource budgets and the profiling metaphor. 

Efficiency-Aware Evaluation in ML. Frugal ML [10] and Green AI [11] advocate for efficiency-aware model selection. MLPerf [12] measures training/inference through-put. SUSTAIN [13] proposes sustainability metrics for RL. Eco2AI [14] tracks carbon emissions. None extend to au-tonomous agent evaluation with multi-dimensional resource profiles. 

Production Observability Gaps. Modern observability stacks (LangSmith, LangFuse, Phoenix) provide tracing and token counting [7], [15], but lack: (1) enforced resource budgets (Docker-level CPU/memory/time limits), (2) multi-dimensional profiles (they track tokens/latency but not peak RSS, CPU time, network bytes, safety violations), (3) stan-dardized task interfaces for cross-agent comparison, (4) 

sealed test sets with cryptographic commitments, and (5) 

efficiency-adjusted metrics that penalize over-budget success. AGENT SLAB ENCH fills these gaps with a profiling-first design. 

Resource-Constrained Agent Work. ReAct [16] and Reflexion [17] optimize reasoning efficiency but evaluate only accuracy. LLM-Augmenter [18] adds retrieval but no resource budgets. RestGPT [19] and API-Bank [20] test API usage without cost/latency constraints. AgentOhana [21] unifies trajectories but not resource measurement. The closest is APBench [22] (concurrent work) which measures latency and token usage for API agents, but lacks memory, network, and compute dimensions, Docker enforcement, sealed test sets, and the profiling metaphor. 

Systems Profiling. perf (Linux), pprof (Go), 

cProfile (Python), nsys (NVIDIA), VTune (Intel) measure CPU, memory, cache, GPU utilization of code functions . None evaluate task correctness. Our contribution is the metaphor transfer : treating an agent episode as a “function” to be profiled, with correctness as one output dimension.

III. A GENT SLAB ENCH DESIGN 

A. Task Environments with Declared Budgets 

AGENT SLAB ENCH v1.0 includes 16 task environments across 6 categories (Table I). Each task declares its re-source budget — the maximum CPU cores, memory, wall-time, and network an agent may consume. Budgets are enforced via Docker container limits ( -cpus , -memory ,

-network , timeout), making over-consumption result in episode termination (recorded as failure with timeout vio-lation). 

Total: 16 tasks, 3,500 test samples — each with a de-clared resource envelope reflecting production requirements. For example, retail substitution (core) has a 180s/8GB bud-get matching real-time inventory decisions; travel planning has 600s/8GB for multi-constraint optimization; sentiment classification runs offline with 60s/2GB and no network. 

B. Profiling Protocol 

The A GENT SLAB ENCH profiling protocol standardizes evaluation across all agents and tasks: Each episode follows: (1) container launch with re-source limits, (2) task initialization via /reset , (3) agent-environment interaction via /step until completion or time-out, (4) resource measurement via container stats and API logs, (5) correctness judgment via LLM judge, (6) EASR computation, (7) JSONL output. This ensures identical eval-uation conditions across all agents. 

C. Profiling Infrastructure  

> •

Docker isolation per task: Fixed CPU quota ( -cpus ), memory limit (-memory ), timeout, network policy (-network=none or bridge). Over-budget episodes terminate with recorded violation.  

> •

Resource measurement: Wall time (ms), peak RSS (MB), CPU time (s), API cost (USD via provider pricing), token count (prompt/completion), HTTP calls, network bytes sent/received.  

> •

REST API interface: /reset , /step , /task ,

/health — standardized across all tasks, enabling agent-agnostic evaluation.  

> •

Multi-seed profiling: 3+ seeds (default: 42, 123, 456) per agent-task pair; configurable for statistical rigor.  

> •

Dev/test splits with SHA256 sealing: Cryptographic commitments prevent contamination; hashes published in SEALED_TEST_SETS.json . 

> •

Output format: Per-episode JSONL profile containing: 

task_id , agent , seed , success , reward ,

latency_ms , cost_usd , peak_mem_mb ,

cpu_time_s , net_calls , net_bytes ,

safety_violations , trajectory .

D. Agents Profiled 

General baselines (5): ReAct [16] (reasoning+acting interleaved), PlanAndSolve [26] (explicit planning), Reflex-ion [17] (verbal self-reflection), Chain-of-Thought [27] (step-by-step reasoning), Random (random action selection). 

Task-specialized (4): RetailAgent (domain logic for substitution rules, margin optimization), WebShoppingAgent (structured search + budget-aware purchasing), TravelPlanningAgent (constraint satisfaction for flights/hotels/activities), CodeGenAgent (API documentation retrieval + template-based generation). Each implements domain-specific heuristics, not just prompting.

A. Why General Baselines Fail on Domain Tasks 

The 0% success of ReAct, PlanAndSolve, CoT, and Re-flexion on retail, code_gen, web_shop, and travel is striking. These methods excel at open-ended reasoning (fact_qa) but lack: (1) domain schema knowledge (product catalogs, API signatures, travel constraints), (2) structured tool use (they hallucinate API calls), (3) constraint optimization (budget-aware shopping, multi-constraint travel). Specialized agents encode these as explicit logic, not prompt engineering. This suggests agent evaluation must measure specialization, not just general reasoning .

B. EASR as a Deployment Gate 

In production, an agent with 90% success but 200% latency budget is a liability. EASR formalizes this: it is 0 for any over-budget episode, regardless of correctness. This creates a Pareto frontier between success and efficiency. Teams can optimize for EASR directly, trading off model size, prompt complexity, and tool use to stay within budgets. C. Profile Output Enables System-Level Optimization 

Per-episode JSONL profiles allow: (a) Pareto analysis —plot success vs. latency/cost to find optimal operating points; (b) regression detection — CI/CD pipelines can flag EASR drops; (c) resource planning — aggregate profiles predict cluster costs; (d) safety auditing — constraint violations are explicit dimensions. This aligns with emerging practices in LLM operations where token usage and latency are tracked per request [7], [15], but A GENT SLAB ENCH adds enforced budgets and multi-dimensional profiles. 

D. Comparison to Other Efficiency Metrics 

EASR differs from Frugal Score [10] (model selection focus) and Green AI [11] (carbon focus) by being task-grounded and budget-relative . A task with 10s budget tol-erates 9s agents; a task with 200ms budget does not. EASR captures this relativity. It also differs from MLPerf’s through-put focus by measuring per-episode profiles, not aggregate throughput. 

E. Limitations of Current Budgets 

Budgets in v1.0 are heuristic (based on pilot runs). Future versions should derive budgets from production SLAs (e.g., P99 latency < 200 ms → budget 150ms). Network budgets should include rate-limit awareness (token bucket models). GPU budgets are not yet enforced (containers run CPU-only). Memory budgets could distinguish between RSS and swap. 

F. Connection to Production Observability Stacks 

AGENT SLAB ENCH complements (not replaces) produc-tion observability tools like LangSmith, LangFuse, and Phoenix. Those tools excel at tracing, debugging, and mon-itoring live traffic. A GENT SLAB ENCH provides the pre-deployment profiling standard — the “dyno run” before pro-duction. A natural integration: A GENT SLAB ENCH profiles gate deployment; production tools monitor drift from profile baselines. 

G. Threat Model and Safety 

The safety dimension (constraint_violations ,

error_count , timeout ) captures: (1) budget overruns (latency/cost/memory), (2) unauthorized tool calls (e.g., agent accessing admin APIs), (3) PII leakage in trajectories, (4) infinite loops (timeout). In our evaluation, TravelAgent had 12% constraint violation rate (mostly budget overruns on complex itineraries); CodeGenAgent had 8% unauthorized import attempts. These are explicitly recorded, not hidden in aggregate accuracy. VII. R EPRODUCIBILITY 

AgentSLABench is designed for full experimental repro-ducibility through sealed artifacts, containerized environ-ments, and deterministic execution.  

> •

Sealed test sets: All 16 tasks provide separate test 

and challenge splits with SHA256 hashes recorded in code/sealed_tests/MANIFEST.json (v1.0). Each split specifies the exact file, sample count, and generation seed (e.g., test seed 456, challenge seed 789), enabling verification of data integrity and prevention of contamination.  

> •

Containerized task environments: Each task runs in an isolated Docker image (agentslabench/<task>:v1.0 ) defined by 

code/tasks/*/Dockerfile with a shared base (code/Dockerfile.base ). Images are versioned and pinned to ensure identical execution environments across runs.  

> •

Deterministic seeds: All randomness is controlled via explicit seeds: generation seeds (456/789 per split in MANIFEST.json ), baseline agent seeds (con-figurable via -seed , default 42), and judge cal-ibration seeds (123). The pyproject.toml and 

requirements.txt pin all Python dependencies.  

> •

Baseline agents: Five reference implementations in-cluded: ReAct, Chain-of-Thought, Plan-and-Solve, Re-flexion, and Random ( code/baselines.py ), all de-terministic given a seed.  

> •

Judge calibration: Human-LLM agreement frame-work ( code/judge_calibration.py ) with cali-bration samples ( calibration_samples.jsonl ,

calibration_samples_100.jsonl ) for repro-ducible evaluation metrics.  

> •

Complete run artifacts: Final evaluation outputs (code/results/final_paper5_results.jsonl ,

final_core5_eval.jsonl ) and judge calibration data (judge_calibration.jsonl ,

human_judge_spotcheck_*.jsonl ) are versioned in the repository. All artifacts are available at https://github.com/ MeherBhaskar/agentslabench (v1.0 release). VIII. C ONCLUSION 

AGENT SLAB ENCH introduces agent profiling — mea-suring autonomous agents the way systems engineers pro-file code: with correctness as one dimension alongside latency, cost, compute, memory, and network. Specialized agents achieve 100% success on 3/5 core tasks (fact_qa, web_shopping, travel_planning) and 66.7–83.3% on retail and code_gen, while staying within declared resource budgets . General baselines fail entirely on 4/5 domain tasks. The framework provides Docker-isolated tasks with declared budgets, sealed test sets, multi-seed profiling, and standard-ized profile output — enabling reproducible, production-realistic agent evaluation.
