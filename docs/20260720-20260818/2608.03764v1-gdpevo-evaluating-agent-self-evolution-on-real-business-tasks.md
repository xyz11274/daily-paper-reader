## 摘要
智能体自进化指智能体根据过往经验更新自身持久状态，并复用该状态以更高效地解决相关任务。自进化能力评估存在诸多难点：现有基准对具有经济价值的任务域覆盖有限，并非所有训练与测试任务的设计都能将测试阶段的性能提升归因于训练经验，且仍易受数据污染影响。本文提出GDPevo，这是一个扎根于GDP相关企业工作流的原生面向进化的基准，同时提供了生成该基准的全自动化数据流水线。其核心机制规则杂交将每个企业工作流分解为原子业务规则，在训练任务中分配这些规则的子集，再在留出测试任务中对规则进行重新组合，从而使测试阶段的性能提升可明确归因。GDPevo覆盖CRM、ERP、金融、医疗、法律和以数据为中心的工作流。其V1版本包含12个任务组共120项任务，每个任务组包含5项训练任务和5项留出测试任务。全自动化设计使该流水线可在两天内将基准集扩展至24个任务组共240项任务（V2版本），为数据污染问题提供了可行的应对方案。基于GDPevo，我们在四种监督类型下评估了四个智能体，每个智能体由支撑框架和模型构成。自进化可稳定提升留出集准确率，最高提升幅度达16.44个百分点。但表现最优的进化后智能体仍远低于91.6%的全信息先知上限，表明当前智能体的自进化能力仍远未得到充分开发。我们将流水线、基准和完整评估结果公开于https://github.com/Prism-Shadow/GDPevo。

## Abstract
Agent self-evolution updates an agent's persistent state from prior experience and reuses it to solve related tasks more effectively. Evaluating self-evolution is difficult: existing benchmarks provide limited coverage of economically valuable task domains, do not always design training and test tasks such that test-time gains can be attributed to training experience, and remain vulnerable to data contamination. We present GDPevo, an evolution-native benchmark grounded in GDP-related enterprise workflows, together with the fully automated data pipeline that generates it. Its core mechanism, rule hybridization, decomposes each enterprise workflow into atomic business rules, distributes subsets of these rules across training tasks, and recombines them in held-out test tasks so that test-time gains are attributable. GDPevo spans CRM, ERP, finance, healthcare, legal, and data-centric workflows. Its V1 release contains 120 tasks in 12 groups, with five training and five held-out test tasks per group. Full automation enables the pipeline to expand the suite to 240 tasks in 24 groups (V2) within two days, providing a practical response to contamination. Using GDPevo, we evaluate four agents, each comprising a harness and a model, under four supervision types. Self-evolution consistently improves held-out accuracy by up to 16.44 percentage points. But the best evolved agents remain far below the fully informed oracle ceiling of 91.6%, indicating that the self-evolution ability of current agents remains far from fully realized. We publicly release the pipeline, benchmark, and full evaluation results at https://github.com/Prism-Shadow/GDPevo.

## 1. 核心问题与研究背景
- 研究背景：智能体自进化是指智能体从过往交互经验中更新自身持久状态（包括参数、记忆、技能、提示等），复用积累的经验更高效地解决后续相关任务，是当前智能体领域的热点研究方向。但自进化算法发展迅速，对应的评估方法却远未成熟。
- 核心问题：现有自进化评估基准存在三个关键缺陷：
  1. 对具备实际经济价值的真实企业业务任务覆盖严重不足；
  2. 多数基准的训练-测试划分不是围绕可迁移能力设计的，测试阶段获得的性能提升无法明确归因于训练阶段积累的经验；
  3. 公开静态基准容易遭遇数据污染，随着大模型快速迭代，很快就会失去评估有效性。

## 2. 提出的方法论
### 核心思想
构建一个**原生面向自进化评估**的基准GDPevo，扎根于真实GDP相关的企业业务流程，解决现有基准的三大缺陷，为自进化智能体研究提供可靠、可扩展的评估基础设施。

### 关键技术细节
1. **核心机制：规则杂交**，实现训练-测试增益的可归因性：
   - 第一步：将每个企业工作流场景分解为原子业务规则，这类规则是企业特有的内部约定，不属于通用大模型的世界知识，必须从训练中学习；
   - 第二步：将完整规则集拆分为多个子集，分散分配到同一个任务组的5个训练任务中；
   - 第三步：在留出的5个测试任务中，重新组合不同的原子规则生成新任务；智能体必须从训练中推断出可复用的规则，才能在测试阶段正确组合应用，因此测试性能提升可明确归因于训练学到的经验。
2. **全自动化基准生成流水线**，可快速扩展对抗数据污染：
   - 阶段1：种子场景发现：从现有公开领域基准筛选符合要求（具备隐藏业务规则、可确定性评估、支持长周期标准操作流程）的种子场景；
   - 阶段2：任务组生成：为每个种子场景构建共享业务环境，按照规则杂交机制生成5个训练任务+5个测试任务，输出任务-规则分配矩阵；
   - 阶段3：校准与独立审核：要求候选任务组满足：无训练经验的base准确率在40%-60%之间、fewshot进化后准确率提升10-30个百分点、进化后准确率低于80%（预留研究空间），再由6个独立审核agent检查，获得至少5票同意才能保留。
   - 扩展能力：全自动化设计让基准可快速刷新，初始V1版本包含12个任务组共120个任务，仅用2天就扩展出V2版本，最终达到24个任务组共240个任务，可快速应对数据污染问题。
3. **基准设计特性**：
   - 采用确定性代码化规则打分，替代LLM裁判，结果可复现、错误可追溯到具体违反的规则；
   - 将推理成本（token消耗、交互轮次、货币成本）作为一级评估指标，同时衡量进化对准确性和效率的提升；
   - 提供多维度诊断视图（分领域性能 breakdown、跨域迁移热力图等），方便研究者分析进化效果。

## 3. 实验设计
- 评估基准/数据集：使用GDPevo全量基准，共24个任务组240个任务，覆盖CRM、ERP、金融、医疗、法律、数据分析6大类企业业务领域，每个任务组共享同一业务环境，包含5个训练任务、5个留出测试任务。
- 评估对象：智能体定义为`支撑框架(harness) + 基础大模型`，共评估4种不同组合：
  1. Codex + GPT-5.5
  2. Claude Code + Opus-4.8
  3. Claude Code + GLM-5.2
  4. Claude Code + DeepSeek-V4-Pro-Preview
- 对比设置：对比4种不同的监督类型（对应不同的自进化范式）：
  1. `base`：无进化，智能体直接尝试测试任务，作为基线；
  2. `fewshot`：提供训练任务的输入和金标答案，类似监督微调，学习技能；
  3. `reflect`：仅提供训练任务输入，智能体自主尝试后反馈得分，共3轮反馈，类似强化学习；
  4. `self`：仅提供训练任务输入，无任何答案相关监督，类似无监督学习。
- 针对性实验：围绕三个研究问题设计实验：
  1. RQ1：不同监督类型对准确率和成本的影响；
  2. RQ2：进化获得的技能跨领域迁移效果；
  3. RQ3：对比不同技能创建器（进化方法），验证进化方法和模型本身哪个对进化效果影响更大，共对比Naive、Claude Code、Codex、OpenCode、deepagents 5种技能创建器。
- 实验控制：每个测试任务重复运行3次取平均结果，每个实验运行在独立隔离的Docker容器中，避免信息泄露。

## 6. 主要结论与发现
1. 所有形式的自进化都能提升测试性能，其中fewshot监督的提升幅度最大，最高比无进化基线提升16.44个百分点；自进化不仅可以提升准确率，还能降低测试阶段的推理成本（如GPT-5.5在fewshot设置下准确率提升15.14个百分点，同时测试成本降低20.88%）。
2. 自进化可以替代部分模型预训练：小模型加自进化可以达到更大规模基础模型无进化的性能，且成本大幅降低（如DeepSeek-V4-Pro-Preview的fewshot性能和GPT-5.5无进化性能相当，成本仅为1/28）。
3. 基础模型能力越强，进化空间越大：最弱的基础模型基线准确率最低，进化增益也最小；最强的基础模型基线准确率最高，进化增益也最大。
4. 跨域迁移特性：fewshot监督（类似监督微调）容易过拟合源域，跨域迁移大多无收益甚至会损害性能；reflect监督（类似强化学习）泛化性更好，跨域迁移很少损害性能，还经常能带来正向收益。
5. 模型本身的能力比进化方法设计更重要：简单朴素的技能创建器效果不输甚至优于复杂的现成技能创建器，过度设计进化方法反而可能降低性能，进化增益的大小主要由基础模型的智能决定。
6. 当前最优的进化后智能体性能仍然远低于91.6%的全信息先知性能上限，说明当前智能体的自进化能力还远未成熟，存在很大的研究空间。

## 8. 不足与局限
1. 全信息先知性能上限是人类+模型协作的近似估计，缺乏覆盖所有领域的真实专家标注金标准，上限本身存在近似误差；
2. 论文实验仅评估了基于技能的非参数自进化方案，虽然GDPevo基准本身支持评估参数进化、记忆进化、提示进化等多种自进化范式，但论文未对多种自进化范式做全面的对比评估；

4. 当前版本仅包含24个任务组共240个任务，领域多样性和任务规模仍有进一步扩展的空间；
5. 基准生成依赖大模型自动完成，生成质量受底层大模型的能力约束。
