## 摘要
AI编程代理的性能高度依赖于其底层的编码规则。然而，现有的编码规则通常是手工设计且固定的，导致过程劳动密集且往往次优。在本工作中，我们提出了RuleEvolve，一个用于编码规则的自演化框架。RuleEvolve维护一个候选编码规则池，并迭代地改进它们。在每次迭代中，它采用一个由LLM驱动的变异模块从现有候选中生成变体，然后使用一个评判模块评估这些变体，并用表现最佳的变体更新规则池。在两种编程代理框架、四种骨干LLM和三个基准上的广泛评估表明，RuleEvolve在生成代码的功能正确性、代码长度和/或生成成本（例如使用的令牌数）方面，均优于人工工程和现有的提示优化基线。

## Abstract
The performance of AI coding agents is highly dependent on their underlying coding rules. However, existing coding rules are typically hand-crafted and fixed, making the process labor-intensive and often suboptimal. In this work, we propose RuleEvolve, a self-evolving framework for coding rules. RuleEvolve maintains a pool of candidate coding rules and iteratively improves them. In each iteration, it employs an LLM-powered mutator module to generate variants from existing candidates, and then uses a judge module to evaluate these variants and update the pool with the best-performing ones. Extensive evaluations across two coding-agent frameworks, four backbone LLMs, and three benchmarks demonstrate that RuleEvolve outperforms both manual engineering and existing prompt optimization baselines in terms of functional correctness of the generated code, code length, and/or generation cost (e.g., tokens used).

## 1. 核心问题与研究动机

- **背景**：AI编程代理（如OpenHands、Claude Code、Cursor）的性能高度依赖其编码规则文件（通常以`AGENTS.md`形式存在，被前置到骨干模型的输入上下文中）。这些规则直接影响生成代码的正确性、长度和推理成本。
- **核心问题**：现有编码规则几乎完全由人工手工编写且固定不变，存在两大痛点：
  - **劳动密集且次优**：人工规则缺乏任务特定对齐，甚至可能降低代理性能（论文引用[11]证实此现象）。
  - **现有自动优化方法不适用**：现有提示优化技术（如Prompt-Ops）主要针对短小的几句话指令，而编码规则是长篇、结构化的文档，搜索空间巨大；同时编程代理的资源密集特性使随机变异策略计算上不可行。
- **整体含义**：论文提出需要一种能自动演化复杂编码规则的框架，以在保持功能正确性的前提下，降低代码长度和生成成本。

## 2. 方法论：RuleEvolve框架

### 核心思想
- 维护一个大小为m的候选编码规则池，通过迭代的"变异-评估-剪枝"过程自动演化规则。
- 将不可微的代理生成过程（多轮交互、工具调用）近似为基于LLM的迭代优化过程。

### 关键技术细节

- **变异模块（Mutator M）**：由LLM驱动，输入编码规则r和变异指导g（如"通过改进措辞、重排或组合步骤、改变风格来变异编码规则"），输出变异候选规则。
- **评判模块（Judge J）**：在特定规则下生成代码、执行代码并评估性能，输出综合得分S。
- **评分公式**：
  - 正确性惩罚项：`E_x[V(x, A_θ(x, ∅)) - V(x, A_θ(x, r))]_+`，确保演化规则不降低功能性能。
  - 综合得分：`S = -|A_θ(x, r)| - λ · E_x[V(x, A_θ(x, ∅)) - V(x, A_θ(x, r))]_+`，其中λ=3000平衡两项，用生成代码字符数近似代码长度和推理成本。
- **迭代流程（Algorithm 1）**：
  1. 初始化：对初始规则做m次变异填充规则池，评估得分。
  2. 每轮迭代：根据历史得分战略性分配N个变异；生成新候选；评判新候选；保留top-m候选。
  3. T轮后返回平均得分最高的规则。
- **战略性变异分配（基于OCBA）**：
  - 目标：最大化正确选择最佳候选的概率（PCS）。
  - 分配权重：`w_i ∝ (σ̂_i / (μ̂_b - μ̂_i))²`，即优先变异性能方差大或均值接近当前最优的候选。
  - 最优候选权重：`w_b = σ̂_b · sqrt(Σ_{i≠b} w_i²/σ̂_i²)`。
  - 新变异候选继承父代的得分集，解决冷启动问题并保证统计稳定性。
