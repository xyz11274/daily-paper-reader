Abstract 

The performance of AI coding agents is highly dependent on their underlying coding rules. However, existing coding rules are typically hand-crafted and fixed, making the process labor-intensive and often suboptimal. In this work, we propose 

RuleEvolve , a self-evolving framework for coding rules. RuleEvolve maintains a pool of candidate coding rules and iteratively improves them. In each iteration, it employs an LLM-powered mutator module to generate variants from existing candidates, and then uses a judge module to evaluate these variants and update the pool with the best-performing ones. Extensive evaluations across two coding-agent frameworks, four backbone LLMs, and three benchmarks demonstrate that RuleEvolve outperforms both manual engineering and existing prompt optimization baselines in terms of functional correctness of the generated code, code length, and/or generation cost (e.g., tokens used). 

1 Introduction 

The evolution of AI coding agents, such as OpenHands [22], OpenCode [2], Claude Code [3], and Cursor [8], has fundamentally redefined code generation tasks by shifting the focus from manual implementation to high-level orchestration. Central to the performance of these agents is the coding rules file, often instantiated as an AGENTS.md document and prepended to the backbone model’s input context [1]. These rules play a critical role in determining the correctness and length of the generated code, as well as the associated generation cost. Despite the critical importance of these rules, they are currently almost exclusively hand-crafted by human developers [18]. This manual process is inherently labor-intensive and suboptimal, as human-written rules often lack task-specific alignment and can even degrade agent performance [11]. Although automatic techniques [23] for prompt optimization have been developed, these methods remain difficult to directly apply to self-evolving coding rules. Existing approaches primarily target short, few-sentence instructions, whereas coding rules are typically long, well-documented guidance that present a significantly larger search space. Furthermore, the resource-intensive nature of coding agents renders previous random mutation strategies computationally prohibitive. Consequently, there is a critical need for a framework that can automatically evolve complex coding rules. To bridge this gap, we propose RuleEvolve, a self-evolving framework for coding rules. The overall pipeline is illustrated in Figure 1. RuleEvolve takes as input a set of coding tasks and aims to evolve coding rules that can generalize to improve code generation on other tasks. Specifically, RuleEvolve maintains a pool of m candidate coding rules and iteratively evolves them. In each iteration, it employs an LLM-powered mutator module to generate N mutations from the current candidates. Each mutation is then evaluated by a judge module , which assesses performance in terms of code

2 Related Works 

2.1 AI-assisted Code Generation 

The landscape of software engineering has been transformed by AI-assisted code generation. To evaluate these AI-generated code, the research community has established several coding benchmarks, such as HumanEval [6] and BigCodeBench [28], which assess the ability of models to generate executable and functional code across a variety of programming tasks. Recent works [16, 26] have sought to enhance the quality of generated code through prompting strategies. However, these efforts primarily focus on the performance of the underlying coding LLM in isolation rather than within the agentic framework. Furthermore, these studies focus on the optimization of task-specific prompts to the coding LLM, without considering the self-evolving of the coding rules that guide the code generation process universally. 

2.2 Coding Rules for AI Coding Agents 

AI coding agents rely on coding rules, typically stored in an AGENTS.md file, to guide the generation of code. These rules and guidance are combined with the system and user prompts to serve as input for the backbone LLM. The specific rules provided influence the structure and style of the generated code. While recent works [10, 11, 7] have explored the impact of these rules on code generation, these studies primarily focus on measurement without providing practical insights into how these coding rules can be systematically improved or evolved. 22.3 Self-evolving Agents 

Existing studies on self-evolving agents primarily focus on models, tools, skills, and mem-ory [25, 19, 20, 27]. While coding rules are central to coding agents, their self-evolving remains largely unexplored. Automatic prompt optimization techniques [23, 14, 21, 9, 17, 15, 4, 12] can theoretically be applied to optimize coding rules; however, these methods primarily target short prompts consisting of only a few sentences. In contrast, coding rules are extensive, well-documented sets of instructions that create a significantly larger search space beyond the capability of existing optimizers. Consequently, applying current prompt optimization techniques directly to coding rules yields suboptimal performance, as confirmed by our experiments with Prompt-Ops [23]. 

3 Problem Definition 

3.1 AI Agents for Code Generation 

We consider an AI coding agent Aθ powered by a backbone LLM with parameters θ. The agent gen-erates code conditioned on a specific programming task and underlying coding rules. In practice, for most modern coding agents, these rules are instantiated via an AGENTS.md document and prepended to the LLM’s input context. Let x ∈ X denote a coding task (i.e., the problem description), r denote the coding rules, and y

denote the generated code, where X is the coding task set. Formally, the coding agent Aθ samples the code y from the conditional distribution: 

y ∼ pθ (· | x, r ). (1) Given a coding task x and fixed parameters θ, the coding rules r significantly influence the code generation process, thereby affecting the correctness, length, and inference cost. While correctness ensures the functional integrity of the code, length and inference cost are equally critical for real-world deployment. Code length determines the performance of the generated code, where optimized logic reduces execution latency and resource consumption. Inference cost directly affect the scalability of the agentic system; by minimizing token usage and generation time, developers can substantially lower API expenses and improve the responsiveness of the development cycle. Formally, we define two primary goals for the coding rule self-evolving process: • The generated code y should be executable and functionally correct. • The evolved coding rules should reduce the code length as possible and minimize inference costs during the generation process.

4.1 Overview 

To achieve these objectives, we propose RuleEvolve, a self-evolving framework for coding rules. As illustrated in Figure 1, RuleEvolve consists of three primary components: a rule pool of fixed size m,a mutator module for generating mutated candidates, and a judge module for evaluation and selection. Given the initial coding rules r, RuleEvolve first employs the mutator module to populate the pool with m mutated versions. In each subsequent iteration, N newly mutated candidates are generated from m candidates in the current pool. Mutations are strategically allocated based on the historical mean and variance of the candidates’ scores. Finally, the m + N candidates are evaluated by the judge module; the top m candidates are retained for the next iteration, while others are pruned. 

Challenge and motivation: The self-evolving of coding rules presents two key challenges. First, the generation process in a coding agent typically involves multi-turn interactions and external tool-calling, rendering the pipeline non-differentiable and precluding direct gradient-based optimization. We address this by implementing an iterative mutation and pruning framework that leverages the mutator module and the judge module to approximate the optimization process (see Section 4.2). Second, unlike standard prompt optimization tasks that involve short targets and low evaluation costs, coding rules are significantly more resource-intensive to evolve. Each rule set requires full agent execution and verification, leading to substantial latency and API token consumption. To avoid resource waste and enhance effectiveness, we propose a strategic mutation-allocation method that prioritizes mutating promising candidates, as detailed in Section 4.3. 

4.2 Iterative Mutation and Pruning Mutator M: The mutator module, powered by an LLM, takes the coding rules r and a mutation guidance g as input to produce a mutated candidate rm = M(r, g ). The mutation guidance g typically consists of a natural language directive, such as: "Mutate the coding rules for an AI coding agent into a new variant by improving wording, reordering or combining steps, and varying the style." 

Judge J : The Judge module provides the evaluation environment for generating code under specific coding rules, executing the generated code, and assessing performance across the dimensions of correctness, length, and inference cost. Specifically, the Judge J takes the coding rules r, the agent 

Aθ , and a task set X as input to produce a score S = J (r, Aθ , X ).As formulated in Section 3.2, this score consists of two components. The first is a correctness penalty designed to ensure that the evolved rules do not degrade the agent’s functional performance. Given the code verifier V, the penalty is defined as: 

Ex∈X [V(x, Aθ (x, ∅)) − V (x, Aθ (x, r ))] + , (4) where Aθ (x, ∅) denotes the code generated by the agent without external coding rules, Aθ (x, r )

denotes the code generated using coding rules r, and [z]+ = max( z, 0) .The second component focuses on the code length and inference cost of the generation process. As illustrated in Figure 2a, there is a high correlation between code characters and token usage during generation. Consequently, we approximate both code length and inference cost using the number of characters of the generated code, denoted by |A θ (x, r )|. The overall score S is formulated as: 

S = −|A θ (x, r )| − λ · Ex∈X [V(x, Aθ (x, ∅)) − V (x, Aθ (x, r ))] + , (5) where λ is a hyperparameter that balances the trade-off between two components.

4.3 Strategic Mutation Allocation 

To avoid meaningless mutations and enhance effectiveness, we employ the Optimal Computing Budget Allocation [5] to distribute N mutations among m candidates wisely. The core objective is to maximize the probability of correctly identifying the best-performing candidate while minimizing redundant evaluations of suboptimal candidates. For each candidate i, we maintain a score set Si containing the score from each iteration’s evaluation. To address the cold-start problem and ensure statistical stability, a newly mutated candidate inherits the score set from its parent. 5.2 Main Results 

Table 1 and Table 2 present a comprehensive comparison of RuleEvolve against other baseline approaches. Generally, RuleEvolve outperforms existing baselines by achieving a superior balance between functional correctness, code length and inference cost. Specifically, RuleEvolve consistently achieves the highest or equal Pass Rate (PR) across all benchmarks. When achieving comparable PRs to "No rule" or "Manual rule", RuleEvolve demonstrates significant improvements in code length and inference cost. For example, on the BigCodeBench (BCB) benchmark within the OpenAI SDK framework, RuleEvolve improves the PR from 0.45 (Manual rule) to 0.49, while simultaneously reducing the average code characters from 2372 to 453.1 and token usage from 1022 to 544.5. Similarly, in the OpenHands environment for the HumanEval (HE) benchmark, RuleEvolve maintains a comparable PR of 0.99 while reducing average code lines to 12.7, compared to 21.7 for human-written rules. We also note that Prompt-Ops occasionally achieves lower code length and inference cost than RuleEvolve in certain scenarios. For instance, on BigCodeBench-Hard (BCB-H) within the OpenAI SDK, Prompt-Ops yields an average token usage of 588.7 compared to 595.8 for RuleEvolve. However, the gains in code length or inference cost come at the expense of functional integrity; in the OpenHands BCB scenario, Prompt-Ops suffers a substantial drop in PR to 0.43, whereas RuleEvolve reaches 0.52. We stress that PR is the most critical metric in autonomous coding; if the generated code is incorrect, optimizing for code length or inference cost becomes meaningless. By prioritizing functional correctness, RuleEvolve ensures that gains in code length or inference cost do not compromise the agent’s primary utility. The comprehensive results across diverse backbones are detailed in Table 5 and Table 6 in the Appendix. Across all evaluated backbone models, RuleEvolve consistently achieves superior or comparable pass rates. At the same time, RuleEvolve significantly reduces code length and inference cost in most cases. For instance, with the gpt-5-mini backbone on BCB, RuleEvolve achieves a PR of 0.46 compared to 0.31 for manual rules, while simultaneously reducing token usage by nearly 40%. Furthermore, RuleEvolve consistently outperforms Prompt-Ops across nearly all backbone–benchmark combinations. While Prompt-Ops often struggles with correctness (e.g., dropping to a 0.67 PR on HumanEval (HE) with Qwen-Coder-30B), RuleEvolve maintains high PRs across all benchmarks and backbone models. We also observe that different backbone models exhibit diverse generation styles; for example, gpt-5-mini tends to produce longer code and requires more generation time, while gpt-5.3-codex is more efficient. 

Multi-seed results: To assess the robustness and statistical stability of RuleEvolve, we performed evaluations across 10 independent seeds using the GPT-4.1-mini backbone on the BigCodeBench dataset. Impact of number of iterations T : Figure 2a shows the evolution of metrics over 20 itera-tions during the evolvement process. The pass rate remains remarkably consistent throughout the iterations, demonstrating that RuleEvolve successfully optimizes for code length and infer-ence cost without compromising the correctness of the generated code. By the twentieth iteration, the metrics level off, suggesting that the rule evolvement process effectively converges.

6 Conclusion 

In this work, we investigate the self-evolvement of coding rules for AI coding agents. We show that coding rules can be evolved to greatly reduce code length and minimize inference costs while maintaining the functional correctness of the generated code. This is achieved by RuleEvolve, our proposed automatic self-evolving framework for coding rules. By employing a mutator, judge module, and a strategic mutation-allocation approach, RuleE-volve successfully evolves coding rules via iterative mutation and pruning.
