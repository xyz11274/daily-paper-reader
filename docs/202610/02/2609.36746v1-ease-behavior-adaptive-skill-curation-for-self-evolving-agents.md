## 摘要
智能体技能为自进化智能体提供了一种轻量级机制，无需更新模型参数即可积累可复用的程序性知识。然而，现有学习型技能策展器通常在不显式建模下游执行器行为的情况下优化策展。我们表明，这可能导致系统性的跨执行器性能退化：使用不同执行器训练的策展器在与各自训练执行器配对时表现最佳，这表明有效的技能策展依赖于执行器。我们将行为自适应技能策展形式化，并引入 EASE，一个学习单一策展器的框架，使其决策能够适应不同执行器的行为。EASE 维护近期执行模式的在线行为画像，并以此画像、当前轨迹和检索到的技能为条件，对不断演化的技能库中的技能进行添加、修改或删除。我们使用强化学习在多个冻结执行器上联合训练共享策展器，并采用检索感知和行为感知的时间归因，将优化聚焦于具有可观测下游影响的策展动作。在 ALFWorld、ScienceWorld 和 WebShop 上，执行器涵盖 Qwen3-8B/32B、GPT-OSS-120B 以及未见过的 Kimi K2.6、DeepSeek V4 Flash 和 Gemini 3.5 Flash，EASE 在无需针对每个执行器微调的情况下优于强大的基于技能和记忆的基线。EASE 还保持少 34.5--41.0% 的技能数量，将技能检索提升 36.3--38.7%，将测得的编辑效用提升 51.8--60.0%，并将部署时推理 token 减少 9.1--14.5%。这些结果确立了行为自适应技能策展作为构建自进化智能体的一种有效原则。

## Abstract
Agent skills provide a lightweight mechanism for self-evolving agents to accumulate reusable procedural knowledge without updating model parameters. However, existing learned skill curators typically optimize curation without explicitly modeling downstream executor behavior. We show that this can cause systematic cross-executor degradation: curators trained with different executors perform best when paired with their own training executor, indicating that effective skill curation is executor-dependent. We formulate behavior-adaptive skill curation and introduce EASE, a framework that learns a single curator that adapts its decisions to different executor behaviors. EASE maintains an online behavioral profile of recent execution patterns and conditions the curator on this profile, the current trajectory, and retrieved skills to add, modify, or remove skills from an evolving repository. We train the shared curator jointly across multiple frozen executors with reinforcement learning, using retrieval-aware and behavior-aware temporal attribution to focus optimization on curation actions with observable downstream influence. Across ALFWorld, ScienceWorld, and WebShop, with executors ranging from Qwen3-8B/32B and GPT-OSS-120B to unseen Kimi K2.6, DeepSeek V4 Flash, and Gemini 3.5 Flash, EASE outperforms strong skill- and memory-based baselines without per-executor finetuning. EASE also maintains 34.5--41.0% fewer skills, improves skill retrieval by 36.3--38.7% and measured edit utility by 51.8--60.0%, and reduces deployment-time inference tokens by 9.1--14.5%. These results establish behavior-adaptive skill curation as an effective principle for building self-evolving agents.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在交互环境中需要长程推理、工具使用和持续适应。基于模型微调的方式在部署阶段往往不可行（API 受限、算力昂贵、持续更新易导致不稳定或过拟合）。
- **轻量替代方案**：将经验积累为“智能体技能”（agent skills），即紧凑、可复用的程序性知识描述，可在不修改执行器参数的前提下被检索和复用。
- **核心问题**：现有学习型技能策展器（如 SkillOS）在优化策展策略时，**未显式建模下游执行器的行为**。论文通过实验（图 1）证明：用不同执行器训练的策展器，在与各自训练执行器配对时表现最佳，错配时性能系统性下降 2.3–10.0 pp。
- **关键洞察**：有效的技能策展是**执行器依赖的**（executor-dependent）。同一技能或策展决策在不同执行器下的下游效用不同，因为执行器的动作偏好、失败模式、恢复行为、推理模式和利用检索指令的能力各异。
- **研究目标**：提出**行为自适应技能策展**（behavior-adaptive skill curation）这一新范式——学习一个共享策展器，根据执行器的在线行为动态调整策展决策，从而支持已见和未见执行器，无需按执行器微调。

## 2. 方法论

### 2.1 核心思想

- 不训练多个执行器专属策展器，而是训练**单一条件策略** πθ，其决策随执行器的**可观测行为**变化。
- 执行器与策展器参数在部署时均冻结，适应仅通过**行为画像更新**和**技能库演化**实现。

### 2.2 关键技术细节

- **在线执行器行为画像**：
  - 对每个执行器维护画像 P_t(E)，聚合最近 W 个已完成任务的执行证据（滑动窗口，默认 W=16）。
  - 特征族包括：动作有效性（被拒动作率、解析失败）、失败恢复（重复被拒、恢复步数）、状态跟踪（重复访问、前置条件违反）、执行效率（每回合步数、预算触达频率）、错误类型、技能利用率（检索频率、显式引用、条件结果）。
  - 缺失信号标记为“不可用”而非零；检索与显式使用证据区分开。
  - 描述符 e_t = [P_t(E); m(E)]，其中 m(E) 为可选静态元数据（模型族、规模、上下文窗口），缺失字段显式标记为未知。

- **行为条件化策展**：
  - 策展器以当前轨迹 ξ_t、反馈 c_t、检索技能 S_t^ret 和行为描述符 e_t 为条件，输出三种操作：**add**（新增技能）、**modify**（修订技能）、**delete**（删除冗余或有害技能）。
  - 更新后的技能库 S_{t+1} 仅对后续任务可见。

- **多执行器强化学习训练**：
  - 仅训练策展器（Qwen3-8B + LoRA），执行器全部冻结。
  - 使用 GRPO 优化，每个训练组固定一个执行器和一条有序任务流（T=10 个相关任务），采样 N=8 条独立 rollout，各自维护独立技能库和画像。
  - 奖励函数：R = r_task + λ_f·r_func + λ_c·r_comp + λ_u·r_qual，其中任务奖励平均 x₂…x_T 的结果，辅助项奖励成功执行的策展调用、技能库紧凑度和训练时评判器评估的内容质量。
  - 优势按组内归一化：A = (R − μ_G)/(σ_G + ε_A)。

- **检索感知与行为感知的时间信用分配**（解决“哪些策展动作真正影响后续执行”的问题）：
  - **门控 1（检索发生率）**：仅当被编辑技能在后续任务中进入检索（或若未编辑本会进入检索，通过补丁仓库测试）时才纳入优化，即 Z_t > 0。
  - **门控 2（行为偏差）**：将后续技能辅助动作序列与缓存的技能无关参考轨迹比较，计算归一化 Levenshtein 偏差 D_j，减去技能无关运行间的背景变异，仅当 D_j > τ（τ=0.05）时纳入。
  - **掩码策略优化**：仅在满足两个门控的策展步骤上最大化 PPO 裁剪代理目标，优势仍由全部 N 条 rollout 计算。
  - 门控仅用于训练；部署时不需要质量评判器、参考轨迹和门控。

### 2.3 算法流程（文字描述）

1. 任务 x_t 到达，执行器检索至多 k=5 个技能并交互，产生轨迹 ξ_t 和反馈 c_t。
2. 将本次执行证据聚合进行为画像 P_t(E)。
3. 策展器以 (ξ_t, c_t, S_t^ret, e_t) 为条件，采样策展操作序列 Δ_t。
4. 更新技能库 S_{t+1} = Δ_t(S_t)，供后续任务使用。
5. 训练时：多执行器 rollout → 计算组相对优势 → 门控筛选策展步骤 → 掩码策略梯度更新。
6. 部署时：策展器与执行器冻结，仅画像和技能库在线更新。

## 6. 主要结论与发现

- **执行器依赖性**：匹配的策展器–执行器对始终优于错配对，错配差距 2.3–10.0 pp，证明技能策展依赖执行器行为。
- **单一策展器可服务多执行器**：EASE 在三个已见执行器上平均分均最优，比匹配专家高 2.7/2.0/1.9 pp；在三个未见执行器上比 SkillOS-best 高 3.8/2.7/2.1 pp，无需按执行器微调。
- **在线适应有效**：继续更新画像比冻结画像提升 3.8/2.2/1.1 pp；继续在线策展比冻结技能库提升 5.9/3.7/2.4 pp；16 任务窗口优于 4 任务窗口和全历史。
- **技能库更紧凑、更有用**：技能数减少 34.5–41.0%，编辑版本检索率提升 36.3–38.7%，编辑回滚收益提升 51.8–60.0%。
- **推理成本更低**：部署时总推理 token 减少 9.1–14.5%，主要来自技能上下文缩短（30.6–41.7%）和环境步数减少，抵消了 150–260 额外策展器 token。
- **消融结论**：移除描述符导致最大性能下降（7.5–9.5 pp），静态模型卡仅恢复 1.8–4.6 pp，在线画像单独接近完整描述符（差 0.5 pp）；移除两个门控损失 4.8–6.5 pp，检索门贡献主要部分，行为门额外贡献 1.3–2.1 pp，随机掩码与无门控相当，说明增益来自“更新哪些步骤”而非“更新多少”。

## 7. 优点

- **问题定义新颖且实证扎实**：首次系统性地将“执行器行为”纳入技能策展的条件变量，并用受控实验（匹配 vs 错配）证明其必要性。
- **方法设计精巧**：
  - 在线行为画像从日志计算，无需额外模型调用，可迁移到未见执行器。
  - 双门控时间信用分配针对“编辑后技能从未被检索”的噪声监督问题，检索门与行为门互补，消融验证有效。
  - 压缩奖励排除描述符 token，避免画像长度本身被奖励扭曲。
- **实验严谨**：
  - 未见执行器完全排除于训练和检查点选择。
  - SkillOS-best 采用乐观选择，EASE 仍全面领先。
  - 训练组内固定执行器和任务序列，组间采样执行器，避免不公平比较。
  - 提供任务顺序敏感性分析（SR 波动 ≤3.3 pp）。
- **效率与效用并重**：不仅报告性能，还系统测量 token 成本、技能库大小、检索率和编辑回滚收益，证明“更少技能、更高效用、更低成本”。
- **可复现性**：代码开源（GitHub 链接），超参数和实现细节在附录中较完整。
