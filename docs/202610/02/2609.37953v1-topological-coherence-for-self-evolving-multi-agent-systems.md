## 摘要
复杂任务本质上耦合了工作流结构、智能体职责、协作与记忆访问：任务区域界定了职责与工具范围，跨区域依赖引发交接，所有权边界界定了私有记忆与选择性共享记忆。现有方法能够联合优化智能体与通信结构，但这种优化本身并不要求职责、交接与记忆边界与任务依赖保持一致。我们将这一要求称为拓扑一致性。我们提出 TOCOMAS，一种拓扑一致的多智能体系统。TOCOMAS 将任务图建立在工具接口之上，将兼容的任务节点组织为可复用的职责域，并推导出依赖诱导且受画像条件约束的协作，以及边界调控的记忆可见性。在线自演化过程中，TOCOMAS 对智能体、协作与记忆策略提出耦合变更，仅为后续任务保留满足结构约束并提升评估奖励的候选方案。在 BBEH、WorkBench、SWE-Bench-Verified 与 CoMemBench 上，TOCOMAS 在多种骨干模型上均较基线提升了任务成功率。CoMemBench 还显示，在已验证进展、交接与记忆隔离方面，TOCOMAS 优于自演化基线。

## Abstract
Complex tasks inherently couple workflow structure, agent responsibility, collaboration, and memory access: task regions delimit responsibility and tool scope, cross-region dependencies give rise to handoffs, and ownership boundaries delimit private and selectively shared memory. Existing methods can jointly optimize agent and communication structures, yet such optimization does not by itself require responsibility, handoff, and memory boundaries to remain consistent with task dependencies. We term this requirement topological coherence. We introduce TOCOMAS, a Topology-Coherent Multi-Agent System. TOCOMAS grounds a task graph in tool interfaces, organizes compatible task nodes into reusable responsibility domains, and derives dependency-induced and profile-conditioned collaboration together with boundary-regulated memory visibility. During online self-evolution, TOCOMAS proposes coupled changes to agent, collaboration, and memory policies, retaining for subsequent tasks only candidates that satisfy structural constraints and improve evaluated reward. Across BBEH, WorkBench, SWE-Bench-Verified, and CoMemBench, TOCOMAS improves task success over baselines across backbones. CoMemBench also shows gains over the self-evolving baseline in verified progress, handoffs, and memory isolation.

# 论文总结：Topological Coherence for Self-evolving Multi-agent Systems（TOCOMAS）

## 1. 核心问题与整体含义

- **研究背景**：基于大语言模型的多智能体系统（MAS）已成为组合专业推理、工具使用与交互策略的通用框架。CAMEL、AutoGen、MetaGPT、ChatDev 等系统使复杂任务变得可及，但也使"组织设计"成为核心问题：系统必须决定每个智能体拥有哪些任务区域、可访问哪些工具与信息、何处需要验证、局部输出如何组合为全局可执行流程。
- **现有方法的不足**：近期工作可自动搜索计算图、智能体程序或工作流，甚至联合演化智能体角色、提示、模型、工具与通信拓扑（如 EvoMAS）。然而，任务工作流、智能体职责、协作与记忆仍是**分别表示的结构**，缺乏显式约束来保证它们在系统变化过程中保持关系兼容。
- **核心问题**：现有联合优化并不要求职责、交接与记忆边界与任务依赖保持一致。作者将这一要求定义为**拓扑一致性（Topological Coherence）**——不是图结构形状的相似性，而是各层从任务拓扑推导出的关系之间的一致性。
- **整体含义**：论文提出 TOCOMAS，将拓扑一致性作为贯穿组织构建与自演化的结构约束，使智能体职责、协作接口与记忆边界从共享的任务-工具拓扑中统一派生。

## 2. 方法论

### 核心思想
- 智能体组织、协作与记忆**不应作为独立的配置选择**，而应从共同的任务拓扑派生，并在演化过程中联合筛选。
- 任务拓扑本身提供统一组织参照：任务区域界定职责与工具范围，跨区域依赖产生交接与可选验证，所有权边界界定私有与选择性共享记忆。

### 关键技术细节

- **问题形式化**：MAS 由配置 C = (G, A, Vin, Vout) 指定，其中 G 为通信图，A 为智能体配置集合（含骨干模型、提示、工具集）。给定任务 q 及其任务图 Tq，定义工具锚定的可执行拓扑 Hq = (Uq, Dq, Ψq)，职责映射 πq: Uq → Sq 将任务节点分组为区域，所有权映射 ϕq: Sq → V 将区域分配给智能体。当职责区域有胜任的拥有者、跨区域依赖有兼容交接、记忆可见性尊重同一所有权边界时，称配置 Cq 满足拓扑一致性。

- **模块一：拓扑智能体组织**
  - 通过 grounding 映射 Ψq 为每个任务节点选择最小有效工具包，受能力覆盖、边语义兼容、副作用约束与提供者连续性约束（排除金标准轨迹与评估器状态）。
  - 用满射 πq 将操作兼容的节点分组为职责区域，收缩区域得到商拓扑 Hq = Hq/πq，保留区域间依赖、隐藏区域内依赖。区域合并仅在商拓扑保持无环时可行。
  - 兼容性画像 aq(u,v) 包含工具重叠、输入-输出兼容、依赖邻接、语义相似度四个分量。
  - 所有权映射 ϕq 要求区域能力 Γ(S) ⊆ 智能体能力 ΓA，非单射（一个智能体可拥有多个兼容区域），无覆盖时由智能体池提供新特化。

- **模块二：结构自适应协作编排**
  - 将跨区域任务依赖推过所有权映射，得到必需通信边 Ereq_q；运行时协作拓扑 Gq = (Vq, Ereq_q ∪ Esp_q)，其中 Esp_q 由智能体画像相似度、查询相关性、工具输入-输出互补性构建。
  - 局部执行与边界感知交接：hij = Route_ij(zi; ξij) ∈ {ρij(zi), ∅}，ρij 仅暴露下游区域所需的工件，必要时触发验证器请求。

- **模块三：边界保持的记忆协调**
  - 每条记忆记录关联生产者智能体、任务区域与来源。可见性策略 Λq 决定区域可用的私有记录与准入边界证据：Mvis_q(Si) = Filter_Λq(Mq; Si)。
  - 语义检索仅在准入视图内排序种子，再经类型化图扩展重建区域上下文：Rq(Si) = Expand_L(Seed_k(q|Si, Mvis_q(Si)); Mvis_q(Si))。语义相关性不能覆盖所有权或共享边界。
  - 所有权变更时，区域私有记忆随区域迁移（μ 映射），保留来源并更新访问权限，防止经验孤立与意外全局共享。

- **模块四：一致性约束的结构演化**
  - 结构投影 Ωq = Struct(Cq) = (πq, ϕq, Gq, Λq)，其中 Λq 是策略，具体记录 Mq 是运行时状态而非演化基因。
  - 演化步骤 t：执行反馈 τq 与累积经验 E 引导结构提案 Ω̃q^(t+1) = Propose(Ωq^(t), τq^(t), E^(t))。提案可只改变部分策略；若改变所有权，编译时需协调交接与记忆权限。
  - 单一结构筛查检查每个任务节点有唯一胜任拥有者、必需跨区域交接与记忆可见性尊重诱导边界。有效候选被执行，仅当通过结构检查且奖励超过父代阈值时才被接受（式 17）。

## 3. 实验设计

### 数据集 / 场景
- **BBEH**：困难推理问题，对照基准答案，报告准确率。
- **WorkBench**：涉及应用工具的工作场所任务，报告任务成功率。
- **SWE-Bench-Verified**：仓库补丁修复，报告官方解决率。
- **CoMemBench**：含可执行依赖图、类型化交接、配对干净/污染实例的多智能体工作流基准，覆盖四个领域（有状态工具使用、仓库代码、离线检索、形式数学），含 800 个干净工作流与 800 个匹配污染变体。

### 评估指标
- BBEH 准确率、WorkBench 任务成功、SWE-Bench-Verified 解决率。
- CoMemBench：SR（终端成功率）、VNCR（已验证节点完成率）、VHS（已验证交接成功率）、ICS（隔离挑战成功率，衡量污染上下文下保持有效目标结果的能力）。

### 对比方法
- **控制组**：Direct LLM Call。
- **固定组织**：Peer Review、SMoA。
- **自动设计**：ADAS、OMAC。
- **自演化基线**：EvoMAS。

### 骨干模型
- 主对比使用 Qwen3.8-27B 与 DeepSeek-V4-Flash；另设 GPT-6-luna 大模型对比。

## 6. 主要结论与发现

- **拓扑一致组织提升通用任务性能**：Qwen3.8-27B 上 TOCOMAS 达 BBEH 54.78%、WorkBench 77.68%、SWE-V 48.00%，分别超最强基线 8.26、15.51、8.00 个百分点；DeepSeek-V4-Flash 上为 55.20%、61.45%、49.00%，同样领先。
- **增益延伸至已验证交接与信息隔离**：Qwen3.8-27B CoMemBench 上 TOCOMAS 达 SR 14.30%、VNCR 41.60%、VHS 51.00%、ICS 84.90%，而 EvoMAS 为 1.00%、30.42%、30.73%、26.80%。
- **消融揭示各机制独立贡献**：职责分配影响已验证进展（VNCR 降 14.33 点）；跨区域交接影响工件接受（VHS 降 40.85 点，SR 归零）；记忆边界影响隔离（ICS 降 19.96 点）；在线演化提升任务成功（WorkBench SR 降 6.52 点）。
- **参数偏好有界范围**：组织亲和度在 0.60 达峰，记忆检索 k=3 达峰，过大分组或检索无益。
- **成本优势**：按进度分箱，TOCOMAS 在 WorkBench 低于 Peer Review 与 SMoA，在 CoMemBench 多数共享进度水平低于其他多智能体曲线，归因于区域内化依赖、投影工件与边界过滤检索降低协调开销。

## 7. 优点

- **概念创新**：明确提出"拓扑一致性"作为结构约束，将职责、交接、记忆边界统一从任务-工具拓扑派生，而非独立设计或事后惩罚。
- **架构系统性强**：四个模块（拓扑组织、协作编排、记忆协调、结构演化）环环相扣，商拓扑、所有权映射、记忆迁移等设计有形式化支撑。
- **演化机制合理**：提案-编译-筛查-奖励接受流程，仅保留满足结构约束且提升奖励的候选，避免无效演化；记忆随区域迁移保留来源，防止经验孤立与越权共享。
- **评估维度丰富**：CoMemBench 将终端成功与已验证进展、交接接受、污染隔离分离，配对污染设计使隔离性评估更严谨。
- **成本分析细致**：按进度分箱而非任务平均，避免任务长度不均导致的成本误读。

## 8. 不足与局限

- **算力信息不完整**：未报告 GPU 数量、总推理时长或总算力开销，复现成本难以估算。
- **基准自建风险**：CoMemBench 为作者团队自建（Zhao et al., 2026），虽设计精巧，但存在自评偏差可能；其他基准为通用基准，覆盖较好。

- **偏差风险**：评估器回执、交接轨迹与模型调用账本虽保留用于审计，但方法私有节点与重复尝试不计入 VNCR 分子，可能影响不同方法的可比性。
