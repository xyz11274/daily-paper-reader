## 摘要
随着大语言模型（LLM）的进步，AI智能体越来越多地部署在开放世界环境中以处理复杂的序列任务（例如文档处理、跨应用协作），这些任务高度依赖从GUI操作到语义API的各类动作。然而，三个核心挑战依然存在：庞大工具生态超出LLM上下文窗口的“规模困境”、工具更新或故障导致质量变化的“非平稳性”，以及反馈格式（像素、文本、结构化数据）异构造成的信息孤岛。为解决这些问题，我们提出AnyAct，一种通用动作层，将可用能力统一为自进化动作空间，使智能体能够在大规模、动态工具生态中高效可靠地运行。AnyAct的核心设计聚焦两个目标：通过分层渐进式检索（过滤任务相关动作）和测试时可靠性演化（剪枝不可靠动作）构建该动作空间，并通过统一多模态反馈的异构观测接地模块实现可靠性感知的动作编排。此外，它定义了混合动作空间（原始动作+语义动作），并优化任务成功率与执行成本之间的平衡。在LiveMCPBench和OSMCP（我们为多粒度动作协作开发的新基准）上的评估展示了最先进的性能。AnyAct在LiveMCPBench上相较于基线方法在各种LLM基础模型上均带来显著性能提升，对于原生能力受限的模型改进尤为明显。在OSMCP上，它仅用50步就达到77.27%的总体成功率，是大多数竞争者所需步数的一半。

## Abstract
As large language models (LLMs) advance, AI agents are increasingly deployed in open-world environments to tackle complex sequential tasks (e.g., document processing, cross-application collaboration), relying heavily on actions ranging from GUI operations to semantic APIs. However, three core challenges persist: the "scale dilemma" of massive tool ecosystems exceeding LLM context windows, the "non-stationarity" of tool quality due to updates or outages, and the "heterogeneity" of feedback formats (pixels, text, structured data) creating information silos. To address these, we propose AnyAct, a universal action layer that unifies available capabilities into a self-evolving action space, enabling agents to operate efficiently and reliably in large-scale, dynamic tool ecosystems. AnyAct's core design focuses on two objectives: constructing this action space via hierarchical progressive retrieval (filtering task-relevant actions) and test-time reliability evolution (pruning unreliable actions), and enabling reliability-aware action orchestration through a heterogeneous observation grounding module that unifies multi-modal feedback. Additionally, it defines a hybrid action space (primitive + semantic actions) and optimizes for a balance between task success rate and execution cost. Evaluations on LiveMCPBench and OSMCP (a new benchmark we developed for multi-granularity action collaboration) demonstrate state-of-the-art performance. AnyAct delivers substantial performance gains over baseline methods across various LLM base models on LiveMCPBench and improvements are particularly notable for models with constrained native capabilities. On OSMCP, it achieves 77.27% overall success with only 50 steps, which is half the steps required by most competitors.

- **研究背景**：随着LLM能力提升，AI智能体正从特定领域应用走向开放世界环境，承担文档处理、跨应用协作、数据分析等复杂序列任务。这些任务依赖从像素级GUI操作、命令行指令到语义API的丰富动作空间。特别是Model Context Protocol（MCP）等开放协议的普及，使可用工具数量爆炸式增长，形成跨多领域、多粒度的大型工具生态。
- **三大核心挑战**：
  - **规模困境（Scale Dilemma）** ：完整API规范集常超出LLM上下文窗口容量，直接暴露所有工具导致检索低效、任务相关性不清晰。
  - **非平稳性（Non-stationarity）** ：开放环境中工具可能因版本更新、服务中断或误导性文档而失败或退化，静态工具选择策略无法应对动态可靠性变化。
  - **异构性（Heterogeneity）** ：GUI动作产生像素、命令行返回文本、API产出结构化数据，模态差异使跨工具协作推理困难，形成信息孤岛。
- **现有方法不足**：要么依赖固定动作集而缺乏泛化能力，要么缺乏对动作可靠性的动态感知而缺乏鲁棒性；两者都无法从经验中演化自身动作空间，难以在任务成功率与执行效率间取得最优权衡。
- **整体含义**：论文提出AnyAct——一种面向自进化智能体的通用动作层，旨在使智能体在大规模、动态演化的工具生态中高效可靠地完成开放世界任务，统一GUI、Shell和MCP动作，支持动作空间的自演化构建与维护。

## 2. 论文提出的方法论

### 2.1 核心思想

- 定义统一动作空间 **A = A_gui ∪ A_cmd ∪ A_api**，其中A_gui提供原子级像素控制（通用性），A_cmd和A_api为语义动作（高效性）。
- 构建**任务条件化的演化子集** A_I^(n) ⊂ A，每任务构建、跨episode修订，同时保留低层原始动作作为可靠回退。
- 联合优化动作层级H、可靠性估计器r和编排策略π，目标函数为：
  - **max_{π,H,r} P(success | I) − λ|τ|**，即最大化成功率同时通过λ惩罚轨迹长度（执行成本），鼓励使用高层动作减少步数，同时确保仅在可靠时选用。

### 2.2 关键技术细节

**（1）分层渐进式检索（Hierarchical Progressive Retrieval）**

- **非对称设计**：仅检索语义动作A_api，基础动作A_base始终可用，实现回退完整性与单次检索。
- **粗到细门控**：
  - 利用工具生态的自然层级（服务器s ∈ S → 工具a ∈ A_s），元数据m(a)=(name, desc)用于粗筛，完整规范spec(a)仅对少量选中工具加载。
  - **服务器短名单**：当|C_0| > N_thresh时，LLM仅接触服务器级元数据，识别高置信工具A_hc和相关服务器S_sel，形成候选池 C_plan = A_hc ∪ (∪_{s∈S_sel} A_s)。
  - **工具重排序**：若候选池超过K，LLM将任务I转为能力导向关键词q，BM25先做词汇筛选得C_lex，再用语义相似度 u(a;q) = sim_sem(q,a) 重排，返回Top-K工具 H(I)。
- **最终动作空间**：A_I = A_base ∪ H(I)，|H(I)| ≤ K。

**（2）测试时可靠性演化（Test-Time Reliability Evolution）**

- 维护每个动作的可靠性分数 r^(n)(a) ∈ [r_min, 1]，跨episode更新，作为检索分数的乘性门控：**u^(n)(a) ← u^(n)(a) · r^(n)(a)**。
- **执行画像**：滑动窗口跟踪近期成功率R_a^(n)和连续失败计数C_a^(n)。
- **更新规则**：
  - 冷启动：调用次数N_a^(n) < N_min时设r=1，避免过早惩罚。
  - 更新公式：**r^(n)(a) = clip( r_base(R_a^(n)) − δ_streak(C_a^(n)), r_min, 1 )**
  - 基础可靠性：R ≥ θ_ρ时为1；否则 r_base(R) = 1 − (1−r_min)·(θ_ρ−R)/θ_ρ。
  - 连续失败惩罚：δ_streak(C) = min(δ_max, δ_step · [C−F]^+)，超过耐心阈值F后快速降级。
- **三种行为状态**：探索（历史不足，不惩罚）、稳定（高成功率保持高排名）、失败（低成功率或持续失败逐步降级，转向可靠替代或回退原始动作）。
- **演化维护**：会话边界计算工具规范指纹h(a)，规范变更时刷新缓存文档评估但保留执行历史。

**（3）异构观测接地（Heterogeneous Observation Grounding）**

- 引入接地算子 **ϕ(·)** 将所有观测转为共享知识表示K。
- 文本/结构化输出：轻量归一化（截断长输出、线性化结构化数据）。
- **视觉接地**：用VLM从截图中提取可操作元素（文本、数字、表格、URL、文件路径、元素ID等），将截图视为"文档解析"而非"场景描述"；多帧序列选代表性关键帧。
- **知识驱动规划**：统一表示ϕ(o_t) ∈ K使推理独立于观测模态，API提取的标识符可参数化GUI动作，截图接地状态可验证命令执行结果。累积为episodic context c_{t+1} = agg(c_t, ϕ(o_t))，输入策略π(a_t | I, c_t, A_I, r^(n))。

## 6. 论文的主要结论与发现

- **LiveMCPBench**：
  - AnyAct在所有4个LLM上均大幅超越Naive基线，对原生能力受限的模型（DeepSeek-V3、DeepSeek-R1、Qwen3-235B）提升近100%。
  - Claude-Sonnet-4上AnyAct达93.55%总体成功率；DeepSeek-V3从42.11%提升至84.95%；DeepSeek-R1从48.42%提升至78.49%；Qwen3-235B从48.42%提升至77.42%。
  - 检索和演化模块均有效：移除任一模块均导致显著性能下降。
- **OSMCP**：
  - AnyAct仅用50步达77.27%总体成功率（153/198），为SOTA，多数竞品需100步。
  - 使用较弱LLM（Claude-4.5-Sonnet vs. Claude-4.5-Opus）仍超越智能体框架方法。
  - AnyAct w/o GUI仅59.09%，证明低层GUI动作对开放世界任务不可或缺。
- **演化效果**：演化过程在不同LLM上均带来显著净增益，但存在权衡——降级不稳定工具时若无替代品，可能导致原本依赖该工具的任务失败。
- **优雅降级**：duckduckgo_web_search因限流持续失败（0/38成功），演化后从排名1降至18（K=15），不再被选中，智能体转而使用可靠新闻源完成任务，零失败调用。
- **鲁棒性**：30%词删除下dense/hybrid检索保持0.75 Top-10重叠，30%描述交换下0.58；期望服务器覆盖率始终18/18；词汇控制方法退化更快（20%删除时0.59）。

- **混合动作空间与成本优化**：原始动作+语义动作结合，目标函数显式平衡成功率与执行成本。
- **实验亮点**：OSMCP基准填补多粒度动作协作评估空白；50步达77.27%成功率，效率优势显著；鲁棒性实验设计巧妙（描述噪声扰动）；案例研究直观展示GUI-MCP切换和优雅降级。
