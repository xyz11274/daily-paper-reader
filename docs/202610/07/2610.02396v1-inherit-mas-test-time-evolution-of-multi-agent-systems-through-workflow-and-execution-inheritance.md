## 摘要
由大语言模型构建的多智能体系统（MAS）通过协调专用智能体来处理复杂任务，但有效的工作流难以预先设计。测试时演化利用执行反馈来改进工作流，然而大幅修改可能破坏有用的组件，而重新执行未改变的请求又会带来冗余计算。受生物演化中遗传与选择相互作用的启发，我们提出了 Inherit-MAS，在工作流和执行两个层面显式地实现继承。一个元模型首先综合出一个由工作智能体组成的工作流，其中声明了角色、通信输入和工具权限，另一个单独提示的评判器对每个已执行的候选方案进行评分并诊断其缺陷。在普通改进轮次中，\emph{工作流继承}从最新完成的候选方案出发，可以丢弃被判定为无用的可移除节点，并应用经过验证的编辑来解决所诊断出的缺陷。当新候选方案执行时，\emph{执行继承}仅在完整解析后的请求与执行上下文匹配时继承符合条件的已存储结果，从而避免冗余的模型和工具调用。在使用 GPT-4o-mini 作为工作智能体时，Inherit-MAS 在 WorkBench 上达到 55.4\% 的完成率，在 HotpotQA FullWiki 上达到 49.7\% 的联合 F1，优于 EvoAgent、EvoMAS 和 TacoMAS。在使用 Qwen3-32B 作为工作智能体时，它在两个基准上也超过了这些演化式 MAS 基线。与在禁用执行继承的情况下重新运行相同控制器相比，执行继承在 WorkBench 上将工作智能体 token 使用量减少了 29.1\%，在 HotpotQA 上减少了 34.6\%，并将总 token 使用量分别减少了 5.3\% 和 18.1\%。

## Abstract
Multi-agent systems (MAS) built from large language models coordinate specialized agents to tackle complex tasks, but effective workflows are difficult to design in advance. Test-time evolution refines workflows using execution feedback, yet broad revisions can disturb useful components, while re-executing unchanged requests can incur redundant computation. Inspired by the interplay of inheritance and selection in biological evolution, we introduce Inherit-MAS, which makes inheritance explicit at the workflow and execution levels. A meta-model first synthesizes a workflow of worker agents with declared roles, communication inputs, and tool permissions, and a separately prompted judge scores each executed candidate and diagnoses its deficiencies. In ordinary refinement rounds, \emph{workflow inheritance} starts from the latest completed candidate, may discard removable nodes judged unhelpful, and applies a validated edit to address the diagnosed deficiency. When the new candidate executes, \emph{execution inheritance} inherits eligible stored results only if the complete resolved request and execution context match, avoiding redundant model and tool calls. With GPT-4o-mini workers, Inherit-MAS achieves 55.4\% completion on WorkBench and 49.7\% joint F1 on HotpotQA FullWiki, outperforming EvoAgent, EvoMAS, and TacoMAS. With Qwen3-32B workers, it also exceeds these evolving-MAS baselines on both benchmarks. Compared with rerunning the same controller with execution inheritance disabled, execution inheritance reduces worker-token usage by 29.1\% on WorkBench and 34.6\% on HotpotQA, and total token usage by 5.3\% and 18.1\%.

# Inherit-MAS 论文中文总结

## 1. 核心问题与整体含义

- **研究动机**：基于大语言模型的多智能体系统（MAS）通过协调角色专用智能体处理复杂任务，但有效工作流难以预先设计。测试时演化（test-time evolution）虽可利用执行反馈改进工作流，却面临两难：大幅修改会破坏已有用组件，而重新执行未变请求又造成冗余计算。
- **核心问题**：如何在有限测试时预算下，利用执行反馈提升 MAS 任务性能，同时控制测试时演化的推理成本？
- **整体含义**：受生物演化中"遗传与选择"相互作用的启发，论文提出 **Inherit-MAS**，在工作流层与执行层显式引入"继承"机制——既保留前序尝试中的有用部分，又避免重复计算，实现累积式自适应。

## 2. 方法论

### 核心思想
- 将测试时 MAS 演化形式化为**显式工作流继承**：每个新候选从最新完成候选（incumbent）出发，保留有用节点，仅做一处经诊断驱动的验证编辑。
- 引入**保守变更定位**与**请求验证的执行继承**，使符合条件的模型与只读工具结果可跨相关候选复用，且不改变被评估候选本身。

### 关键技术细节
- **初始合成与评判**：元模型根据任务 x 与接口 I 合成初始工作流 G₀；独立提示的评判器 J 返回四维评分（完成可能性、需求覆盖、工件接地、整体质量）及文本批评与 keep/fix 建议。
- **工作流继承（两阶段）**：
  - **Select**：从最新完成候选出发，仅当反馈或记录输出表明某节点无贡献或有害时，才将其加入丢弃集 Δ⁻，并做有效性校验（可单独移除节点未必可联合移除）。
  - **Edit**：在保留工作流上应用**一处**经校验的原子编辑（改提示、改子任务、改工具、增删节点/边、重排输入、插入节点等），编辑仅改变声明范围内的字段，其余保持不变。
- **执行继承**：
  - **定位**：计算受影响区域 Dₖ = Δₖ ∪ Desc(Δₖ)，区分结构未变节点与可能受影响节点。
  - **验证与继承**：对节点 v 构造完整解析请求 rₖ,ᵥ（含规格、有序上游记录、执行上下文指纹 φₖ），用 SHA-256 生成键 κₖ,ᵥ；仅当节点合格、请求完全匹配且记录通过完整性校验时才继承存储结果，否则实时执行并存储。
  - 状态改变操作永不可继承；有状态任务每个候选从同一初始环境副本开始，由唯一 sink 实时执行写操作。
- **排序与返回**：按硬失败数、输出有效性、整体质量、需求覆盖、工件接地、候选索引的优先级返回最高排名候选的输出，不重新执行。

## 3. 实验设计

- **数据集/场景**：
  - **WorkBench**：职场任务（邮件、日历、项目管理、CRM、分析数据库），以最终环境状态为结果导向评估，主指标为官方完成率。
  - **HotpotQA FullWiki**：多文档推理，主指标为官方联合 F1（答案 + 句子级支撑事实）。
- **对比方法**：
  - Single ReAct（非 MAS 参考）
  - EvoAgent、EvoMAS、TacoMAS（三种演化式 MAS 基线）
- **骨干模型**：GPT-4o-mini 与 Qwen3-32B 两种 worker 配置；合成/精炼与评判使用 GPT-5.4-mini。
- **预算设置**：每条轨迹含初始工作流 + 4 个后续候选，每轮一次 Select 与一次验证编辑；检索共享 4 次 BM25 调用/候选。

## 6. 主要结论与发现

- **性能**：GPT-4o-mini 下 WorkBench 完成率 55.4%（超最佳演化基线 TacoMAS 20.8 点），HotpotQA 联合 F1 49.7%（超 TacoMAS 1.9 点）；Qwen3-32B 下同样领先。Inherit-MAS 是唯一在四种基准-骨干组合中均匹配或超越 Single ReAct 的演化式 MAS。
- **逐轮提升**：WorkBench 累计提升 9.2 点，HotpotQA 提升 5.0 点，表明演化过程产生渐进更优性能。
- **成本节约**：执行继承减少 WorkBench 29.1%、HotpotQA 34.6% 的 worker token，总 token 分别减少 5.3% 与 18.1%。
- **重要发现**：后续候选并非单调更优，保留并排序早期工作流对最终性能至关重要；局部编辑提供最清晰的成本杠杆，但**局部性不能作为编辑质量的代理**。

## 7. 优点

- **方法创新**：将生物演化中"遗传+选择"思想显式映射到 MAS 测试时演化，工作流继承与执行继承双层设计清晰、互补。
- **工程严谨**：请求级 SHA-256 验证、执行上下文指纹、确定性验证器、状态改变操作不可继承等设计，保证了继承的安全性与可审计性。
- **成本意识**：在提升性能的同时显著降低 token 消耗，并区分 live token 与 inherited token equivalent，账目透明。
- **实验客观**：冻结配置、金标准隔离、失败保留在分母、报告配对胜负平与编辑家族级描述性统计，并主动承认非随机化编辑效应与跨骨干差异。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量与训练时长，本地部署细节有限，复现成本难以精确评估。
