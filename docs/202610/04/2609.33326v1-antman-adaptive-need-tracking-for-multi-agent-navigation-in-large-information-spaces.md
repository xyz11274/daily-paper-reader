## 摘要
信息搜寻智能体日益需要在过大而无法穷尽处理的信息空间上运行。然而，许多多智能体系统围绕可用空间的静态划分来组织计算，导致协调开销随着信息被分割的方式增长，而非取决于查询仍需要什么。我们提出 ANTMAN，一种自适应协调框架，将不断演化的未解决信息需求视为运行时协调的单元。ANTMAN 维护一个可修订的需求图，追踪未解决的需求、累积的证据、先前的尝试和搜索进展，并利用该状态在新证据被发现时控制工作节点选择、路由和任务局部恢复。通过将协调策略与特定基底的搜索接口分离，同一需求条件化机制可以跨不同信息空间运行。在多文档问答、受控长上下文扩展和真实结构化导航上的实验表明，ANTMAN 在不同设置下均保持有效，包括在执行被委托给显著更小的工作模型时。在可搜索上下文增加 16 倍的情况下，ANTMAN 的活跃协调仅增加 1.23 倍，而划分驱动的基线则增加超过 15 倍，同时保持了较强的答案质量。

## Abstract
Information-seeking agents increasingly operate over information spaces that are too large to process exhaustively. Yet many multi-agent systems organize computation around static partitions of the available space, causing coordination to grow with how information is segmented rather than with what the query still requires. We introduce ANTMAN, an adaptive coordination framework that treats evolving unresolved information needs as the unit of runtime coordination. ANTMAN maintains a revisable Need Graph that tracks unresolved requirements, accumulated evidence, prior attempts, and search progress, and uses this state to control worker selection, routing, and task-local recovery as new evidence is discovered. By separating the coordination policy from substrate-specific search interfaces, the same need-conditioned mechanism can operate across different information spaces. Experiments across multi-document question answering, controlled long-context scaling, and realistic structured navigation show that ANTMAN remains effective across settings, including when execution is delegated to substantially smaller worker models. Under a 16x increase in searchable context, ANTMAN increases active coordination by only 1.23x, compared with more than 15x for partition-driven baselines, while preserving strong answer quality.

# ANTMAN 论文深度总结

## 1. 核心问题与研究动机

- **背景**：信息搜寻智能体（information-seeking agents）面对的信息空间越来越大，无法穷尽处理。多智能体协作是缓解单个工作节点上下文负担的常见策略。
- **核心问题**：现有长上下文多智能体系统（如 LongAgent、Chain of Agents）普遍采用**静态分区**方式组织计算——将输入切分为固定大小的块，每块分配给一个工作节点。这导致**协调开销随信息空间的分割数量增长，而非随查询实际需求增长**。
- **关键矛盾**：当底层信息需求保持固定时，扩大可用上下文不应要求成比例增加智能体数量。但分区驱动设计使工作节点数量机械地随上下文规模增长。
- **研究问题**：如何让智能体搜索越来越大的信息空间，而不让协调开销随空间本身增长？
- **核心洞察**：信息搜寻是一个动态过程（Bates 1989），新发现的信息会改变搜索者对问题的理解并重定向搜索。有效协调需要的不是初始查询分解，而是对"仍未解决的需求"的显式、可修订表示。

## 2. 方法论

### 2.1 核心思想
- 以**不断演化的未解决信息需求**（而非输入分区）作为运行时协调的单元。
- 维护一个**可修订的需求图（Revisable Need Graph）**作为运行时控制状态，追踪未解决需求、累积证据、先前尝试和搜索进度。
- 将**协调策略**与**基底特定的搜索接口**分离，使同一机制可跨不同信息空间运行。

### 2.2 三大组件

**（1）静态基底图（Static Substrate Map）**
- 信息空间 I 被确定性划分为 M 个territory：T = P(I) = {τ₁, ..., τ_M}
- 每个territory关联一个 WorkerCard cᵢ = Card(τᵢ)，描述该区域的范围和内容摘要。
- 关键点：定义了**可用**的工作节点，而非每个查询**必须参与**的工作节点。工作节点是范围特化的，共享同一搜索/检查/返回证据接口。

**（2）可修订需求图（Revisable Need Graph）**
- G_t = (N_t, Δ_t)，其中 N_t 是需求节点集，Δ_t 是依赖关系。
- 每个需求 n 的状态：z_t(n) = (s_t(n), E_t(n), H_t(n), p_t(n))，分别表示解决状态、累积证据、尝试历史、当前进度。
- 图在运行时被修订：G_{t+1} = U(G_t, r_t)，更新操作可解决需求、保持未解决、将失败需求重构为 n′、或引入新依赖/需求。

**（3）需求条件化协调与恢复**
- 协调循环：选择未解决需求 n_t = Select(G_t) → 路由 i_t = Route(n_t, G_t, C) → 执行 r_t = Exec(w_{i_t}, n_t, τ_{i_t}) → 更新图。
- 工作节点仅执行**有界局部搜索**，全局状态保存在 G_t 中。
- 若反复尝试无进展，触发**任务局部恢复**：重构需求（reframe）、重路由（reroute）或回退（fallback）。
- 路由采用两阶段：非 LLM 检索阶段（稀疏词法匹配 + 精确词匹配 + 稠密相似度 + 倒数排名融合）筛选候选 WorkerCard，再由编排器决定是否/何处派发。

### 2.3 空间解耦理论保证
- 定义实现需求集 H(q)、每需求最大路由尝试次数 ρ、激活工作节点集 A(q)。
- **命题 1**：|A(q)| ≤ K(q) ≤ ρH(q)，因此 |A(q)| ≤ min{M, ρH(q)}。
- **含义**：M 仅作为候选池大小出现，不作为乘性因子。当信息需求有界时，扩大信息空间不会强制增加活跃协调。
- **对比**：分区驱动方法满足 |A_partition(q)| = Θ(M)，而 ANTMAN 满足 |A_ANTMAN(q)| ≤ min{M, ρH(q)}。

## 6. 主要结论与发现

1. **空间解耦**：信息空间扩大16倍时，ANTMAN 活跃协调仅增1.23倍，模型调用增1.21倍；而 LongAgent 和 CoA 协调增超15倍，调用增约11-13倍。
2. **需求敏感**：固定512K空间下，需求从1增至16单元，活跃协调从5.0增至8.2个工作节点，调用从35.5增至86.2次，且100%恢复全部证据并正确回答。
3. **答案质量保持**：多文档QA上 ANTMAN 平均 EM 0.711 / F1 0.814，优于所有基线；结构化导航上 RepoProbe 38.21、SWE-QA-Pro 79.78、GAIA 58.3%，均领先。
4. **小模型有效性**：ANTMAN-H（Qwen3-8B 执行）在 RepoProbe、SWE-QA-Pro、GAIA 上分别保留全量 ANTMAN 的 89.2%、93.5%、98.3% 性能。
5. **显式需求状态的价值**：Graph-free Adaptive 在512K下降23.82%，GAIA下降16.67%，证明收益超越通用自适应重规划。
6. **位置鲁棒性**：ANTMAN 的中间位置差距仅 +.015，而直接全上下文推理为 −.181，显著缓解"lost in the middle"问题。
7. **机制互补**：Recovery 在受控扩展中关键，Adaptive Rerouting 在仓库导航中重要，GAIA 单territory场景下 rerouting 无影响。

- **架构分离优雅**：静态基底图（可用能力）与运行时需求图（实际协调）的分离，使同一机制跨文档、代码、Web 等基底通用。

- **消融系统**：6个变体清晰拆解 Need Revision、Rerouting、Recovery 的独立贡献，并指出不同环境下的机制差异。
