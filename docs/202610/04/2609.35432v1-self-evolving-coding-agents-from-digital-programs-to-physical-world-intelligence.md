## 摘要
视觉-语言-动作（VLA）和世界-动作（WAM）模型将观测和指令直接映射为机器人动作。这种直接性将策略与训练绑定：微小的布局或视角变化就会导致失败，指令泛化能力差。根本原因在于表示：任务需求、条件、进度和故障恢复被隐式编码在动作序列中，使其难以检查或修改。数字编码智能体提供了一个先例：LLM调用工具、验证结果，并基于反馈以可执行代码的形式进行修改。显式状态、可管理执行和可修改流程的相同工作模式，构成了物理世界中泛化和长时程执行的基础，使物理经验能够作为可重用程序、记忆或证据返回。我们提出物理编码，将任务状态和执行表示为代码。作为世界的代码记录对象、关系、约束和进度；作为策略的代码组织规划、验证、恢复和执行。我们构建了HexaAnything，它调用感知、规划和控制工具，包括VLA/WAM策略，并根据外部反馈进行在环决策。经过验证的轨迹成为数据和记忆，使得从工具和Harness向模型权重、架构，最终向硬件和任务设计的进化成为可能。在RoboCasa365上，HexaAnything在Composite-Unseen和整体成功率上优于XR-1 VLA，并且其Harness训练的HexaModel在每个划分上都优于基础模型，表明代码轨迹内化了物理执行。在PhyBench和双臂AgileX机器人上，该智能体自主完成物理实验和大多数桌面任务，通常比已发表结果更快。我们观察到数据、模型和工具的自我进化；未来工作目标是权重内化、自主重新设计架构、语言、表示和任务，以及在制造业和科学中的部署。

## Abstract
Vision-language-action (VLA) and world-action (WAM) models map observations and instructions directly to robot actions. This directness ties a policy to training: minor layout or viewpoint changes cause failure, and instructions generalize poorly. The root cause lies in representation: task requirements, conditions, progress, and failure recovery are implicitly encoded in action sequences, making them difficult to inspect or revise. Digital coding agents offer a precedent: LLMs call tools, verify results, and revise from feedback as executable code. The same working pattern of explicit state, manageable execution, and revisable procedures underlies generalization and long-horizon execution in the physical world, letting physical experience return as reusable programs, memory, or evidence. We propose Physical Coding, representing task state and execution as code. Code as World records objects, relations, constraints, and progress; Code as Policy organizes planning, verification, recovery, and execution. We build HexaAnything, which calls perception, planning, and control tools, including VLA/WAM policies, and makes in-the-loop decisions from external feedback. Verified traces become data and memory, enabling evolution from tools and Harness to model weights, architectures, and ultimately hardware and task design. On RoboCasa365, HexaAnything improves Composite-Unseen and overall success over XR-1 VLA, and its Harness-trained HexaModel beats the base on every split, indicating code traces internalize physical execution. On PhyBench and a dual-arm AgileX robot, the agent autonomously completes physics experiments and most tabletop tasks, often faster than published results. We observe data, model, and tool self-evolution; future work targets weight internalization, autonomous redesign of architectures, languages, representations, and tasks, and deployment in manufacturing and science.

## 2. 方法论

### 核心思想
- **Physical Coding**：将任务状态和执行过程都表示为可执行代码，形成两个耦合的可执行工件：
  - **Code as World**：记录任务相关对象、关系、观测、状态、约束和进度谓词。
  - **Code as Policy**：组织规划、工具调用、动作执行、验证、恢复和重规划。
- 两者共同构成物理状态与动作之间的可执行接口，使中间进度可检查、失败可定位、修改可测试。

### 关键技术细节
- **HexaAnything**：物理编码智能体的具体实现，包含模型（LLM）和Harness（运行时环境）。
- **Harness架构**包含五个接口：
  1. **Tools**：感知、导航、运动原语、夹爪控制、学习动作模块（VLA/WAM作为可调用工具之一）。
  2. **Workflow**：将长时程指令分解为可观测子目标，决定何时调用、中断或替换工具。
  3. **Verifier**：基于视觉证据、工具输出和物理传感器检查语义谓词，独立于模型自报的完成信号。
  4. **Recovery**：处理抓取失败、物体掉落、动作模型停滞等，通过安全停止、重试、重新观测和重规划恢复。
  5. **Memory**：存储带来源和准入检查的任务、对象和技能级轨迹。

### 公式与算法流程（文字说明）
- **运行时定义**：Harness $H_t = (O_t, T_t, V_t, R_t, M_t, \Gamma_t)$，分别表示观测接口、工具注册表、验证器、恢复算子和来源感知记忆，$\Gamma_t$ 为执行契约、权限、预算和安全门。
- **策略步骤生成**：$n_t = \pi_{\theta_t}(z, W_t, P_t, O_{\leq t}, M_t)$，$u_t = \text{Dispatch}(n_t, T_t)$。
- **世界更新与验证**：$W_{t+1} = \text{UpdateWorld}(W_t, O_{t+1}, y_t)$，$q_t = V_t(W_{t+1}, y_t, z)$，其中 $q_t$ 是类型化裁决（PASS/FAIL/INSUFFICIENT EVIDENCE/BLOCKED/SAFETY STOP），而非模型生成的完成标记。
- **完整轨迹**：$\xi = \{z, W_{0:T}, P_{0:T}, O_{0:T}, u_{0:T}, y_{0:T}, q_{0:T}, M_{0:T}\}$，是归因和后续更新的单元。
- **自进化循环**（七步）：指定→执行→验证→诊断→提议→评估→选择与提交。候选更新仅在独立评估显示其改善目标且不违反其他组件契约时才被采纳。
- **四个进化目标**：Harness、数据与环境、模型与算法、具身与计算基板，表示与接口进化贯穿所有四个目标。

## 6. 主要结论与发现

- **Harness效果**：在动作模型固定为XR-1的情况下，HexaAnything将Composite-Unseen成功率从34.3%提升至38.3%，Composite-Seen从54.8%提升至61.5%，整体从56.6%提升至61.1%。

- **工具进化**：在RoboDojo三个任务上，经过两轮修订，成功率从0%/40%/0%提升至80%/100%/100%，权重不变，增益完全来自Harness。
- **PhyBench**：GPT-6-Astra和Opus 5.5在全部30次试验中均获得有效结果，平均相对误差低于5%；Qwen3.8-Max仅在5/10、3/10、3/10次试验中获得有效估计。
- **真实机器人**：7个任务中5个在全部3次试验中成功，tic-tac-toe比GPT-Policy快2.7倍，拧瓶盖快3.5倍，放积木比Robocurve快2.4倍且token少4.7倍。
- **总体结论**：验证轨迹可转化为数据与记忆，实现工具、Harness到模型权重的自进化；但完全自主的模型、表示、环境和具身协同进化仍是未来工作。

## 7. 优点

- **问题诊断深刻**：通过指令遮蔽实验（92.3% vs 96.2%）有力证明了VLA模型对指令的不敏感性，揭示了表示层面的根本问题。
- **方法论创新性强**：将数字编码智能体的范式系统性地迁移到物理世界，提出Code as World和Code as Policy的耦合表示，使物理执行可检查、可修正、可复用。
- **验证器独立设计**：强调验证器必须独立于提出动作的模型，返回类型化裁决而非二元自报，防止模型自我确认错误。
- **自进化框架完整**：提出四目标（Harness、数据与环境、模型与算法、具身与计算）和七步循环（指定→执行→验证→诊断→提议→评估→选择），并引入证据阶梯（E0-E4）区分不同层级的改进。
- **跨域验证**：从仿真操作（RoboCasa365、RoboDojo）到模拟科学实验（PhyBench）再到真实双臂机器人，展示了方法的通用性。
- **工具进化实验设计严谨**：RoboDojo实验固定任务定义和评估器，仅修改工具代码，权重不变，清晰归因于Harness。
- **真实机器人部署务实**：提出"Vibe as Policy"模式，编程智能体在回合间编写、验证和冻结工具，执行智能体在运行时组合它们，兼顾灵活性与安全性。

## 8. 不足与局限

- **实验覆盖有限**：
  - Harness效果仅在一个动作模型（XR-1）和一个基准（RoboCasa365）上验证。
  - 长时程复杂任务（Section 8.2）已设计但未评估。

- **偏差风险**：
  - Fold cloth实验中操作员为每次调用选择像素，测量的是工具和接口而非自主感知。
  - 已发表参考结果来自不同硬件和操作限制，非同一机器人公平对比。
  - 部分训练数据由先前轮次训练的模型产生，存在自我强化偏差风险。
- **应用限制**：
  - 模型与验证器可能协同适应（co-adaptation），导致验证器失去独立性。
  - 从稀疏轨迹中学习物理因果性仍是开放问题。
  - 终身记忆的隐私保护、专家修正与仿真轨迹的融合、避免向狭窄或自生成评估器优化等问题尚未解决。
  - 部署需要针对不安全机器人动作、破坏性命令、提示注入和秘密泄露的安全测试。
  - 算力资源信息不透明，无法评估训练成本和可复现性。
- **理论局限**：
  - 未建立自主模型架构搜索、无限制自我重写或在无约束物理环境中部署的能力。
  - 四目标的协同进化仍是长期研究计划，当前仅展示了Harness、工具和首次数据到模型的更新。
