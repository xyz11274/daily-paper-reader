## 摘要
基于大语言模型构建的多智能体系统（MAS）通过协调专用智能体来处理复杂任务，但有效的工作流难以预先设计。测试时演化利用执行反馈来改进工作流，然而大幅修改可能破坏有用的组件，而重新执行未改变的请求则会造成冗余计算。受生物演化中遗传与选择相互作用的启发，我们提出了 Inherit-MAS，在工作流和执行两个层面显式地实现继承。一个元模型首先合成由工作智能体组成的工作流，其中声明了角色、通信输入和工具权限，另一个单独提示的评判器对每个已执行的候选方案进行评分并诊断其缺陷。在普通改进轮次中，\emph{工作流继承}从最新完成的候选方案开始，可以丢弃被判定为无用的可移除节点，并应用经过验证的编辑来解决诊断出的缺陷。当新候选方案执行时，\emph{执行继承}仅在完整解析后的请求和执行上下文匹配时继承符合条件的已存储结果，从而避免冗余的模型和工具调用。在使用 GPT-4o-mini 作为工作智能体时，Inherit-MAS 在 WorkBench 上达到 55.4\% 的完成率，在 HotpotQA FullWiki 上达到 49.7\% 的联合 F1，优于 EvoAgent、EvoMAS 和 TacoMAS。在使用 Qwen3-32B 作为工作智能体时，它在两个基准上也超过了这些演化式 MAS 基线。与禁用执行继承重新运行相同控制器相比，执行继承在 WorkBench 上将工作智能体 token 使用量减少 29.1\%，在 HotpotQA 上减少 34.6\%，总 token 使用量分别减少 5.3\% 和 18.1\%。

## Abstract
Multi-agent systems (MAS) built from large language models coordinate specialized agents to tackle complex tasks, but effective workflows are difficult to design in advance. Test-time evolution refines workflows using execution feedback, yet broad revisions can disturb useful components, while re-executing unchanged requests can incur redundant computation. Inspired by the interplay of inheritance and selection in biological evolution, we introduce Inherit-MAS, which makes inheritance explicit at the workflow and execution levels. A meta-model first synthesizes a workflow of worker agents with declared roles, communication inputs, and tool permissions, and a separately prompted judge scores each executed candidate and diagnoses its deficiencies. In ordinary refinement rounds, \emph{workflow inheritance} starts from the latest completed candidate, may discard removable nodes judged unhelpful, and applies a validated edit to address the diagnosed deficiency. When the new candidate executes, \emph{execution inheritance} inherits eligible stored results only if the complete resolved request and execution context match, avoiding redundant model and tool calls. With GPT-4o-mini workers, Inherit-MAS achieves 55.4\% completion on WorkBench and 49.7\% joint F1 on HotpotQA FullWiki, outperforming EvoAgent, EvoMAS, and TacoMAS. With Qwen3-32B workers, it also exceeds these evolving-MAS baselines on both benchmarks. Compared with rerunning the same controller with execution inheritance disabled, execution inheritance reduces worker-token usage by 29.1\% on WorkBench and 34.6\% on HotpotQA, and total token usage by 5.3\% and 18.1\%.

# Inherit-MAS 论文深度总结

## 1. 核心问题与研究动机

- **背景**：基于大语言模型（LLM）的多智能体系统（MAS）通过协调角色专用智能体来完成复杂任务，但有效的工作流（角色划分、工具分配、信息流、验证机制）难以预先设计。
- **测试时演化的困境**：现有演化式 MAS 方法利用执行反馈改进工作流，但存在两个核心矛盾：
  - **修改范围问题**：大幅修改工作流可能破坏已经有效的组件（例如检索策略与整合步骤耦合时，改动一处会干扰另一处）。
  - **冗余计算问题**：保留配置不等于保留结果的有效性；重新执行未改变的请求会浪费模型和工具调用。
- **核心研究问题**：如何在有限测试时预算下，利用执行反馈提升 MAS 任务性能，同时控制测试时演化的推理成本？
- **灵感来源**：生物演化中"遗传（inheritance）"与"自然选择（selection）"的相互作用——遗传为演化提供记忆，选择保留有益变异、淘汰有害变异。

## 2. 方法论

### 2.1 核心思想
将测试时 MAS 演化形式化为**显式的工作流继承 + 执行继承**：每次候选方案从最新完成候选（incumbent）出发，保留有用节点，仅做一处经过验证的定向编辑；执行时对请求完全匹配的节点复用已存储结果。

### 2.2 关键技术细节

- **初始合成与评判**：
  - 元模型根据任务 x 和接口 I 合成初始工作流 G₀（有向无环图，节点含角色、提示、工具、输入输出）。
  - 单独提示的评判器 J 返回四维评分（完成可能性、需求覆盖、工件接地、整体质量）及文本批评与 keep/fix 建议。

- **工作流继承（Workflow Inheritance）**：
  - **Select（选择）**：从最新完成候选 G_{p(k)} 出发，节点选择器 P_sel 提出可丢弃节点集合 Δ⁻_k，仅当反馈表明该节点无贡献或有害时才丢弃；需通过确定性验证器 Valid 检查（含联合可移除性）。
  - **Edit（编辑）**：在保留工作流 G′_k 上应用**一处**经过验证的原子编辑 a_k（来自有限编辑菜单：提示、子任务、工具、增删节点/边、重排输入、插入节点等），编辑仅改变声明范围内的字段，其余保持不变。
  - **重启机制**：当无有效输出或最高质量分仅比首个完成候选高 ≤1 分时，最后一轮使用工作流重合成（无继承）。

- **执行继承（Execution Inheritance）**：
  - **变更定位**：计算受影响区域 D_k = Δ_k ∪ Desc_{G_k}(Δ_k)，区分结构未变节点与可能受影响节点。
  - **请求验证与继承**：对每个节点构造完整解析请求 r_{k,v}（含当前规格、有序上游记录、执行上下文指纹 φ_k），计算 SHA-256 哈希 κ_{k,v}；仅当节点合格（Eligible，如无状态变更工具）且存储记录通过完整性验证时才继承，否则实时执行并存储。
  - **状态变更操作永不可继承**，由唯一 sink 节点实时执行。

- **排序与返回**：按（硬失败数、输出有效性、整体质量、需求覆盖、工件接地、候选顺序）的优先级比较键 s_k 选出最优候选，返回其存储输出，不重新执行。

## 3. 实验设计

### 3.1 数据集与 Benchmark
- **WorkBench**：真实职场任务（邮件、日历、项目管理、CRM、分析数据库），以最终环境状态为评估目标，主指标为官方完成率（completion）。
- **HotpotQA FullWiki**：多文档推理，需返回答案及句子级支撑事实，主指标为官方联合 F1（joint F1，答案与支撑事实的联合精确率/召回率调和平均）。

### 3.2 对比方法
- **Single ReAct**：单智能体参考基线（非 MAS）。
- **EvoAgent**：从初始专家智能体通过进化操作扩展为 MAS。
- **EvoMAS**：通过变异和交叉演化配置，保留有前景配置与累积经验。
- **TacoMAS**：耦合快速能力更新与慢速拓扑演化。

### 3.3 实验配置
- 两种工作智能体骨干：**GPT-4o-mini** 与 **Qwen3-32B**（非思考模式）。
- 元模型与评判器统一使用 **GPT-5.4-mini**（EvoAgent 除外，其全角色使用同一模型）。
- 每个轨迹含初始工作流 + 4 个后续候选，每轮 1 次 Select + 1 次验证编辑。
- WorkBench 130 个任务，HotpotQA 300 个问题，所有系统在相同固定任务集上评估。

## 6. 主要结论与发现

- **性能领先**：Inherit-MAS 在两种骨干、两个 benchmark 上均超越所有演化式 MAS 基线，且是唯一在每个设置中匹配或超过 Single ReAct 的演化式系统。
  - GPT-4o-mini：WorkBench 完成率 55.4%（超最佳基线 TacoMAS 20.8 分），HotpotQA 联合 F1 49.7%（超 TacoMAS 1.9 分）。
  - Qwen3-32B：WorkBench 46.2%（超最佳基线 11.5 分），HotpotQA 42.7%（超 TacoMAS 2.8 分）。
- **渐进改进**：官方性能随改进轮次单调上升（WorkBench +9.2 分，HotpotQA +5.0 分）。
- **成本节约**：执行继承减少 29.1%（WorkBench）和 34.6%（HotpotQA）的工作智能体 token，总 token 节约 5.3% 和 18.1%。
- **继承集中于局部编辑**：Prompt 编辑继承 47.3%–75.0% 的 token 等价；重启轮继承率最低（17.6%–21.0%）。
- **局部性不等于质量**：局部编辑提供成本杠杆，但并非编辑质量的代理指标（Table 3 显示各编辑族质量增量在不同 benchmark 上符号不一致）。
- **排序有价值**：在线排序优于"返回最后候选"和"返回初始候选"，但仍有 oracle 头寸空间（WorkBench oracle 82 vs 返回 72；HotpotQA 56.3% vs 49.7%）。

## 7. 优点

- **方法创新**：将生物演化的"遗传+选择"思想显式映射到 MAS 测试时演化，工作流继承与执行继承两个层面分工明确。
- **保守变更定位**：Select 仅在证据支持时丢弃节点，Edit 限制为单处验证编辑，保护有用组件不被扰动。
- **请求级精确复用**：执行继承基于完整解析请求的 SHA-256 哈希匹配，而非模糊相似度，保证复用结果的正确性；状态变更操作永不继承，安全性高。
- **成本效益显著**：在提升性能的同时大幅降低 token 消耗，且成本核算细致（区分 live 与 inherited token 等价）。
- **实验严谨**：冻结配置、gold-free 评判、确定性运行时验证、存储完整性审计、配对效应分析，方法论透明度高。
- **可复现性**：代码开源，任务列表与评分脚本公开，基线适配细节有文档。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量等硬件细节，仅给出推理服务配置和 token/美元成本。
- **基线适配偏差**：部分基线为 benchmark 适配实现而非发布默认，跨系统比较可能包含实现差异；TacoMAS 的 HotpotQA 发布接口无法提供有效联合 F1。
