## 摘要
智能体进化器自动化了围绕语言模型智能体的提示、技能和工作流的设计，然而它们所遵循的优化过程仍由人工设计：一个固定的搜索循环决定如何评估候选者、保留哪些候选者以及何时停止搜索。我们提出FREEEVOLVE，它也将这一过程自动化。环境指定目标、目标智能体、评估器、数据和资源限制；在这些限制内，进化器自身决定测试什么、收集多少证据、追求哪些候选者以及何时停止。这些决策遵循一个可编辑的进化技能，我们通过元进化来改进它，方法是对每个候选技能所产生的新目标智能体进行评分。因此，优化过程变成了一种从经验中习得的能力，而非预先设计的循环。在tau3-bench、ARC-AGI-2、ARC-AGI-3和Terminal-Bench 2.1上，FREEEVOLVE自行控制进化过程，却在主要留出指标上平均提升13.6分，并达到或超过人工设计的进化器。所学过程随经验持续改进：元进化技能在新目标智能体上比种子技能增加6.9分，展示了跨环境的可迁移性。

## Abstract
Agent evolvers automate the design of the prompts, skills and workflows around language model agents, yet the optimization process they follow is still designed by hand: a fixed search loop decides how candidates are evaluated, which are kept and when the search stops. We propose FREEEVOLVE, which automates this process as well. An environment specifies the goal, target agent, evaluator, data and resource limits; within these limits, the evolver itself decides what to test, how much evidence to collect, which candidates to pursue and when to stop. These decisions follow an editable evolution skill, which we improve through meta-evolution by scoring each candidate skill on the fresh target agent it produces. The optimization process thus becomes a capability learned from experience rather than a loop engineered in advance. On tau3-bench, ARC-AGI-2, ARC-AGI-3 and Terminal-Bench 2.1, FREEEVOLVE controls the evolution campaign by itself, yet improves the primary held-out metric by 13.6 points on average and matches or exceeds hand-designed evolvers. The learned process keeps improving with experience: meta-evolved skills add 6.9 points over the seed skill on fresh target agents, demonstrating transferability across environments.

# FreeEvolve 论文深度总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体的性能高度依赖其外围"套件"（harness），包括提示、技能、工作流、工具调用与失败恢复逻辑。近期研究（GEPA、OpenEvolve、EvoX、HyperAgents 等）已开始自动化这些组件的设计，形成"智能体进化器"（agent evolver）。
- **核心问题**：尽管进化器自动化了"编辑什么"，但它们所遵循的**优化过程本身仍由人工设计**——一个固定的搜索循环预先决定了评估哪些任务、重复多少次、如何比较候选、何时停止。这带来两个问题：
  1. 需要大量领域设计专业知识；
  2. 固定循环内嵌了关于评估噪声、任务难度、课程安排、并行度的假设，这些假设随智能体和环境变化，却无法被进化器根据新证据动态调整。
- **研究问题**：能否将优化过程本身也自动化，使进化器自行组织改进活动，并从经验中学会如何组织？
- **整体含义**：论文将"优化过程"从预先工程化的固定循环，重新定义为一种**可从经验中习得的智能体能力**，并通过元进化（meta-evolution）实现该能力的持续改进与跨环境迁移。

## 2. 方法论

### 2.1 核心思想

- 分离"改进问题"与"解决该问题的过程"：环境只定义目标、可编辑目标、数据与资源约束；进化器被调用一次后全程掌控，自行决定下一步做什么。
- 两个层级共享同一接口与进化操作：
  - **智能体层（worker level）**：进化器改进目标智能体的 harness。
  - **元层（meta level）**：将"进化技能"（evolution skill，一个 Markdown 指令文件）作为可编辑目标，通过完整 worker 进化战役的结果来改进它。

### 2.2 关键技术细节

- **有界接口（Bounded Interface）**：环境定义为
  `E[x0] = (g, D, x0, RE, CE)`
  其中 g 为目标，D 为数据，x0 为初始可编辑目标，RE 为执行函数，CE 为有效请求约束。
  执行返回：`a = RE(x, u)`，其中请求 `u` 由进化器选择（任务选择、重复次数、并发、超时等）。
- **战役自主性（Campaign Autonomy）**：进化器一次调用即运行完整战役：
  `x⋆ = Evolve(s; E[x0]) ≡ s(g, D, x0, RE, CE)`
  没有外部循环固定执行次数、搜索组织或停止决策。进化器可自适应地聚焦失败密集任务、重复不确定比较、重新分配资源、按证据停止。
- **元进化（Meta-Evolution）**：构造元环境
  `Em[s0] = (gm, Dm, s0, Rm, Cm)`，其中 `Dm = {Ew_i[wi]}_{i=1}^n` 为 worker 环境集合。
  元层执行函数：
  `Rm(s, u) = EvaluateWorkers({Evolve(s; Ew_i[wi]) : i ∈ I(u)})`
  即候选技能不单独评分，而是通过它组织的完整 worker 战役及其产出的 worker 来评判。
  元进化本身也是同一操作的又一次应用：`s⋆ = Evolve(s_outer; Em[s0])`。
- **嵌套限制**：元环境被排除在 Dm 之外，嵌套深度限定为两层。
- **实现**：进化器实例化为 Claude Code + 单个 `SKILL.md` 指令文件；`run.sh` 实现 RE；环境文件固定，仅声明的目标可编辑。种子技能只规定"倾向"（以环境为真值来源、保留证据、从最佳目标继续、使用时间预算），不规定迭代次数、分支结构、课程或停止规则。

## 6. 主要结论与发现

- **Q1**：无需人工设计循环，FreeEvolve 在 4 个环境的主留出指标上平均提升 13.6 分，在 3 个 benchmark 上超过专家设计进化器，并匹配或超过 EvoX、HyperAgents；Terminal-Bench 2.1 上 pass@3 最佳但均值略逊于 GEPA。
- **Q2**：种子技能平均仅提升 0.6 分；元进化技能在此基础上再增 6.9 分，改善所有 pass@3 指标，并在所有环境超过无数据 LLM 重写——说明执行经验而非指令改写驱动增益。
- **Q3**：冻结的技能可跨环境迁移，多数目标指标为正；单源技能会降低 Terminal-Bench 均值，联合 τ3+TB2.1 元进化则改善所有指标。跨模型迁移中，FreeEvolve harness 在 4 个非原生设置上保持平均 5.3 分增益，且始终是最强 harness。
- **Q4**：固定任一评估决策（全集、固定并发、无超时）都会产生更弱 worker，后两者还消耗更多 token；轨迹显示进化器会动态改变评估分辨率、开分支、合并发现、重复确认并选择最终 worker。
- **Q5**：Haiku 4.5 无法产生留出增益；从 Sonnet 4.6 起元进化持续改善，最强 Opus 模型产出最佳 worker（Sonnet 4.6 优于 Opus 4.6）。
- **效率**：0.74B tokens 时 FreeEvolve 产出的技能已超过基线两倍 token 成本所能达到的水平。

## 7. 优点

- **概念创新**：明确识别"人工设计的搜索循环"是智能体进化中最后的手工组件，并将其重构为可学习的战役策略。
- **接口设计清晰**：环境与进化器边界分离，使同一技能可复用于不同任务、模型、硬件（如 Slurm 只需替换 Rm 与 Cm）。
- **元进化对象独特**：不同于以往元进化"为下一轮生成固定过程"，FreeEvolve 元进化的是**在内层战役中持续活跃**的技能，且技能本身是文本目标，无需新机制。
- **实验设计较严谨**：留出集隔离、关键词防泄漏、fresh-worker 评估、跨环境与跨模型迁移、固定决策消融、定性轨迹分析多角度验证。
- **实用价值**：技能可冻结复用，强模型进化、弱模型部署，降低重复进化成本；token 效率优于基线。

## 8. 不足与局限

- **模型能力门槛**：Haiku 4.5 无法有效行使战役自主性，方法对进化器模型能力有明确下限要求，限制了低成本场景的适用性。
- **迁移边界**：单源技能在 Terminal-Bench 2.1 上降低均值，说明当目标环境的硬件与执行行为差异较大时迁移可能失效；需要联合多环境元进化才能稳健。
- **成本对齐不严格**：自主循环与固定循环方法的评估预算难以精确匹配，比较基于"改进前沿"而非等成本，可能影响结论的公平性解读。
- **统计稳健性**：每个 benchmark 仅一次搜索运行，留出评估方差较大（部分 ±8 分以上），未报告多次元进化的方差或置信区间。
- **嵌套深度限制**：元环境被排除在 Dm 之外，嵌套限定两层，未探索更深层递归自我改进的潜力与风险。
- **安全与审计**：论文自述元进化可能放大错误、消耗大量算力、使行为变化来源难以追溯；虽有限制嵌套、保留记录、固定模型能力等控制，但不适用于高风险自主部署。
- **算力信息不完整**：未明确 GPU 型号与数量，实验以 CPU 节点和 API 调用为主，缺乏能耗与碳排放报告。
- **应用限制**：当前验证限于 4 个 benchmark，未覆盖真实生产环境、多模态任务或需要长期在线适应的场景。
