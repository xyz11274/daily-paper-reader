## 摘要
随着大语言模型的发展，AI 智能体正从孤立的、特定领域的任务迈向长时程、跨领域的工作流。这一转变暴露出两个挑战：日益增长的驾驭复杂度使人工设计难以规模化，而对特定领域的更紧耦合限制了单一驾驭的通用性。因此，核心问题从如何为某一领域设计更强的驾驭，转变为如何自主构建专用驾驭、通过经验改进它们，并跨领域编排它们。我们提出 Raven，即“驾驭之驾驭”，一个开源多智能体生态系统，能够为特定模型和领域自动构建并演化模块化驾驭，将每个可执行的模型—驾驭对视为可组合的智能单元。为支持“全领域协作网络”，其宿主智能体分解目标、将子任务匹配到专用智能体、协调执行依赖并整合结果，同时宿主档案库与 EverOS 跨任务保存经验，而 Skill Forge 将这些经验转化为可复用流程。我们的理论确立了在共享资源预算下，此类组合能够将可靠任务覆盖范围扩展到超过现有单个智能体所能达到的范围的充分条件。在复杂且长时程的任务上，Raven 显著优于最先进的智能体系统，推动了可组合智能体智能的前沿。

## Abstract
As large language models advance, AI agents are moving beyond isolated, domain-specific tasks toward long-horizon, cross-domain workflows. This transition exposes two challenges: increasing harness complexity makes manual design difficult to scale, while tighter coupling to specific domains limits the generality of a single harness. The central question thus shifts from how to engineer a stronger harness for one domain to how to autonomously construct specialized harnesses, improve them through experience, and orchestrate them across domains. We introduce Raven, \emph{The Harness of Harnesses}, an open-source multi-agent ecosystem that automatically constructs and evolves modular harnesses for specific models and domains, treating each executable model--harness pair as a composable unit of intelligence. To support an \emph{All-Domain Collaboration Network}, its Host Agent decomposes goals, matches subtasks to specialized agents, coordinates execution dependencies, and integrates results, while a host archive and EverOS preserve experience across tasks and Skill Forge makes that experience available as reusable procedures. Our theory establishes sufficient conditions for such composition to expand reliable task coverage beyond that of the available individual agents under a shared resource budget. On complex and long-horizon tasks, Raven significantly outperforms the state-of-the-art agent systems, pushing the frontier of composable agentic intelligence.

## 2. 方法论

### 2.1 核心思想

- **Harness of Harnesses**：Raven 不追求单一最强 harness，而是**自动构建并演化**面向特定模型与领域的模块化 harness，并将其作为可组合单元进行编排。
- **三层能力支撑**：
  1. **Host Agent 编排**：分解目标 → 匹配子任务到注册的专用智能体 → 构建 DAG → 调度执行 → 整合结果。
  2. **Harness 自演化**：基于 HarnessBank，通过诊断失败、提出候选 harness、门控筛选与语义基因库保留精英。
  3. **记忆与技能复用**：EverOS 持久化用户上下文与智能体经验；Skill Forge 将经验转化为可复用流程。

### 2.2 关键技术细节

- **理论框架（第 2 章）**：
  - 将 harness 化智能体形式化为 `ai = Agent(Mi, hi): Hi → Δ(Ui)`，即模型 + harness 诱导的随机策略。
  - 定义**任务相对能力**：`pS(t; B) = P(Vt(ω, YS) = 1, CS ≤ B)`，即在预算 B 内正确完成任务的概率。
  - **确定性组合可靠性（Lemma 1）**：若计划兼容且每个操作成功，则协议在预算内交付正确记录并终止。
  - **组合可靠性定理（Theorem 1）**：`qt(ζ, π) ≥ [1 − ε(ζ, π)]+`，其中 `ε(ζ, π) = Σ εj` 为节点与边错误之和，**无需独立性假设**。
  - **宿主级可靠性（Proposition 1）**：`pSH(t; B) ≥ (1 − ηH(t; B))(1 − ε̄(t; B))`。
  - **超越个体能力（Corollary 1）**：若组合可靠性下界 > 任何单个智能体的成功率，则任务属于 `Cnew(B, δ)`，即组合扩展了可靠任务覆盖。
  - **任务族覆盖（Corollary 2 & 3）**：通过类型化任务文法与编译构造，给出有限预算下任务族覆盖的充分条件。

- **多智能体协作（第 3 章）**：
  - **异构智能体注册表**：支持四种执行后端（进程内 Raven 循环、CLI、ACP、OpenAI 兼容 API），记录状态性、文件能力、进度报告三项能力标签。
  - **分阶段编排指导**：默认仅携带简短描述，需要多智能体时加载完整指南，降低上下文成本。
  - **图构建与准入验证**：五组检查（格式、图结构、智能体能力、状态、环境），任一失败即拒绝并返回修复指针。
  - **依赖就绪调度**：`Ready = {v : pending, 未提交, 所有前驱 completed 且 settled}`，共享并发信号量。
  - **完成裁决**：独立 LLM 调用判断节点是否完成，负面裁决触发异常报告与宿主干预（继续/放弃/重规划）。
  - **澄清请求**：宿主优先从对话与记忆中自动填充答案，涉及审批的请求始终转交用户。
  - **共享组记忆**：宿主在每轮后对每个智能体生成评估（verdict），分 close 与 feedback 两阶段，存入对应智能体库。

- **Harness 自演化（第 4 章）**：
  - **模块化策略接口**：Memory、Planning、Capability、Action 四个可编辑策略组件，围绕冻结模型。
  - **诊断驱动演化**：从失败轨迹识别症状、编辑位置与预期行为变化，生成可执行补丁。
  - **语义基因库**：`Br: Wedit × Yfail → H(Xedit) ∪ {⊥}`，每个（编辑类别，病理标签）单元保留一个精英。
  - **门控筛选**：有效性门 → 激活门 → 配对增益门（`tpair ≥ λscreen = 1.96`），通过者进入全训练评估。
  - **竞争性档案更新**：每单元保留全训练效用最高的候选，平局保留现任。

- **记忆系统（第 5 章）**：
  - **情节轨迹形成**：语义边界检测 → 源片段 → 情节叙事 + 原子事实 + 前瞻（带有效区间）。
  - **语义巩固**：在线聚类形成 MemScene，结合相似度与时间邻近性；用户画像更新。
  - **重构式检索（HYBRID）**：BM25 + 稠密检索 → RRF 确定扩展顺序 → 逻辑校准分数排序 → 事实可取代父情节。
  - **用户上下文组装**：宿主 Markdown 档案 + EverOS 召回，标记为不可信上下文。

- **Skill Forge（第 6 章）**：
  - **策展技能目录**：六阶段策展（解析、过滤、去重、质量评估、发布准入、附加先验与索引），参考发布含 96,401 个活跃技能。
  - **任务感知检索与选择**：查询重写 → 三源并发检索（local/memory/hub）→ 名称分组 RRF 融合 → 代表选择 → 正文获取与策略检查 → LLM 门控选择。
  - **经验驱动技能自演化**：执行案例 → 意图聚类 → 选择更新上下文 → 结构化 LLM 生成 add/update/none 操作 → 验证与血统记录 → 持久化。

## 6. 主要结论与发现

1. **组合可扩展可靠覆盖**：理论证明在共享预算下，互补的局部能力、兼容的交接与有界规划/执行错误可使组合系统解决单个智能体无法可靠解决的任务。
2. **编排优势一致**：Raven 在 MAOB 上四项指标、两个 backbone 全部领先，Exact Match 提升约 10 个百分点。
3. **Harness 演化有效**：冻结 backbone 下，七个 benchmark 全部提升，证明执行策略适应可跨域迁移。
4. **专用 harness 显著优于通用 harness**：研究、编码、设计、运维四个领域均取得一致增益。
5. **技能复用有效且依赖 harness**：策展技能库在 12 个比较中全部提升；Raven 比 OpenClaw 更能将相同技能转化为成功执行（执行–验证–修复循环）。
6. **成本效益**：Raven-Oncall 以更低成本实现更高成功率；Raven-Research 在可比推理成本下取得最高准确率。
7. **依赖预测仍是难点**：所有系统的 Edge F1 均低于 Node F1，表明依赖关系预测比专家选择更难。

## 8. 不足与局限

- **理论假设较强**：可靠性定理要求**兼容计划、宿主能在预算内找到该计划、提供者在选定上下文中实现其契约**，实际适用性取决于实现是否满足这些条件；论文承认“测量平均成功率本身不能建立条件可靠性前提”。
- **算力披露不足**：未报告系统训练/开发的总算力，Harness 演化的开发计算量未量化。
- **部分实验公平性存疑**：
  - 公开排行榜基线模型配置未知。
  - PresentBench 任务覆盖不一致，失败生成被排除。
  - 研究实验未隔离单个 harness 组件效应。
  - 商业服务成本不可直接比较。
- **数据污染风险**：基准公开可获取，论文承认 BrowseComp 和 HLE 的绝对分数可能高估。
- **共享组记忆未评估**：论文明确说明该层默认禁用且**未在报告中评估**，其对编排和任务性能的影响尚待建立。
- **依赖预测仍是瓶颈**：Edge F1 普遍低于 Node F1，说明依赖关系预测的准确性仍有较大提升空间。
- **应用限制**：
  - 需要注册的机器、GPU 资源、外部 API（Serper、Jina Reader）等基础设施。
  - 部分实验依赖内部评估框架 AgentEval 和内部 benchmark（AI4S），**可复现性受限**。
  - 技能覆盖不均：数学（4 任务）和金融经济（9 任务）增益接近零。
- **理论未区分可计算性**：论文指出分析未在编排系统与能模拟它的单程序之间做可计算性区分，即理论不排除单个程序以相同接口和资源模拟组合系统。
