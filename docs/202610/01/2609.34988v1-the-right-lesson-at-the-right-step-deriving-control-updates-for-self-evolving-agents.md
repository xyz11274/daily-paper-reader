## 摘要
自进化智能体通过复用过去的经验来改进未来的行为，通常以全局提示、记忆或反思的形式实现。然而，这些机制很少控制经验在何处生效。在长工具使用工作流中，同一教训可能纠正一个决策却干扰另一个决策，使得经验复用成为局部控制问题而非单纯的记忆问题。我们提出 EvoCUE（通过证据的控制更新实现进化），一个从已完成的智能体执行中学习可复用控制程序更新的框架。EvoCUE 将智能体表示为一个显式的状态机控制器，其节点执行模型或工具调用，边定义控制下一步传递的位置。这使得工作流可以在精确位置进行编辑，因此每个学习到的更新可以指定添加什么、在何处作用以及何时应用。从已完成的轨迹中，EvoCUE 利用残差目标和观察到的执行轨迹来提出局部化的指令或技能编辑。每个候选更新在其将作用的位置进行评估，即从同一检查点恢复父控制器和编辑后的控制器，并比较它们的最终结果。被接受的编辑与适用性规则一起编译，在留出任务上确认，并由后续执行继承。我们在长工具使用环境中评估 EvoCUE，其中学习到的约定必须到达正确的执行步骤。从一个没有基准特定引导指令的最小 AppWorld 控制器出发，EvoCUE 学习到缺失的任务完成约定，并在 Test-Normal 和 Test-Challenge 上大幅提高成功率。在 PAST-Bench 办公工作流中，EvoCUE 将组织要求从先前片段迁移到后续任务，提高任务执行质量。这些结果表明，自进化智能体应将经验置于控制流内部，而不仅仅将其存储为文本。

## Abstract
Self-evolving agents improve future behavior by reusing past experience, typically as global prompts, memories, or reflections. Yet these mechanisms rarely control where experience takes effect. In long tool-use workflows, the same lesson may correct one decision but distract another, making experience reuse a problem of localized control rather than memory alone. We introduce EvoCUE (Evolution through Control Updates from Evidence), a framework for learning reusable control-program updates from completed agent executions. EvoCUE represents the agent as an explicit state-machine controller, whose nodes perform model or tool calls and whose edges define where control passes next. This makes the workflow editable at precise locations, so each learned update can specify what to add, where it acts, and when it applies. From completed trajectories, EvoCUE uses residual goals and observed execution traces to propose localized instruction or skill edits. Each candidate is evaluated at the point where it would act by resuming the parent and edited controllers from the same checkpoint and comparing their final outcomes. Accepted edits are compiled with applicability rules, confirmed on held-out tasks, and inherited by later executions. We evaluate EvoCUE on long tool-use environments where learned conventions must reach the right execution step. From a minimal AppWorld controller without benchmark-specific onboarding instructions, EvoCUE learns the missing task-completion convention and substantially improves success on Test-Normal and Test-Challenge. On PAST-Bench office workflows, EvoCUE transfers organizational requirements from prior episodes to later tasks, improving task-execution quality. These results show that self-evolving agents should place experience inside the control flow, rather than only store it as text.

## 1. 核心问题与整体含义

- **研究动机**：自进化智能体（self-evolving agents）通常通过复用过去经验（全局提示、记忆、反思）来改进未来行为，但这些机制**很少控制经验在何处生效**。
- **核心痛点**：在长工具使用工作流中，同一条经验可能纠正一个决策却干扰另一个决策。经验复用本质上是**局部控制问题**，而非单纯的记忆问题。
- **关键例证**：AppWorld 中一条关于任务完成约定的指令，放在第一步只能解决 16 个任务中的 5 个，放在后续步骤则能解决 14 个——**位置决定效果**。
- **第二难点**：局部编辑的影响会扩散到后续多个动作，而反馈通常只在任务结束时才观察到。从任务起点重跑会混入无关变异，难以归因。
- **整体含义**：自进化智能体应把经验放入**控制流内部**，而非仅作为文本存储；学习不仅要决定"保留什么"，还要决定"在哪里生效"。

## 2. 方法论：EvoCUE 框架

### 核心思想
- 将智能体表示为**显式状态机控制器** C = (G, π, Ω)：节点执行模型/工具调用，边定义控制流向，边可携带指令。
- 每个学习到的更新（edit）明确指定三要素：**内容（what）、位置（where）、适用时机（when）**。

### 关键技术细节

- **残差目标（Residual Goals）**：从已完成轨迹中估计任务指令里"公开历史尚未显示为满足"的需求，将失败定位到可编辑位置。例如"导出前需审批"若历史中无审批记录，则成为残差目标。
- **局部化编辑提案**：
  - 指令编辑：在指定边上添加文本，作用域可为当前调用、技能调用或下一动作。
  - 结构编辑：在边上插入 1–6 个原语操作的可执行技能，含前向分支与成功/失败返回。
  - 提案前检查：节点存在性、草稿状态兼容性、操作符输入有效性。
- **配对试验（Paired Trials）**：
  - 从编辑作用点前的检查点 j 恢复环境状态、公开历史、控制器状态与剩余预算。
  - 分别运行父程序 C 与编辑后程序 C⊕δ 至任务结束。
  - 效应公式：**d_tj(δ; C) = Y_tj(C⊕δ) − Y_tj(C)**，其中 Y 为最终任务得分。
  - 因共享前缀，排除了编辑作用前的一切变异。
- **适用性规则拟合**：
  - 枚举至多两个等式测试的规则 q（基于执行阶段、草稿有效性、残差目标状态、进度、重复性等类别特征）。
  - 选择公式：**q̂_δ ∈ argmax_q [ p̂_Sδ(q)·d_δ,q − λ|q| ]**，其中 p̂ 为覆盖任务比例，d 为平均效应，λ 为复杂度惩罚。
  - 通过条件：至少覆盖 2 个任务、平均效应为正、且 p̂·d − λ(|q̂|+|δ|) > 0。
- **编译、确认与继承**：
  - 通过的编辑编译为带规则的调用或内部节点。
  - 在**独立确认任务集**上从任务起点比较 C′ 与 C。
  - 满足预设接受标准后，C′ 被继承用于后续任务。
- **试验记忆**：记录所有试验（含被拒的），供后续提案参考，避免重复失败方向。

## 6. 主要结论与发现

- **AppWorld**：从最小控制器出发，EvoCUE 学到缺失的任务完成约定（非问题任务应留空答案），Test-Normal 成功率从 13.7% 升至 79.2%（110 改进、0 回退），Test-Challenge 从 6.7% 升至 70.0%（270 改进、6 回退）。基线最多提升 4.8 点。
- **位置至关重要**：同一指令放第一步解决 5/16，放后续步解决 14/16；关键是完成决策时指令是否可用。
- **学习过程**：前两轮提案（简短回答、草稿修订）均失败；第三轮通过残差目标定位到完成步骤，配对试验 5/8 改进、0 回退，确认后继承。
- **PAST-Bench**：任务执行分数从 0.608 升至 0.772（基线最多 +0.06）；未见任务族从 0.35 升至 0.73。
- **额外领域**：初始程序已高分或任务较短，EvoCUE 未接受任何更新，说明方法适用于需要长程约定的场景。
- **核心结论**：经验驱动的适应应学习"复用何种经验"以及"经验应进入控制流的何处"。

## 7. 优点

- **概念创新**：将经验复用重新定义为局部控制问题，而非记忆问题，视角新颖且切中要害。
- **显式控制表示**：状态机使编辑位置、作用域、适用时机均可精确表达与检验。
- **配对试验设计**：从匹配检查点恢复执行，共享前缀，有效隔离编辑的下游效应，归因清晰。
- **适用性规则学习**：用因果推断思路（异质效应估计）拟合"何时应用"，避免全局注入。
- **严格确认机制**：独立任务集确认 + 试验记忆保留失败记录，降低过拟合与回退风险。
- **实验严谨**：学习/测试分离、冻结程序、多基线同条件、重复运行、置信区间、未见任务族迁移。
- **可解释性**：每个编辑有内容、位置、证据链与试验记录，支持人工审查。

## 8. 不足与局限

- **适用性规则泛化有限**：规则从有限观测任务推断，更广迁移与异常处理仍是开放问题。
- **依赖可恢复状态**：配对试验需要可恢复的执行检查点，并非所有环境都支持。
- **离线冻结评估**：当前在训练后冻结程序，未验证长任务流上的在线学习；指令累积会导致成本膨胀。
- **基线非官方复现**：基线使用最小提示而非官方提示，性能低于已发表数字，不能据此评判原方法。
- **PAST 判官差异**：使用自选 LLM 判官而非基准默认判官，可能引入评分偏差。
- **回退风险**：PAST 中有一个远迁移任务从 0.796 回退到 0.510，说明复用并非一致有益。
- **确认数据稀缺时保守**：未见任务族仅 2 个可改进确认任务，配对确认拒绝了所有编辑，牺牲召回换取防回退。
