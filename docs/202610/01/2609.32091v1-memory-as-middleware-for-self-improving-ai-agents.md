## 摘要
AI智能体在默认情况下跨会话是无状态的，因此在操作上是失忆的：每个会话开始时，对先前的失败、修复、偏好或成功策略几乎没有持久的知识。结果，智能体重复同样的错误并丢弃来之不易的经验。主流的解决方案是\emph{定制记忆}——将检索、持久化和学习逻辑手工接入一个智能体并绑定到一个存储引擎。这造成了一个碎片化的格局，其中记忆无法独立于拥有它的智能体进行替换、共享、隔离或推理。我们认为这是一个中间件问题：智能体记忆理应成为一个一等的、可插拔的层，就像数据访问、消息传递和持久化各自成为中间件关注点一样。我们通过六个系统挑战来发展这一愿景：双向可插拔性、宿主原生介入、多租户隔离、写路径一致性、带来源的联邦共享以及生命周期治理。我们提出了ALTK-Evolve，一个用于自我改进智能体的记忆中间件参考实现，并用它来推动未来记忆中间件的更广泛研究议程。

## Abstract
AI agents are stateless across sessions by default and therefore operationally amnesic: each session begins with little durable knowledge of prior failures, repairs, preferences, or successful strategies. As a result, agents repeat the same mistakes and discard hard-won experience. The dominant fix is \emph{bespoke memory}---retrieval, persistence, and learning logic hand-wired into one agent and bound to one storage engine. This creates a fragmented landscape where memory cannot be swapped, shared, isolated, or reasoned about independently of the agent that owns it. We argue that this is a middleware problem: agent memory deserves a first-class, pluggable layer, just as data access, messaging, and persistence each became middleware concerns.   We develop this vision through six systems challenges: two-sided pluggability, host-native interposition, multi-tenant isolation, write-path consistency, federated sharing with provenance, and lifecycle governance. We present ALTK-Evolve, a reference implementation of memory middleware for self-improving agents, and use it to motivate a broader research agenda for future memory middleware.

# 论文总结：Memory as Middleware for Self-Improving AI Agents

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体默认跨会话无状态，本质上是"操作性失忆"——每次会话开始时对先前的失败、修复、偏好和成功策略几乎没有持久知识，导致重复犯错、丢弃经验。随着智能体从单次对话演变为长期运行的软件行为体（规划、调用工具、多智能体协作），这种失忆成为可靠性天花板。
- **现有方案的困境**：主流做法是"定制记忆"（bespoke memory），将检索、持久化、学习逻辑手工接入单个智能体并绑定到单一存储引擎。这导致记忆无法互换、共享、隔离或独立推理，每个团队重复造轮子且互不兼容。
- **核心主张**：智能体记忆应成为**一等、可插拔的中间件层**，位于智能体与存储之间，向多个宿主（Claude Code、Codex 等）和多个后端暴露统一契约，并承担隔离、一致性、共享、溯源、用户控制和生命周期治理等横切关注点。
- **类比依据**：数据访问、消息传递、事务、缓存、持久化都曾是被手工接入应用的逻辑，直到系统社区将其抽取为中间件。作者认为智能体记忆是下一个这样的层。
- **范围界定**：聚焦通过工具在长期运行的操作上下文中行动的软件智能体（编码、工作流、企业智能体）；不涉及具身智能体（其记忆与感知控制耦合，约束不同）。

## 2. 方法论

### 2.1 核心思想

- 记忆中间件应同时优化三个设计目标：
  - **准确性（Accuracy）**：让智能体行动更好，而非记得更多；包括检索正确记忆、目的导向压缩、避免陈旧/重复/矛盾记忆污染。
  - **成本（Cost）**：压缩存储、惰性召回、按需注入上下文、按部署环境打包记忆以适配资源预算。
  - **控制（Controls）**：按租户和范围隔离、可归因、默认私有、可保留/审查/删除。作者强调成本和控制是记忆成为系统问题（而非仅建模问题）的关键。

### 2.2 记忆类型模型

- 记忆不能是单一无差别的向量袋，必须分为三类并置于独立但链接的命名空间：
  - **情景记忆（Episodic）**：任务/会话中发生的事——轨迹、决策、错误、结果。
  - **语义记忆（Semantic）**：关于用户、项目、环境的稳定事实。
  - **程序记忆（Procedural）**：如何执行重复性操作。
- 三类记忆在表示与访问、写入语义、压缩方式、老化与治理上均不同；混合会导致"检索干扰"（高容量工具调用内容淹没稀疏的语义事实）。

### 2.3 六大系统挑战

1. **双向可插拔性（Two-sided pluggability）**：下方抽象异构存储（文件、pgvector、分布式向量库、托管服务），上方抽象异构智能体宿主；契约两侧稳定，更换存储不影响智能体，支持新宿主不影响存储。当前缺乏类似 SQL 的通用接口，可能需要新的"智能体记忆编程模型"。
2. **宿主原生介入（Host-native interposition）**：不同宿主暴露不同介入原语（生命周期钩子、用户命令、工具协议、项目级指令文件）；中间件需绑定任一原语并呈现相同逻辑行为（行动前召回、行动后捕获），无需智能体作者编写记忆专用代码。
3. **多租户隔离（Multi-tenant isolation）**：命名空间按用户、团队、项目、智能体、仓库或任务划分；隔离须适用于存储、检索、整合、发布、删除和审计全流程。
4. **写路径一致性（Write-path consistency）**：朴素追加式记忆会腐烂（重复、陈旧建议、过度泛化、矛盾）；写路径须作为协调问题，决定新增、更新、合并、取代、隔离或拒绝候选记忆。协调对象是"行为影响"而非数据项。
5. **带来源的联邦共享（Federated sharing with provenance）**：显式可见性模型（默认私有、刻意发布）+ 联邦机制（订阅/同步而不复制整个存储）+ 溯源（可追溯至轨迹、用户、智能体、模型或策略）。共享扩大安全隐私面，需准入检查、溯源验证、默认私有。
6. **生命周期治理（Lifecycle governance）**：保留、过期、压缩、审计、审批、删除；多作者（智能体、用户、其他智能体、组织）需策略钩子规定谁可创建、审批、编辑、删除、过期、压缩或共享。

### 2.4 参考架构与实现（ALTK-Evolve）

- **经验飞轮**：捕获（capture）→ 提取（extract）→ 整合（consolidate）→ 存储（store）→ 检索（retrieve）→ 注入（inject），闭环通过智能体自身。
- **类型化记忆模型**：三类记忆分命名空间；通用单元为"实体"（entity），含内容、类型标签、元数据（触发条件、溯源、所有权与可见性、指南类别/理由/实现步骤/支持计数与成败证据）。
- **智能体面向接口**：六个逻辑操作——检索、写入、整合、发布、删除、检查。任务中操作为 MCP 工具（stdio/SSE）；整合与检查为控制平面操作，通过客户端库、CLI 和 Web 界面暴露（智能体可用记忆，但策展记忆是受治理的人类可见行为）。
- **宿主绑定**：Claude Code（插件+指令文件导入+技能）、Codex（全局指令文件指针+召回优先协议）、Claw Code（插件+技能+可选工具前钩子）、IBM Bob（全局规则文件+命令+MCP 服务器）。
- **从轨迹到可复用记忆**四步：
  1. **任务分割**：识别轨迹中实际执行的不同任务。
  2. **子任务识别**：分解为子任务粒度（比任务级更可复用）。
  3. **泛化**：抽象掉任务特定实体（如"某播放列表"→"目标播放列表"）。
  4. **聚类与整合**：按语义相似度聚类，合并去重为综合指南。
- **目的导向摘要（Purpose-directed gisting）与分层存储**：摘要嵌入向量索引，完整原文存于持久存储并有指针；压缩提示编码摘要用途（语义记忆突出用户属性偏好，程序记忆突出检索/计算内容、参数和结果）；工具调用摘要与对话摘要分命名空间；读取时由模型在上下文中决定是否取回原文（自适应记忆保真度）。

## 6. 主要结论与发现

- **记忆有效**：任务目标完成率从 69.6% 升至 73.2%；更严格的场景目标完成率从 50.0% 升至 64.3%（+14.3 个百分点）。
- **最难任务收益最大**：Hard 层级的场景目标完成率从 19.1% 翻倍以上至 47.6%。
- **归因明确**：由于智能体模型和推理循环未改动，增益可归因于作为可分离层提供的记忆，而非智能体本身的变化。
- **可移植**：同一记忆层无修改运行于四个独立开发的编码智能体宿主，验证了双向可插拔性和宿主原生介入的实践可行性。
- **总体结论**：记忆应成为一等中间件层，使智能体记忆可插拔、可共享、可隔离，从而持续积累经验并自我改进；更广泛的挑战——定义抽象、一致性模型、策略和基准——尚待系统社区解决。

## 7. 优点

- **问题定位精准**：将"智能体记忆"从应用逻辑重新框定为中间件问题，类比数据库/SQL、消息队列、缓存的历史演进，论证有说服力且具启发性。
- **设计空间系统化**：六大挑战并非凭空发明，而是从定制系统的反复失败模式（上下文泄漏、记忆腐烂、孤岛、不可问责影响）与中间件历史经验交叉推导而来，逻辑自洽。
- **类型化记忆的结构性论证**：清晰说明情景/语义/程序记忆在表示、访问、写入语义、压缩、老化上的分歧，并用"检索干扰"的具体例子（一周工具调用淹没一行偏好）说明为何类型化是结构要求而非标注约定。
- **目的导向摘要与分层存储**：摘要作为索引而非替代、原文始终可恢复、读取时自适应保真度，设计精巧且实用。
- **控制平面与数据平面分离**：整合与检查刻意不暴露给智能体工具面，而通过 CLI/Web 界面供人类治理，体现了对"受治理的记忆"的深思。
- **可移植性实证**：跨 4 个宿主、3 个存储后端实际运行，而非仅声称可插拔。
- **研究议程有依赖结构**：明确指出编程模型与一致性语义为两项基础工作，其余构建其上，为社区提供了清晰的路线图。
