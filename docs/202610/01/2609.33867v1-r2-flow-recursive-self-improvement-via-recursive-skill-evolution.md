## 摘要
基于LLM的智能体可以通过复用和修订其编排为可执行过程的技能，在任务间实现自我改进。基于流的训练契合这一循环：它按奖励比例采样过程，流经每个技能的流量为其下一次技能库修订提供信用。使这种自我改进可靠面临三个障碍：流训练在树状历史上会遭遇策略坍缩；基于非负流的信用将频繁使用视为收益；技能库编辑依赖于策略所优化的任务奖励。我们提出R$^2$ Flow，一种递归自我改进框架，在共享状态编排图上交替进行策略学习、独立验证和版本化技能库更新。该图合并仅在独立步骤顺序上不同的历史，使流训练能够在等价执行间汇集证据。训练所得流的流量份额读出对反向策略不变，而单独的有符号效用对技能进行排序以决定更改哪些技能，验证器证据决定编辑是否必要，残差方差平台期决定何时更新。已提交的编辑重塑下一次策略学习所依据的图，实现递归技能进化。在问答、数学推理、交互式决策和代码生成中，R$^2$ Flow在任务准确率和技能库编辑精度上优于启发式编排、强化学习和技能进化基线，并可在不同执行器间迁移。代码见 https://github.com/beita6969/r2flow。

## Abstract
LLM-based agents can improve themselves across tasks by reusing and revising the skills they orchestrate into executable procedures. Flow-based training fits this loop: it samples procedures in proportion to reward, and the flow through each skill credits it for the next library revision. Three obstacles stand in the way of making this self-improvement reliable: flow training suffers strategy collapse over tree-structured histories; nonnegative flow-based credit rewards frequent use as if it were benefit; and library edits rest on the task reward the policy optimizes. We introduce R$^2$ Flow, a recursive self-improvement framework that alternates policy learning, independent verification, and versioned skill-library updates on a shared-state orchestration graph. The graph merges histories that differ only in the order of independent steps, allowing flow training to pool evidence across equivalent executions. A flow-share readout of the trained flow, invariant to the backward policy, and a separate signed utility rank which skills to change, verifier evidence decides whether an edit is warranted, and a residual-variance plateau sets when to update. Committed edits reshape the graph the next policy learns on, realizing recursive skill evolution. Across question answering, mathematical reasoning, interactive decision making, and code generation, R$^2$ Flow improves task accuracy and library-edit precision over heuristic orchestration, reinforcement learning, and skill-evolution baselines, and transfers across executors. Code is available at https://github.com/beita6969/r2flow.

# R² Flow 论文深度总结

## 1. 核心问题与整体含义

- **研究背景**：基于 LLM 的智能体正从"单次回答"转向"编排可复用技能为可执行过程"，因此自我改进的目标不仅是完成任务，更是改进后续所用的过程，形成"训练策略→更新技能库→再训练"的递归循环。
- **核心问题**：要让这种递归自我改进可靠，存在三大障碍：
  - **策略坍缩（Strategy Collapse）**：状态若定义为完整交互历史，则每个状态只有一个父节点，编排图退化为树，反向策略恒为 1。仅在独立步骤顺序上不同的执行落在不同分支，证据无法共享，流概率被分散到同一过程的多种重排序上，导致"可重排序更多"的过程获得不成比例的采样质量。
  - **无差别信用分配（Indiscriminate Credit）**：流份额与使用计数天然非负，可靠性后验只衡量"调用是否成功"，都无法说明技能"是否有益"。一个被频繁调用的有害技能会显得关键并存活到下一轮。
  - **未经验证的技能进化（Unverified Evolution）**：技能库编辑依据的正是归因存疑的任务奖励，且基于点估计，无法区分"证据不足"与"确认失败"，技能可能在证据积累前就被剪枝。
- **整体含义**：论文提出 R² Flow，将策略学习、独立验证与版本化技能库更新统一在一个递归循环中，使智能体无需人工干预即可持续自我改进。

## 2. 方法论

### 核心思想
- 在**共享状态编排图**上交替运行两个循环：
  - **内循环**：策略在自身 rollout 上用 R²TB 目标训练，直到残差方差进入平台期。
  - **外循环**：基于验证器证据提交技能库编辑，编辑重塑下一阶段的图。

### 关键技术细节

- **编排图与共享状态（§4.1）**
  - 原始历史 $H_t$ 通过映射 $\sigma$ 抽象为共享状态 $s_t = (E_t, \prec_t, A_t, V_t, \Omega_t)$，即已提交事件集、依赖序、规范化产物、已验证事实、环境可观测量。
  - 仅在独立步骤顺序上不同的历史被合并为同一状态（Mazurkiewicz 迹等价）；若存在依赖（如 B 消费 A 的输出），则保留依赖序，顺序仍区分。
  - 合并后状态有多个合法前驱，反向策略成为真正的选择（Proposition 1）。

- **流训练与流份额（§4.2）**
  - 前向策略 $P_F$ 即 Supervisor $\pi_\theta$，按技能标识与结构化参数分解；反向策略 $P_B$ 在入边上用 hindsight 特征 softmax 归一化。
  - **R²TB 目标**：子轨迹平衡残差 $\delta_{i:j} = \ell(s_i) + \sum \log P_F - \ell(s_j) - \sum \log P_B$，损失为几何衰减加权的残差平方和，终端流锚定到温度化奖励 $R_\eta(x)=(R(x)+\epsilon)^\eta$，并引入每域偏置 $b_d$ 吸收终端残差共享偏移。
  - **流份额 $\Psi_0(u)$**：在兼容参考三元组 $(F^0, P_F^0, P_B^0)$ 下，技能份额为其所有边的归一化边流之和，对反向策略不变（Corollary D.9），从训练策略 rollout 用 $e^{-\delta_{0:T}}$ 加权估计。
  - **有符号效用 $\tilde{A}_e$**：对比固定参考策略 $\nu$（在合法事件上均匀）的期望温度化奖励差，并用边级平衡违反量 $|\delta_e|$ 做一致性折扣。正值表示该事件优于该状态下的平均合法替代。

- **验证器门控的技能进化（§4.3）**
  - **是否编辑（Whether）**：每次调用带上下文 $z$，验证器标签更新分层 Beta 后验，用可信下界 LCB 与上界 UCB 决策。区间过宽→defer 收集更多证据；UCB 低于质量阈值→refine 或 prune。验证预算按参考边流 $\varphi_0(e)$ 分配。
  - **编辑哪些（Which）**：库算子 $\Phi$ 结合流份额、调用计数、可信界与有符号效用，按顺序执行 defer / split / refine / retain / prune（单技能）、consolidate（技能对）、generate（上下文簇）。
  - **何时编辑（When）**：用残差方差 $V_q = \text{Var}_{\tau|q}[\delta_{0:T}]$ 作为无分区函数依赖的停滞统计量；当拟合斜率在容差内平坦、近期相对下降非负但很小、且归一化技能熵下降时，宣告阶段边界。
  - 每次编辑版本化，需通过配对 rollout 在成功率、温度化奖励、token 成本、延迟上的非劣性检验，否则回滚。

## 3. 实验设计

- **数据集**：共 12 个，覆盖四个任务域。
  - **IID（6 个，用于训练 Supervisor）**：HotpotQA、TriviaQA、AIME 2026、HealthBench、MBPP+、ALFWorld。
  - **OOD（6 个，仅用于最终评估）**：MuSiQue-Ans、NQ-Open、MATH-Hard、GPQA、SWE-bench、WebShop。
  - 每个数据集固定 128 条记录、固定种子；AIME 2026 用全部 30 题。
- **指标**：QA 用 Exact Match（主指标）与 Answer F1；AIME/MATH/GPQA 用准确率；HealthBench 用原生 rubric 均值；ALFWorld/WebShop 用成功率；SWE-bench 用 resolved 率；MBPP+ 用 pass@1。
- **对比方法**：
  - 直接回答的 Qwen3.5-9B 与 DeepSeek-V4-Flash；
  - SFT、GRPO（训练 Supervisor 骨干）；
  - AFlow（工作流图优化）、FlowSteer（强化渐进画布编辑）、Trace2Skill、SkillOpt（技能进化基线）。
  - 所有方法共享同一冻结的 Qwen3.5-9B 执行器、工具集、检索语料与推理预算。
- **实验组**：
  - RQ1 分布内性能、RQ2 分布外性能、RQ3 跨执行器迁移（6 个其他冻结执行器）；
  - RQ4 组件消融（9 个变体 × 12 数据集 = 108 个消融单元）；
  - RQ5 训练目标对比（GRPO、DB、TB、TTB、SubTB、R²TB）；
  - RQ6 阶段间改进、编辑精度、有害技能剪枝。

## 6. 主要结论与发现

- **性能领先**：R² Flow 在所有 IID 与 OOD 数据集上均领先，IID 平均比最强基线 SkillOpt 高 2.03 EM 与 5.57 准确率点；OOD 高 3.83 EM 与 2.85 准确率点；所有平均增益 p < 10⁻³。
- **超越大模型**：9B 骨干的 R² Flow 在全部 12 个数据集上超过直接提示的 DeepSeek-V4-Flash。
- **跨执行器迁移**：固定训练好的 Supervisor，在 6 个其他冻结执行器上平均提升 15.70–24.64 点，并将 IID 执行器间差距从 14.5 缩小到 6.9 点；较弱执行器获益更多（Pearson r = −0.97）。
- **组件贡献**：共享状态贡献最大（7.31 IID / 5.99 OOD 点）；均匀 $P_B$ 损失 4.52 IID 点；仅按份额排序损失 3.61 点；用后验均值替代可信界损失 2.23 IID / 2.97 OOD 点；重置阶段状态损失约 5 点。
- **训练目标**：R²TB 在 OOD 上比次优的 SubTB 高 1.69–6.17 点，GRPO 最低。
- **递归改进**：8 个阶段 OOD 从 71.2 升至 81.02，37 次提交编辑中 33 次提升留出验证分数（精度 0.89）；基于奖励标签的编辑中 25/44 提高训练奖励却降低验证分数，导致准确率在第 3 阶段后下降。
- **有害技能剪枝**：R² Flow 剪掉 12 个注入有害技能中的 11 个（6 个在第 2 阶段前），而仅按份额排序保留 8 个，Bayesian-Agent 保留 6 个，SkillFlow 保留 7 个。

## 7. 优点

- **问题刻画精准**：将自我改进的可靠性障碍清晰拆解为策略坍缩、无差别信用、未验证进化三点，并逐一给出对应设计。
- **理论扎实**：附录给出 Proposition 1–3 及 A–D 节的完整证明，包括共享状态图的良定义性、反向策略不变性、流份额归一化、验证器后验的幂后验解释与分位数单调性。
- **设计解耦清晰**：将"份额"（多少流量）与"有符号效用"（是否有益）分离，将"训练奖励"与"验证器证据"分离，避免了优化器利用评估器的经典问题。
- **阶段控制优雅**：用残差方差平台期作为无分区函数依赖的阶段边界统计量，理论上有 log Z 平移不变性。
- **实验全面**：覆盖四域十二数据集、六执行器迁移、108 消融单元、六目标对比、八阶段递归分析，且共享执行器与预算，公平性较好。
- **可复现**：代码、权重、数据集开源，报告 5 次运行均值与标准差。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量与总训练时长，难以评估实际资源门槛与可复现成本。
- **执行器覆盖有限**：迁移实验中的执行器多为同代或相近规模模型，未验证跨架构（如 MoE、非 Transformer）或极小模型的表现。
- **阶段触发敏感性**：固定阶段长度与平台期触发的差距仅 1.58–2.03 点，触发机制的鲁棒性与超参（$\epsilon_b, \gamma_{var}, h_0$）敏感性未充分讨论。
- **验证器依赖**：方法核心依赖独立验证器（单元测试、schema 校验、断言等），在缺乏可靠验证器的开放域任务（如创意写作、主观对话）中适用性受限。
- **健康领域风险**：HealthBench 仅作基准，论文明确声明 R² Flow 不用于提供医疗建议，但技能库自我进化在敏感领域的潜在风险仍需更系统的安全评估。
- **偏差风险**：所有数据集为公开英文基准，跨语言、跨文化泛化未验证；OOD 数据集虽留出，但任务类型与 IID 同属四域，真正的开放世界泛化仍待检验。
- **编辑精度非完美**：0.89 的编辑精度意味着约 11% 的提交编辑未提升验证分数，长期递归循环中误差累积的风险未被量化分析。
