## 摘要
视觉-语言-动作（VLA）和世界-动作（WAM）模型将观测和指令直接映射为机器人动作。这种直接性将策略与训练绑定：微小的布局或视角变化就会导致失败，且指令泛化能力差。根本原因在于表示：任务需求、条件、进度和故障恢复被隐式编码在动作序列中，使其难以检查或修改。数字编码智能体提供了一个先例：LLM调用工具、验证结果，并根据反馈以可执行代码的形式进行修改。显式状态、可管理执行和可修改流程的相同工作模式，构成了物理世界中泛化和长时程执行的基础，使物理经验能够作为可重用程序、记忆或证据返回。我们提出物理编码（Physical Coding），将任务状态和执行表示为代码。作为世界的代码（Code as World）记录对象、关系、约束和进度；作为策略的代码（Code as Policy）组织规划、验证、恢复和执行。我们构建了HexaAnything，它调用感知、规划和控制工具（包括VLA/WAM策略），并根据外部反馈进行在环决策。经过验证的轨迹成为数据和记忆，使得从工具和Harness向模型权重、架构，最终向硬件和任务设计的进化成为可能。在RoboCasa365上，HexaAnything在Composite-Unseen和整体成功率上优于XR-1 VLA，并且其经Harness训练的HexaModel在每个划分上都优于基础模型，表明代码轨迹内化了物理执行。在PhyBench和双臂AgileX机器人上，该智能体自主完成物理实验和大多数桌面任务，通常比已发表结果更快。我们观察到数据、模型和工具的自我进化；未来工作旨在权重内化、自主重新设计架构、语言、表示和任务，以及在制造业和科学中的部署。

## Abstract
Vision-language-action (VLA) and world-action (WAM) models map observations and instructions directly to robot actions. This directness ties a policy to training: minor layout or viewpoint changes cause failure, and instructions generalize poorly. The root cause lies in representation: task requirements, conditions, progress, and failure recovery are implicitly encoded in action sequences, making them difficult to inspect or revise. Digital coding agents offer a precedent: LLMs call tools, verify results, and revise from feedback as executable code. The same working pattern of explicit state, manageable execution, and revisable procedures underlies generalization and long-horizon execution in the physical world, letting physical experience return as reusable programs, memory, or evidence. We propose Physical Coding, representing task state and execution as code. Code as World records objects, relations, constraints, and progress; Code as Policy organizes planning, verification, recovery, and execution. We build HexaAnything, which calls perception, planning, and control tools, including VLA/WAM policies, and makes in-the-loop decisions from external feedback. Verified traces become data and memory, enabling evolution from tools and Harness to model weights, architectures, and ultimately hardware and task design. On RoboCasa365, HexaAnything improves Composite-Unseen and overall success over XR-1 VLA, and its Harness-trained HexaModel beats the base on every split, indicating code traces internalize physical execution. On PhyBench and a dual-arm AgileX robot, the agent autonomously completes physics experiments and most tabletop tasks, often faster than published results. We observe data, model, and tool self-evolution; future work targets weight internalization, autonomous redesign of architectures, languages, representations, and tasks, and deployment in manufacturing and science.

- **结构性缺陷**：长时程任务需要跟踪对象、约束、未完成子目标、状态变化、完成条件和恢复决策，而这些**均未在动作块和停止信号中显式表示**。开环成功率约为各步成功率之积 ∏pᵢ，中间漂移只能在末端暴露。
- **核心诊断**：问题不在于"模型能否预测更好的动作"，而在于"系统是否维护了一个可在执行全程被检查和修正的表示"。
- **研究含义**：借鉴数字编码智能体（LLM 调用工具、验证结果、以代码形式修改）的成功范式，将**显式状态、可管理执行、可修改流程**引入物理世界，使物理经验能作为可重用程序、记忆或证据返回系统。

## 2. 方法论：Physical Coding

### 2.1 核心思想
将物理任务的状态与执行**统一表示为可执行代码**，形成两个耦合的可执行工件：
- **Code as World（作为世界的代码）**：记录任务相关对象、关系、观测、状态变量、约束和进度谓词，每个条目携带来源（provenance）。
- **Code as Policy（作为策略的代码）**：组织规划、工具调用、执行、验证、分支、循环、恢复和重规划。

### 2.2 关键技术细节
- **从感知到世界程序**：场景结构由图像写成代码（VCode 方式，不读仿真器状态）；测量值来自工具（检测器、深度、位姿、仪器读数）；执行状态来自机器人本体感受和工具返回值。机器人反复观测同一场景，条目**逐条增量更新**而非重新生成，矛盾可见。
- **从物理能力到策略程序**：能力以**类型化工具**暴露（感知、运动规划、抓取、放置、接触控制，以及终端/文件/Python 工具），VLA/WAM 作为其中一个动作工具被调用。策略节点类型化（观测、动作、VLA 调用、判断、验证、恢复、分支、顺序、循环），可在运行前静态检查。
- **闭环执行**：每次工具调用后重新观测、更新世界程序、评估谓词。**判定结果（而非工具自身状态或模型声明）**决定继续、重观测、恢复或停止。
- **验证器（Verifier）**：返回类型化判定——PASS / FAIL / INSUFFICIENT_EVIDENCE / BLOCKED / SAFETY_STOP。验证器必须独立于提出动作的模型，防止自我确认错误。
- **形式化定义**：Harness 表示为 Ht = (Ot, Tt, Vt, Rt, Mt, Γt)，即观测接口、工具注册表、验证器、恢复算子、来源感知记忆和执行契约。完整轨迹 ξ = {z, W₀:ₜ, P₀:ₜ, O₀:ₜ, u₀:ₜ, y₀:ₜ, q₀:ₜ, M₀:ₜ} 是归因和后续更新的单元。

### 2.3 自进化框架
- **四个耦合进化目标**：Harness（工具/工作流/验证器/恢复）、数据与环境、模型与算法、具身与算力；表示与接口进化横切四者。
- **七步进化循环**：指定（冻结任务分布与协议）→ 执行（记录类型化轨迹）→ 验证（独立评估器）→ 诊断（定位瓶颈）→ 提议（有界编辑）→ 评估（回归测试/金丝雀/留出集）→ 选择与提交（或回滚）。
- **版本化工件包**：av = (Wv, Pv, Hv, Dv, Mv, Ev)，候选更新需通过改进、安全、来源和兼容性门控。
- **证据阶梯**：E0（可运行）→ E1（oracle 可完成）→ E2（可区分策略）→ E3（训练新检查点有提升）→ E4（迁移到真实机器人或分布偏移）。

### 2.4 系统实现：HexaAnything
- 由通用语言模型（或 Harness 轨迹训练的 HexaModel）编写世界与策略程序，Harness 负责运行并建立"编码-动作-状态-反馈"接口。
- 五接口分离：工具、工作流、验证器、恢复、记忆。
- 执行契约：GoalContract（原始任务文本不可变）、ObservationEnvelope（观测来源）、TrialOutcome（任务完成/停止原因/评估器身份）、ExperimentSpec（任务 ID/种子/预算）。
- 恢复采用**故障关闭（fail-closed）**：未完成或模糊状态不会被静默提升为成功。

## 3. 实验设计

### 3.1 数据集与场景
- **RoboCasa365**：三个划分——Atomic-Seen（18 任务）、Composite-Seen（16 任务）、Composite-Unseen（16 任务），每任务 50 个种子。
- **RoboDojo**：统一仿真与真机操作基准，用于工具自进化实验（Fold cloth、Pour vase、Press by number）。
- **PhyBench**（论文自建）：Isaac Sim 中的模拟实验室，三个物理实验——胡克定律测弹簧刚度、单摆测重力加速度、耦合振子测简正模频率。
- **AgileX PiPER-X 双臂真机平台**：两个 6-DoF 臂、四个 RealSense D435 相机，7 个桌面任务。

### 3.2 对比方法
- **XR-1（native）**：RoboCasa365 上的 SOTA VLA，不使用 Harness。
- **Codex**：通用编码智能体，同一 GPT-5.6-Sol 驱动。
- **HexaAnything**：分别由 GPT-5.6-Sol、Qwen3.8-27B、HexaModel v0.1 驱动。
- **PhyBench 对比**：GPT-6-Astra、Opus 5.5、GPT-5.6-Sol、Qwen3.8-Max。
- **真机对比**：GPT-Policy、Robocurve 的已发表结果（不同硬件，非同一机器人测量）。

### 3.3 主要实验组
1. **Harness 效果（固定动作模型）**：RoboCasa365 三划分 + 三个 Composite-Unseen 任务各 100 种子。
2. **模型进化**：HexaModel v0.1 在相同 Harness 中对比基座模型。
3. **工具进化**：RoboDojo 三任务两轮修订 + Fold cloth 七版本开发记录。
4. **科学实验**：PhyBench 三任务 × 四模型 × 10 次试验。
5. **真机迁移**：7 个桌面任务 × 3 次试验。

## 5. 实验数量与充分性

### 5.1 实验规模
- RoboCasa365：3 划分 × 50 种子 × 4 种规划器配置；3 个长时程任务 × 100 种子。
- RoboDojo：3 任务 × 3 轮修订；Fold cloth 7 个工具版本 × 5 种子。
- PhyBench：3 任务 × 4 模型 × 10 次试验 = 120 次。
- 真机：7 任务 × 3 次试验 = 21 次。

### 5.2 充分性与公平性评估
- **优点**：所有条件在相同任务和随机种子下评估；Harness 效果实验固定动作模型（XR-1），归因清晰；工具进化实验固定任务定义和评估器，仅改工具代码；Fold cloth 最终版本在**无特权信息**条件下重新评估（3/5 开发种子、4/5 留出种子）。
- **不足**：
  - Harness 效果仅用**一个动作模型（XR-1）**、一个基准验证。
  - HexaAnything 相对 Codex 的整体优势仅 1.6 个百分点，且 Codex 在 Atomic-Seen 上领先。
  - 长时程证据仅来自 RoboCasa365 内置复合任务；论文自设计的更长任务**尚未评估**。
  - RoboDojo 工具进化种子数少（Fold cloth 仅 5 个）；Fold cloth 中操作员为每次调用选择像素，测量的是工具与接口而非自主感知。
  - PhyBench 每模型每任务仅 10 次试验；真机每任务仅 3 次试验。
  - 真机对比参考来自**不同硬件**，非同一机器人测量。
  - 论文自述"证据是初步的（preliminary）"。

## 6. 主要结论与发现

- **Harness 效果**：固定 XR-1 动作模型，HexaAnything 将 Composite-Unseen 从 34.3% 提升至 38.3%（+4.0），Composite-Seen 从 54.8% 至 61.5%（+6.7），整体从 56.6% 至 61.1%。三个长时程任务分别提升 31.0、15.0、17.0 个百分点。
- **模型进化**：HexaModel v0.1 在**所有划分**上优于基座 Qwen3.8-27B（Atomic-Seen 80.8→81.0，Composite-Seen 61.0→62.3，Composite-Unseen 37.3→39.5，整体 60.5→61.7），且在 Composite-Unseen 上超过 GPT-5.6-Sol（39.5% vs 38.3%）。
- **工具进化**：RoboDojo 三任务成功率从 0%/40%/0% 提升至 80%/100%/100%；改进**非单调**（Pour vase 第一轮降至 0%，第二轮升至 100%）。
- **科学实验**：三个前沿模型在 PhyBench 上端到端完成全部实验，平均相对误差均低于 5%；Opus 5.5 在胡克定律（1.3%）和单摆（1.0%）最准，GPT-6-Astra 在耦合振子（0.8%）最准。
- **真机迁移**：7 个任务中 5 个三次全部成功；在可比已发表结果中，井字棋快 2.7×、拧瓶盖快 3.5×、放积木快 2.4× 且 token 少 4.7×。
- **总体判断**：提供了 Harness、工具、数据到模型三个层面的**初步自进化证据**，但完整的模型-表示-环境-具身协同进化仍是未来工作。

## 7. 优点

- **问题诊断深刻**：通过指令遮蔽实验（92.3% vs 96.2%）量化了 VLA 对指令的不敏感性，将问题从"动作预测"重新定位为"表示可检查性"，视角新颖且论证扎实。
- **方法论统一优雅**：Code as World 与 Code as Policy 共享同一可执行媒介，使状态、动作、反馈、改进四者统一，验证器可独立检查，失败可局部化归因。
- **验证器中心设计**：类型化判定（PASS/FAIL/INSUFFICIENT_EVIDENCE/BLOCKED/SAFETY_STOP）+ 来源追踪 + 故障关闭 + 回滚机制，有效防止模型自我确认错误和评估器-策略共适应。
- **归因严谨**：通过固定动作模型、固定任务与评估器、版本化父本、留出集、无特权信息重评估等设计，将 Harness 增益与模型增益分离。
- **跨域验证**：从操作任务（RoboCasa365/RoboDojo）到科学实验（PhyBench）再到真机（AgileX），展示了接口的通用性。
- **诚实的局限性陈述**：论文明确列出证据的初步性、种子数少、参考结果来自不同硬件等问题，学术诚信度高。
- **自进化路线图清晰**：四目标 + 七步循环 + 证据阶梯（E0–E4）为后续研究提供了可操作框架。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量、训练时长，难以评估成本与可复现性。
- **实验覆盖有限**：
  - Harness 效果仅一个动作模型、一个基准。
  - 长时程任务（论文自设计的 10,000 步任务）**设计但未评估**。
  - PhyBench 仅仿真，每模型每任务 10 次；真机每任务仅 3 次。
- **偏差风险**：
  - Fold cloth 中操作员选择像素，测量的是工具与接口而非自主感知；操作员曾阅读评估器源码。
  - 真机对比参考来自不同硬件与操作限制，非严格同条件比较。
  - HexaAnything 相对 Codex 优势仅 1.6 点，且 Codex 在 Atomic-Seen 领先，Harness 增益的稳健性存疑。
- **应用限制**：
  - 未建立自主架构搜索、无限制自改写或非约束物理环境部署。
  - 模型与验证器共适应、从稀疏轨迹学习物理因果、终身记忆隐私、专家修正与仿真/真机失败混合优化等问题仍开放。
  - 部署需安全测试（不安全动作、破坏性命令、提示注入、秘密泄露）。
- **方法论局限**：
  - 验证器在仿真中依赖基准自带成功检查，真机依赖操作员判断，独立性程度不一。
  - 工具进化改进非单调，缺乏收敛性保证。
  - 四目标协同进化仅提出框架，未实证。
