## 摘要
由大语言模型构建的多智能体系统（MAS）通过协调专用智能体来处理复杂任务，但有效的工作流难以预先设计。测试时演化利用执行反馈来改进工作流，然而大幅修改可能破坏有用的组件，而重新执行未改变的请求又会带来冗余计算。受生物演化中遗传与选择相互作用的启发，我们提出了 Inherit-MAS，在工作流和执行两个层面显式地实现继承。一个元模型首先合成由工作智能体组成的工作流，并声明其角色、通信输入和工具权限，随后由一个单独提示的评判器对每个已执行的候选方案进行评分并诊断其缺陷。在普通改进轮次中，\emph{工作流继承}从最新完成的候选方案开始，可以丢弃被判定为无用的可移除节点，并应用经过验证的编辑来解决所诊断出的缺陷。当新候选方案执行时，\emph{执行继承}仅在完整解析后的请求与执行上下文匹配时，才继承符合条件的已存储结果，从而避免冗余的模型和工具调用。在使用 GPT-4o-mini 作为工作智能体时，Inherit-MAS 在 WorkBench 上达到 55.4\% 的完成率，在 HotpotQA FullWiki 上达到 49.7\% 的联合 F1，优于 EvoAgent、EvoMAS 和 TacoMAS。在使用 Qwen3-32B 作为工作智能体时，它在两个基准上也超过了这些演化式 MAS 基线。与禁用执行继承、重新运行相同控制器相比，执行继承在 WorkBench 上将工作智能体 token 使用量减少了 29.1\%，在 HotpotQA 上减少了 34.6\%，并将总 token 使用量分别减少了 5.3\% 和 18.1\%。

## Abstract
Multi-agent systems (MAS) built from large language models coordinate specialized agents to tackle complex tasks, but effective workflows are difficult to design in advance. Test-time evolution refines workflows using execution feedback, yet broad revisions can disturb useful components, while re-executing unchanged requests can incur redundant computation. Inspired by the interplay of inheritance and selection in biological evolution, we introduce Inherit-MAS, which makes inheritance explicit at the workflow and execution levels. A meta-model first synthesizes a workflow of worker agents with declared roles, communication inputs, and tool permissions, and a separately prompted judge scores each executed candidate and diagnoses its deficiencies. In ordinary refinement rounds, \emph{workflow inheritance} starts from the latest completed candidate, may discard removable nodes judged unhelpful, and applies a validated edit to address the diagnosed deficiency. When the new candidate executes, \emph{execution inheritance} inherits eligible stored results only if the complete resolved request and execution context match, avoiding redundant model and tool calls. With GPT-4o-mini workers, Inherit-MAS achieves 55.4\% completion on WorkBench and 49.7\% joint F1 on HotpotQA FullWiki, outperforming EvoAgent, EvoMAS, and TacoMAS. With Qwen3-32B workers, it also exceeds these evolving-MAS baselines on both benchmarks. Compared with rerunning the same controller with execution inheritance disabled, execution inheritance reduces worker-token usage by 29.1\% on WorkBench and 34.6\% on HotpotQA, and total token usage by 5.3\% and 18.1\%.

## 1. 核心问题与整体含义

- **研究背景**：基于大语言模型（LLM）的多智能体系统（MAS）通过协调角色专用智能体来处理复杂任务，但有效的工作流（角色分配、工具权限、信息流、验证机制）难以预先设计。初始执行往往暴露出证据收集、工具使用或协调方面的弱点。
- **核心问题**：测试时演化（test-time evolution）虽可利用执行反馈改进工作流，但存在两个关键矛盾：
  - **大幅修改会破坏已有有用组件**：例如改变检索策略可能同时扰动已经有效的整合步骤。
  - **重新执行未改变的请求造成冗余计算**：保留某智能体的配置并不保证其先前结果仍然适用，因为修订可能改变其接收的信息。
- **整体含义**：论文受生物演化中"遗传（inheritance）与选择（selection）"相互作用的启发，提出 **Inherit-MAS**，在工作流层面和执行层面显式引入继承机制，使测试时演化既能利用执行反馈累积改进，又能控制推理成本。
- **核心研究问题**：如何让 MAS 利用执行反馈提升任务表现，同时控制测试时演化的推理成本？

## 2. 方法论

### 核心思想
- 将测试时 MAS 演化形式化为**显式的工作流继承**：每个新候选从最新完成的候选（incumbent）出发，保留被节点级评判判定为有用的节点，并通过**一次经过验证的编辑**针对诊断出的缺陷进行修改。
- 引入**保守的变更定位**与**请求验证的执行继承**，使符合条件的模型与只读工具结果能在相关候选间直接复用，而不改变被评估的候选本身。

### 关键技术细节

**（1）问题形式化**
- 工作流表示为有向无环图 $G=(V,E)$，节点 $v$ 具有角色、提示、工具集、解码配置及声明的输入输出。
- 执行 $G$ 产生输出 $y$、可观测轨迹 $\tau$ 和成本账本 $c$；任务表现由效用函数 $U$ 衡量。
- 在 $K$ 个候选尝试预算内搜索，$k^*$ 为最终选中候选索引。

**（2）初始合成与评判**
- 元模型合成初始工作流 $G_0 = S(x, I)$，其中 $x$ 为任务，$I$ 为接口（允许的角色、工具、输入输出格式、执行环境）。
- 单独提示的评判器 $J$ 返回四维评分 $q_k = (q^{cmp}_k, q^{cov}_k, q^{grd}_k, q^{all}_k)$（完成可能性、需求覆盖、工件接地、整体质量）及文本批评 $\gamma_k$（含 keep/fix 建议）。

**（3）工作流继承（Workflow Inheritance）**
- **Select（选择）**：从最新完成候选 $G_{p(k)}$ 出发，节点选择器 $P_{sel}$ 提出丢弃集 $\Delta^-_k$，仅当反馈或记录输出表明该节点无贡献或有害时才丢弃。丢弃集必须满足 $\Delta^-_k \subseteq R(G_{p(k)})$（可单独移除且保持有效的节点集）且剪枝后工作流有效。
- **Edit（编辑）**：在保留工作流 $G'_k$ 上应用**一次**经过验证的编辑 $a_k$，编辑从有限菜单中选取（提示替换、子任务替换、工具增删、节点增删、边增删、输入重排、节点插入等），编辑后必须通过确定性验证器（无环、输入输出兼容、工具授权等）。
- 编辑仅改变所选编辑声明范围内的字段，保留其余工作流不变。

**（4）执行继承（Execution Inheritance）**
- **变更定位**：比较 $G_k$ 与 $G_{p(k)}$，计算受影响区域 $D_k = \Delta_k \cup Desc_{G_k}(\Delta_k)$，其中 $\Delta_k$ 包含所有新节点及局部规格、入线顺序或有效执行设置发生变化的保留节点。
- **请求验证**：节点 $v$ 的解析请求 $r_{k,v}$ 包含当前规格、有序上游记录和执行上下文指纹 $\phi_k$；查找键为 $\kappa_{k,v} = h(r_{k,v})$（SHA-256 规范化序列化）。
- **继承条件**：$z_{k,v} = 1\{Eligible(v, e_k) \wedge ValidRecord(M, \kappa_{k,v}) = 1\}$，即节点符合条件且存在通过完整性验证的匹配记录。
- **资格限制**：无状态改变工具的语言模型节点和确定性只读操作可继承；状态改变操作永不继承。有状态任务中每个候选从相同初始环境的全新副本开始，仅指定 sink 节点执行状态改变动作。
- 继承命中不消耗实时 worker token，原始用量单独记录为"继承 token 等价量"。

**（5）排序与返回**
- 排序键 $s_k = (-b_k, \mathbb{1}\{y_k \text{ valid}\}, q^{all}_k, q^{cov}_k, q^{grd}_k, -k)$，优先最小化硬执行失败，其次偏好有效输出，再按质量、覆盖、接地排序，最后偏好较早候选。
- 预算耗尽后返回最高排名已完成候选的输出，不重新执行工作流。

## 6. 主要结论与发现

- **性能优势**：Inherit-MAS 在两个基准、两种骨干下均超越所有演化式 MAS 基线。
  - GPT-4o-mini：WorkBench 完成率 55.4%（比 Single ReAct 高 13.8 点，比最佳基线 TacoMAS 高 20.8 点）；HotpotQA 联合 F1 49.7%（比 Single ReAct 高 3.7 点，比 TacoMAS 高 1.9 点）。
  - Qwen3-32B：WorkBench 46.2%（与 Single ReAct 持平，比最佳基线高 11.5 点）；HotpotQA 联合 F1 42.7%（比 Single ReAct 高 5.6 点，比 TacoMAS 高 2.8 点）。
- **唯一匹配或超越 Single ReAct 的演化式 MAS**：在全部四个基准-骨干设置中。
- **逐轮改进**：WorkBench 每轮累计提升 9.2 点（首轮贡献 6.9 点），HotpotQA 提升 5.0 点。
- **执行继承显著降低 token**：相比禁用继承的独立重跑，worker token 减少 29.1%（WorkBench）和 34.6%（HotpotQA），总 token 减少 5.3% 和 18.1%。
- **成本优势**：Inherit-MAS 总 token 用量远低于 EvoMAS（WorkBench 1/16.8，HotpotQA 1/13.7）和 TacoMAS（WorkBench 1/22.9，HotpotQA 1/2.1）。
- **演化非单调**：候选性能并非逐轮递增，在线排序对最终性能至关重要（WorkBench 排序返回 55.4% vs 最后候选 50.0%）。
- **局部性不等于编辑质量**：局部编辑提供成本杠杆（token 加权继承率 57.5%/81.8%），但质量提升与局部性不直接相关。

## 7. 优点

- **方法创新性**：
  - 将生物演化中"遗传与选择"的类比形式化为工作流继承和执行继承两个显式机制，概念清晰且具理论美感。
  - 执行继承采用**完整解析请求 + 执行上下文指纹**的精确匹配，而非模糊缓存，保证结果可复现性。
  - 变更定位（受影响区域计算）与请求验证分离，既保证保守性又允许受影响区域内请求重收敛时的继承命中。
- **工程严谨性**：
  - 编辑菜单有限且经过确定性验证器检查，保证结构有效性。
  - 状态改变操作永不继承，有状态任务使用全新环境副本 + 单一 sink 执行写入，设计安全。
  - 继承记录有完整性验证（格式、请求键、内容哈希），不一致记录导致阻塞错误而非静默未命中。
- **实验设计亮点**：
  - 执行继承消融采用**独立重跑**而非简单关闭标志，避免轨迹依赖偏差。
  - 在确定性运行时（Qwen3-14B + LiveCodeBench）验证三种执行条件产生字节相同输出，为继承等价性提供证据。
  - 报告配对差异和胜负平计数，而非仅报告均值。
  - 明确区分"继承 token 等价量"与"实时 provider token"，避免成本虚报。
- **成本效益**：在提升性能的同时大幅降低 token 消耗，具有实际部署价值。
