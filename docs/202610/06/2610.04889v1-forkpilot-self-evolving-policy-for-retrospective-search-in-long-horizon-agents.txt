Abstract 

Interactive language-model agents increasingly solve complex tasks through long-horizon, multi-call reasoning, where errors in beliefs or actions can compound across tool interactions. Retrospective search can recover from such failures but is prone to misallocation. Delayed outcomes obscure the contribution of intermediate search decisions, leading to Attribution Complexity , while evolving execution evidence leads to Adaptation Complexity , where previously learned estimates become stale. To address these challenges, we first introduce Search Value Dynamics (SVD), which characterizes the evolving trade-off between the gain and cost of retrospective search. Building on SVD, we propose F ORK PILOT , a self-evolving two-stage policy-learning framework. In the first stage, F ORK PILOT learns a search-value policy offline from completed trajectories through automatically constructed outcome comparisons. In the second stage, it makes search decisions on the current observations and then self-evolves, incorporating newly completed trajectories into subsequent policy updates. We evaluate F ORK PILOT across 6 diverse benchmarks and 7 widely used LLM backbone families, including four open-source families, GPT-5.6 Sol and Opus 4.8 in a production agentic system, against 9 competitive baselines, including real-world harness deployment used by hundreds of thousands of paid users. F ORK PILOT achieves comparable state-of-the-art performance while reducing token usage by up to 59.2%, demonstrating its efficacy. 

# 1 Introduction 

Interactive language-model agents solve long-horizon tasks through tool calls, acting on evolving observations that only partially reveal the environment state (Liu et al., 2024; Zhou et al., 2024b). Failures can stem from incorrect beliefs about this state or poor actions despite accurate beliefs (Tang et al., 2026; Djuhera et al., 2026). Prior work has studied information gathering through tool use (Yao et al., 2023b), reflection on task feedback (Shinn et al., 2023), and correction with external verification (Gou et al., 2024). Retrospective test-time search examines failed or partially successful trajectories alongside grader or verifier feedback (Zhou et al., 2024a; Yu et al., 2025). Actions and observations in the trajectory, together with feedback on task completion, help the agent revisit beliefs and decisions, seek further observations, and explore alternatives. When earlier states can be restored, search can fork from a state, preserving the valid action prefix while trying another continuation (Koh et al., 2024). In Figure 1(a), an archive access failure prompts the agent to review its trajectory and inspect key bindings. Finding that the archive still uses the old key, the agent forks from an earlier state to migrate the archive and verify the bindings before disabling the old key.

Searching before enough evidence accumulates may waste forks (Holt et al., 2026), while waiting too long leaves less budget to recover. Even an improving fork does not establish that further search on the same trajectory is worth its cost (Snell et al., 2025). Its effects may emerge only after later tool calls, making its contribution difficult to separate from subsequent actions (Feng et al., 2025). New observations can reveal recovery actions or make further search unpromising, requiring repeated decisions about when to retrospect, which trajectory to explore, and how much to search (Yao et al., 2023b; Zhou et al., 2024a). Existing work addresses computation allocation through input-adaptive budgets, confidence-based stop-ping, and complexity-based token allocation (Damani et al., 2025; Fu et al., 2025; Lin et al., 2025), while learned planning policies decide when to deliberate during interaction (Paglieri et al., 2025). Complemen-tarily, experience-based methods such as Reflexion (Shinn et al., 2023), ReasoningBank (Ouyang et al., 2026), and ACE (Zhang et al., 2026) leverage previous trajectories and feedback to improve reasoning and guide exploration through evolving reflections, memory, and context. However, retrospective search in long-horizon, multi-call reasoning requires more than adjusting reasoning budgets or improving action selection through accumulated experience. Delayed, entangled outcomes obscure the incremental benefit of additional search and whether it justifies its computational cost, creating Attribution Complexity , while evolving tool observations and changes in the environment can render previously learned search-value estimates stale, creating Adaptation Complexity . These challenges motivate two research questions: Q1: How can we theoretically understand the value of retrospective search under delayed rewards and evolving observations in long-horizon, multi-turn tool interaction? Q2: Can models self-evolve through accumulated experience to dynamically allocate inference resources, balancing effectiveness and efficiency? 

To answer these questions, we first introduce Search Value Dynamics (SVD), which characterizes the evolving trade-off between the gain and cost of retrospective search. Building on SVD, we propose 

FORK PILOT , a self-evolving two-stage policy-learning framework. F ORK PILOT can bootstrap its search-value policy from completed trajectories using automatically constructed outcome comparisons. During 2deployment, it cit makes search decisions on the current observations and then self-evolves, incorporating newly completed trajectories into subsequent policy updates. This self-evolving refinement provides a mechanism for adapting search allocation to live real-world environments that evolve independently of the agent’s actions. We evaluate F ORK PILOT across 6 diverse benchmarks and 7 widely used LLM backbone families. We also deploy F ORK PILOT in a production agentic system, where the agent uses GPT-5.6 Sol and Claude Opus 4.8 served through production inference platforms employing state-of-the-art caching. We compare against 9 competitive baselines, including a real-world harness deployment used by hundreds of thousands of paid users. Across all experiments, F ORK PILOT achieves comparable state-of-the-art performance while reducing token usage by up to 59.2%, demonstrating its efficacy. As shown in Figure 1(b), F ORK PILOT lies on the empirical quality-token Pareto frontier across benchmarks and backbones.

FORK PILOT implements these requirements in two stages. Stage I learns search effects and their reliability from paired completed trajectories, which may be collected both during an offline initialization phase and from tasks subsequently completed during deployment. These paired replays follow the same reference rule 

ρ and form a source pool Dn. As additional deployment tasks are completed, newly available trajectory pairs extend Dn to Dn′ , where n′ > n , and Stage I refits the controller parameters θn′ on the expanded pool before a subsequent evaluation stage. Stage II operates within each evaluated task: the fitted controller parameters remain fixed, while search allocations are repeatedly recomputed as new trajectory evidence becomes available. Thus, Stage I enables the policy to evolve across completed tasks, whereas Stage II adapts its search decisions within a task without online parameter updates.

# 4 Experiments 

We comprehensively evaluate F ORK PILOT against 9 competitive baselines across 6 diverse benchmarks on 7 backbone families. Our experiments answer the following four questions: Q1: Does FORK PILOT consistently achieve efficiency across diverse benchmarks? Q2: Does FORK PILOT consistently consistently achieve efficiency across different backbone model scales? Q3: Does FORK PILOT retain its efficiency gains on frontier black-box models? Q4: Does FORK PILOT require privileged feedback or large bootstrap samples?

# 5 Related Work 

Retrospective Search and Adaptive Computation. Retrospective search improves reasoning by revisiting earlier decisions and exploring alternative trajectories. Tree of Thoughts (Yao et al., 2023a), Language 10 Agent Tree Search (Zhou et al., 2024a), and ExACT (Yu et al., 2025) instantiate this idea for reasoning and interactive agents. More broadly, metareasoning and resource-rational planning study which computations are worth performing under limited resources (Russell and Wefald, 1991; Hay et al., 2012; Callaway et al., 2018). Recent LLM methods further adapt test-time computation according to query difficulty, intermediate confidence, or subproblem complexity, including compute-optimal scaling (Snell et al., 2025), input-adaptive allocation (Damani et al., 2025), Certaindex (Fu et al., 2025), Learning When to Plan (Paglieri et al., 2025), and Plan-and-Budget (Lin et al., 2025). 

Learning to Control Search. A complementary line of work learns from completed interactions to improve future reasoning. Reflexion (Shinn et al., 2023), ReasoningBank (Ouyang et al., 2026), ACE (Zhang et al., 2026), GEPA (Agrawal et al., 2026), and Trace2Skill (Ni et al., 2026) use prior trajectories to construct reflections, memories, optimized context, or reusable skills. These methods primarily improve what information is available to the agent rather than learning how much retrospective computation should be allocated during execution. 

# 6 Conclusion 

Long-horizon, multi-call reasoning makes retrospective search a dynamic computation-allocation problem: delayed outcomes obscure the contribution of intermediate search decisions, while evolving execution evidence can make previously learned estimates stale. We characterize these challenges as Attribution Complexity and Adaptation Complexity , and introduce Search Value Dynamics (SVD) to characterize the evolving trade-off between the gain and cost of retrospective search. Building on SVD, we propose FORK PILOT , a self-evolving two-stage policy-learning framework. F ORK PILOT first learns a search-value policy offline from completed trajectories, then, in the second stage, makes search decisions on the current observations and then self-evolves, incorporating newly completed trajectories into subsequent policy updates. 21 B.5 Online updates and censoring 

A task can enter the next fitting block only after all required downstream outcomes are complete. Online replay calls are logged as learning cost. A retained full-budget source panel preserves recovery opportunities that an adaptive policy might otherwise stop observing. No-future-improvement labels from truncated executions are censored rather than treated as zero search value. Task roles for predictor fitting, margin fitting, and residual calibration remain disjoint and stable as the source prefix grows. The encoder, heads, normalization, support index, and margin are versioned and frozen as one artifact before held-out evaluation. Within a task, changing tool observations refresh the controller input and decision scores, but do not update these fitted parameters. Across completed source tasks, a later artifact may be fitted and deployed to a subsequent block. Inner source validation can select update hyperparameters; the outer test panel cannot determine whether an update is deployed. At cold start, none of these fitted artifacts or statistics is available, so the system uses the host fallback until fitting and calibration become possible. 

B.6 Baseline definitions 

RTS and RDS. Full Retrospective Tree Search (RTS) uses the common retrospective-search host with a configuration selected on source validation to favor task score. Its three beams retain alternative continuations from earlier resumable states for exploration. The common scorer prioritizes promising branches for further expansion, providing exploitation within the search. At each eligible state, RTS executes the complete selected rollout allocation, subject to the hard host cap shared by all search-control methods. Retrospective Depth Search (RDS) reviews one initial rollout and continues only from its final resumable node. It does not fork from earlier states. RDS therefore tests how much additional depth along a single trajectory can achieve without exploring alternative retrospective branches. The eight comparators in the seven-backbone matrix are BoN-5, RTS, RDS, ACE, ReasoningBank, Reflexion, GEPA, and Trace2Skill. BoN-5 samples five complete candidates and selects by the common scorer. ACE, ReasoningBank, Reflexion, GEPA, and Trace2Skill use their declared context, memory, or prompt intervention while sharing the evaluation harness and token accounting. Scores increase from 69.00 to 75.00 and from 64.43 to 64.95. Thus, deferring trajectory launches offers further savings beyond the default parallel configuration. Latency is not measured here; the potential delay from successive attempts remains unquantified. 

FORK PILOT retains uncached-token savings under both host schedules. Against schedule-matched RTS, F ORK PILOT reduces uncached tokens by 44.4%/59.2% under parallel execution and 36.5%/64.1% under sequential execution on AutomationBench/ τ 3-Bench. Under the sequential schedule, raw-token usage is nearly identical to RTS on AutomationBench and 34.8% lower on τ 3-Bench, with respective score differences of −2.00 and −4.64 points. These operating points show that F ORK PILOT ’s uncached-token efficiency benefit is not restricted to three-way parallel rollout, although the quality–cost trade-off varies with the host schedule.

# D Self-evolving and Stopping Protocols 

D.1 True cold start and nested source-size curves 

Each of five Q2 source orders is drawn independently of task outcomes and shared across training regimes; three controller seeds are fit per order. Nested prefixes contain 0, 100, 200, 300, and 400 completed source tasks per outer fold. At zero, there are no trained weights, calibration residuals, source normalizers, or experience-memory entries. Every request is handled by the host fallback under the predeclared deployment cap. A hand-initialized predictor with previously calibrated thresholds would instead constitute a warm start and is excluded from the cold-start condition. The Q2 deployment cap is held fixed across all source sizes and regimes within a backbone and uses the same host reservation rule as Q1. The full-source batch endpoint is therefore directly aligned with the corresponding Q1 F ORK PILOT operating point rather than being evaluated under a second, undocumented cap. Training and replay budgets are logged separately from deployment cost. For batch fitting , the predictor is initialized afresh at each nonzero N and fitted on that prefix’s fitting tasks, with its margin and residual correction trained only on their assigned roles. For online updates , the first nonzero artifact is fitted after the first completed block; subsequent artifacts warm-start from the preceding version and update on the expanded prefix, including retained fitting tasks. Recalibration uses all eligible completed tasks in the fixed margin and calibration roles. The source self-evolving policy used for paired targets remains the same frozen host across regimes, so different target definitions do not explain a curve difference. Any paired replay evidence exposed to one learned regime is also available to the other at the correspond-ing source-size state. The comparison therefore isolates incremental fitting under an expanding source pool with matched evidence availability. Each artifact is frozen before the common held-out panel is evaluated. Held-out tasks and their feedback never enter updates, and the state schedule does not depend on their scores. The frozen cold-start control retains its initial fallback without updates.

D.3 Manual and learned stopping under the same action scope 

The manual rule skips the current retrospective round when the permitted incumbent score qt ∈ [0 , 1] reaches 

ρ. Otherwise it permits the host’s fixed fork and depth configuration, subject to the common resource interface. It does not terminate the underlying task or remove future reconsideration opportunities. The primary settings are ρ ∈ { 0.6, 0.8, 0.9, 1.0}. A stronger manual control selects ρ from {0.50 , 0.55 , . . . , 1.00 } on inner source validation using the same quality-cost objective. The displayed selected values are 0.85 for Qwen3.5-9B and 0.75 for Qwen3.5-27B; held-out outcomes cannot choose them. The learned-stopping-only policy is the singleton-action special case of Eqs. 1-4: Ft = {ufix } and 

Pt = ∅. It therefore executes the common fixed action if and only if Lt(ufix ) > 0 and otherwise skips the round. It cannot change fork count or depth and has no probe action. All self-evolving policies use identical host generation, permitted feedback, and restoration rules. Source-only resource-cap selection targets the common cost range while leaving the fixed fork/depth setting unchanged. Thresholds that cannot attain the target range remain identified as unmatched. The primary contrast is learned-stopping-only versus the source-selected manual control at matched cost. Full F ORK PILOT adds the action-conditioned fork/depth menu and bounded probing; its additional score difference measures those allocation changes jointly. Access to history is permitted for every arm, while the scalar manual policy intentionally uses only the incumbent score. The dense validation-selected threshold is the primary hand-designed stopping control. 

D.4 Same-host mechanism controls 

The current-score learned controller is a two-layer gain-cost MLP trained on the same paired records and invoked at every opportunity, but its state contains only incumbent score, remaining budget, action descriptor, and feasibility mask. The one-shot learned controller uses the full prefix at the first retrospective opportunity and holds that allocation for the remainder of the task. The frozen-prefix controller recomputes feasibility and remaining budget but reuses the first recurrent representation. The no-margin controller uses the full refreshed representation and action menu with bBt(u) = 0 . All variants use the same source-role assignments, optimization budget, candidate actions, self-evolving protocol, and outer test tasks. Action frequencies in Table 15 are measured at the common retrospective opportunities before fallback filtering. For Table 16, a state-changing event class is assigned without reading downstream paired outcomes. The hindsight action is the feasible action with greatest realized paired net target under protocol Γ, with skip assigned zero. “Sign flip” records a change in the sign of the best non-skip paired target from the state immediately before to the state immediately after the event. This analysis tests whether new evidence changes the allocation target; it does not claim that hindsight actions are available online.
