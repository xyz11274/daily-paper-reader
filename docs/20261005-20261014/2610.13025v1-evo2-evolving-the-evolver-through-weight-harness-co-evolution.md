## 摘要
自演化智能体越来越多地被用于在无需人工干预的情况下改进语言模型系统，其方式要么是更新权重，要么是改进框架。现有方法通常分别追求这些方向：一些方法利用自生成经验更新模型权重，而另一些方法则重写定义智能体如何使用提示、工具、上下文和执行反馈的框架。然而，这些方法忽视了模型权重与智能体框架之间的关系。为了连接这些过程并确保智能体有效且平滑地自演化，我们提出了 Evo$^2$，一个用于权重-框架协同演化的框架。对于框架更新，我们设计了一个统一的双角色流水线，其中单一策略同时充当 Proposer（撰写框架编辑）和 Reflector（诊断其效果并指导修订）。对于权重更新，框架修改及其执行结果指导 Proposer 和 Reflector 的训练。我们进一步开发了 EvoTIDE，一种训练流水线，通过编辑提取和前缀延续恢复可用轨迹，然后结合 SFT 与跨两个角色的交错 GRPO。在三个编码基准上的大量实验表明，Evo$^2$ 显著优于现有的自演化方法。它在 Polyglot 上达到 82.1%，在 SWE-bench Verified 上达到 48.3%，而最强基线分别为 62.6% 和 41.0%。我们还表明，演化后的框架无需进一步演化即可迁移到不同任务，并在跨基准评估中排名第一。我们的双角色框架改进框架也能够扩展到使用专有模型的自演化，将 GPT-5-mini 智能体的性能从 24.4% 提升到 48.3%。这些结果证明了框架 Evo$^2$ 跨领域的适用性及其跨模型和任务的广泛可迁移性。

## Abstract
Self-evolving agents are increasingly used to improve language model systems without human intervention through either weight updates or harness improvements. Existing approaches typically pursue these directions separately: some methods update model weights using self-generated experience, while others rewrite the harness that defines how an agent uses prompts, tools, context, and execution feedback. However, these approaches overlook the relationship between model weights and the agent harness. To connect these processes and ensure effective and smooth agent self-evolving, we propose Evo$^2$, a framework for weight-harness co-evolution. For harness updates, we design a unified dual-role pipeline that a single policy serves as both a Proposer, which writes harness edits, and a Reflector, which diagnoses their effects and guides revision. For weight updates, harness modifications and their execution outcomes guide the training of both the Proposer and the Reflector. We further develop EvoTIDE, a training pipeline that recovers usable trajectories through edit extraction and prefix continuation, then combines SFT with interleaved GRPO across the two roles. Extensive experiments across three coding benchmarks demonstrate that Evo$^2$ significantly outperforms existing self-evolution methods. It achieves 82.1% on Polyglot and 48.3% on SWE-bench Verified, compared with 62.6% and 41.0% for the strongest baseline, respectively. We also show that the evolved harnesses transfer to different tasks without further evolution and rank first in cross-benchmark evaluations. Our dual-role harness improvement framework is also able to extend to self-evolution with proprietary models, improving a GPT-5-mini agent's performance from 24.4% to 48.3%. These results demonstrate the applicability of the framework Evo$^2$ across domains and its broad transferability across models and tasks.

## 1. 核心问题与整体含义

- **研究背景**：自演化智能体（self-evolving agents）旨在无需人工干预的情况下持续改进语言模型系统，当前主要有两条技术路线：
  - **权重更新路线**：模型生成解，利用任务反馈筛选有用输出并训练自身（如 STaR、ReST^EM、Absolute Zero 等）。
  - **Harness 改进路线**：模型检查并重写定义智能体如何使用提示、工具、上下文和执行反馈的程序（如 SICA、DGM、HGM、GEPA 等）。
- **核心问题**：这两条路线通常被**分开追求**，忽略了模型权重与智能体 harness 之间的内在关联：
  - 模型能力决定了它能提出什么样的修改、如何解读执行反馈；
  - 每次被评估的修改又揭示了哪些改动有效、为何失败、不同改进如何交互——这些经验本可反过来指导模型训练。
- **整体含义**：论文提出 **Evo²**，将 harness 演化与权重训练连接为**协同演化**闭环——更好的 evolver 构建更好的 harness，更好的 harness 又为训练更好的 evolver 提供经验，从而让经验同时积累在**可执行程序**和**模型参数**中。

## 2. 方法论

### 2.1 核心思想
- 单一策略 π_θ 同时充当 **Proposer**（撰写 harness 编辑）与 **Reflector**（诊断效果并指导修订），二者共享参数。
- Harness 演化采用**树搜索**组织，引入 **crossover searching** 跨分支迁移有用策略。
- 权重演化通过 **EvoTIDE** 训练管线完成，将 harness 演化过程中产生的轨迹转化为训练数据。

### 2.2 关键技术细节

**（1）双角色 Harness 演化**
- **Proposer 两种模式**：
  - *Type A*：接收父 harness h_p 及其任务表现，自主选择修改，生成编辑 e₀ 得到候选 h₀。
  - *Type B*：接收 harness 与 Reflector 的显式指令 d，将其实现为编辑 e₁，得到修订候选 h₁。
- **Reflector 三种动作**：
  - *revise*：给出改进候选的具体指令；
  - *crossover*：给出整合其他分支策略的指令；
  - *keep*：保留候选不再编辑。
- **形式化流程**（式 1）：
  - e₀ ∼ π_θ(· | P_A, h_p, z_p)，h₀ = Apply(h_p, e₀)
  - (m, d, j) ∼ π_θ(· | R, h_p, h₀, z₀, S)
  - e₁ ∼ π_θ(· | P_B, h₀, d)，h₁ = Apply(h₀, e₁)
  - 其中 P_A、P_B、R 为角色提示，S 为策略库，j 为 donor 标识（仅 crossover 使用）。

**（2）Crossover Searching**
- 维护策略库 S = {s_j}，每条记录描述机制、观察效果及是否已存在于当前候选。
- Reflector 选择能解决当前候选执行问题的 donor 策略，指令 d 指定如何整合 s_j。
- Type B Proposer 将机制适配到候选源码；crossover 子节点保留 recipient 为树父节点并记录 donor 策略。

**（3）EvoTIDE 训练管线**
- **数据收集**：记录角色提示、模型响应、应用的编辑、父子 harness、任务评估结果。
- **轨迹恢复**：
  - *Edit extraction*：从推理与对话消息中搜索具体文件编辑并转为规定动作格式；
  - *Prefix continuation*：截断到最后一次成功应用的编辑，恢复中间 harness 后从该前缀继续生成，保留有效编辑、重生成失败后缀。
- **奖励设计**（式 2）：
  - r_exec_P = V̂(h′) − V̂(h)，r_exec_R = V̂(h₁) − V̂(h₀)
  - keep 动作奖励为 0；格式错误、无法应用/启动的编辑给负奖励；no-op 编辑、不可用 harness、无效 crossover 指令均受惩罚。
  - Type B 根据是否触及指令中指定的文件给予小幅加减分；Reflector 的正收益仅在轨迹中有证据表明新增机制实际运行时才计入。
- **训练流程**：
  - *SFT 预热*：混合成功的自主编辑、定向编辑与 Reflector 响应，平衡各角色与模式。
  - *树维护与父采样*（式 3）：保留多深度节点，根节点固定采样份额 ρ，其余按权重 w(h) = ε_p + |V̂(h) − 1/2| 采样——**高分与低分父节点都获得更多曝光**，既改进强候选也修复弱候选。
  - *交错角色训练*：每轮冻结快照 π_θ̄_r 提供对手行为；Proposer 组与 Reflector 组分别计算优势，两组损失平均后单次更新；轮末刷新快照。
  - *策略优化*：GRPO，组内均值基线 A_i = r_i − (1/G)Σr_j，按固定最大响应长度 L_max 归一化，截断响应从损失中屏蔽。

## 6. 主要结论与发现

- **编码任务全面领先**：Polyglot 82.1%（最强基线 GEA 62.6%）、SWE-bench Verified 48.3%（HGM 41.0%）、LiveCodeBench 58.0%（HGM 56.0%）。
- **Harness 可迁移**：6 个迁移方向中 5 个最优，无需进一步演化即可跨 benchmark 使用，领先幅度 2.5–18 分。
- **专有模型同样受益**：GPT-5-mini 从 24.4% 提升至 48.3%（近乎翻倍），Claude Haiku 4.5 从 42.2–45.0% 提升至 47.8%——说明**双角色搜索本身即可带来改进**，无需权重更新。
- **记忆任务最优**：LoCoMo 60.4 F1（HGM 56.2），LongMemEval 71.5%（HGM 64.4）。
- **权重演化有效**：训练后的 evolver 在 Polyglot +16.3、SWE-bench +5.0、LoCoMo +9.3、LongMemEval +10.6。
- **性能提升不依赖更多推理算力**：Evo² harness 每任务 3.6K tokens、10.2 次调用，而 HGM/DGM 用 6.6K–6.9K tokens、26–37 次调用却准确率更低；Polyglot 上甚至比未演化 harness 更省（36 vs 43 次调用）。

## 7. 优点

- **概念创新**：首次将 harness 演化与权重训练统一为协同演化闭环，弥补了此前两条路线割裂的空白。
- **架构优雅**：单一策略兼任 Proposer 与 Reflector，共享参数，避免维护两套模型，训练信号直接来自编辑的实际执行效果。
- **Crossover 机制**：跨分支策略迁移让树搜索中的发现可被复用，减少重复探索，降低评估预算。
- **工程细节扎实**：edit extraction 与 prefix continuation 有效回收部分失败轨迹，提升数据利用率；parent pool 采样兼顾强弱候选，避免只优化强分支。
- **实验维度丰富**：跨 benchmark 迁移、跨模型（开源/专有）、跨领域（编码/记忆）验证，泛化性证据较充分。
- **成本意识**：明确报告推理 tokens 与调用次数，证明改进来自 harness 效率而非暴力增加算力。

## 8. 不足与局限

- **算力信息缺失**：未披露训练所用 GPU 型号、数量与时长，难以评估方法的总成本与可复现性。

  - 依赖可执行 harness 与自动评估器，对无法自动评估的开放任务适用性存疑；
  - 任务执行器需保持固定，若执行器本身变化，协同演化假设可能失效；
  - 记忆任务仅在一个数据集上演化、另一个上迁移，跨领域泛化证据仍偏薄。
