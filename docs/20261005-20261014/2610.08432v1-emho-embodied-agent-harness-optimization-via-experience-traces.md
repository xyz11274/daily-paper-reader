## 摘要
提升具身智能体通常侧重于通过训练优化底层模型，而控制规划、上下文和工具使用的周边智能体框架则通常依赖人工设计。我们探究该框架能否在稀疏环境反馈下，直接从经验轨迹中自我改进。我们提出具身智能体框架优化（EMHO），这是一个自进化框架，保持具身模型冻结，通过分析执行轨迹和先前的框架历史来迭代修订其框架。EMHO 的优化超越了技能或恢复提示，改变了智能体监控进度、使用视觉工具、将观察落地以及应对失败的方式。为了用单一框架支持多个子任务，我们引入 EMHO-Merge，它通过使用回合级收益与损失来指导基于证据的细化，决定何时以及如何应用修订后的行为，从而解决跨子任务联合优化单一共享框架时的权衡问题。我们在 EmbodiedBench 上针对导航和操作任务评估 EMHO，EMHO 在 Qwen 9B 和 27B 模型上均持续提升任务成功率。定性分析表明，EMHO 不仅从失败和无效行动中恢复，还重塑了具身智能体解释环境并与环境交互的方式。

## Abstract
Improving embodied agents often focuses on optimizing the underlying model through training, while the surrounding agent harness that controls planning, context, and tool use is typically engineered. We ask whether this harness can instead improve itself directly from experience traces under sparse environmental feedback. We propose EMbodied Agent Harness Optimization (EMHO), a self-evolving framework that keeps the embodied model frozen and iteratively revises its harness by analyzing execution trajectories and prior harness history. EMHO optimizes beyond skills or recovery prompts, modifying how the agent monitors progress, uses vision tools, grounds observations, and responds to failures. To support multiple subtasks with a single harness, we introduce EMHO-Merge, which addresses trade-offs in jointly optimizing a single shared harness across subtasks by using episode-level gains and losses to guide evidence-supported refinement of when and how revised behaviors are applied. We evaluate EMHO on EmbodiedBench across navigation and manipulation tasks, and EMHO consistently improves task success for both Qwen 9B and 27B models. Qualitative analysis shows that EMHO goes beyond recovering from failures and unproductive actions to reshape how the embodied agent interprets and interacts with its environment.

# EMHO 论文深度总结

## 1. 核心问题与研究动机

- **背景**：具身智能体的性能提升长期依赖底层视觉-语言模型（VLM）的训练优化，而围绕模型的 **harness**（框架）——即组织规划、上下文与记忆、工具选择、观察呈现和失败恢复的运行时逻辑——通常依赖人工工程。
- **核心问题**：在具身环境中，反馈往往**稀疏且诊断性弱**（仅有动作级有效性反馈和延迟的回合级成功/失败信号），能否让 harness 直接从经验轨迹中自我改进？
- **与已有工作的差异**：
  - 编码/命令行环境中的 harness 优化（如 Meta-Harness、Self-Harness）可利用失败测试、异常等明确诊断信号，具身环境不具备这一条件。
  - 已有的具身自改进工作（EmbodiSkill、VASO、ASPIRE、Zetta）仅聚焦于**特定组件**（可复用技能、恢复机制），而智能体行为由规划、上下文、工具使用、视觉落地、失败恢复等**多种交互机制**共同决定，仅更新单一组件无法解决根源问题。
- **整体含义**：论文主张将**更广泛的 harness 本身**作为优化对象，在模型冻结的前提下，通过经验轨迹实现自进化，并进一步探索单一共享 harness 跨子任务的联合优化。

## 2. 方法论

### 2.1 核心思想
- 保持具身模型 \(M\) 冻结，仅优化 harness \(H\)，目标是最大化期望任务成功率：
  \[
  H^\star = \arg\max_{H \in \mathcal{H}} \mathbb{E}_{e \sim \mathcal{D}}[y_e(M, H)]
  \]
- EMHO 采用**双循环**结构：
  - **内循环（任务求解）**：当前 harness 在搜索集上执行任务，记录经验轨迹。
  - **外循环（harness 更新）**：优化器分析轨迹与历史，提出针对性修订。

### 2.2 关键技术细节

- **内循环：经验轨迹收集**
  - 第 \(i\) 次迭代，轨迹记录为 \(T_e^{(i)} = (x_e, \{(o_t, p_t, z_t, a_t, f_t)\}_{t=1}^{T_e}, y_e)\)，分别对应观察、计划、工具交互、执行动作、环境反馈和最终结果。

- **外循环：历史感知的 harness 精炼**
  - 优化器接收当前父 harness \(H_{par}^{(i)}\)、全部经验轨迹 \(E^{(0:i)}\) 和完整 harness 历史 \(H_{hist}^{(0:i)}\)（含被拒绝的候选及其结果）。
  - 候选 harness 仅在搜索集成功率 \(s(\tilde{H}^{(i+1)}) > s(H_{par}^{(i)})\) 时才替换父代，否则保留原父代。
  - 关键设计：**被拒绝候选的经验仍可用于指导后续修订**。

- **EMHO-Merge：增益-损失感知的精炼**
  - 针对单一共享 harness 跨子任务优化时的权衡问题。
  - 将最近候选与父代对比：失败→成功的回合为**增益** \(G^{(i)}\)，成功→失败的回合为**损失** \(L^{(i)}\)。
  - 当同时存在增益和损失且修复次数未用完时（\(r^{(i)}=1\)），优化器检查配对的增益/损失轨迹，寻找可区分"何时有益、何时有害"的可观察条件，**调整行为应用的时机或方式**（而非引入全新行为），以保留增益、减少损失。
  - 每个原始修订最多允许一次修复尝试。

- **可编辑的 harness 组件**（以操作任务为例）：
  - 规划（SKILL.md、system.md、final_planner.md、agent.py、planner.py 等）
  - 视觉与工具使用（tool_orchestrator.py、vision_policy.py、tool_select.md）
  - 记忆与上下文（module_selector.py、memory.py、memory_render.md、safe_context.md）
  - 验证（parser.py、repair.py、repair.md）

## 3. 实验设计

- **Benchmark**：EmbodiedBench，覆盖**导航（Navigation）**和**操作（Manipulation）**两大类任务。
  - 导航子任务：Base、Common Sense、Complex Instruction、Visual Appearance、Long Horizon。
  - 操作子任务：Base、Common Sense、Complex Instruction、Visual Appearance、Spatial Relationship。
- **底层模型**：Qwen3.5-9B 和 Qwen3.8-27B-FP8。
- **视觉工具**：Depth Anything 3（深度估计）、SAM 3（分割）、zoom 工具。
- **实验设置**：每个任务将 benchmark 均分为不相交的**搜索集**和**留出集**；基于原始 EmbodiedBench 实现初始化 harness，每个任务执行 **10 次优化迭代**。
- **对比方法**：
  - 前沿模型直接推理：GPT-5、Claude-4.6-Sonnet、Gemini-2.0-flash、InternVL3-78B、gemma-3-27b-it。
  - **One-Shot Harness 修订**：由 Claude Opus-5 和 GPT-5.6 Sol 基于初始 harness 和代表性任务示例一次性生成改进 harness。
  - **Skill-only 优化**：仅累积和精炼文本恢复指导。
  - **EMHO（Separate）**：各子任务独立优化。
  - **EMHO（Combined）**：跨子任务池化经验轨迹优化单一共享 harness。
  - **EMHO-Merge**：增益-损失感知的共享 harness 优化。

## 6. 主要结论与发现

- **性能提升**：EMHO 在导航和操作任务上均持续提升成功率，最高增益分别为导航 **23.3%**、操作 **33.3%**；9B 模型的导航 harness 在搜索集上达到与更大已发表模型竞争的水平。
- **超越一次性修订**：EMHO 优于 Claude Opus-5 和 GPT-5.6 Sol 的一次性 harness 修订，后者倾向于给出宽泛指导（如"循环时改变策略"），而 EMHO 将重复模式转化为**具体操作条件**（如"移动被阻挡时终止当前计划剩余动作、避免重试同方向、基于更新观察重新规划"）。
- **全 harness 优于 Skill-only**：全 harness 优化不仅能发现更好的行为规则，还能改变交互历史的表示方式、添加显式检测机制，并确保状态暴露给后续规划。
- **EMHO-Merge 有效管理跨子任务权衡**：在导航和操作上，EMHO-Merge 的平均成功率均高于 EMHO（Combined），通过增益-损失轨迹细化行为激活条件（如将避障限制在有阻塞证据的情况下）。
- **行为重塑**：定性分析表明 EMHO 不仅改善失败恢复，还改变了智能体监控进度、编排感知工具、将视觉观察落地为后续动作的方式。
- **演化规律**：
  - 恢复类编辑在早期占主导，非恢复类编辑随时间推移逐渐增多（操作任务中尤为明显）。
  - 规则随迭代变得更加细致，从通用反应逐步转化为上下文相关的策略。

## 7. 优点

- **问题定位新颖**：将优化对象从模型或单一技能组件扩展到更广泛的 harness，填补了具身智能体自改进研究中的一个空白。
- **方法设计合理**：
  - 双循环结构清晰，内循环收集经验、外循环提出修订，符合自进化范式。
  - 保留被拒绝候选的经验用于后续修订，避免信息浪费。
  - EMHO-Merge 的增益-损失配对分析机制针对性地解决了跨子任务联合优化的核心矛盾。
- **实验对比全面**：同时对比了前沿模型直接推理、前沿模型一次性修订、Skill-only 优化和多种 EMHO 变体，层次分明。
- **定性分析深入**：不仅报告成功率，还通过轨迹级指标（距离变化、重复计划比例、工具使用率、目标到达率等）揭示行为变化的机制，增强了结论的可信度。
- **消融实验设计合理**：清晰分离了经验轨迹和 harness 历史两个信息源的互补作用。

## 8. 不足与局限

- **过拟合风险**：作者明确指出，搜索集上表现最好的 harness 不一定是留出集上表现最好的；后期迭代中搜索性能持续提升而留出性能可能停滞或下降，表明 harness 可能过度专门化于优化过程中观察到的轨迹。
- **模型覆盖有限**：仅使用 Qwen3.5-9B 和 Qwen3.8-27B-FP8，未验证其他模型家族（如 Llama、GPT 系列）上的泛化性。
- **优化深度有限**：每个任务仅 10 次迭代，可能未充分探索 harness 空间。
- **留出集评估的解释性**：作者承认留出集结果是"回顾性总结"，因为搜索集和留出集的最大值可能出现在不同迭代，不能作为单一搜索选择 harness 的泛化性能估计。
- **算力信息缺失**：未报告具体的 GPU 型号、数量或推理时长，难以评估方法的计算成本。
- **应用限制**：方法依赖 LLM 作为优化器进行 harness 修订，优化过程本身需要大量推理调用；在真实机器人场景中的部署可行性未经验证。
- **EMHO-Merge 的修复限制**：每个机制仅允许一次修复尝试，可能不足以充分解决复杂的跨子任务冲突。
- **环境反馈的稀疏性**：尽管方法针对稀疏反馈设计，但在反馈更加匮乏或延迟更长的真实环境中是否仍然有效，尚待验证。
