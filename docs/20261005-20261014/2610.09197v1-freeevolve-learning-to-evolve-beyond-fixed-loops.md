## 摘要
智能体进化器自动化了围绕语言模型智能体的提示、技能和工作流的设计，然而它们所遵循的优化过程仍由人工设计：一个固定的搜索循环决定如何评估候选、保留哪些候选以及何时停止搜索。我们提出 FREEEVOLVE，它将这一过程也自动化。环境指定目标、目标智能体、评估器、数据和资源限制；在这些限制内，进化器自身决定测试什么、收集多少证据、追求哪些候选以及何时停止。这些决策遵循一个可编辑的进化技能，我们通过元进化来改进它，方法是对每个候选技能在其产生的新目标智能体上进行评分。优化过程因此成为一种从经验中习得的能力，而非预先工程化的循环。在 tau3-bench、ARC-AGI-2、ARC-AGI-3 和 Terminal-Bench 2.1 上，FREEEVOLVE 自行控制进化过程，却在主要留出指标上平均提升 13.6 分，并达到或超过人工设计的进化器。所学过程随经验持续改进：元进化技能在新目标智能体上比种子技能增加 6.9 分，展示了跨环境的可迁移性。

## Abstract
Agent evolvers automate the design of the prompts, skills and workflows around language model agents, yet the optimization process they follow is still designed by hand: a fixed search loop decides how candidates are evaluated, which are kept and when the search stops. We propose FREEEVOLVE, which automates this process as well. An environment specifies the goal, target agent, evaluator, data and resource limits; within these limits, the evolver itself decides what to test, how much evidence to collect, which candidates to pursue and when to stop. These decisions follow an editable evolution skill, which we improve through meta-evolution by scoring each candidate skill on the fresh target agent it produces. The optimization process thus becomes a capability learned from experience rather than a loop engineered in advance. On tau3-bench, ARC-AGI-2, ARC-AGI-3 and Terminal-Bench 2.1, FREEEVOLVE controls the evolution campaign by itself, yet improves the primary held-out metric by 13.6 points on average and matches or exceeds hand-designed evolvers. The learned process keeps improving with experience: meta-evolved skills add 6.9 points over the seed skill on fresh target agents, demonstrating transferability across environments.

# FreeEvolve 论文深度总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体的性能高度依赖其外围"harness"（提示、技能、工作流、工具调用逻辑等）。近期研究已开始自动化 harness 的设计，即"智能体进化器"（agent evolver）——通过执行目标智能体、分析失败、修改 harness 来提升性能。
- **核心问题**：尽管进化器自动化了"编辑什么"，但其**优化过程本身仍由人工设计**——一个固定的搜索循环预先决定了评估哪些任务、重复多少次、如何比较候选、何时停止。这带来两个问题：
  - 需要大量领域设计经验；
  - 固定循环隐含了对评估噪声、任务难度、课程安排、并行度的假设，而这些假设随环境和证据变化，进化器却无法据此调整。
- **核心追问**：**优化过程本身能否被自动化，使进化器自行组织改进活动，并从经验中学会如何组织？**
- **整体含义**：论文将"进化活动组织"从人工工程化的循环，重新定义为一个**可学习、可迁移的智能体能力**。这标志着智能体自改进从"自动化产物"迈向"自动化改进过程"。

## 2. 方法论

### 2.1 核心思想
- 分离**改进问题**与**求解过程**：环境只定义边界（目标、可编辑目标、数据、资源约束），进化器被调用一次后完全掌控整个进化活动，直到返回改进后的目标。
- 两个层级：
  - **智能体层（campaign autonomy）**：进化器自主决定评估什么、分配多少资源、何时分支、何时停止。
  - **元层（meta-evolution）**：把"进化技能"（evolution skill，一个 markdown 指令文件）作为可编辑目标，通过完整的内层进化活动来评估候选技能。

### 2.2 关键技术细节

- **有界接口**：环境定义为
  `E[x0] = (g, D, x0, RE, CE)`
  其中 g 为目标，D 为数据，x0 为初始可编辑目标，RE 为执行函数，CE 为有效请求约束。
- **执行函数**：`a = RE(x, u)`，进化器选择请求 u（任务、重复次数、并发、超时等），返回分数、轨迹、日志。
- **一次调用完成整个活动**：
  `x⋆ = Evolve(s; E[x0]) ≡ s(g, D, x0, RE, CE)`
  没有外部循环固定执行次数、搜索结构或停止条件。
- **进化器实例化**：Claude Code + 自包含的 SKILL.md 指令文件。种子技能只固定"倾向"（以环境为真值、保留证据、从最佳目标继续、使用时间预算），不规定课程、评估计划、接受规则。
- **元进化**：构造元环境
  `Em[s0] = (gm, Dm, s0, Rm, Cm)`，其中 `Dm = {Ew_i[wi]}` 为 worker 环境集合。
  元层执行函数：
  `Rm(s, u) = EvaluateWorkers({Evolve(s; Ew_i[wi]) : i ∈ I(u)})`
  候选技能**没有独立分数**，只能通过它产生的 worker 及其活动轨迹来评判。
- **嵌套限制**：元环境被排除在 Dm 之外，嵌套深度限制为两层。
- **边界意义**：环境假设与进化策略分离，支持跨执行设置复用（如 Slurm 集群只需替换 Rm 和 Cm，进化器与技能不变）。

## 6. 主要结论与发现

- **Q1**：无需人工循环，FreeEvolve 在 4 个环境的主要留出指标上平均提升 **13.6 分**，在 7 个指标中的 6 个匹配或超越人工设计进化器。
- **Q2**：种子技能仅带来平均 0.6 分提升；元进化技能在此基础上再增 **6.9 分**，并在所有 pass@3 指标上提升，且优于无数据 LLM 重写——说明**执行经验而非指令改写**是增益来源。
- **Q3**：技能可跨环境迁移（τ3-bench 技能在 ARC-AGI-2 达 64.3%，ARC-AGI-3 达 71.0% RHAE）；联合元进化（τ3-bench + TB2.1）可改善所有目标指标。worker harness 也可跨模型迁移，在 Sonnet/Haiku 上保持平均 5.3 分增益。
- **Q4**：固定任一评估决策都会削弱 worker 且常增加 token 消耗；轨迹显示进化器会动态调整评估分辨率、开分支、合并发现、重复确认。
- **Q5**：模型能力存在门槛——Haiku 4.5 无法带来留出提升，Sonnet 4.6 起稳定提升，最强 Opus 产生最佳 worker（但 Sonnet 4.6 优于 Opus 4.6）。

## 7. 优点

- **概念创新**：首次将"进化活动的组织"本身作为可学习对象，而非固定循环，明确区分"自动化产物"与"自动化过程"。
- **架构优雅**：worker 层与 meta 层共用同一环境接口与 Evolve 操作，元进化无需新机制，嵌套深度受控（两层）。
- **可迁移性强**：技能冻结后可直接安装到新环境、新模型，无需继承源 worker 或活动状态。
- **实验严谨**：留出集隔离、防越界检查、多次评估报告方差、跨模型与跨环境双重迁移验证。
- **效率优势**：token 效率显著优于基线，且支持 Slurm 等异构执行设置。
- **可审计性**：保留全部评估记录，候选生成与接受分离，限制嵌套。

## 8. 不足与局限

- **模型能力依赖**：需要足够强的 evolver 模型（Sonnet 4.6 以上），弱模型（Haiku）完全无效，限制了低成本部署。
- **迁移边界**：单源技能在 Terminal-Bench 2.1 上会降低 mean，ARC-AGI-2 技能也降低其 pass@3，说明当目标环境硬件/执行行为差异大时迁移失效。
- **Terminal-Bench 表现**：mean 分数落后 GEPA，论文归因于 CPU 密集与并发阻塞，暴露环境资源暴露不足的问题。
- **成本对齐不严格**：自主方法与固定循环方法难以精确匹配评估预算，比较基于"改进前沿"而非等成本。
- **算力信息不完整**：未报告 GPU 型号与数量，算力以 CPU 节点与墙钟时间描述，复现细节受限。
- **安全与伦理**：论文自述元进化可能放大错误、消耗大量算力、难以定位行为变化来源，不适用于高风险自主部署。
- **实验覆盖**：仅 4 个 benchmark，ARC-AGI-3 留出仅 8 个游戏，统计功效有限；定性轨迹分析仅 1 例。
