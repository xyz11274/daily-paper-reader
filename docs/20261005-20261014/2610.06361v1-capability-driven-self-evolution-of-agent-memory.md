## 摘要
记忆自演化利用任务反馈来迭代改进可执行记忆程序，这些程序用于存储和检索来自过去交互的信息。现有方法通常采用整体演化，从混合反馈中推导修正方向，并通过整体性能判断进展。这可能模糊优化方向，并掩盖被其他方面退化所抵消的能力特定收益，使有前景的方向未得到充分探索。我们引入能力驱动演化，将搜索引导从整体性能扩展到个体能力维度，保留有前景的修正，并将探索扩展到整体演化边界之外。我们提出PrisMem，它使用依赖感知的能力选择来优先考虑具有潜在跨能力收益的目标，并使用历史引导的诊断来改进能力专家。轨迹引导集成在成对差异案例上比较已评估的程序，利用它们的行为差异将互补收益整合为统一的记忆程序。实验表明，PrisMem在BEAM-1M和LongMemEval-M上分别比最强基线高出10.54和7.83个百分点，证明了其在百万token历史上的有效性。

## Abstract
Memory self-evolution uses task feedback to iteratively improve executable memory programs that store and retrieve information from past interactions. Existing approaches typically adopt holistic evolution, deriving revision directions from mixed feedback and judging progress by overall performance. This can obscure optimization directions and hide capability-specific gains offset by regressions elsewhere, leaving promising directions underexplored. We introduce capability-driven evolution, which extends search guidance from overall performance to individual capability dimensions, preserving promising revisions and expanding exploration beyond the boundaries of holistic evolution. We propose PrisMem, which uses dependency-aware capability selection to prioritize targets with potential cross-capability benefits and history-guided diagnosis to refine capability specialists. Trace-guided integration compares evaluated programs on paired differential cases, using their behavioral differences to consolidate complementary gains into a unified memory program. Experiments show that PrisMem outperforms the strongest baselines by 10.54 and 7.83 percentage points on BEAM-1M and LongMemEval-M, respectively, demonstrating its effectiveness on million-token histories.

# 论文总结：Capability-Driven Self-Evolution of Agent Memory（能力驱动的智能体记忆自演化）

## 1. 核心问题与整体含义

- **研究背景**：记忆已成为 LLM 智能体的关键组件，使其能保留并利用历史交互信息。这些交互包含显式事实、隐式偏好、动态变化状态等多样信息，不同请求需要不同能力（事实检索、时序追踪、偏好识别、跨会话综合等），因此有效记忆本质上是多维的。
- **核心问题**：现有自演化记忆方法普遍采用**整体式演化（holistic evolution）**，即从混合反馈中推导修正方向，并以整体任务性能判断进展。这导致两个问题：
  - **优化方向模糊**：混合反馈将不同能力任务的失败混在一起，同一记忆组件可能对应多种效果不同的修正方向。
  - **能力增益被掩盖**：某项能力的提升可能被其他能力的回退抵消，整体分数不变甚至下降。论文分析显示，**80.5% 未带来整体增益的修正仍至少提升了一项能力**。
- **整体含义**：论文提出**能力驱动演化（capability-driven evolution）**，将搜索引导从单一整体性能维度提升到多个能力维度，保留有前景的修正，突破整体演化的探索边界。

## 2. 方法论

### 核心思想
- 将整体记忆演化分解为**能力特定方向**（类比棱镜分光），通过能力级反馈提供聚焦诊断和明确方向，通过能力级评估保留无整体增益但有潜力的修正。

### 关键技术细节

- **细粒度记忆接口**：将记忆程序分解为五个组件——Extraction（抽取）、Indexing（索引）、Planning（规划）、Retrieval（检索）、Answer（回答），提供更局部的修改边界，帮助定位失败阶段。

- **能力集合**：实例化五种代表性能力——事实检索（F）、时序追踪（T）、偏好提取（P）、跨会话综合（M）、对抗性（A）。离线用 LLM 为训练/验证任务标注一个主能力和最多两个次能力（测试时不提供标签）。

- **三阶段演化流程**：
  - **Stage I 冷启动**：用 T1=5 轮联合考虑所有能力的反馈，快速建立平衡基础程序。构建**指标表**，通过语义相似度衡量参考证据与（i）抽取的记忆单元、（ii）以证据为查询线索检索的内容、（iii）针对实际问题检索的内容之间的匹配，定位抽取/索引/检索弱点。
  - **Stage II 能力精炼**：
    - **依赖感知能力选择**：优先选择自身弱或成为其他能力瓶颈的能力。定义结构基率先验 D(cp→cs)（主能力 cp 任务中需要 cs 的频率）、错误集中度 F（cs 专家在 cp 任务上的错误是否过度集中于需要 cs 的任务）、传入错误压力 I（公式 4）、综合紧迫度 U（公式 5，用 max 而非 sum 避免度中心性偏差），最后用历史分配次数 nt(c) 折减得到优先级 ρ（公式 6）。
    - **历史引导诊断**：选择 K=5 个严重、历史上可操作且多样化的失败案例。用历史引导优先级权重 w（公式 7）排序，高历史分数识别"回归见证"，分母折减频繁选中的案例和次能力组合，促进多样覆盖。
  - **Stage III 轨迹引导整合**：从整体最优程序出发，按谱系拓扑顺序整合各能力专家。采用**配对差分案例**策略——为每个能力选择基程序与专家分数差距最大的训练案例，比较执行结果暴露行为差异，指导整合。最多 T3=3 轮，若整合未提升整体分数或某能力下降超过 θ 则返回重试。

- **高效演化**：
  - **紧凑诊断上下文**：去除冗余内容并标记省略，保留与问答相关片段，诊断案例 token 成本平均降低 44%。
  - **修订感知执行复用**：比较候选与父程序的组件，从最早受影响阶段开始重执行，复用未受影响组件的输出。

## 3. 实验设计

- **数据集/场景**：
  - **BEAM**（Tavakoli et al., 2026）和 **LongMemEval**（Wu et al., 2025），覆盖长多会话历史中的多样问题类型。
  - 在短上下文划分（BEAM-100K、LongMemEval-S，约 100K token）上训练 20 轮，在长划分（BEAM-1M、LongMemEval-M，超 100 万 token）上测试，验证泛化能力。
  - BEAM：160 训练问题（8 对话）、120 验证问题（6 对话）、700 测试问题（35 对话）。LongMemEval：分层采样 60 训练、60 验证、200 测试。

- **Benchmark**：以各 benchmark 提供的 LLM judge 分数为指标，整体分数为所有问题平均，能力级分数按原生问题类型映射分组平均。

- **对比方法**（7 个代表性基线）：
  - 静态方法：Mem0、A-MEM、HippoRAG2、SimpleMem、LightMem。
  - 自演化方法：M⋆（种群式反思代码搜索）、EvolveMem（失败诊断适配检索基础设施和答案生成配置），两者均采用整体演化。

- **模型**：Qwen3.8-27B 作为任务、反思、编码、评判模型；Qwen3-Embedding-8B 作为嵌入模型。附录中补充 GPT-5.5 结果。

## 6. 主要结论与发现

- PrisMem 在 BEAM-1M 和 LongMemEval-M 上分别超越最强基线 **10.54 和 7.83 个百分点**，在几乎所有能力比较中取得最佳性能。
- 整体演化相比静态方法增益有限（M⋆ 在 BEAM 上仅提升 0.99 pp，EvolveMem 在 LongMemEval 上仅 0.34 pp），反映混合反馈模糊方向和整体分数掩盖能力增益的问题。
- 消融显示：移除能力驱动演化下降 10.15 pp（主要增益来源）；移除轨迹引导整合下降 3.16 pp；round-robin 目标选择下降 2.55 pp；随机案例选择下降 5.26 pp。
- 演化轨迹分析表明：能力分数在 Stage II 中间歇性提升，精炼一个能力可同时更新其他能力专家（反映能力依赖）；最终整合程序接近历史能力级峰值。
- 整合优于路由：PrisMem 比 question-only router 高 5.65 pp，比 oracle-label router 高 1.12 pp，说明整合互补机制优于选择单一专家程序。
- 演化程序可跨模型（Qwen3.8-27B → GPT-5.5）和跨数据集（BEAM → LongMemEval）迁移，保持强性能。
