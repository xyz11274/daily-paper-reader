## 摘要
大型语言模型智能体正越来越多地被部署到真实环境中执行复杂任务。然而，在这些环境中正确行为所需的知识往往是隐性的、未公开的，并且会随时间变化。近期的持续学习框架试图通过让智能体从服务经验中改进来应对这一挑战。但这些方法的有效性和局限性尚未得到充分刻画。现有基准仅提供部分覆盖：一些显式提供目标知识，另一些假设环境是静态的，而那些支持持续适应的基准在规模和知识多样性上仍然有限。为了实现系统性评估，我们形式化了一个演化环境流式数据集（EESD），其中智能体必须在隐藏策略演化时，从交互和结果反馈中推断、应用并修正潜在的环境知识，并提出了 ServeLearnBench，涵盖零售支持、银行和销售话术生成，包含 53 个环境窗口和 7,718 个任务。我们评估了五种学习框架（RAG、Mem0、SkillOpt、Continual Harness 和 Prime）在六个模型（GPT-5.6 Terra、Opus 5、Kimi K3、GLM-5.3、DeepSeek V4.1 Flash 和 GLM-5.3 Flash）上的表现，覆盖 28 个模型-框架组合和 252 次学习运行。我们的评估揭示了三个主要发现：任务能力与从经验中学习之间仍存在显著差距；持续适应成本高昂，且可能使原本正确的行为退化；探索不足成为有效适应的关键瓶颈。总体而言，ServeLearnBench 提供了一个受控测试平台，用于诊断这些局限性，并追踪智能体通过服务经验持续可靠改进的进展。

## Abstract
Large language model agents are increasingly deployed to perform complex tasks in real-world environments. However, the knowledge required for correct behavior in these environments is often implicit, undisclosed, and subject to change over time. Recent continual-learning harnesses seek to address this challenge by enabling agents to improve from serving experience. Yet the effectiveness and limitations of these methods are not yet well characterized. Existing benchmarks provide only partial coverage: some explicitly provide the target knowledge, others assume a static environment, and those that support continual adaptation remain limited in scale and knowledge diversity. To enable systematic evaluation, we formalize an evolving-environment streaming dataset (EESD), in which agents must infer, apply, and revise latent environment knowledge from interaction and outcome feedback as hidden policies evolve, and introduce ServeLearnBench, spanning retail support, banking, and sales-pitch generation with 53 environment windows and 7,718 tasks. We evaluate five learning harnesses (RAG, Mem0, SkillOpt, Continual Harness, and Prime) across six models (GPT-5.6 Terra, Opus 5, Kimi K3, GLM-5.3, DeepSeek V4.1 Flash, and GLM-5.3 Flash), covering 28 model-harness pairs and 252 learning runs. Our evaluation reveals three main findings: a substantial gap remains between task capability and learning from experience; continual adaptation is costly and can degrade already-correct behavior; and insufficient exploration emerges as a key bottleneck to effective adaptation. Overall, ServeLearnBench provides a controlled testbed for diagnosing these limitations and tracking progress toward agents that continually and reliably improve through serving experience.

# ServeLearnBench 论文深度总结

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体正被广泛部署于真实业务环境（客服、金融审核、销售等），但这些环境中决定正确行为的知识往往是**隐性的、未公开的、且随时间变化**的。智能体不能只依赖一次性能力测试，而必须从服务交互与失败反馈中持续学习。
- **核心问题**：现有持续学习框架（如 SkillOpt、Continual Harness、Prime）虽能更新记忆/技能/策略，但"能更新"不等于"学到了有用且可复用的知识"。论文追问三个问题：
  1. 当前智能体能多好地从服务经验中持续学习？
  2. 这种学习的代价（计算与已有能力损失）有多大？
  3. 什么因素使持续学习真正有效？
- **现有基准的缺口**：
  - 部分基准**直接提供目标知识**，只测保留与应用，不测发现；
  - 部分基准要求发现隐藏知识，但**假设环境静态**；
  - 支持动态环境的基准**规模与知识多样性有限**。
- **整体含义**：论文提出 **EESD（演化环境流式数据集）** 抽象与 **ServeLearnBench** 基准，为"智能体从部署经验中持续可靠改进"提供受控诊断平台。

## 2. 方法论

### 2.1 核心思想：EESD 抽象

- 将评估形式化为**按时间排列的环境窗口序列**：D = W₀ ∥ W₁ ∥ … ∥ W_{S−1}，每个窗口 Wₛ 由潜在环境状态 θₛ 支配，窗口内固定、窗口边界可变。
- 环境可**引入新策略、修订已有策略、或恢复曾激活的策略**，且状态及其变化对学习框架完全不可见。

### 2.2 关键技术细节

- **服务/测试划分**：每个窗口 Wₛ = D^serve_s ∥ D^test_s，二者覆盖同一活跃行为组件 C(θₛ)，但任务实例不相交：
  - Cov(D^serve_s) = Cov(D^test_s) = C(θₛ)，D^serve_s ∩ D^test_s = ∅
  - 目的：测试任务衡量**对新实例的迁移**，而非对服务样本的记忆。
- **Hidden-Dependent vs. Fully Specified**：
  - Hidden-Dependent：仅凭可见信息不足以确定正确行为，测"是否学到隐藏知识"；
  - Fully Specified：可见信息已足够，测"适应是否破坏原本正确的行为"。
- **难度分层**：
  - L1（习得）：引入全新状态；
  - L2（修订与组合）：修订旧状态，加入多策略/排序/批量任务；
  - L3（非单调演化）：加入反转、移除、重新进入，保留 L2 组合复杂度。
- **奖励函数**：分领域设计——Retail/Banking 用确定性规则验证最终数据库状态与答案（二进制奖励）；Pitch 用结构化 LLM 评分（连续 0–100）。
- **参考基线**：Blind（无学习、无经验）与 Oracle（直接获得活跃隐藏策略），用于界定可学习空间。

## 3. 实验设计

### 3.1 场景与 Benchmark

- **三个领域 × 三个难度 = 九个场景**：
  - **Retail**：多轮客服（取消/修改订单、退货/换货），隐藏规则为类别型资格范围（支付方式、品类、目的地、退款方式等）；
  - **Banking**：案件审核（授权交易、提额、转账筛查），隐藏规则为数值阈值与范围限制；
  - **Pitch**：单轮销售话术生成（40–80 词），隐藏状态为顾客偏好画像，全部为 Hidden-Dependent。
- **规模**：53 个环境窗口、4,508 个服务任务、3,210 个留出测试任务，共 **7,718 个任务**。

### 3.2 对比方法

- **5 种学习框架**：RAG、Mem0、SkillOpt、Continual Harness (CH)、Prime；
- **6 个模型**：GPT-5.6 Terra、Opus 5、Kimi K3、GLM-5.3、DeepSeek V4.1 Flash、GLM-5.3 Flash；
- **28 个模型–框架组合、252 次学习运行**（30 个可能组合中 2 个因成本省略）；
- 另加 Blind 与 Oracle 两个非学习基线。

### 3.3 分析维度

- 学习速度（AULC₁₀：新策略前 10 次遭遇的平均正确率）；
- 适应对 Fully Specified 任务的损害；
- 探索度（AUC_E：同一策略下不同答案数量）与知识获取（AUC_KA：首次成功后 5 次的正确率）；
- 成本–性能 Pareto 前沿（token 与 API 成本）。

## 4. 资源与算力

- **论文未明确披露 GPU 型号、数量或训练时长**。所有模型均通过 API 访问（OpenAI、Anthropic、Fireworks），属于推理侧评估而非本地训练。
- 论文报告了**API 成本与 token 消耗**作为资源指标：
  - 推断隐藏策略的成本是遵循已公开策略的 **4–101 倍**（如 Kimi K3 上 Prime 花费 $2,479，Oracle 仅 $102）；
  - Prime 每任务成本最高（$0.232 服务 / $0.142 测试），CH 以约一半成本达到接近性能；
  - GLM-5.3 与 Kimi K3 的每任务成本约为 GLM-5.3 Flash 的 14–16 倍。
- 附录 D.5 提到曾尝试 SFT 与 GRPO 训练，但 14B/32B 模型难以生成成功轨迹，**未报告具体训练算力**。

## 5. 实验数量与充分性

- **实验规模**：28 个模型–框架组合 × 9 个场景–难度设置，共 252 条学习运行；另有 Blind/Oracle 基线。
- **分析深度**：
  - 学习速度分析覆盖 31 个 Banking 策略与 37 个 Retail 策略；
  - 探索度分析覆盖 Retail/Banking 各难度、每框架 20–52 个策略；
  - 成本分析基于 180 条开源模型运行记录。
- **充分性与公平性**：
  - **优点**：同一模型块内 Blind/Oracle/各框架使用相同模型与推理强度；任务流与评分一致；测试任务完全隔离于学习更新；结果由脚本渲染而非手工填写。
  - **局限**：
    - 各框架的更新节奏、状态容量、学习侧算力**未统一**（作者明确说明这是刻意保留各方法原生设计），因此比较的是"完整系统"而非隔离的框架效应；
    - 不同 provider 返回的推理历史不同（Terra 无 CoT、Opus 仅摘要、Fireworks 保留完整推理），可能影响依赖轨迹的学习框架；
    - Pitch L1 每个 24 项窗口仅 6–8 种有效属性组合，**不应视为独立统计重复**；
    - 无标准误或置信区间报告。

## 6. 主要结论与发现

1. **持续学习存在显著性能差距**：Oracle 平均 Hidden 准确率 95.4%，Blind 仅 14.1%；但 28 个模型–框架组合中最好的在 Retail L3 仅达 59.6%，中位数仅 22.0%。任务能力本身不是瓶颈，**从经验中学习才是**。
2. **持续学习没有免费午餐**：
   - 成本高昂（推断隐藏策略是遵循公开策略的 4–101 倍）；
   - 适应会损害原本正确的行为：所有学习框架在 Retail 的 Fully Specified 准确率均低于 Blind（98.9 vs. 89.5–95.5）；Banking 上除 Prime 和 Mem0 外也均下降。
3. **有效探索是关键瓶颈**：框架的探索度排序（Prime 1.16 > CH 1.02 > RAG 0.88 > Mem0 0.65 > SkillOpt 0.51）与 Hidden 奖励排序完全一致（ρ = 1.00）；探索主要是**框架属性**而非模型属性。
4. **知识获取与探索是不同瓶颈**：首次成功后，Prime/CH 的 AUC_KA 达 78%/76%，而 Mem0/RAG 仅 41%/38%；SkillOpt 善于复用但难以发现，RAG 善于发现但难以复用。
5. **学习与丢弃同样困难**：同一策略被撤销时，丢弃速度与学习速度相当，多数框架在策略变更后首张票仍沿用旧策略。

## 7. 优点

- **问题定义清晰**：EESD 抽象精确刻画了"隐藏 + 演化 + 流式"三重要求，填补了现有基准的交叉空白。
- **基准设计严谨**：
  - 服务/测试覆盖同一行为组件但实例不相交，有效区分迁移与记忆；
  - Hidden-Dependent 与 Fully Specified 正交划分，可分离"学习增益"与"附带损害"；
  - Blind/Oracle 双基线界定可学习空间。
- **评估规模大且系统**：28 个模型–框架组合、252 次运行，跨三领域三难度，覆盖类别规则、数值阈值、组合阈值与潜在偏好多种知识类型。
- **分析维度深入**：不止于最终分数，还追踪学习速度、探索度、知识获取、成本–性能前沿，并识别出探索与知识获取两个独立瓶颈。
- **成本核算细致**：区分服务侧与测试侧成本，拆分学习侧与推理侧开销，提供 token 与美元双重视角。
- **诚实披露局限**：明确说明框架间资源未对齐、推理历史差异、Pitch 统计重复性不足等问题。

## 8. 不足与局限

- **框架比较不完全公平**：各框架的更新节奏、状态容量、学习侧算力、运行时（Prime 自带沙箱与代码解释器，基础智能体更强）均未统一，CH vs. Prime 的差异包含运行时因素。
- **模型推理历史不一致**：不同 provider 返回的 CoT 信息量不同，可能系统性影响依赖轨迹的学习框架。
- **统计严谨性有限**：无置信区间或标准误；Pitch L1 有效组合少，不宜作独立统计推断；Mem0 的知识获取曲线基于最少策略数（6 个 Retail 策略），不确定性最高。
- **训练式方法未充分探索**：SFT/GRPO 仅初步尝试，14B/32B 模型难以生成成功轨迹，未给出训练算力与完整结果。
- **应用限制**：
  - SkillOpt 的验证重放依赖模拟器（每张服务票约 0.85 次额外执行），在真实部署中不可行；
  - 基准使用固定评分器（Pitch 用 GLM-5.3 Flash 评判，包括评判自身），可能存在评分偏差；
  - 隐藏策略由人工设计，真实环境中策略变化的分布可能不同。
- **成本门槛**：完整评估成本高昂（部分组合因成本被省略），可能限制复现与扩展。
