## 摘要
交互式智能体可以将经验转化为可复用的技能，然而现有的自演化技能库主要通过积累新知识来改进。失败可能催生新技能，而随着新证据的出现，先前存储的技能却较少被重新审视。然而，仅靠增长并不能确保可靠性，因为检索到的技能在当前任务条件下可能不适用，而现有技能可能编码了错误指定的操作边界。因此，可靠的技能演化不仅需要添加知识，还需要对已存储的内容进行测试和修正。我们提出 Skill-V，一个可验证的自演化技能库。为使存储的知识可测试，我们提出将技能表示为带版本、可证伪的契约，将语义意图与可观察的行为标准联系起来。我们利用环境结果来驱动技能库演化。具体而言，任务失败促使添加技能，而契约评估与任务结果之间的不一致则引导对现有技能边界的修正。为验证这些修正，我们要求它们保留受保护的语义约束，并在历史回放证据上满足评分标准-结果指标的非回归准则。最后，我们采用一种适用性感知过滤器，排除被确信为不适用于当前任务的候选技能。在 ALFWorld 和 WebShop 上，Skill-V 分别达到 95.3% 和 85.9% 的成功率，同时保持比以增长为导向的基线更紧凑的技能库。适用性感知过滤减少了错误的技能调用，而基于结果的修正纠正了错误指定的技能边界，且不会降低在先前观察到的证据上的性能。这些结果表明，可靠的技能演化不仅仅需要积累经验：技能库必须学会保留哪些知识、何时修正它，以及何时应用它。

## Abstract
Interactive agents can turn experience into reusable skills, yet existing self-evolving skill libraries primarily improve by accumulating new knowledge. Failures may lead to new skills, while previously stored skills are less often revisited as new evidence arrives. However, growth alone does not ensure reliability, as a retrieved skill may be inapplicable under the current task conditions, and an existing skill may encode a mis-specified operational boundary. Reliable skill evolution therefore requires not only adding knowledge, but also testing and revising what is already stored. We introduce Skill-V, a verifiable self-evolving skill library. To make stored knowledge testable, we propose representing skills as versioned, falsifiable contracts that link semantic intent to observable behavioral criteria. We use environment outcomes to drive library evolution. Specifically, task failures motivate skill addition, while disagreements between contract evaluations and task outcomes guide revisions to existing skill boundaries. To validate these revisions, we require them to preserve protected semantic constraints and satisfy non-regression criteria for rubric-outcome metrics on historical replay evidence. Finally, we employ an applicability-aware filter to exclude candidates judged confidently inapplicable to the current task. Across ALFWorld and WebShop, Skill-V achieves success rates of 95.3% and 85.9%, respectively, while maintaining a more compact skill library than growth-oriented baselines. Applicability-aware filtering reduces incorrect skill invocations, and outcome-grounded revisions correct mis-specified skill boundaries without degrading performance on previously observed evidence. These results show that reliable skill evolution requires more than accumulating experience: the library must learn which knowledge to retain, when to revise it, and when it should be applied.

## 1. 核心问题与整体含义

- **研究动机**：交互式智能体能够将交互经验转化为可复用技能，但现有自演化技能库（如 SkillRL、Skill1、SkillOS 等）主要依赖"增长导向"的演化范式——失败时新增技能，而已存储的技能很少随新证据被重新检验。
- **核心痛点**：
  - 检索到的技能可能在语义上相关，但在当前任务条件下**不适用**。
  - 已存储技能可能编码了**错误指定的操作边界**：过宽则允许无效行为，过窄则排除有效策略。
  - 这类不可靠性严重限制智能体的长期自主自我改进能力。
- **核心研究问题**：智能体如何在扩展技能库的同时，持续检验并修正已存储的知识？
- **整体含义**：论文主张可靠的技能演化不仅是"积累更多知识"，更关键的是学会**保留哪些知识、何时修正、何时应用**，从而为可信的递归自我改进提供原则性基础。

## 2. 方法论

### 2.1 核心思想
- 将每个技能表示为**带版本、可证伪的契约**（versioned, falsifiable contract），把语义意图与可观测行为标准显式关联，使存储知识可被环境结果检验。
- 技能形式化定义为四元组：`sᵢ = (φᵢ, pᵢ, ρᵢ, νᵢ)`
  - **φᵢ**：语义意图与预期适用范围（受保护的语义约束，修订时不可被覆盖）。
  - **pᵢ**：可复用过程（自然语言步骤）。
  - **ρᵢ**：可执行评分标准（rubric），含适用条件 Aᵢ 与加权行为准则 Cᵢ，准则可为硬约束或软约束。
  - **νᵢ**：版本记录（技能版本、rubric 版本、可追溯性、更新原因、证据 ID）。

### 2.2 结果驱动的技能演化（两条互补路径）
- **技能新增**：任务失败暴露能力缺口，语言模型更新器分析失败轨迹，提出新技能（初始为语义形式，rubric 待编译），立即可用于检索与提示。
- **技能修订**：比较 rubric 判断与真实环境结果，产生四类诊断信号：
  - rubric 通过 + 任务成功 → 支持当前边界；
  - rubric 失败 + 任务失败 → 一致的负证据；
  - **rubric 通过 + 任务失败 → 契约可能过宽或欠指定**；
  - **rubric 失败 + 任务成功 → 契约可能过严**。
- **聚合评分公式**：对所有适用契约的加权准则得分归一化，得到 `q(τ)`，再经阈值 η=0.7 与硬约束检查得到契约级判断 `ŷ_rub(τ) = I[q(τ) ≥ η ∧ H(τ) = 0]`。

### 2.3 证据门控（Evidence Gate）验证
- 对每个技能维护有界回放缓冲区 Eᵢ，将 rubric 通过/失败视为对环境结果的预测。
- 计算三个指标：**不一致率 Disc**、**成功轨迹上的假阴性率 FNR**、**平衡准确率 BAcc**。
- 候选修订 ρ′ᵢ 被接受需满足：
  - `Disc(ρ′ᵢ) ≤ Disc(ρᵢ)`，`FNR(ρ′ᵢ) ≤ FNR(ρᵢ)`，`BAcc(ρ′ᵢ) ≥ BAcc(ρᵢ)`；
  - 保留受保护语义约束、具备非空可执行支持、满足契约规范；
  - 若修改了硬准则，则至少一项指标需**严格改进**。
- 修订为**原地替换**，不增加库大小；被拒候选保留原版本。

### 2.4 适用性感知的技能使用
- 先用 Qwen3-Embedding-0.6B 做语义检索（候选池为最终预算的 2 倍）。
- 再由 LLM 适用性判断器输出 {APPLICABLE, NOT APPLICABLE, UNCERTAIN} 及置信度，仅当**确信不适用且置信度 ≥ 0.8** 时剔除。
- 剩余候选中保留语义相似度在最高分 ε=0.15 范围内的技能，最终取 Top-K（通用 6 个 + 任务特定 5 个）。
- 若判断不可用，回退到语义 Top-K 检索。

## 6. 主要结论与发现

- **性能显著提升**：相比 GRPO，ALFWorld 成功率从 77.6% 提升至 **95.3%**（+17.7 个百分点）；WebShop 平均分从 79.3 提升至 **92.5**，成功率从 66.1% 提升至 **85.9%**。
- **紧凑库即可达到强性能**：Skill-V 约 200 条存储条目，不到 Skill1（5000 技能）的 4%，却在 Look、Clean、Heat 子任务上达到 100% 成功率。
- **外部知识贡献可分离**：固定策略后，无外部技能 78.59%，初始库 88.99%，演化后库 95.30%，证明演化库带来 +6.31 点的额外增益。
- **双向边界修正缺一不可**：仅新增技能 68.8%，仅失败驱动修订 67.2%，完整 Skill-V 95.3%，差距至少 21.9 点。
- **Evidence Gate 关键**：无门控时 46 次提交中 9 次回归、仅 27 次满足完整标准，任务成功率仅 75.0%；有门控时 10 次提交全部通过，成功率 95.3%。
- **适用性过滤有效**：纯语义检索 71.9%，加契约检查 89.1%，再加 LLM 判断达 95.3%；训练中约 29.6% 的候选被判定为确信不适用。
- **非奖励塑形效应**：加入 rubric 过程奖励反而略降至 93.8%，说明收益来自可验证知识演化而非密集奖励。

## 7. 优点

- **概念创新**：将技能从"静态知识条目"重新定义为"可证伪契约"，把技能维护提升为与技能获取同等重要的一等公民。
- **严谨的验证机制**：Evidence Gate 采用 Disc/FNR/BAcc 三指标非回归约束，并区分软/硬准则，防止无根据的自我改写，直接缓解灾难性遗忘。
- **双向修正**：同时处理"过宽"（rubric 通过但任务失败）与"过严"（rubric 失败但任务成功）两类边界错误，而非仅积累约束。
- **紧凑高效**：原地版本替换不增加库大小，避免增长导向方法的库膨胀问题。
- **工程安全设计**：不执行模型生成代码，证据匹配器限定于预定义声明式算子集，策略思考被严格排除在轨迹之外，防止"计划但未执行"的动作虚假满足准则。
- **消融设计清晰**：通过固定策略分离策略参数与外部知识的贡献，通过过程奖励对照排除奖励塑形假说，逻辑严密。

## 8. 不足与局限

- **环境类型受限**：契约评估依赖离散文本准则，难以直接迁移到视觉或连续控制环境，需多模态评估机制或程序化奖励函数。
- **无技能删除机制**：框架只修正操作边界，若初始技能根本性错误，系统只会严格限制其使用而非彻底丢弃，需额外的自动弃用机制。
- **历史依赖风险**：严格验证高度依赖历史轨迹，若环境规则随时间变化，旧证据可能不再代表正确行为；需时间加权缓冲区等机制。
- **实验覆盖有限**：仅两个文本交互环境，未验证视觉、连续控制或多智能体场景；Skill1 的库规模差异使比较存在一定不可比性。
- **算力报告不完整**：未披露 GPU 型号、训练总时长与总计算量，复现成本难以精确评估。
- **外部模型依赖**：适用性判断、技能提议与 rubric 编译均依赖 DeepSeek-V4-Flash，引入 API 成本、延迟与外部服务稳定性风险（论文提到 30 秒超时与五分钟熔断）。
- **因果归因模糊**：环境结果是轨迹级的，多个契约可能同时适用，论文明确承认诊断信号不构成因果信用分配，仅用于优先排序候选更新。
