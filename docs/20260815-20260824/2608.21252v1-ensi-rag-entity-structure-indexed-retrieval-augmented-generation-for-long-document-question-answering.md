## 摘要
面向长关联文档的问答（QA）仍颇具挑战，因为相关证据可能分布在多个实体及其关系之间。现有检索增强生成（RAG）方法通常将文档索引为原始分块，并通过嵌入相似度完成检索。当分块边界将实体与支撑证据分隔开，或问题需要在语料库中进行多跳推理时，这类方法的性能会出现下降。我们提出EnSI-RAG（Entity-Structure-Indexed Retrieval-Augmented Generation，实体结构索引检索增强生成），这是一个构建与查询无关、以实体为中心索引的框架。每条记录(e, t, k, v)代表实体e、其类型t、属于{属性、关系、方面}的语义类别k以及值v，同时保留指向原始源段落的链接。查询阶段，这些记录用作检索句柄，由大语言模型（LLM）将检索到的段落整合为最终答案。该设计将证据定位与答案合成分离开来，同时保留可追溯的源证据。在Loong和Oolong测试中，EnSI-RAG取得了78.24的平均准确率，相较于作为参考的已发布基线分数高出6.62个百分点，表明该方法在这些设置下具备有效性。代码可从https://github.com/RamonMeng/EnSI-RAG获取。

## Abstract
Question answering (QA) over long, connected documents remains challenging because relevant evidence may span multiple entities and their relationships. Existing retrieval-augmented generation (RAG) methods typically index documents as raw chunks and retrieve them through embedding similarity. Their performance degrades when chunk boundaries separate entities from supporting evidence or when a question requires multi-hop reasoning across the corpus. We propose EnSI-RAG (Entity-Structure-Indexed Retrieval-Augmented Generation), a framework that constructs a query-independent, entity-centered index. Each record (e, t, k, v) represents an entity e, its type t, a semantic category k in {property, relation, aspect}, and a value v, while retaining links to the original source passages. At query time, these records serve as retrieval handles, and an LLM synthesizes the retrieved passages into the final answer. This design separates evidence localization from answer synthesis while preserving traceable source evidence. Across Loong and Oolong, EnSI-RAG achieves an average accuracy of 78.24. Relative to the published baseline scores used as references, this is 6.62 points higher, suggesting its effectiveness across these settings. The code is available at https://github.com/RamonMeng/EnSI-RAG.

# EnSI-RAG 论文总结

## 1. 核心问题与研究背景
- 长文档问答是大语言模型的经典挑战：真实场景中回答问题所需的证据通常分散在多个文档、多个实体及其关联关系中，需要模型完成证据定位、跨实体聚合与多跳推理。
- 现有两类主流方案都存在缺陷：
  1. 扩展LLM上下文窗口的方案存在“lost in the middle”效应，对证据聚合、多跳推理类任务效果仍然不佳；
  2. 传统检索增强生成（RAG）方案采用固定长度分块索引，依赖嵌入相似度检索，分块边界容易割裂实体与支撑证据，或将无关内容混入同一检索单元，导致检索到的内容局部相似但不完整，多跳推理性能明显下滑。
- 核心研究问题：解决长文档问答中语义碎片化、实体证据割裂、多跳证据定位难的痛点。

## 2. 提出的方法论
### 核心思想
将检索单元从机械固定分块改为语义连贯的实体中心单元，用结构化实体索引作为检索句柄，保留原始源段落用于最终答案生成，将**证据定位与答案合成分离**，兼顾检索精准性和信息完整性。整体框架分为离线预处理（查询无关，一次构建重复使用）和在线问答两个阶段：
### 关键技术流程
1. **离线预处理阶段**
   - **实体中心段落构建**：不采用固定长度分块，根据文档结构和任务需求动态划分段落，每个段落语义自包含，围绕单个核心实体组织，保留核心实体及其完整支撑上下文，同时保留原始文档的源信息，大幅减少语义碎片化和无关内容污染。
   - **结构化实体信息提取**：从每个段落提取结构化记录，每条记录包含`实体e + 实体类型t + 语义域`，语义域分为三类：属性（实体自身特征值）、关系（实体与其他实体的连接）、方面（实体讨论的特定维度），所有记录保留对应原段落ID，提取仅用于生成检索句柄，不替代原始证据，降低提取错误的影响。
   - **实体结构索引构建**：构建查询无关的结构化索引，索引规则为`[实体][实体类型][语义类别:域名称=值] → 匹配的原段落ID集合`，支持双向关系索引（如论文的引用和被引用同时建立索引），同一个检索键保留所有匹配段落，不提前合并为单一值，保留所有备选证据满足不同推理需求。
2. **在线问答阶段**
   - **检索计划生成与匹配**：将用户查询转换为结构化检索计划，单跳问题直接完成检索，多跳问题按推理链分步检索，每一步根据检索需求对索引键做匹配打分，汇总得到候选原段落集合，重排后输出。
   - **答案生成**：将用户查询和检索到的原始段落输入LLM，由LLM直接完成证据整合，生成最终答案，结构化索引仅负责证据定位，不承担推理任务。

## 3. 实验设计
- **测试数据集与基准**：采用两个互补的长文档问答基准：
  1. Loong：覆盖金融、法律、学术领域的异质多文档推理基准，本次实验评估子集共177个问题，采用平均准确率评估；
  2. Oolong：侧重长输入大规模信息聚合的基准，本次实验评估子集共192个问题，非数值问题采用LLM评判、数值问题采用官方偏差指标评估；
- **对比基线**：一共对比8种主流方法，包括：传统RAG、LongRAG、GraphRAG、直接长上下文推理BaseModel、DocETL、Chain-of-Agent、RLM、当前SOTA方法SLIDERS，所有基线分数引用自已发表的公开结果。

## 6. 主要结论与发现
- 主效果：EnSI-RAG在两个基准上取得平均78.24%的准确率，比公开参考基线提升6.62个百分点，性能优于包括当前SOTA SLIDERS在内的所有对比方法；
- 设计验证：细粒度实体段落比粗粒度段落效果更好，以金融表格为例，按行切分比整个表格作为一个段落准确率提升8.5个百分点；语义域粒度需要适配领域：金融、学术领域适合粗粒度抽象减少词汇稀疏性，法律领域需要保留细粒度区分保证检索精准性；检索少量高相关证据比检索更多证据效果更好，额外冗余证据会引入干扰降低准确率；
- 整体结论：分离证据定位与答案合成的设计，比传统分块RAG和纯结构化数据库问答都更适合长文档问答任务。

## 7. 方法亮点
1. 用实体中心语义段落替代固定分块，从根源解决了传统分块的语义割裂和污染问题；
2. 结构化索引仅作为检索句柄，不替代原始源证据，结构化提取错误不会直接影响最终答案，比纯结构化问答方法鲁棒性更强；
3. 分离证据定位与答案合成，兼顾了结构化检索的精准性和LLM的语义整合能力，在传统RAG和纯结构化方法之间找到了更优的平衡点；
4. 支持动态适配不同领域的文档结构，可根据任务和文档类型调整段落边界，通用性强。

## 8. 不足与局限
1. 离线预处理需要LLM完成实体提取和索引构建，预处理成本较高，对于动态更新的语料库，新增文档需要重新预处理，灵活性不足；
2. 实验仅在两个公开基准上验证，未覆盖更多领域、更多类型的长文档场景，泛化能力需要进一步验证；
3. Loong数据集的评估子集和基线所用子集可能不完全一致，部分对比不是严格控制变量的头对头对比；
4. 检索深度为固定配置，未针对问题复杂度做动态调整，对于超复杂多跳任务可能存在检索不足或冗余的问题。
