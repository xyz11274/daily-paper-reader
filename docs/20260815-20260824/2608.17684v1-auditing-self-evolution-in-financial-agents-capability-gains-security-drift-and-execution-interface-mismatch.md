## 摘要
自演化智能体可将经验转化为可复用的技能、工作流或记忆，但仅靠演化后的准确率无法说明习得行为是否保留了原本正确的行为与安全属性。我们在模拟电子银行环境中，采用匹配的良性获取轨迹、密封评估端点、基于执行的检查与独立状态重放，对SkillOpt、智能体工作流记忆（AWM）和ReasoningBank开展审计。在Qwen 3.7 Flash上，SkillOpt将良性效用从0.741提升至0.837，同时对注入内容的暴露率从0.820升至0.943。暴露后的条件攻击成功率从0.605降至0.562，但整体攻击成功率（ASR）从0.496升至0.530，未授权金融状态变更率升至0.685。在三个独立演化谱系中，能力、暴露率和未授权状态变更均出现上升，而攻击成功率仅在两个谱系中上升。ReasoningBank将效用提升至0.859，且未提高总体攻击成功率，但未授权状态变更率仍略高于静态基准。AWM暴露出一个独立的评估风险：原文字面形式的WebArena文本动作封包会干扰我们原生函数调用执行器中的工具执行。事后敏感性测试显示，仅移除该封包即可将效用从0.319恢复至0.756，同时暴露率从0.299升至0.909，攻击成功率从0.195升至0.575。因此，审计自演化金融智能体不能仅关注准确率，还需要跟踪行为退化、攻击面接触、未授权金融状态变更以及工件-执行器兼容性。

## Abstract
Self-evolving agents turn experience into reusable skills, workflows, or memories, but post-evolution accuracy alone does not show whether learned behavior preserves previously correct behavior or security. We audit SkillOpt, Agent Workflow Memory (AWM), and ReasoningBank in simulated e-banking using matched benign acquisition trajectories, sealed evaluation endpoints, execution-grounded checks, and independent state replay. On Qwen 3.7 Flash, SkillOpt raises benign utility from 0.741 to 0.837 while exposure to injected content rises from 0.820 to 0.943. Conditional attack success after exposure falls from 0.605 to 0.562, yet overall attack success rate (ASR) rises from 0.496 to 0.530 and unauthorized financial state changes rise to 0.685. Across three independently evolved lineages, capability, exposure, and unauthorized-state changes increase in all three, whereas ASR increases in only two. ReasoningBank raises utility to 0.859 without increasing aggregate ASR, although unauthorized state changes remain slightly above Static. AWM reveals a separate evaluation hazard: a literal WebArena text-action envelope disrupts tool execution in our native function-calling executor. In a post-hoc sensitivity test, removing only that envelope restores utility from 0.319 to 0.756, while exposure rises from 0.299 to 0.909 and ASR from 0.195 to 0.575. Auditing self-evolving financial agents therefore requires tracking regressions, attack-surface contact, unauthorized financial-state change, and artifact-executor compatibility, not accuracy alone.

## 1. 核心问题与研究背景
- 背景：自演化大语言模型智能体可将交互经验转化为可复用的技能、工作流与记忆，能够持续提升任务性能，在金融领域的应用越来越广泛。
- 现有缺陷：传统评估仅关注自演化后的整体任务准确率，无法检测两个核心问题：①演化过程中是否出现原有正确行为的退化；②能力提升的同时，安全属性是否发生漂移，比如是否无意中扩大了提示注入的攻击面，产生更多实际金融危害。
- 核心问题：研究良性自演化过程中，金融智能体的能力变化与安全风险的耦合规律，提出适配的审计框架。

## 2. 提出的方法论
- 核心思想：提出一套基于执行的端到端审计协议，将能力变化、安全风险拆解为多个可量化的独立维度，弥补单一准确率指标的不足。
- 关键技术细节：
  - 基准预校验：提前对原始基准的任务检查规则做正确性验证，修复错误检查项，得到修正后的可信测试集。
  - 盲测设计：将每个任务划分为多个变体，演化阶段仅使用训练变体，所有评估端点在所有演化产物完全冻结前保持密封，避免评估过拟合。
  - 受控演化设计：运行3组独立的完整演化谱系，同一谱系内所有待审计的自演化方法使用字节完全相同的良性训练轨迹，消除训练轨迹噪声对结果的干扰，跨谱系的结果差异用来验证结论的可重复性。
  - 风险指标分解：将整体攻击成功率（ASR）分解为`暴露率（注入内容进入模型可见交互的概率）`和`条件攻击成功率（暴露后攻击成功的概率）`，满足公式 $ASR = P(暴露) \times P(攻击成功|暴露)$（本文实验中未暴露时攻击全部失败，分解完全成立），以此区分"接触攻击内容变多"和"暴露后更容易被攻击"两种不同风险；额外增加`未授权金融状态变更率`指标，直接比对执行后的终端账户状态和合法授权状态，统计产生未授权变更（未授权转账、改密码等）的比例，捕捉攻击者目标之外的实际危害。

## 3. 实验设计
- 场景与数据集：采用修正后的AgentDojo电子银行模拟测试套件，包含15个任务族（原16个，修复后去掉1个无效任务）、9类提示注入攻击目标、11个可调用工具；额外预留12个原始检查规则未修改的任务子集用于敏感性验证。
- 基准与对比方法：以未演化的静态智能体为基准，审计三种当前主流的自演化方案：SkillOpt（基于轨迹编辑更新自然语言技能文档）、Agent Workflow Memory（AWM，从成功轨迹归纳可复用工作流）、ReasoningBank（从成败经验蒸馏提取可检索的推理记忆）。

## 6. 主要结论与发现
- 能力提升和安全漂移是解耦的，安全漂移是方法依赖的，并非能力提升的必然结果：
  - SkillOpt：良性任务效用提升9.6个百分点，但攻击暴露率提升12.3个百分点，未授权金融状态变更率提升10.2个百分点；整体ASR小幅上升3.4个百分点，该上升源于暴露率提升（自演化后更主动读取外部内容，更多接触到攻击注入内容），暴露后的条件攻击成功率反而下降；三个独立谱系中，能力提升、暴露上升、未授权变更上升全部一致，只有整体ASR上升在1个谱系中不成立，说明暴露率和实际状态变更是比整体ASR更稳定的风险指标。
  - ReasoningBank：良性效用提升11.9个百分点，整体ASR没有上升，暴露率还略低于静态基准，但未授权状态变更率仍略高于静态基准。
- 执行-接口不匹配是严重的评估混淆变量：直接移植AWM的WebArena文本动作封包时，和原生函数调用执行器不兼容，导致70%以上的工具调用无法执行，误得出"能力大幅下降、安全性提升"的错误结论；仅移除封包保留原有工作流内容后，效用从0.319恢复到0.756，ASR从0.195上升到0.575，暴露出真实风险。
- 仅看目标攻击成功率会低估实际危害：所有实验条件下，都存在一定比例未达成攻击者预设目标，但依然产生了未授权金融状态变更的情况，基于状态的审计比仅看ASR多识别出17%~29%的有害案例。
- 核心结论：审计自演化金融智能体不能仅依靠准确率，必须同时追踪行为退化、攻击面暴露、未授权金融状态变更、演化工件与执行器兼容性四个维度的指标。

## 7. 优点
- 首次针对自演化金融智能体的安全风险提出了多维度、端到端的可复现审计框架，弥补了传统评估只关注准确率的缺陷。
- 实验设计严谨：通过匹配训练轨迹、密封评估端点、三次独立重复等设计严格控制混杂变量，避免评估偏差，结论可信度高。
- 发现了两个之前被学界忽略的关键风险：①安全漂移可分解为暴露率变化和易感性变化，暴露率是比整体ASR更稳定的风险信号；②执行-接口不匹配会导致完全错误的评估结论，该风险在演化后部署场景中普遍存在但之前未被重视。
- 提前修复了基准测试的验证规则错误，提供了可信的测试基底，所有结果支持独立复现。

## 8. 不足与局限
- 仅在单个主模型（Qwen 3.7 Flash）、单个模拟电子银行场景做了实验，结果不能直接推广到其他模型和生产环境。
- 仅测试了一轮离线良性自演化，没有研究多轮连续自演化的渐进式退化风险。
- 部分敏感性实验为事后设计，跨执行器验证因为基线暴露率已经饱和无法得出有效结论。
- 未见过的任务样本量过小，无法验证跨任务迁移的规律；安慰剂对照实验的长度无法完全匹配，仅能做敏感性分析，无法得出因果结论。
- 三种自演化方法为端到端对比，无法将结果差异归因到单个具体组件（更新规则、表示方式等）。
- 模拟环境缺少部分风险场景（如预定支付删除），部分类型的危害无法观测。
