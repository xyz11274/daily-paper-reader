## 摘要
智能体框架决定了语言模型智能体如何使用指令、工具和运行时组件，但适配这些框架需要高昂的验证成本。现有提出-验证方法通常在固定任务集上对每个候选打分，会在不相关行为上浪费采样轮次，还会让聚合分数掩盖特定的回归问题。我们提出HarnessLens，这是一个预算感知的自动化框架进化框架。HarnessLens联合探索任务空间与用户可配置组件，从执行轨迹中导出候选修改，并借助可归因证据门控，在与行为相关的任务上选择性验证每个候选。在三个智能体框架和四个基准上的实验表明，HarnessLens将平均留出性能提升了7.6-13.6%，同时消耗的评估预算远低于对比基线。这些结果证明，在交互预算受限的情况下，带有显式归因的行为感知验证能够实现更可靠、样本效率更高的框架进化。我们的代码可在https://github.com/jhxu5214/HarnessLens获取。

## Abstract
Agent harnesses shape how language-model agents use instructions, tools, and runtime components, but adapting these harnesses requires costly verification. Existing propose-and-verify methods typically score every candidate on a fixed task set, wasting rollouts on unrelated behaviors and allowing aggregate scores to obscure specific regressions. We introduce HarnessLens, a budget-aware framework for automated harness evolution. HarnessLens jointly explores the task space and user-configurable components, derives candidate modifications from execution trajectories, and selectively verifies each candidate on behavior-relevant tasks using an attributable-evidence gate. Across three agent harnesses and four benchmarks, HarnessLens improves average held-out performance by 7.6-13.6% while consuming substantially less evaluation budget than competing baselines. These results demonstrate that behavior-aware verification with explicit attribution enables more reliable and sample-efficient harness evolution under constrained interaction budgets. Our code is available at https://github.com/jhxu5214/HarnessLens.

## 1. 核心问题与研究背景
- 智能体框架（Agent Harness）是决定LLM智能体感知任务、调用工具、执行动作的基础结构，包含指令、技能、工具描述、内存等可配置组件，直接决定LLM智能体的任务性能。
- 研究背景：手动设计适配的有效框架成本极高，且训练好的框架难以跨模型/环境迁移，亟需自动化的框架自主进化方案。
- 现有方案缺陷：当前自动进化普遍遵循「提出-验证」范式，但验证环节均采用固定任务集、随机批次或预选择子集，不对候选修改适配验证任务，存在三个核心问题：
  1. 大量验证任务与修改目标行为无关，浪费交互预算与采样轮次
  2. 无关任务带来的噪声会稀释修改本身的性能信号，聚合评分容易掩盖特定行为的性能退化（回归问题）
  3. 验证产生的轨迹证据没有系统性复用到后续进化过程中，样本利用率低

## 2. 提出的方法论
### 核心思想
针对每个候选框架修改，基于修改的目标行为、影响组件、回归风险自适应选择验证任务，通过可归因的行为证据判断修改是否保留，在有限交互预算内实现高效可靠的框架进化。

### 问题定义
将框架进化定义为**固定交互预算约束下的预期成功率最大化问题**：从初始框架出发，在总交互次数不超过预算B的前提下，搜索能最大化任务成功率的框架配置，最终性能用留出测试集的通过率衡量。

### 算法流程与关键技术
HarnessLens分为三个核心阶段，全程由确定性控制器管控预算、复用轨迹：
1. **上下文探索**
   - 任务空间探索：仅基于训练任务的查询、环境描述，按目标对任务分组，不执行任务，为后续验证任务选择提供依据
   - 框架空间探索：分析现有框架的配置、文档和运行时行为，识别所有可修改的用户配置组件，记录每个组件的修改方式、影响的行为范围
2. **轨迹诊断**
   - 经验提取：从初始框架和后续验证的执行轨迹中，提取可复用的成功经验和重复出现的缺陷，每个经验/缺陷关联对应支撑轨迹
   - 经验分析：结合任务分组和可修改组件信息，生成修改提案，过滤证据不足的提案，供后续进化使用
3. **框架进化（迭代式改进）**
   每一轮迭代包含三个核心步骤：
   - 候选生成：基于剩余预算、证据强度、回归风险选择一个提案，生成候选框架，做轻量运行时检查，失败直接淘汰
   - 行为感知验证（核心创新）：针对候选修改选择验证批次，优先选择支撑提案的轨迹对应任务、同目标分组的相关任务、能检测回归的原有成功任务；批次大小满足剩余预算约束，在当前框架和候选框架上用匹配条件做验证，再做轨迹诊断获取行为变化
   - 归因证据门控与更新：只有当修改存在可归因的目标行为改进、且无观测到的可归因回归时，才进入二次确认批次；二次确认后同时满足行为证据有效、整体指标提升才更新当前框架。
   - 迭代终止：当没有足够证据的提案、或剩余预算不足以完成下一轮验证时终止，返回最终框架。

## 6. 主要结论与发现
1. HarnessLens在极低预算下实现了最优性能：相比现有方法，HarnessLens将平均留出测试性能提升了7.6%~13.6%（OpenCode提升13.6%，Codex提升7.6%，Pi提升9.2%），仅消耗HarnessFix约2/3预算、Self-Harness约1/24预算
2. 行为感知验证天然避免回归：HarnessLens从未出现性能低于初始框架的情况，而现有基线方法在一半的实验设置中出现了性能退化
3. 更多验证轮次不代表更好的框架：基线中预算最高的Self-Harness性能反而最差，固定任务集验证容易积累有害修改，只有针对性验证才能提升泛化性能
4. 两个核心创新缺一不可：移除行为感知批次选择或归因证据门控都会导致性能大幅下降，二者共同作用才实现高效进化。

## 7. 方法与实验亮点
