## 摘要
面向用户端产品的LLM智能体可靠部署，其核心依赖并非原始任务解决能力，而是一致性与限界感知：即在重复试验中保持行为一致，且能够识别请求何时无法、或尚且无法被安全满足。CAR-bench在车载助手领域揭示了这一可靠性缺口：由LLM模拟的用户会发出不完整或模糊的请求，要求智能体通过多轮对话与工具使用消除不确定性，同时严格遵守领域策略。即便前沿模型，在其至少一次可解决任务（Pass@3）与跨试验持续可解决任务（Pass^k）之间也存在显著差距。我们通过TRACE（TRAjectory-Contrastive Evolution，轨迹对比进化）弥合了这一差距，该方法无需修改模型权重，即可迭代提升基于技能的智能体的行为知识。这些知识被组织为由模块化可检索技能构成的技能库，每个技能编码一套独立完整的工具使用规则与行为准则。TRACE通过智能体自进化循环演化该技能库：每轮评估结束后，它按调用的技能对轨迹分组，通过对比成功与失败行为精炼每个技能。更新后的技能库将指导后续轮次，而在部署阶段，动作器会在每一步执行基于状态的技能编排。在GPT-5.5上，TRACE将一致性指标（Pass^3）提升了34.6个百分点，从59.9%升至94.5%，同时将潜在性能与可靠性能之间的差距缩小至仅4.0个百分点。在官方隐藏测试集上，TRACE使用GPT-5.6-Sol获得第一名，Pass^3得分达到70%，相较基线实现了40%的相对提升。这些结果表明，TRACE可将模型的高潜力转化为稳定、一致的性能增益。项目主页：https://darwin-agent.github.io/Car-bench-TRACE

## Abstract
Reliable deployment of LLM agents in user-facing products depends not on raw task-solving ability but on consistency and limit-awareness: behaving the same way across repeated trials, and recognizing when a request cannot, or cannot yet, be safely fulfilled. CAR-bench exposes this reliability gap in the domain of in-car assistants: an LLM-simulated user issues incomplete or ambiguous requests, requiring the agent to resolve uncertainty through multi-turn dialogue and tool use while strictly adhering to domain policies. Even frontier models show a substantial gap between what they can solve at least once (Pass@3) and what they solve consistently across trials (Pass^k). We bridge this gap with TRACE (TRAjectory-Contrastive Evolution), which iteratively improves a skill-based agent's behavioral knowledge without modifying model weights. This knowledge is organized as a Skill Bank of modular, retrievable skills, each encoding a self-contained set of tool-use rules and behavioral guidelines. TRACE evolves this bank through an agentic self-evolution loop: after each evaluation round, it groups trajectories by the skills invoked and refines each skill by contrasting successful and failed behaviors. The updated bank then guides subsequent rounds, while during deployment the Actor performs state-conditioned skill orchestration at every turn. On GPT-5.5, TRACE improves consistency (Pass^3) by 34.6 points, from 59.9% to 94.5%, while shrinking the gap between potential and reliable performance to just 4.0 points. On the official hidden set, TRACE achieved first place using GPT-5.6-Sol, attaining a Pass^3 score of 70%-a 40% relative improvement over the baseline. These results show that TRACE converts high model potential into stable, consistent performance gain. Project homepage: https://darwin-agent.github.io/Car-bench-TRACE.

# 2. 论文提出的方法论
## 核心思想
提出**TRACE（轨迹对比进化，TRAjectory-Contrastive Evolution）框架**，不需要修改底层模型权重，通过构建自进化的模块化技能库存储可复用的行为知识，将模型的潜在任务能力转化为稳定一致的可靠表现，框架是模型无关的，可适配任意底层大模型。

## 关键技术与流程
框架包含两个互补角色的智能体：负责执行任务的`Actor（动作器）`和负责优化技能库的`Curator（策展器）`，整体分为三个阶段：
1. **技能库初始化**：Curator通过自底向上分层抽象构建初始库
   - 任务级蒸馏：对每个任务对比多次评估轨迹，提炼包含成功行为和常见失败模式的任务级技能
   - 类型级聚合：按任务类型合并任务级技能，删除任务特定细节，保留同类任务共享的行为规则
   - 操作级抽象：跨任务类型按底层操作合并技能，相同操作的行为规则统一为可复用能力，实现跨场景知识迁移
   - 技能分解：将泛化的大技能拆分为细粒度的单一能力技能，保证推理时可精准激活，最终每个技能由「一句话描述（用于路由匹配）」和「技能本体（包含工具规则、行为准则、避坑提示）」组成
2. **轨迹对比驱动的迭代技能进化**：每轮评估后Curator更新技能库
   - 按技能分组：将轨迹按本轮调用的技能分组，未匹配的轨迹单独存放用于挖掘新技能
   - 部署忠实重建：区分推理阶段Actor可见信息和进化阶段Curator的特权信息，保证优化后的技能不依赖推理阶段无法获取的信息
   - 对比精炼：对已有技能，结合成功/失败轨迹总结错误模式并更新技能，过大技能进一步拆分；对未匹配轨迹挖掘新技能；最终删除任务id、记忆化答案、环境特定值，通过严格去硬编码保证可迁移性
3. **部署阶段状态条件技能编排**：推理每轮重新动态编排
   - 基于当前对话历史匹配所有技能描述，自动决定激活的技能数量、排序，得到有序技能序列
   - 按顺序提取技能本体，和对话历史组合成最终prompt生成动作，更新对话状态后下一轮重新编排，保证技能始终匹配当前对话进度。

# 3. 实验设计
- **测试场景与基准**：使用CAR-bench车载智能体基准，包含58个互联工具、19条领域规则，任务分为三类：①基础任务（测试常规任务完成）②幻觉任务（故意移除所需能力，要求智能体承认缺失而非伪造）③消歧义任务（引入可控歧义，要求智能体合理消歧必要时确认）
- **评估指标**：`Pass@k`（k次试验至少做对一次的任务占比，衡量潜在能力）、`Pass^k`（k次试验全部做对的任务占比，衡量可靠一致性），二者差值为一致性缺口，越小越好。
- **对照设置**：对比同一底层大模型的「默认提示+原生工具调用」基线，仅增加TRACE的技能库和技能编排，控制变量验证TRACE增益；测试了GPT-5.5（中等推理强度）、GLM-5.2（高推理强度）两个底层 backbone，技能库仅用GPT-5.5轨迹进化，直接迁移到两个 backbone 测试跨模型迁移能力；额外增加CAR-bench官方隐藏集的盲测评估泛化能力。

# 6. 主要结论与发现
- TRACE大幅提升一致性，缩小可靠性缺口：GPT-5.5上Pass^3提升34.6个百分点（从59.9%到94.5%），一致性缺口从27.8个百分点缩小到仅4.0个百分点；GLM-5.2上Pass^3提升22.0个百分点。
- 技能库具备跨模型迁移能力：仅用GPT-5.5轨迹进化的技能，直接迁移到GLM-5.2仍能带来显著增益，说明学到的是可迁移的行为规则而非特定模型的拟合模式。
- 对安全敏感的难点任务提升最显著：基线表现最差的消歧义任务，GPT-5.5上Pass^3从39.3%提升到94.6%，大幅抹平了不同任务类型的性能差距。
- 泛化能力达标：在CAR-bench官方隐藏集取得第一名，Pass^3达到70%，相较基线提升20个百分点（相对提升40%），没有过拟合公开训练集。
- 开销trade-off：Pass^3相对提升40%仅带来22%的相对延迟增加，性能增益远大于延迟开销，但token使用量和推理成本有明显上升。

# 7. 方法与实验的亮点
- 切中产业落地痛点：不同于多数研究关注提升原始任务解决能力，TRACE聚焦产品化必需的一致性和限界感知，对准实际落地需求。
- 落地成本低：模型无关，不需要微调修改底层模型权重，仅在推理侧增加行为知识引导，适配闭源商用大模型。
- 可迁移性设计：操作级抽象+严格去硬编码约束，避免过拟合特定任务，学到通用可复用的行为规则。
- 动态适配多轮对话：每轮重新基于当前状态做技能编排，保证技能始终匹配对话进展，适配多轮交互的动态变化。
- 实验设计严谨，控制变量严格，结论可信度高。

# 8. 不足与局限
- 可扩展性不足：当前技能编排是让大模型每轮匹配所有技能描述，技能库规模扩大后效率会明显下降，需要引入学习型或分层编排方法。
- 无在线进化能力：技能仅在离线评估阶段进化，部署后没有从在线任务执行到技能库的反馈更新通道，无法在运行时动态修正技能。
- 推理开销较高：每 trial 平均token量提升72.4%，推理成本提升58.8%，仍需要进一步优化压缩。
