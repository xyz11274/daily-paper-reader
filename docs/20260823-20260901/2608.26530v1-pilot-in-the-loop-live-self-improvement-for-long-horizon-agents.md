## 摘要
长时域智能体运行会生成可同时改进当前运行与未来工作的经验。大多数自我改进方法仅在执行结束后处理该经验，因此无法调整正在进行的当前运行，也不能立即应用并验证从中获取的经验教训。我们认为自我改进应当改为实时进行，利用新产生的经验同时调整当前运行并更新持久框架。现有智能体架构无法完全支持这一目标：单智能体自校正将任务执行与轨迹评估合并在同一上下文内，而子智能体委托虽然分离了执行，但通常无法重定向正在运行的活跃子智能体。我们提出PILOT，这是一个用于实时自我改进的管理者-工人框架，通过两种耦合机制实现目标：（1）实时引导允许独立的管理者在执行过程中重定向或终止活跃的工人；（2）实时自演化将执行过程中显现的流程与故障模式提炼为可复用的技能与记忆。在两个固定主干模型和三个基准测试上，PILOT在六种配置中的五种排名第一。在Terminal-Bench 2.0上，PILOT相比同类框架最高超出9.8个百分点。在自我改进设置下，PILOT结合GLM-5.1提升14.6个点，结合Kimi-K2.6提升12.4个点。平均输出token数分别下降42.9%和47.4%，而每百万输出token的成功评估数分别提升110.3%和134.0%。

## Abstract
Long-horizon agent runs generate experience that can improve both the current run and future work. Most self-improvement methods process this experience only after execution ends, so they cannot redirect the active run or immediately apply and validate lessons learned from it. We argue that self-improvement should instead be live, using emerging experience both to redirect the active run and to update the persistent harness. Existing agent architectures do not fully support this goal. Single-agent self-correction combines task execution and trajectory assessment within one context, while subagent delegation separates execution but typically cannot redirect an active subagent. We present PILOT, a supervisor-worker harness for live self-improvement through two coupled mechanisms: (1) live steering lets a separate supervisor redirect or abort the active worker during execution; and (2) live self-evolution distils procedures and failure modes revealed during execution into reusable skills and memory. Across two frozen backbones and three benchmarks, PILOT ranks first in five of six configurations. On Terminal-Bench 2.0, PILOT outperforms counterpart harnesses by up to 9.8 percentage points. In the self-improvement setting, PILOT gains 14.6 points with GLM-5.1 and 12.4 points with Kimi-K2.6. Mean output tokens fall by 42.9% and 47.4%, while successful evaluations per million output tokens rise by 110.3% and 134.0%, respectively.

# 论文详细总结
## 1. 核心问题与研究背景
- 背景：长时域（长周期）智能体执行任务过程中会产生大量经验，这些经验既可以修正当前正在运行的任务，也可以提升未来同类任务的表现。
- 现有方法缺陷：
  1. 绝大多数自我改进方法都是事后处理，仅在任务运行结束后才提取经验，无法修正当前正在执行的任务，也不能立即验证新学到的经验，效率和可靠性不足。
  2. 现有架构存在缺口：单智能体自校正方案中，同一个智能体需要同时承担任务执行和错误诊断，执行细节会占用诊断所需的上下文，影响错误识别效果；子智能体委托方案虽然分离了执行和监督，但主智能体只能等待子智能体运行结束后获取结果，无法中途重定向正在运行的活跃子智能体。
- 核心诉求：需要支持实时自我改进的架构，同时实现「修正当前活跃运行」和「更新持久化知识」两个目标。

## 2. 提出的方法论
### 核心思想
将自我改进改为实时进行，提出监督-工人（supervisor-worker）分离的架构`PILOT`，用运行过程中产生的新经验同时修正当前任务、更新持久化框架（harness），形成自我改进闭环。

### 关键技术细节
PILOT核心是两个耦合机制：
1. **实时引导（Live Steering）**
   - 监督者和工人通过双向实时通道保持连接，工人侧支持三类事件上报：通知（报告进度/中间结果/风险，上报后继续执行不暂停）、提问（需要监督输入时暂停等待回复）、结果（任务完成后上报最终结果）。
   - 监督者侧支持两类操作：引导（发现工人走偏时，检查对应轨迹后给工人下一步下发引导指令）、终止（判断继续运行无意义时直接中断当前工人会话）。
   - 工人上下文隔离，执行探索、死胡同、冗余输出都保留在工人独立上下文中，监督者上下文仅保留目标、全局事件、偏差信息，避免执行细节分散监督注意力。

2. **实时自演化（Live Self-Evolution）**
   - 监督者在运行过程中即可提取成功流程、项目规范、失败模式等可复用知识，实时更新持久化框架的技能库和记忆。
   - 之后 spawn 的新工人（无论同任务还是未来任务）都会加载更新后的框架，形成完整的自我改进闭环。
- 实现说明：PILOT基于Pi编码智能体运行时扩展，使用同一个冻结主干模型同时承担监督者和工人角色，仅更新框架的技能和记忆，不更新模型参数。

## 3. 实验设计
- 测试场景与基准：共使用3个长时域真实任务基准，覆盖两类任务域：
  1. Terminal-Bench 2.0：包含89个需要多步shell操作的系统/工程任务
  2. SWE-bench Multilingual：多语言仓库级代码修复基准
  3. SWE-bench Pro：更长、更难的仓库级issue修复基准
- 主干模型：使用两个冻结开放权重模型GLM-5.1和Kimi-K2.6，同一个模型同时承担监督者和工人角色，控制变量排除模型能力差异的影响。
- 对比基线：
  - Terminal-Bench 2.0 对比：Pi、OpenCode、Terminus 2、Hermes
  - 代码修复基准 对比：Pi、OpenCode、Mini-SWE-Agent、Hermes
- 评估设置：
  1. 一次性设置：每个任务从零开始使用全新框架，测试实时引导对当前任务的修正效果
  2. 自我改进设置：将Terminal-Bench 2.0任务分为多轮迭代，每轮所有任务共享框架，运行过程仅允许用自身轨迹和环境反馈更新框架，不提前开放基准验证信号，仅在一轮结束后保留成功任务的更新到下一轮框架，测试完整实时自改进闭环效果。

## 6. 主要结论与发现
1. 一次性设置下，PILOT在6组骨干-基准配置中5组排名第一，Terminal-Bench 2.0上对比同类基线最高提升9.8个百分点，提升效果跨主干、跨任务域通用，难任务提升幅度更大。
2. 自我改进设置下，PILOT通过率随迭代持续提升：GLM-5.1提升14.6个百分点，Kimi-K2.6提升12.4个百分点，远高于基线Pi（提升2.3个百分点）和OpenCode（提升7.9个百分点）。
3. 自改进过程中，PILOT的技能库持续增长，token效率大幅提升：平均输出token数降低42.9%~47.4%，每百万输出token的成功任务数提升110.3%~134.0%。
4. 实时引导的价值主要体现在难任务上，简单任务本身在工人能力范围内不需要外部纠正，难任务执行链长、错误容易累积，实时引导能提前纠正偏差挽回任务。

## 7. 方法与实验亮点
1. 首次明确提出长时域智能体实时在线自我改进的问题，填补了现有架构的缺口，将当前任务纠正和未来知识更新整合为统一闭环。
2. 架构设计简洁清晰，通过监督-工人角色分离解决了现有方案的固有缺陷，两个核心机制易落地实现。
3. 实验设计严谨，控制变量到位，覆盖多种真实场景，不仅验证了任务性能提升，还验证了推理成本的下降，实际应用价值突出。

## 8. 不足与局限
1. 迭代式自我改进需要多次运行任务，算力成本远高于单次推理，因此当前实验仅覆盖3个基准和2个开放权重主干，更广泛的基准测试和闭源模型验证留作未来工作。
2. 当前实验中监督者和工人使用同一个主干模型，没有探索不同能力模型配对的方案，也没有分析异质配对在监督质量、任务性能和成本之间的权衡关系。
