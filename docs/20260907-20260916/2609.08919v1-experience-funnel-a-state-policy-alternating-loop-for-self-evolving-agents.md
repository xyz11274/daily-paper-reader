## 摘要
由大语言模型（LLM）驱动的自主智能体通过交互不断积累经验，这为通过自进化改善未来行为创造了机会。一个根本性挑战在于：如何将丰富但任务特定的交互经验转化为可复用的模型能力，同时又不牺牲对新观测证据的快速适应能力。显式文本状态（如技能与智能体运行框架）能够提供快速、人类可读且可编辑的适应方式，但会导致对外部上下文的持续依赖；参数化策略则提供紧凑且可复用的能力，但更新速度要慢得多。我们提出“经验漏斗”（Experience Funnel），一种自进化框架，通过交替循环将快速的状态适应与缓慢的策略固化耦合起来。交互轨迹首先被蒸馏为显式文本状态，新获得的经验可在其中被快速纳入并验证。随后，该框架有选择地识别那些在状态多次修订后仍然有用的、由状态所支持的行为，并通过感知状态转移的蒸馏将其固化到策略中。更新后的状态—策略对继而生成新的轨迹，为下一轮状态适应与策略固化提供新的证据。在多种智能体基准上的实验表明，“经验漏斗”在智能体能力上持续优于仅进行状态演化和策略内化的方法，同时逐步将有用的显式经验转化为自主的策略能力。

## Abstract
Autonomous agents powered by large language models (LLMs) continuously accumulate experience through interaction, creating an opportunity to improve future behavior through self-evolution. A fundamental challenge is how to transform abundant, task-specific interaction experience into reusable model competence without sacrificing the ability to adapt rapidly to newly observed evidence. Explicit textual states, such as skills and agent harnesses, provide fast, human-readable and editable adaptation, but incur persistent dependence on external context; parametric policies provide compact and reusable competence, but are substantially slower to update. We present \textit{Experience Funnel}, a self-evolving framework that couples fast state adaptation with slow policy consolidation in an alternating loop. Interaction trajectories are first distilled into an explicit textual state, where newly acquired experience can be rapidly incorporated and validated. The framework then selectively identifies state-enabled behavior that remains useful across state revisions and consolidates it into the policy through transition-aware distillation. The updated state--policy pair subsequently generates new rollouts, providing fresh evidence for the next round of state adaptation and policy consolidation. Experiments across diverse agent benchmarks show that \textit{Experience Funnel} consistently improves agent capability over state-only evolution and policy-internalization approaches, while progressively converting useful explicit experience into autonomous policy competence.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在反复交互中不断积累经验（成功轨迹揭示有效策略，失败轨迹暴露决策错误与能力缺口），但如何把大量**任务特定**的交互经验转化为**可复用的模型能力**，同时不牺牲对新证据的快速适应，是自进化的根本难题。
- **两条既有路线各有硬伤**：
  - **显式文本状态**（记忆、技能、流程指令、agent harness）：可快速修改、人类可读可编辑，但持续依赖外部上下文；无限累积会推高检索与上下文开销，引入冗余/冲突指导，管理复杂度不断上升。
  - **参数化策略**（RL / 蒸馏内化）：能力紧凑、可复用、无需外部上下文，但更新慢；若把全部观测经验立即吸收进参数，会把噪声、样本特异的、或已掌握的行为一并固化。
- **关键洞察**：显式经验的价值是**策略依赖**的——对当前策略有用的指导，在策略提升后可能变冗余、互补甚至冲突。因此核心挑战不是"积累更多经验"，而是**如何让经验在显式状态与参数策略之间逐步迁移**，并保留快速可编辑的适应通道。
- **现有工作的空白**：SkillOpt、ACE、SkillRL、ReSkill、HarnessForge、OPID、SEED 等分别解决了"文本技能演化"或"技能内化"的局部问题，但未回答：经验应如何从原始轨迹**逐级过滤**为可编辑状态、**选择性固化**为长期策略能力，并在策略演化后**重新审视**？

## 2. 方法论：Experience Funnel

### 2.1 总体思想
用一个**状态—策略交替循环**把"快的状态适应"与"慢的策略固化"耦合起来，演化链为：
(S_k, π_k) → S_{k+1} → π_{k+1} → S_{k+2} → π_{k+2} → …

### 2.2 阶段一：状态演化（State Evolution）
- **反思批次**：当前状态—策略对部署并收集足够轨迹后冻结为一个 reflection batch，做**跨轨迹**（而非单样本）的模式识别。
- **候选编辑生成**：把反复出现的可复用流程、常见失败模式、纠正策略总结为对当前状态的高层文本编辑（如"匹配任务要求的精确名词""忽略语义干扰项""行动前先核验对象"）。
- **验证门控**：候选更新在**独立留出验证集**上、以当前策略执行，只有提升环境级结果才被接受，从而过滤样本特异或不可靠的编辑。
- **状态修订**：接受更新后，用新策略重新部署，后续轨迹既提供新经验，也提供关于已有指导效用的**延迟证据**——互补部分保留/精炼，冗余部分退役，未解决失败触发新编辑。策略条件化的修订避免了文本指导的无限膨胀。

### 2.3 阶段二：Transition-Aware Skill Distillation
**（a）轨迹级选择（决定"固化什么"）**
对每个实例 x_i，用当前策略 π_k 在三种条件下评估：
- r⁰_i = R(π_k, x_i)（无状态）、r⁻_i = R(π_k, x_i, S_k)（旧状态）、r⁺_i = R(π_k, x_i, S_{k+1})（新状态）

相对无状态执行的效用：b⁻_i = I[r⁻_i > r⁰_i]，b⁺_i = I[r⁺_i > r⁰_i]。由此区分四类行为：
- **新近有用 (0,1)**、**持续有用 (1,1)**、**退步 (1,0)**、**无效 (0,0)**

轨迹权重 a_i：新近有用取 1，持续有用取 α，其余取 0（仅保留前两类参与固化）。

**（b）Token 级归因（决定"在哪里蒸馏"）**
在相同前缀下比较冻结策略带/不带已接受状态的预测分布 p⁺_{i,t} 与 p⁰_{i,t}（同一模型参数，仅文本状态条件不同），用 **Jensen–Shannon 散度** d_{i,t} = D_JS(p⁺‖p⁰) 量化局部行为响应，并在轨迹内归一化为 w_{i,t}。

**（c）策略固化**
- π_θ 从 π_k 初始化，**只接收无状态上下文**；状态条件分支 p⁺ 充当特权监督（privileged supervision）。
- 蒸馏损失：L_distill = Σ a_i w_{i,t} · D_KL(π_θ(·|x_i, y_{i,<t}) ‖ p⁺_{i,t}) / Σ a_i w_{i,t}，即把监督集中在"既影响结果、又对状态条件敏感"的决策上。
- 总目标：L_consolidate = L_state-free_RL + λ_distill · L_distill（图中标注奖励优化使用 GRPO）。
- 候选策略 ˜π_{k+1} 仅当其**无状态性能**通过验证准则时才提交，随后与新状态一起重新部署，开启下一轮。

- **跨环境验证**：ALFWorld（具身交互）、WebShop（网页导航），检验状态—策略模式是否可迁移。
- **对比基线（三类）**：
  - 基础模型：Qwen3.5-4B
  - 显式状态演化：SkillOpt-Lite、SkillOpt
