## 摘要
设计有效的Lean证明智能体是形式数学推理中的核心挑战。除了构建更强的证明器之外，近期工作强调围绕Lean的工作流程：智能体如何分解证明义务、使用工具和编译器反馈、诊断失败、修复证明以及维护结构化证明上下文。受代码级自进化智能体的启发，我们研究这些工作流程是否可以进化而非手工设计。我们提出一种自进化的Lean证明智能体，其中一个小型固定可信运行时包裹一个完全可变的工作空间：证明工作流程、提示和工具。与大多数针对固定外部基准进行优化的自进化系统不同，我们的系统使智能体及其基准协同进化。在代际之间，最高得分智能体（冠军）通过掌握阈值控制的课程更新来修订活跃任务分布，仅在当前级别掌握后才引入更难的证明义务，并且通过单锚重校准在更新后的基准上重新运行冠军，以使分数随难度上升而保持可比性。所有进化都保持在基于Lean的验证循环内：无论智能体如何重写自身，只有当其行为在可信快照下产生Lean验证的证明时才计为成功，并且每次尝试必须生成机器可读、基于Lean的证明上下文，其表示可以进化但锚定被强制执行。我们运行协同进化轨迹和固定基准基线15个活跃代，并在保留的miniF2F测试集上进行比较。最佳协同进化智能体达到45.1%的保留解决率，而种子为12.7%，最佳固定基准智能体为32.0%，表明基于验证器的自进化可以在协同进化基准下改进Lean证明工作流程。

## Abstract
Designing effective Lean proof agents is a central challenge in formal mathematical reasoning. Beyond building stronger provers, recent work emphasizes the workflow around Lean: how an agent decomposes proof obligations, uses tools and compiler feedback, diagnoses failures, repairs proofs, and maintains structured proof context. Motivated by code-level self-evolving agents, we study whether such workflows can be evolved rather than hand-designed. We present a self-evolving Lean proof agent in which a small fixed, trusted runtime wraps a fully mutable workspace: the proof workflow, prompts, and tools. Unlike most self-evolving systems, which optimize against a fixed external benchmark, our system coevolves the agent and its benchmark. Between generations, the highest-scoring agent (the champion) revises the active task distribution through a mastery-throttled curriculum update that introduces harder proof obligations only after the current level is mastered, and a single-anchor recalibration re-runs the champion on the updated benchmark to keep scores comparable as difficulty rises. All evolution stays inside a Lean-grounded verification loop: however the agent rewrites itself, a success counts only when its behavior yields Lean-verified proofs under a trusted snapshot, and each attempt must emit a machine-readable, Lean-grounded proof context whose representation may evolve but whose groundedness is enforced. We run the coevolving trajectory and a fixed-benchmark baseline for 15 active generations and compare them on a held-out miniF2F test split. The best coevolving agent reaches a 45.1% held-out solve rate, versus 12.7% for the seed and 32.0% for the best fixed-benchmark agent, showing that verifier-grounded self-evolution can improve Lean proof workflows under a coevolving benchmark.

## 2. 方法论：核心思想、关键技术细节

### 核心思想：固定可信运行时 + 可变工作区 + 协同进化基准

- **固定可信运行时**：负责所有与正确性和奖励相关的机制（Lean验证、评估、基准管理、证明上下文验证），不参与进化搜索。运行时使用一个固定的Lean snapshots来重验证每个证明，防止智能体伪造证明。
- **可变工作区**：包含智能体的证明工作流、提示模板、工具代码。智能体通过受限编辑接口重写自身代码，每次修改后的智能体必须先通过代码级冒烟测试（基本执行检查），然后进入评估。
- **证明上下文契约**：每个证明尝试必须返回三元组 (ok, proof_body, proof_context)。proof_context的表示可自由演进（图、树、列表等），但必须满足接地要求：根节点存在、至少一个非根数学声明、依赖边指向已知项、任何标记为“已解决”的项必须由Lean验证证据支撑。可信运行时独立重验证所有claimed解决的证明和证书。
- **基准协同进化**：从难度分层的候选池中选取主动基准（初始76题，L1:L2:L3=27:46:3）。每代结束后，若冠军的原始解决率 > γ (0.30)，则触发基准更新：
  - 从被该代所有智能体解决的题目中最多移除κ个（κ=6），优先移除低难度题目。
  - 对每个移除的题目，若冠军在该难度的解决率 ≥ τ (0.70)，则从下一级难度（ℓ+1）替换；否则从同级横向替换。
  - 替换时优先选择已有失败记录较多的领域（weakness-driven）。
- **单锚校准**：为了保持分数跨代可比，将冠军在新基准上的原始解决率与系数c结合，更新 c_{t+1} = c_t * r_t / max(r_{t+1}, ε)，初始c_0=1。这样冠军的归一化分数保持不变，其他智能体的归一化分数=原始分数×c。
- **父代选择**：在代内使用基于带权重的选择，权重 w = max(q, 0) / (1+n_c)，其中q为归一化分数，n_c为该智能体的子代数。代内采用流式架构：一个智能体一旦被评估即立刻可作父代，从而允许早期强子代产生更多后代。

## 6. 主要结论与发现

- **协同进化显著提升泛化能力**：最佳协同进化智能体（c144，第15代）在held-out miniF2F test上达到45.1%解决率，而种子仅12.7%，固定基准最优智能体为32.0%。
- **固定基准的局限性**：固定基准下进化很快饱和，后期突变主要保持现有性能而非开拓新能力；协同进化通过基准硬化迫使智能体不断拓展。
- **演化的工作流以修复为中心**：高分智能体普遍采用紧凑的Lean-error修复循环（生成完整证明→检查错误→有限次重试），而非分解优先的蓝图工作流。分解工作流出现过但通常被修剪，因为其复杂性和组装困难。
- **工具演化主要用于对抗幻觉**：智能体自发开发了引理名称检查、验证签名缓存、namespace搜索等工具，防止虚构Lean名称进入证明。
- **证明上下文变得可检查但未深入**：尽管契约要求接地，但智能体更倾向于从最终证明中提取have节点构成浅层星状图，而非深层的已验证子目标图。只有少数分支（c44/c47）实现了细粒度节点级验证。
- **验证器接地是有效的防欺骗机制**：所有claimed solves都经过Lean重验证，可信运行时防止了智能体自报告虚假成功。
