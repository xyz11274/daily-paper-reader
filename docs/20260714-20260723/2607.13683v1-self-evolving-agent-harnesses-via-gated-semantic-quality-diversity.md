## 摘要
LLM智能体的真实任务表现既取决于其模型的冻结部分，也取决于周围的框架：提示词、注入知识、运行时控制与配置。在部署中，框架通常是唯一可用的杠杆，因此自动改进它是提升性能的自然途径，而无需修改权重。难点不在于生成变更，而在于判断哪些变更真正有效。自生成的反馈充满噪声，表面上的提升可能是测量伪像或仅过度拟合调优任务的编辑。我们提出一个自演化智能体框架，将提议变更与信用分配分离：语言模型诊断失败并提出补丁，而所有采样、测量和显著性检验由确定性代码负责，因此每个被认可的改进在设计上都是可信的。补丁填充一个基于门控的分类质量多样性存档（GSME），其键值对应于补丁所解决的病理（WHERE x WHY），而非它修复的任务——这是一种抗过拟合的归纳偏置；泛化能力在演化完成后通过密封测试集进行评估。在七个领域中使用冻结的开源模型，框架通过训练选择并在密封测试中计分一次；其认可的增益为+9至+15.5个百分点，且保留了训练增益的86-147%，证明其泛化而非过拟合。获胜补丁追踪模型的主导病理，而非其规模或族系：更换模型会改变病理与补丁，而相同的病理-补丁匹配在两个模型族系中重复出现。可迁移的是诊断与信用分配循环，而非任何特定框架。

## Abstract
An LLM agent's real-task performance is shaped as much by the harness around its model as by the frozen model itself: its prompts, injected knowledge, runtime control, and configuration. In deployment the harness is often the only lever available, so improving it automatically is the natural way to raise performance without touching the weights. The hard part is not generating changes but knowing which one truly helped. Self-generated feedback is noisy, and an apparent gain can be a measurement artifact or an edit that merely overfits the tasks it was tuned on. We present a self-evolving agent-harness framework that separates proposing changes from crediting them: a language model diagnoses failures and proposes patches, while all sampling, measurement, and significance testing are owned by deterministic code, so every credited improvement is trustworthy by construction. Patches populate a gated, categorical quality-diversity archive (GSME) keyed on the (WHERE x WHY) pathology an edit addresses rather than the tasks it fixes, an anti-overfitting inductive bias; generalization is measured on a sealed test scored only after evolution. Across seven domains with a frozen open-weight model, the harness is train-selected and scored once on a sealed test; its credited gains there are +9 to +15.5pp and retain 86-147% of the training gain, evidence they generalize rather than overfit. The winning patch tracks the model's dominant pathology, not its size or family: changing the model can change the pathology and the patch, while the same pathology-to-patch match recurs across two model families. What transfers is the diagnose-and-credit loop, not any specific harness.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：LLM 智能体的实际表现受限于其外围框架（*harness*：提示词、注入知识、运行时控制、配置等），而非仅依赖冻结的模型权重。在部署中，框架通常是唯一可调节的杠杆。
- **挑战**：自动改进框架面临两个核心困难：
  - 自我生成的反馈噪声大：单次评估波动、沙箱不稳定、验证器超时等测量伪像会导致虚假提升。
  - 搜索空间巨大且易过拟合：贪婪搜索会崩溃到少数安全编辑（如提示词调整），且补丁容易过拟合到训练任务而非真正的故障模式。
- **目标**：设计一个可信任的自动演化循环，使框架改进能够可靠累积并泛化，而非漂移或过拟合。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将“提议变更”与“信用分配”严格分离。语言模型（更强大的 Evolver）负责诊断失败、提出语义补丁；而所有采样、测量、显著性检验均由确定性代码控制，确保每个被认可的改进在构造上就是可信的。
- **关键技术细节**：
  - **三重回门控机制**（§3.4）：
    - 有效性门（Validity Gate）：运行前检查环境健康，运行后对基础设施失败进行重试（最多2次），避免将环境问题计入失败。
    - 激活门（Activation Gate）：只当补丁机制实际触发时才将其效果归因于该补丁，否则不认可。
    - 显著性门（Significance Gate）：基于配对 2σ 检验（per-task 配对差值，z ≥ 1.96），而非简单均值改进。这消除了任务间难度差异的方差。
  - **门控语义质量多样性存档（GSME）**（§3.3）：
    - 存档以 *(WHERE × WHY)* 病理为键索引（WHERE 是编辑的杠杆：prompt/knowledge/runtime/config；WHY 是诊断的失败病理，如思考溢出、未验证终结等）。
    - 每个细胞只保留一个精英补丁。这种按病理而非任务组织的归纳偏置天然抗过拟合。
    - 选择策略：质量偏向选择（扩展全局最佳框架）+ 跨细胞重组。多样性保留避免了崩溃到单一安全编辑。
  - **演化循环**（Algorithm 1）：冷启动 → 每轮设计 3-4 个候选 → 预过滤（丢弃无激活信号或从未触发的）→ 锚点子集快速筛选 → 全训练集 K=3 评估 → 三重回门 → 最佳框架进入下轮。终止条件：连续 10 轮未提升或达到 20 轮上限。
  - **分层采样** 以降低计算成本：探针子集（15-30 锚点任务，K=1）淘汰明显差的候选；估计器子集驱动轮次导航；全训练集 K=3 用于基线和最终认可数字。
  - **密封测试**：演化完成后对保留的测试集进行一次打分，提前完全不访问，避免任何数据泄露。

## 6. 主要结论与发现

- **核心发现**：演化框架可在七个领域上获得显著的密封测试改进（+9 到 +15.5 pp），且保留训练增益的 86-147%，证明泛化而非过拟合。
- **病理-补丁匹配规律**：获胜补丁针对模型的主导病理（如思考溢出、未验证终结、粗心回答等），不同模型需要不同补丁，且该规律跨模型家族（Qwen 和 Gemini）重现。

- **其他**：GSME 存档的多样性避免了崩溃到仅提示词编辑；配对 2σ 门控有效过滤噪声和虚假提升；树感知分数借用可大幅降低评估成本而不牺牲决策准确性。

## 7. 优点

- **方法论严谨性**：严格分离提议与信用分配，确定性代码控制所有定量判断，每个认可改进均可审计、可重复。
- **抗过拟合设计**：GSME 按病理而非任务组织存档，自然抗过拟合；密封测试确保最终评估无污染；配对 2σ 检验排除测量噪声。
- **实验可靠性**：所有报告结果来自密封测试的单一对比，避免了多次比较膨胀；保留率指标进一步佐证泛化。
- **安全性**：三重回门不仅认可好的，还能主动拒绝有害或无意义的候选（如 TB2 拒绝了显著负增益候选）。
- **实际应用价值**：聚焦于冻结模型的框架优化，适用于模型权重不可变（租用、封闭或训练成本过高）的部署场景。
