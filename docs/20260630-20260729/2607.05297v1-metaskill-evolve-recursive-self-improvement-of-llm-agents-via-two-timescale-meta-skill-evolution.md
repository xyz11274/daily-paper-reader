## 摘要
最近的LLM智能体能够处理越来越长视野、开放式的任务，而外部技能（即提供给智能体的可重用程序性知识）进一步扩展了这种能力。然而，固定的手工编写的技能很少是最优的，也无法适应智能体遇到的任务多样性。自我改进的智能体通过从执行轨迹中重写自己的技能文件来解决这个问题，从而在具有挑战性的基准测试中取得了有意义的改进。然而，这种自我演化仍然是非递归的：它只改进了任务技能（智能体做什么），而改进过程（如何改进）是一次性编写并固定不变的。我们引入了MetaSkill-Evolve，一个双时间尺度框架，使智能体的技能改进变得递归：每个分支都包含一个任务技能$s$和一个分支本地的元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件分别参数化了改进流程中的分析器、检索器、分配器、提议器和演化器智能体。任务技能在快速循环中演化，而元技能在较慢的循环中演化，通过将同一流程应用于自身，无需额外的模型或目标。在所有五个流程智能体共享单个冻结基座模型的情况下，MetaSkill-Evolve在三个智能体基准测试（OfficeQA、SealQA、ALFWorld）上优于无技能、静态技能和单层演化基线，相对于原始基座模型，在保留的测试集上准确率分别提高了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 1. 核心问题与整体含义（研究动机与背景）
- 现有LLM智能体通过**外部技能**（可重用的程序性知识，如Markdown文件）来增强处理长视野、开放式任务的能力。但手工编写的固定技能难以适应任务多样性，因此出现了**自我改进系统**（如EvoSkill、GEPA、SkillWeaver），它们通过执行轨迹重写技能文件。
- 然而，这些自我改进方法**仅优化任务技能（智能体做什么）**，而改进流程本身（如何改进，包括失败诊断、编辑提议、搜索分配等）是**一次性编写、固定不变的**。这种非递归的限制导致当改进流程本身不再合适时，整个系统会停滞。
- 核心研究问题：**能否将改进流程本身作为一等对象，与它产生的任务技能共同进化？** 本文提出了**MetaSkill-Evolve**，实现了**递归自我改进**：改进操作符（元技能）通过同一管道反射式地应用于其自身。

## 2. 方法论：核心思想、关键技术细节
### 2.1 核心思想
- **双时间尺度框架**：每个分支状态b = (s, m, h)，其中s是任务技能，m是分支本地的元技能，h是迭代历史。
  - **快循环**：每次迭代更新任务技能s。
  - **慢循环**：每H次迭代更新元技能m，使用与快循环完全相同的五智能体管道，但处理对象换为元技能文件。
- 元技能m = (ψ, σ, α, π, ε)，五个组件分别参数化管道中的五个角色：
  - ψ：诊断策略（分析器）— 将失败映射为标签ϕ和分析a。
  - σ：共享策略（检索器）— 选择同分支和跨分支的灵感。
  - α：分配策略（分配器）— 设定每步的子代预算K∈[1, K_max]。
  - π：编辑提议策略（提议器）— 生成具体的编辑δ。
  - ε：编辑执行策略（演化器）— 写入磁盘并验证。
- 所有五个智能体共享一个**冻结的Gemma-4 31B基座模型**，因此全部改进归因于技能和元技能的进化，而非增加模型容量。

### 2.2 关键技术细节
- **持久化进化有向无环图（DAG）**：用SQLite记录所有节点（分支状态）和边（谱系边、灵感边）。仅当子代严格改进父代（ΔU>0）时才进入存档（可被选为未来父节点）。
- **前向选择得分**：每个候选父节点v的分数为 η₁U(s) + η₂P(m|s) + η₃N(b)，其中：
  - U(s)：任务效用（验证集准确率）。
  - P(m|s)：元生产率（期望每个子代的改进量）。
  - N(b)：分支新颖性（1/(1+已选次数)），防止枯竭。
- **快循环流程**：选父节点→恢复snapshot→评估训练批→选最差样本→分析器诊断→检索器获取灵感→分配器设定子代数→提议器生成K个编辑→演化器写入并验证→评估子代→慢循环（每H次）→提交节点到DAG→刷新边界。
- **慢循环流程**：收集最近H个子代的元生产率 P̂ → 构建合成元失败轨迹 f_m → 分析器锁定问题组件（ψ/σ/α/π/ε之一）→ 检索器跨分支匹配 → 分配器设定预算 → 提议器和演化器顺序/并行地重写所有五个元技能文件（保持跨组件一致性）。每个子代读取前一个子代的结果，实现增量细化。

## 6. 论文的主要结论与发现
1. **递归自我改进可行且有效**：将改进流程本身作为可进化对象，通过同一管道自递归，显著提升了任务技能的准确性，且无需额外模型或训练。
2. **双时间尺度分离必不可少**：快循环优化任务技能，慢循环优化元技能，H=2最优（每两次快循环更新一次元技能）。
3. **元生产率 P(m|s) 是关键信号**：前向选择中融合效用、生产率和新颖性，避免了贪婪搜索陷入停滞。
4. **组件贡献因领域而异**：OfficeQA中分配策略α最重要（-19.7分），SealQA中提议策略π最重要（-8.42分），ALFWorld中跨分支共享是慢循环改进的唯一来源。
5. **总改进主要来自慢循环**：在QA基准上，慢循环分别贡献+6.38和+8.05分；在ALFWorld上贡献全部+1.92分。
