## 摘要
长周期大语言模型系统中的智能体自我进化很大程度上是程序性的：有用的经验不仅仅是存储的信息，而是可复用的搜索、调试和验证程序。然而，当前的评估并未孤立这种迁移形式。智能体基准测试测试单次任务解决；记忆基准测试针对信息保留而非程序复用。我们引入了EvoAgentBench，这是一个通过能力引导迁移在四个智能体领域（网络研究、算法推理、软件工程和知识工作）进行智能体自我进化的基准测试。EvoAgentBench从智能体执行中提取轨迹感知的能力，将其规范化成操作单元，并构建连接共享程序重叠任务的领域特定能力图。通过设计，每个测试任务都有经过验证的训练侧能力支持。在528/267的训练/测试划分、两种框架和三种主干的设置下，精心策划的能力内容在不同模型家族中可靠地迁移，但当前没有自动方法能在所有设置中持续获得正面收益。EvoAgentBench将自我进化评估从总体准确率比较转向对经验编码、路由和吸收的细粒度诊断。该基准测试可在https://huggingface.co/datasets/EverMind-AI/EvoAgentBench公开获取。

## Abstract
Agent self-evolution in long-horizon LLM systems is largely procedural: useful experience is not merely stored information, but reusable procedures for searching, debugging, and verification. Yet current evaluations do not isolate this form of transfer. Agent benchmarks test single-episode task solving; memory benchmarks target information retention rather than procedural reuse. We introduce EvoAgentBench, a benchmark for agent self-evolution via Ability-guided transfer across four agentic domains: web research, algorithmic reasoning, software engineering, and knowledge work. EvoAgentBench extracts trace-grounded Abilities from agent executions, canonicalizes them into operational units, and builds domain-specific Ability Graphs linking tasks that share procedural overlap. By design, every test task is backed by verified training-side Ability support. Across a 528/267 train/test split, two scaffolds, and three backbones, curated Ability content transfers reliably across model families, but no current automatic method sustains positive gain in all settings. EvoAgentBench shifts self-evolution evaluation from aggregate accuracy comparison to fine-grained diagnosis of experience encoding, routing, and uptake. The benchmark is publicly available at https://huggingface.co/datasets/EverMind-AI/EvoAgentBench.

## 1. 核心问题与整体含义（研究动机与背景）

当前的大语言模型（LLM）智能体虽然能独立解决长周期任务，但理想情况下应从先前执行中保留可复用的程序性知识（如搜索、调试、验证流程），而非每次都从头开始。然而，现有的智能体基准仅测试单次任务解决能力，记忆基准只关注信息回忆而非程序复用，自我进化基准则混淆了工件质量、任务顺序与检索策略等因素。**核心问题**是：缺乏一个能够明确控制训练侧“能力”支持、并测量程序性知识是否真正跨任务迁移的评估框架。EvoAgentBench 旨在填补这一空白，通过引入**能力图（Ability Graph）** 来保证每个测试任务都有训练侧能力的支持，从而将自我进化评估从整体精度比较转向经验编码、路由和吸收的细粒度诊断。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
智能体自我进化的本质是“轨迹到程序”的迁移：将执行经验提炼为可复用的操作单元，称为**能力（Ability）**。每个能力包含触发条件、可复用程序、边界条件及角色（方法、防护、工作流）。通过构建领域内任务间的能力共享图来定义转移结构，并基于此划分训练/测试集，保证测试任务有训练侧能力支持。

### 2.2 关键技术流程（三阶段构建管道）

- **阶段1：多骨干轨迹收集**  
  对每个任务，使用三个构建骨干（Kimi-K2.5、GLM-5.1、DeepSeek-V3.2）在两个框架（OpenClaw、Nanobot）下执行无技能基线，得到多骨干轨迹池。

- **阶段2：轨迹感知能力提取与规范化**  
  - 使用单个LLM（Claude Sonnet 4.6）从每个任务的轨迹中提取原始能力卡片（raw Ability cards），包括触发条件、程序、边界、角色及证据。
  - 通过嵌入阻塞（embedding blocking）和LLM三评委裁决+领域专家审查进行规范化合并，得到规范能力单元。合并要求操作等价而非语义相似。

- **阶段3：能力图构建与感知迁移划分**  
  - 每个领域构建无向能力图：节点为任务，边表示共享至少一个规范能力单元。
  - 使用Louvain社区检测划分能力社区，然后进行约束抽样：每个测试任务必须与至少一个训练任务共享能力（即训练侧支持），同时避免测试任务完全由构建骨干解决或失败（保留头部空间）。最终得到528训练/267测试任务，零个无支持测试任务。

## 3. 实验设计

### 3.1 评估场景与基准
- **四个领域**：Web研究（BrowseComp-Plus）、算法推理（LiveCodeBench）、软件工程（SWE-Bench Verified）、知识工作（GDPVal）。
- **两种智能体框架**：OpenClaw（功能丰富）和Nanobot（超轻量）。
- **三个骨干**：Qwen3.5-27B、Qwen3.5-397B、Gemma-4-31B。
- **对比方法**：
  - **Vanilla**：无进化状态。
  - **Memento**：基于嵌入相似性检索最近训练案例。
  - **ReasoningBank**：蒸馏自然语言策略池并基于策略相似性检索。
  - **GEPA**：在训练集上进化单个提示并广播至所有测试任务（无检索）。
  - **Anchor Skill**（诊断参考）：使用策展侧能力标签检索训练侧构建的技能，不可部署但测量能力内容是否可转移。

### 3.2 评估指标
- 各领域使用原生指标：BrowseComp-Plus用LLM裁判（binary），LiveCodeBench用pass@1（隐藏测试），SWE-Bench用解决率（测试套件），GDPVal用LLM裁判（比对参考答案）。
- 主要观测：每个测试任务相对于Vanilla的增益Δ，以及总体平均Δ（等权平均四个领域）。
- 额外汇报：智能体执行步数变化（成本分析）。

## 6. 主要结论与发现

1. **能力内容可跨模型家族转移**：诊断参考Anchor Skill在所有骨干上均产生正向平均Δ（+7.5, +10.5, +5.8），且所有24个单元格均为正，表明能力图中学得的程序性知识能从构建骨干泛化至评估骨干。
2. **自动方法存在负迁移**：每个自动方法（Memento、ReasoningBank、GEPA）至少在某个骨干-框架-领域单元格出现负迁移，其中Memento在Nanobot/Qwen3.5-27B的SWE任务上Δ达-36.3。这表明当前自动方法在经验提取、路由或吸收上存在瓶颈。
3. **瓶颈在于方法侧而非域侧**：Anchor始终正收益，说明训练侧能力信息足够；自动方法失败源于其自身机制（如Memento的表面相似性匹配、GEPA的无适应性广播）。
4. **成本-精度解耦**：进化不一定降低成本。Anchor和ReasoningBank有时减少步数，但GEPA和Memento常增加开销（尤其Gemma-4-31B骨干）。因此单独报告精度会掩盖行为分布的异质性。
5. **多设置评估必要**：不同骨干、框架下方法排名变化，单一设置评估不可靠。

## 7. 优点

- **方法论创新**：首次定义并构建了轨迹感知的“能力图”，实现了程序性经验迁移的结构化评估，并保证测试任务有训练侧能力支持。
- **细粒度诊断**：将评估从整体精度比较转向“经验编码、路由、吸收”三阶段诊断，可定位方法瓶颈。
- **严格的泄漏控制**：训练侧信息与测试侧严格隔离；自动方法仅通过自己的执行和路由访问进化状态。
- **跨域、多骨干、多框架的广泛评估**：覆盖文本智能体的四大典型任务类型，使用两种不同架构的框架和三个不同规模的模型，提高了结论的泛化性。
- **开源基准**：提供公开数据集，促进后续研究。

## 8. 不足与局限

- **领域覆盖有限**：仅限文本智能体，未涉及多模态或具身智能体。
- **能力提取依赖单一LLM**：虽然后续三评委裁决+专家审查缓解了偏差，但替代提取器的影响未讨论。
- **骨干数据污染风险**：评估骨干可能在预训练中见过源基准数据，但所有方法共享相同骨干，对比仍然公平；然而绝对分数可能偏高。
- **测试任务数较少**：每个领域56-86个测试任务，可能不足以支持细粒度领域内分析。
- **算力信息缺失**：不利于实验复现和资源评估。
- **绝对增益幅度有偏**：测试任务偏向于构建骨干留有头部空间的任务，因此Δ大小不代表在随机任务上的期望增益，仅支持方法间比较。
- **仅考虑一种进化范式（离线预建状态）**：在线增量学习（如流式任务）未覆盖，与StreamBench、LifelongAgentBench等有区别。
