## 摘要
自进化框架通常优化任务解决方案，而将周围的框架视为固定不变。我们提出了框架感知自进化（HASE），一个智能强化学习框架，其中单个模型可以在多轮动作空间中生成任务解决方案或编辑选定的框架组件。HASE使单个Qwen3-8B模型能够匹配使用Claude Code作为框架提议者的GPT-OSS-120B模型的文本分类性能。在Alpha因子挖掘中，HASE超越了已报道的GPT-OSS-120B基线。HASE还能修复不完善的评估组件，并在圆填充算法发现中收敛到最先进的性能。这些结果表明，HASE通过一个统一的智能过程改进了框架和解决方案。

## Abstract
Self-evolving frameworks usually optimize task solutions while treating the surrounding harness as fixed. We introduce Harness-Aware Self-Evolving (HASE), an agentic reinforcement-learning framework in which a single model can generate task solutions or edit selected harness components in a multi-turn action space. HASE enables a single Qwen3-8B model to match the text-classification performance of a GPT-OSS-120B model that uses Claude Code as the harness proposer. In alpha factor mining, HASE outperforms the reported GPT-OSS-120B baseline. HASE also repairs imperfect evaluation components and converges to state-of-the-art performance in circle-packing algorithm discovery. These results show that HASE improves the harness and the solution through one unified agentic process.

## 1. 论文的核心问题与整体含义

**研究动机**：现有自进化系统（如FunSearch、AlphaEvolve、ThetaEvolve等）在迭代生成和评估代码等结构化工件时，通常将外围**框架（Harness）**视为固定不变。框架包括提示（prompt）、记忆（memory）、上下文检索（retrieval）、工具接口（tool interface）、状态管理（state management）和评估器（evaluator）等组件。固定框架假设存在两个根本限制：

- 人工编写的评估器可能不完整或与外部环境不一致，模型可能利用这些漏洞而非真正解决问题（reward hacking）。
- 引导组件（如提示、记忆、检索策略）可能提供较差的搜索先验，限制了模型的潜在表现。

**整体含义**：本文提出**HASE（Harness-Aware Self-Evolving）**，首次将框架组件视为可进化的对象，并与模型权重、任务解决方案在同一强化学习框架内协同优化，从而提升系统的整体能力。

## 2. 论文提出的方法论

**核心思想**：HASE 是一个基于智能体强化学习（Agentic RL）的框架，允许单一模型在多轮动作空间中交替选择：
- 生成对象级解决方案（如代码、因子、分类标签）；
- 编辑选定的框架组件（通过沙箱工具执行读/写操作）。

**关键技术细节**：

- **框架组件分类**：
  - **引导组件**（Guidance Components）：如提示、记忆格式化、检索脚本、上下文选择，用于改善搜索；可自由进化。
  - **评估组件**（Evaluation Components）：如验证器和评分器，定义解决方案的有效性和任务指标；其进化必须由真实世界评估器（oracle）锚定，仅当本地代理分数与 oracle 分数分歧时才允许修复。

- **统一动作空间**：模型可通过 `ls`、`cat`、`grep`、`replace`、`overwrite` 等沙箱命令读/写框架文件，并可通过 `done` 提交最终解。模型自主决定何时生成解、何时编辑框架。

- **训练算法（算法1）**：
  - 维护一个持久框架 `h`、一个策略 `π_θ`、一个阶段候选池 `C_p` 和（可选）一个不匹配集 `M`。
  - 每个阶段包含多个 GRPO 轮次。每轮模型 rollout 多条轨迹（可包含框架编辑），最终提交解。轨迹奖励仅取决于解质量（框架编辑本身无直接奖励）。
  - 引导组件候选：通过 proof-of-concept (PoC) 短列表——若某编辑后的轨迹获得了比当前持久框架更好的任务分数，该编辑加入候选池。阶段边界上，用验证集对候选进行过滤、排序并提交最优的持久更新。
  - 评估组件候选：仅当本地代理分数与 oracle 分数出现分歧（即不匹配集 `M` 中发现新案例）时，评估器编辑才被考虑。提交的补丁必须修复 `M` 中的更多不匹配且不破坏必要接口与回归测试。

- **奖励设计**：
  - 引导编辑：无直接奖励，通过PoC间接激励。
  - 评估编辑：奖励与消除不匹配集中案例的数量成正比，避免无约束的奖励篡改。

## 6. 论文的主要结论与发现

1. **HASE 使单个 8B 模型在文本分类上匹配了 GPT-OSS-120B + Claude Code 的系统性能**（86.98% vs 86.8%），证明了框架进化可以弥补模型规模差距。
2. **在 Alpha 因子挖掘中，HASE（8B）超越了所有公开基线**，包括 GPT-OSS-120B（AER 14.35% vs 7.89%，IR 1.70 vs 0.80）。
3. **在圆填充中，HASE 从不完整的评估器出发，通过两次修复（边界检查、容差修正），最终达到与 AlphaEvolve 相同的 SOTA（2.635983）**。
4. **在 Heilbronn 三角形中，HASE 修复评估器后，协同进化达到有效分数 0.036082，而冻结权重仅能到 0.02188**，证明权重进化对适应修复后评估器至关重要。
5. **框架进化是安全且自限制的**：评估器修复由真实世界分歧驱动，引导组件进化通过阶段边界验证，避免了无约束的奖励黑客。

## 7. 优点

- **统一框架**：首次将模型权重、框架组件和任务解决方案放在同一个 RL 优化循环中，无需外部强大的编码代理。
- **机制清晰**：区分引导组件和评估组件，分别采用不同的进化策略（引导自由进化、评估器锚定真实世界），解决了安全与自动化的矛盾。
- **高效性**：仅使用 8B 模型即可匹配或超越 120B 模型的性能，展示了框架进化的杠杆效应。
- **泛化能力**：在分类、金融、几何连续优化三个领域均有效。
- **严谨的评估控制**：Alpha因子挖掘中设计了未来信息泄漏检测（随机游走测试 + 截断检验）和跨 LLM 审计，确保结果可信。
