## 摘要
用户反馈为大语言模型的持续改进提供了天然监督，但单条反馈消息可能对应多种具有不同泛化范围的行为更改。本文提出SLIFT，这是一种基于用户反馈任务相对视角的选择性自学习框架。SLIFT将每条反馈消息分解为原子组件，并相对于原始任务将每个组件划分为Fix、Spec或Null三类：分别对应任务有效性要求、兼容的特定条件细化，以及不存在可靠正向更新方向的内容。为了在合适的范围引入各类更改，SLIFT在共享的冻结骨干网络上训练两个互补的LoRA适配器：通用器通过反馈条件自蒸馏将Fix要求整合为默认行为，专用器仅观测任务和通用器的响应，为适用的、未满足的Spec细化要求提供残差引导。Null组件不触发正向更新。在不同骨干网络上的实验表明，SLIFT在MemoryBench和WildFB基准上均取得了出色性能，针对性分析进一步检验了其底层机制。我们的代码发布于：https://anonymous.4open.science/r/SLIFT

## Abstract
User feedback offers natural supervision for persistent LLM improvement, but a single message may support multiple behavioral changes with different scopes of generalization. We introduce SLIFT, a selective self-learning framework built on a task-relative view of user feedback. SLIFT decomposes each feedback message into atomic components and interprets each component relative to the original task as Fix, Spec, or Null: requirements for task validity, compatible condition-specific refinements, or content with no reliable positive update direction. To incorporate each change at the appropriate scope, SLIFT trains two complementary LoRA adapters on a shared frozen backbone: a Generalist that consolidates Fix requirements into default behavior through feedback-conditioned self-distillation, and a Specialist that observes only the task and Generalist response to supply residual guidance for applicable, unmet Spec refinements. Null components induce no positive update. Across backbones, SLIFT achieves strong performance on both MemoryBench and WildFB, with targeted analyses further examining its underlying mechanisms. We release our code at https://anonymous.4open.science/r/SLIFT.

# 1. 核心问题与研究背景
- 背景：大语言模型已广泛部署在交互式系统中，用户交互产生的反馈是天然低成本的持续优化监督信号，将交互反馈转化为模型持久的行为改进，是大模型落地后持续迭代的核心问题之一。
- 现有痛点：
  1. 真实用户反馈天然是复合性的，单条反馈通常同时包含多种不同泛化范围的行为修正需求，现有方法大多将整条反馈作为单一监督信号，没有区分不同需求的适用范围。
  2. 错误的范围分配会导致严重问题：若将仅适用于特定场景的条件性细化修正作为默认全局行为，会导致在不相关场景的错误泛化；反馈中还存在大量无可靠更新方向的噪声内容，也会干扰模型学习。
  3. 现有两类主流方案（非参数外部存储记忆类、全范围参数更新类）都没有解决差异化更新范围的问题：压缩反馈为标量奖励会丢失精细信息，直接全范围蒸馏又容易出现泛化错误。

# 2. 提出的方法论
## 核心思想
提出SLIFT（基于任务相对反馈分解的选择性自学习框架），核心思路是将用户反馈相对于原始任务做原子分解和分类，针对不同类别的反馈需求匹配不同泛化范围的学习通路，实现差异化的选择性更新，从根源避免错误泛化。

## 关键技术细节
### （1）任务相对的反馈预处理
用原始冻结的主干模型完成两步处理：
- 原子反馈提取：将复合的整条用户反馈拆分为多个最小、自包含的独立信号组件。
- 任务相对分类：以原始任务的有效响应空间为参照，将每个原子组件分为三类：
  1. `Fix`：所有满足原始任务的有效响应都必须满足该要求，缺失会导致任务无效，属于任务必需的修正，需要整合为模型默认行为。
  2. `Spec`：属于任务有效范围内的可选细化，不满足也不影响任务有效性，仅适用于特定条件，需要保持条件性，不能直接作为默认行为。
  3. `Null`：模糊、无关、冲突或不提供可靠更新方向的内容，不触发任何正向更新。

### （2）双通路差异化学习
在共享的冻结主干上训练两个独立LoRA适配器，分别处理两类有效反馈：
- **通用器（Generalist）适配器**：专门学习`Fix`类组件，通过反馈条件化离线自蒸馏训练：用冻结主干生成Fix条件下的事后分布作为教师，让通用器在不额外输入反馈的前提下拟合该分布，同时添加KL散度行为锚定正则，避免修改和Fix无关的原始行为；训练后冻结通用器，将Fix要求整合为模型默认行为。
- **专用器（Specialist）适配器**：专门学习`Spec`类组件，学习基于任务和通用器生成的默认响应，判断是否需要条件性细化：训练目标由冻结主干利用特权信息（Spec组件）生成，若通用响应已满足所有Spec要求则目标为`KEEP`（保留原响应），若存在未满足的适用Spec要求则目标为`APPLY`+仅包含未满足需求的残差引导；训练时输入仅为原始任务和通用响应，不需要额外输入原始反馈。

### （3）推理流程
1. 通用器基于原始任务生成默认响应；
2. 专用器基于任务和默认响应，输出`KEEP`或`APPLY`+残差引导；
3. `KEEP`直接返回默认响应，`APPLY`则由冻结通用器基于残差引导做一次整合修正，输出最终结果。

# 6. 主要结论与发现
1. SLIFT在两个基准的多个主干模型上都取得了优于所有对比基线的性能：在MemoryBench所有输入输出长度分区都获得最高平均分数，在WildFB上显著提升指令遵循和开放域响应质量，同时保持原有知识推理能力不受损。
2. 所有核心设计都对性能有正向贡献：去掉原子分解、去掉任务上下文做分类、合并双通路为单通路、去掉`KEEP`监督都会带来明显性能下降，设计合理性得到验证。
3. 通用器提供整体性能提升，专用器仅对少量需要细化的样本做稀疏修改，不会带来大量不必要的更改，开销可控。
4. 在在线增量学习场景下，SLIFT能从新收集的on-policy反馈中持续获得收益，每次迭代都比基线获得更大提升。
5. 效率方面：SLIFT总参数更新成本低于SFT和DPO，平均推理成本低于检索和外部记忆类方法，推理成本不会随训练日志规模增长而升高。

# 7. 优点
1. 思路创新：首次明确提出用户反馈的任务相对分类框架，区分不同泛化范围的反馈需求，针对性设计双通路学习，从根源解决了反馈学习中的错误泛化问题。
2. 不需要额外监督：所有监督信号都由原始冻结主干生成，不需要更强的教师模型、人工标注或额外奖励模型，落地成本低。
3. 实验设计完备：覆盖不同主干、不同场景，消融实验充分，多维度分析验证了模块作用，结论可信。
4. 工程轻量：基于LoRA实现，不需要微调整个主干，存储训练成本低，适合大模型的持续迭代。

# 8. 不足与局限
1. 反馈分解和分类的准确率依赖原始主干的能力，小模型的分类错误率更高，在高噪声的真实反馈场景下性能会受影响。
2. 目前仅在10B参数以下的开源模型上验证，未在更大规模的千亿参数模型上测试，方法的可扩展性有待验证。
3. 对Null组件仅做不更新处理，没有进一步挖掘其中可能存在的有效信息，反馈信息利用率还有提升空间。
4. 推理需要最多三次模型前向，相比单步推理的原生参数更新方法有一定额外开销。
