## 摘要
现有多智能体基准测试主要在竞争性环境、20步以内的短时程交互中进行，或仅聚合个体性能，未能分离并突出基于LLM的智能体真正的协作能力。我们提出AgentWorld，一个包含100个人工标注任务（以及100个增强变体）的基准，用于评估长时程、多智能体协作。任务跨越50多个交互轮次，在一个丰富的MMORPG沙盒中进行，需要3-20个具有不对称角色和能力的智能体，在黑盒设定下通过通信、联合规划和资源共享进行协调，其中每个智能体独立行动，无法访问其他智能体的内部状态。为了在传统二元任务成功之外量化协作有效性，我们提出因果协作有效性（CCE），一种基于图的指标，追踪智能体动作之间的因果依赖，并衡量团队努力中实际对结果有贡献的比例。使用Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini和DeepSeek R1-70B进行的实验表明，即使最佳模型也仅达到52.0%的任务成功率，并存在系统性失败模式，包括通信中断、角色混淆以及无法跨轮次维持共享计划。AgentWorld完全开源。

## Abstract
Existing multi-agent benchmarks primarily test in competitive settings, short-horizon interactions under 20 steps, or simply aggregate individual performance, failing to isolate and highlight genuine collaboration capabilities of LLM-based agents. We introduce AgentWorld, a benchmark of 100 human-annotated tasks (with 100 augmented variants) for evaluating long-horizon, multi-agent collaboration. Tasks span 50+ interaction rounds across a rich MMORPG sandbox and require 3-20 agents with asymmetric roles and abilities to coordinate through communication, joint planning, and resource sharing under a blackbox setting where each agent acts independently without access to others' internal states. To quantify collaboration effectiveness in addition to conventional binary task success, we propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions and measures what fraction of a team's effort actually contributed to the outcome. Experiments with Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B show that even the best model achieves only 52.0% task success, with systematic failure modes including communication breakdowns, role confusion, and inability to maintain shared plans across rounds. AgentWorld is fully open-source.

# AgentWorld 论文深度总结

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体正从单轮推理走向自主工具使用与多步执行，多智能体协作（MAC）成为关键能力。然而现有基准存在三大缺陷：
  - **任务时程过短**：多数基准交互步数在 20 步以内，无法评估持续协调能力。
  - **混淆低层控制与协作**：如 Minecraft 类环境要求精确 3D 导航、方块放置等，使协作能力难以从动作控制熟练度中分离。
  - **大规模社会模拟缺乏可量化目标**：如 Project Sid 侧重涌现社会行为，而非有明确结果的任务。
- **整体含义**：论文提出 **AgentWorld**——一个基于 MMORPG 沙盒的长时程、协作导向基准，旨在隔离并凸显 LLM 智能体真正的协作能力，而非个体推理或低层控制能力。

## 2. 方法论

### 2.1 核心思想
- 构建一个**复杂度适中**的环境：足够复杂以支持多样化协作场景，同时通过高层 API 抽象掉低层控制，使基准分数主要反映联合规划与协调质量。
- 采用**黑盒设定**：智能体无法观察其他智能体的内部状态、观察或动作历史，协调只能通过显式聊天消息完成。

### 2.2 关键技术细节
- **沙盒基础**：基于开源 MMORPG 引擎 Kaetram，包含 1056×768 瓦片、9 种生物群系、380+ 物品、144 种怪物、70+ NPC、1531 个可采集资源节点、8 种技能。
- **智能体-环境接口**：自定义抽象层暴露 **13 个高层 API 工具**（如 `move`、`attack`、`harvest`、`craft`、`transfer`、`chat`），每个工具封装多步游戏机制（如 `attack_entity` 自动完成寻路、攻击、战斗、拾取）。
- **回合制编排**：将实时游戏转为回合制，每轮每个智能体依次接收观察、选择一个工具调用、等待解析后下一个智能体行动，确保确定性回合顺序。
- **任务结构**：每个任务包含主目标、非对称角色配置（技能、出生点、初始物品）、回合预算、任务特定上下文文档、Python 成功判定函数。

### 2.3 评估指标
- **任务成功率（SR）**：由每个任务的 Python 验证脚本程序化检查最终游戏状态。
- **部分成功率（PSR）**：基于验证器报告的中间检查点，计算达成比例的平均值。
- **因果协作有效性（CCE）**：
  - 构建**因果动作图（CAG）**：节点为所有动作，有向边表示"动作 x 因果上使能动作 y"。
  - **反向追踪算法**：先识别直接达成目标的成功动作集 S，然后逐轮向后扫描，用 LLM 判断哪些先前动作因果上使能了已识别的贡献动作，累积贡献集 C。
  - **公式**：`CCE = |C| / |T|`，其中 T 为所有智能体所有轮次的动作全集；失败任务 CCE = 0。
  - **逐智能体贡献（PAC）**：`PAC_i = |C ∩ T_i| / |T_i|`，揭示哪些智能体有效、哪些无效。
  - **关键设计**：LLM 仅做相对客观的二元因果判断（"捕虾是否使能了后续转移虾"），而非主观质量评分（"1-5 分评价协作"），提高可复现性。

## 3. 实验设计

### 3.1 数据集 / 场景
- **100 个人工标注主任务** + **100 个 LLM 增强变体**（由 Claude Opus 生成，经人工验证）。
- 任务覆盖 **8 个类别**：战斗、制作、采集、交易、探索、生存、建造、协调。
- 任务规模：3–20 个智能体（多数为 3 个，长尾至 20 个）；回合预算 25–55 轮（平均 38 轮）。
- 增强变体在目标、出生点、初始物品上变化，经人工验证 100% 保留多智能体协作需求、目标语义和角色非对称性。

### 3.2 对比方法
- **四个前沿模型**：Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B。
- **额外模型**：Muse-Glimmer-30B、Gemma 4 26B A4B（临时结果）。
- **五个基线**：
  - 随机动作（无 LLM）
  - 单智能体（所有角色和物品分配给一个智能体）
  - 无通信（禁用聊天和消息工具）
  - 共享计划无通信（先接收人类编写的共享计划再执行）
  - Oracle 通信（一个智能体观察所有消息并协调团队，建立通信质量上界）

### 3.3 消融实验
- 在 35 任务子集上消融四个设计组件：移除非对称角色信息、缩短回合预算（50→10）、随机化出生点、移除任务文档。

## 6. 主要结论与发现

- **最佳模型仅 52.0% 任务成功率**（Gemini 3 Flash），Claude Haiku 4.5 为 45.0%，GPT-5 Mini 为 36.0%，DeepSeek R1-70B 为 20.0%。
- **CCE 极低**：最佳模型 CCE = 0.320，即不到三分之一的动作因果上贡献于任务完成；DeepSeek 仅 0.125，近 88% 动作被浪费。
- **通信量不等于协作质量**：GPT-5 Mini 发送最多聊天消息（44.1 条/任务）但排名第三；Gemini 通信适中（11.0 条）却成功率最高。
- **任务难度差异显著**：生存任务最易（50–100% SR），协调（0–50%）、建造（0–60%）、交易（8–46%）最难。
- **增强集显著更难**：所有模型 SR 大幅下降（Gemini 52→24%，Claude 45→26%）。
- **系统性失败模式**：
  - 通信中断（无法分享关键信息）
  - 角色混淆（重复工作或越权行动）
  - 无法跨轮次维持共享计划
  - 通信错误类型：陈旧冗余（37.7%）、错误识别（16.4%）、事实错误（14.8%）、过早宣布完成（11.5%）、非实质性输出（11.5%）、逻辑不一致（8.2%）。
- **基线对比**：随机动作 5.7%，单智能体 28.6%，无通信 22.9%，共享计划无通信 17.6%，Oracle 通信 60.0%——表明任务确实需要多智能体协调，且即使完美通信仍有 40% 失败率，说明长时程规划和资源分配本身具有内在难度。
- **消融结论**：移除任务文档（54.3→29.4%）和缩短时程（54.3→37.1%）影响最大，验证了这些设计组件的关键性。

## 7. 优点

- **环境设计精巧**：通过 13 个高层 API 工具抽象低层控制，使基准分数真正反映协作能力而非动作控制熟练度，这是对现有基准的重要改进。
- **黑盒设定真实**：智能体无法访问彼此内部状态，只能通过显式通信协调，更贴近真实多智能体部署场景。
- **CCE 指标创新**：基于因果动作图的图基指标，将 LLM 角色限制为二元因果判断而非主观质量评分，显著提高可复现性；经人类一致性验证（κ=0.64）和跨 judge 鲁棒性验证（排名完全保持）。
- **任务设计严谨**：100 个人工标注任务 + 100 个增强变体，覆盖 8 个类别，任务规模从 3 到 20 个智能体，回合预算 25–55 轮，且经试点实验校准。
- **实验全面**：包含主实验、基线对比、消融实验、CCE 鲁棒性验证、人类一致性验证、运行间方差分析、通信失败模式分析。
- **完全开源**：沙盒环境、任务定义、验证器、评估脚本和标注平台全部开源。

## 8. 不足与局限

- **算力信息缺失**：未披露 GPU 型号、数量或推理时长，影响可复现性和资源评估。
- **运行间方差分析不足**：仅基于单模型（Gemini 3 Flash）三次运行，无法建立跨模型稳定性或统计显著性。
- **CCE 依赖 LLM judge**：虽然二元因果判断比主观评分更客观，但仍依赖 LLM，且采用"宽松包含"策略（边际有帮助的动作也计为贡献），使 CCE 应被理解为真正有用动作比例的**上界**。
- **增强任务质量**：增强变体由 LLM 生成，虽经人工验证 10% 样本，但未全量验证；部分变体难度适当性存疑（如替代敌人是否真的更弱）。
- **模型覆盖有限**：仅评估四个主要模型（加两个额外模型），且部分结果为临时性；未涵盖更多开源模型或不同规模模型。
- **任务类别不均衡**：战斗和制作任务最多，协调和建造任务最少，可能影响类别层面的结论稳健性。
- **应用限制**：基准基于 MMORPG 沙盒，其协作模式（资源采集、制作链、战斗协调）与真实世界专业协作（如软件开发、科学研究）存在差距，结论向真实场景的泛化需谨慎。
- **黑盒设定的双刃剑**：虽然更真实，但也可能低估了在允许部分状态共享场景下模型的协作能力。
