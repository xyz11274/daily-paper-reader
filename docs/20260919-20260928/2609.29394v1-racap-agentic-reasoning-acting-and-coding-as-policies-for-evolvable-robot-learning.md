## 摘要
通用机器人智能体必须从经验中学习、迁移到新任务并高效行动。代码即策略（Code as Policies, CaP）方法在运行时生成和修复程序，会引入延迟，并将可复用机制与任务特定决策纠缠在一起。我们提出 RACaP，一个智能体框架，将编码移至进化阶段，并在部署时使用推理与行动（ReAct）循环调用冻结的、带类型的策略 API。两阶段策略结合能力课程学习与自主自进化，以改进 API、ReAct 执行框架和经验记忆。这些 API 编码可复用的物理机制，同时暴露参数以支持运行时自适应。ReAct 结合任务特定的工作记忆、长期经验记忆和视觉反馈来选择动作、验证结果并从失败中恢复，而无需修改源代码。RACaP 在 LIBERO-90 上达到 54.4% 的成功率，在零样本 LIBERO-PRO 上达到 45.0%，在 LIBERO-Long 上达到 46.0%，而 CaP 基线在长时程任务上最高仅为 4.0%。在 LIBERO-PRO 上，其成功率达到 CaP 基线的 2.5 倍，策略时间中位数加速 1.9 倍。为便于在机器人上高效部署，拒绝采样微调将 GPT-5.6 ReAct 决策蒸馏到 Qwen3-VL-8B-Instruct 中，实现每次决策推理加速 13.2 倍，并将重复物理调用从 16 次减少到 4 次。这些结果表明，将可复用代码与运行时决策分离，有助于持续进化、有效迁移和高效的长时程控制。

## Abstract
General-purpose robot agents must learn from experience, transfer to new tasks, and act efficiently. Code as Policies (CaP) methods generate and repair programs at runtime, incurring latency and entangling reusable mechanisms with task-specific decisions. We introduce RACaP, an agentic framework that moves coding to evolution and uses a Reasoning-and-Acting (ReAct) loop to call frozen, typed Policy APIs at deployment. A two-phase strategy combines capability curriculum learning with autonomous self-evolution to improve the APIs, the ReAct harness, and experience memory. The APIs encode reusable physical mechanisms while exposing arguments for runtime adaptation. ReAct combines task-specific working memory, long-term experience memory, and visual feedback to select actions, verify outcomes, and recover from failures without modifying source code. RACaP achieves 54.4% success on LIBERO-90, 45.0% on zero-shot LIBERO-PRO, and 46.0% on LIBERO-Long, compared with at most 4.0% for CaP baselines on long-horizon tasks. On LIBERO-PRO, it achieves 2.5 times the success rate of CaP baselines and a 1.9-fold speedup in median policy time. For efficient on-robot deployment, rejection-sampled fine-tuning distills GPT-5.6 ReAct decisions into Qwen3-VL-8B-Instruct, yielding a 13.2-fold per-decision inference speedup and reducing repeated physical calls from 16 to 4. These results show that separating reusable code from runtime decisions supports continued evolution, effective transfer, and efficient long-horizon control.

## 1. 核心问题与整体含义

- **研究动机**：通用机器人智能体需要从经验中学习、迁移到新任务，并在物理执行中高效行动。Code as Policies（CaP）方法虽然灵活，但存在两个根本性矛盾：
  - **运行时编码慢**：CaP-X 单次编码迭代需 6.8–23.8 秒，多轮试验需 60.8–113.6 秒，且可能引入语法错误、选错物体或重复无效动作。
  - **可复用机制与任务特定决策纠缠**：生成的程序常混合可复用的物理机制（如抓取几何）与任务特定常量（如物体名、坐标、抓取高度），导致跨任务迁移困难。
- **已有自改进 CaP 方法的不足**：
  - RATS 通过"新颖性与可学习性"的玩耍目标存储程序，但该目标不保证对下游任务有正向效果（实验中 LIBERO-90 玩耍反而使成功率从 21.1% 降至 11.1%）。
  - ASPIRE 验证并检索程序修复，但许多修复仍绑定于固定距离或抓取高度，且仍在任务执行期间保留源代码生成/修复。
- **核心研究问题**：CaP 系统应如何划分"进化时代码"与"运行时决策"，使其既能持续进化、跨任务迁移，又能适应当前物理状态？
- **整体含义**：论文提出 **evolution-to-execution** 问题，主张将编码移至进化阶段，运行时仅保留 ReAct 循环中的可操控函数调用，从而分离"可复用代码"与"场景依赖决策"。

## 2. 方法论

### 2.1 核心思想

- 将系统分解为三个持久组件：**带类型的策略 API（Policy APIs, Aθ）**、**ReAct 智能体执行框架（πφ）**、**长期经验记忆（M）**，即 Π = (Aθ, πφ, M)。
- **Policy APIs** 编码可复用的几何与接触机制，同时暴露参数供 ReAct 操控。
- **ReAct** 保留场景依赖的选择：动作顺序、函数参数、恢复策略、停止决策。
- 部署时**冻结源代码**，但保留自适应决策能力。

### 2.2 关键技术细节

- **两阶段进化策略**：
  - **Phase 1（能力课程学习）**：在 41 任务运输队列上依次建立基础 pickplace（Seed）、几何（Geometry）、重试（ReAct）、失败反馈（Reports）、视觉修正（Visual），成功率从 13/41（31.7%）提升至 28/41（68.3%）；再扩展至全部 90 任务，引入六种接触力学 API 与执行框架优化，从 40/90（44.4%）提升至 48/90（53.3%）。
  - **Phase 2（自主自进化）**：系统聚类当前失败、选择下一能力目标、提出单一变更（API、参数暴露、工具报告、ReAct 路由或记忆），并在相同任务、种子、预算下与冻结父系统配对比较，仅当严格提升原生成功率时晋升。共生成 32 个提案、测试 23 个候选，产生 9 次晋升。
- **运行时架构**：
  - **Full ReAct**：解析完整指令、排序目标、检查语义状态、路由六种 API。
  - **Transport ReAct**：专注单一源到目标子目标，使用 pickplace、insert、push、look、check、done。
  - 六个类型化提示角色：task_plan、task_plan_review、state_preflight、state_decide、transport_decide、transport_reflect。
- **记忆结构**：任务目标驱动的工作记忆（当前 episode）+ 长期经验记忆（跨 episode 的可复用教训，不存储特权答案）。
- **目标函数**：
  - API 选择（式 2）：θ* = argmax Στ∈Ddev [S(τ, Aθ′, πφ, M) − S(τ, Aθ, πφ, M)]，奖励配对增益超过回归的机制。
  - ReAct 与记忆选择（式 3）：词典序目标，先最大化成功率，再最小化 ReAct 轮数。
- **拒绝采样微调（RFT）**：将 GPT-5.6-sol 教师的 ReAct 决策蒸馏到 Qwen3-VL-8B-Instruct，仅保留原生成功、满足 schema 约束、含有效视觉证据的 rollout（54 接受 / 40 拒绝），训练角色特定 LoRA 适配器，冻结基座与视觉编码器。
