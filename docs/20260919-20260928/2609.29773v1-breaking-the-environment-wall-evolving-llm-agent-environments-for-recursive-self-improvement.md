## 摘要
许多现实世界任务（例如办公工作流、科学实验）要求LLM智能体与其环境反复交互以进行上下文相关的操作。然而，此类环境往往并非智能体就绪。首先，信息常常分散且碎片化地存在于环境中。其次，环境中的相关证据常常与误导性信息和相互冲突的版本混杂在一起。第三，环境随时间演化，引入新的噪声和更具挑战性的任务。这些挑战会显著降低最先进AI智能体的性能（例如从83.9%降至57.6%）。为应对这些挑战，我们提出Env-Rethink（一个具有27B后训练模型的系统），它支持三项主要能力：（1）它自适应地构建收集映射（用于组织相关文件）和事件日志（用于将跨数据关系置于上下文中），以补充必要的上下文；（2）它进一步利用后训练模型（通过离线轨迹学习）来识别环境中潜在的噪声问题；（3）它最终通过虚拟事件历史来演化环境，这些历史改变环境状态和证据关系，从而产生更棘手的任务以进一步改进智能体。实验表明，Env-Rethink能够有效提升下游任务性能（在30个任务上，九个模型的标准通过率提升超过15.1%）。

## Abstract
Many real-world tasks (e.g., office workflows, scientific experimentation) require LLM agents to interact repeatedly with their environments for context-dependent operations. However, such environments are often not agent-ready. First, information is often scattered and fragmented across the environment. Second, relevant evidence in the environment is often mixed with misleading information and conflicting versions. Third, environments evolve over time, introducing new noise and more challenging tasks. These challenges can substantially degrade performance for state-of-the-art AI agents (e.g., from 83.9% to 57.6%). To address these challenges, we propose Env-Rethink (a system with 27B post-trained model) that supports three main capabilities: (1) It adaptively builds Collection Maps (for organizing related files) and Event Logs (for contextualizing cross-data relationships) to supplement necessary context; (2) It further leverages the post-trained model (through offline trajectory learning) to identify underlying noise issues in the environment; (3) It ultimately evolves environments through virtual event histories that alter environmental states and evidence relationships, producing more tricky ones for further agent improvement. Experiments show that Env-Rethink can effectively improve downstream task performance (with over 15.1% rubric pass rate improvement across nine models on 30 tasks).

# 论文总结：Breaking the Environment Wall

## 1. 核心问题与整体含义

- **研究动机**：真实世界任务（办公工作流、科学实验等）要求 LLM 智能体与持久化文件环境反复交互，但这类环境往往"非智能体就绪"（not agent-ready）。
- **三大环境瓶颈**：
  - 信息分散、碎片化地散布在环境中；
  - 相关证据与误导性信息、冲突版本混杂；
  - 环境随时间演化，不断引入新噪声与更难任务。
- **性能冲击**：在 30 个困难任务、9 种模型-框架配置下，平均评分通过率从干净环境的 **83.9% 骤降至噪声环境的 57.6%**（下降 26.3 个百分点）。
- **三种典型失败模式**：
  - 搜索不足、阅读不完整（遗漏修正、约束与支撑证据）；
  - 把文件名当作版本指示（如误信 `final.bib`，忽略后续撤回通知）；
  - 复用相似文件而不核验需求（把不兼容假设带入交付物）。
- **整体含义**：论文主张"环境侧干预"（组织、准备、演化）是与模型参数更新互补的一条路径，可为智能体的**递归自我改进**提供新范式——既让现有任务更易执行，又生成可验证的更难任务。

## 2. 方法论

### 核心思想
Env-Rethink 是一个统一系统，包含三个互补模块：**环境组织**、**学习式环境准备**、**事件驱动环境演化**。三者共享"任务请求不变、只改变证据暴露方式与状态"的原则。

### 关键技术细节

- **模块一：证据链接的环境组织（Section 4）**
  - **Collection Map（收集地图）**：先按目录结构确定性分组，由 Collection Summarizer 生成卡片；Semantic Coordinator 提出拆分/合并/转移/多归属建议，确定性程序校验并保证文件全覆盖（集合可重叠）；Collection Refiner 更新卡片，迭代进行。
  - **Event Log（事件日志）**：History Synthesizer 读取文件提出候选历史（会话由读/写/拷贝/导出事件组成，记录 actor、action、time、path、provenance）；引用证据与生成器推断严格分离；独立 Evidence Reviewer 校验引用匹配、判断有据、动作与文件一致、与现存文件一致；失败则修复，超预算则丢弃；后续轮次隐藏已用文件以覆盖其他材料；Timeline Integrator 合并为统一日志。
  - **两种准备输入**：EGS（仅用环境文件与元数据）与 TGS（额外使用任务监督，如 clean/noise 文件标签，但禁止在公开日志中复述评分标准）。

- **模块二：学习式环境准备（Section 5）**
  - 核心是一个**文件验证器**：输入文件集合、清单、读文件工具与指令（**不含下游用户请求**），输出每个文件的 standard/noise 划分、类别、观察阶段、家族归属、时间线信息与支撑证据。
  - **六类标签**：authoritative record、false final version、fabricated authority、misleading redirection、superseded version、out-of-scope file。
  - **数据构造**：攻击场景（权威目标+诱饵链）、版本家族、重定向组、填充文件；教师来自 DeepSeek/GLM/Gemini 家族，通过 Claude Code 在隔离沙箱中执行。
  - **轨迹资格审核**：读保真检查 + 划分 F1≥0.9、零权威误拒、强诱饵全对、版本顺序正确；失败则由独立 agent 修改提示重试（最多 2 次），仍失败则剔除。
  - **训练目标（SFT 损失）**：
    - $L_{SFT}(\theta) = -\frac{1}{\sum_t m_t}\sum_{t=1}^{T} m_t \log p_\theta(x_t | x_{<t})$
    - 其中 $m_t$ 仅选中助手 token（工具调用、中间叙述、最终判断），工具返回的文件内容不贡献损失。
  - **部署**：验证器判断用于文件选择与证据报告，报告与选中文件一并交给下游任务智能体。

- **模块三：事件驱动环境演化（Section 6）**
  - **反默认决策点（counter-default decision point）**：配对"看似可信的错误选择"与"唯一能纠正它的证据"及"拒绝错误选择的检查"；每个变体至少 3 个，证据链不短于种子。
  - **四类决策点**：时间型（更新是否已生效）、排除型（撤回/未登记/缺底层事件）、例外规则型、数值型（需从源输入重算）。
  - **生成公式**：
    - $(E_{t+1}, y_{t+1}, V_{t+1}, \Delta H_{t+1}) = G_\phi(E_t, q, V_t, H_t, D_t; z_t)$
    - 其中 $q$ 固定，$y_{t+1}$ 为更新后的参考答案，$\Delta H_{t+1}$ 记录新事件，$D_t$ 为可用失败反馈。
  - **验证**：结构检查（事件、文件引用、装配、材料放置、评估资产语法、任务指令逐字节比对）+ 答案验证（新参考解须通过、旧期望输出须失败）+ 捷径审计。
  - **难度评估**：种子与变体在匹配配置与预算下配对运行，区分决策错误、缺失输出与环境故障。

## 3. 实验设计

- **数据集 / 场景**：
  - **Environment-Hard**：30 个困难任务（改编自 Workspace-Bench），共 1,280 条评分项；其中 15 个为训练源任务（1,579 文件），15 个为留出任务（617 文件）；全部标注集 2,196 文件（192 标准 + 2,004 噪声）。
  - **Terminal-Bench 2.1**：59 个种子任务（4 易 + 55 中），覆盖 14 个类别；排除 1 个变体参考运行失败的任务后保留 58 个，其中 55 个有配对结果。
- **Benchmark 与评价指标**：
  - Environment-Hard 用 rubric pass rate（通过检查数 / 1,280）；
  - Terminal-Bench 2.1 用原生二元任务成功（需通过全部检查），每臂名义 3 次试验。
- **对比方法**：
  - 环境组织：TGS vs. EGS vs. Noise（无组织层），5 个模型；
  - 学习式准备：Full（全部噪声文件）vs. Qwen3.8-27B（未适配模型选文件）vs. Env-Rethink（训练模型选文件+证据报告），9 个下游模型；另设 GT 标签选择作为参考上界；
  - 环境演化：种子 vs. 演化变体，4 个模型（DeepSeek-V4.1-Flash、Gemini-3.8-Flash、Qwen3.8-Flash、GLM-5.3-Flash）。
- **消融实验**：TGS 组件消融（去掉 Collection Map / 去掉 Event Log），在 DeepSeek-V4.1-Flash 上。

## 4. 资源与算力

- **基础模型**：Qwen3.8-27B（27B 稠密模型，上下文容量 256k）。
- **适配方式**：LoRA 监督微调（rank 64 / alpha 128，作用于全部线性层）。
- **训练配置**：3 个 epoch，1,780 训练样本 / 201 开发样本，学习率 1×10⁻⁴（cosine），bf16，训练上下文 32k，DeepSpeed ZeRO-3。
- **硬件**：**一台配备 8 张 H20 GPU 的机器**。
- **训练时长**：**9 小时 44 分 46 秒**，共 168 个优化步。
- **训练指标**：最终训练损失 0.199 / token 准确率 93.6%；开发损失 0.197 / token 准确率 94.1%。
- **说明**：论文未报告环境组织模块（Collection Map / Event Log 合成）与演化模块（Environment Evolver）的推理算力开销，也未给出教师轨迹生成的总 token 或调用成本。

## 5. 实验数量与充分性

- **实验组数概览**：
  - 动机实验：9 种模型-框架配置 × Clean/Noise 两条件；
  - 环境组织：5 个模型 × 3 条件（TGS/EGS/Noise）；
  - 学习式准备：模块级评估（2 个模型 × 2 个数据划分 × 4 项指标）+ 下游评估（9 个模型 × 3 条件 × 30 任务 × 1,280 检查）；
  - 环境演化：55 个配对任务 × 4 个模型 × 每臂 3 次试验；
  - 消融：2 个组件 × 1 个模型。
- **充分性评价**：
  - **较充分**：下游评估覆盖 9 个模型、6 个家族，且所有条件在同一任务集上配对比较；演化研究覆盖 10+ 技术类别，并给出类别级与任务级案例。
  - **客观性**：使用 rubric 检查与原生二元成功判定，缺失输出计零但保留分母；演化采用配对种子-变体运行以控制任务难度差异。
  - **公平性**：所有模型在相同任务、相同检查集下比较；演化中种子与变体使用匹配配置与执行预算。
  - **潜在不足**：环境组织实验仅 5 个模型；消融仅 1 个模型；演化仅 4 个模型且部分任务试验数不足 3 次（如 GLM 在 largest-eigenval 上种子 1/2、变体 0/3）。

## 6. 主要结论与发现

- **环境组织有效**：TGS 在全部 5 个模型上优于 EGS，两者均优于 Noise。例如 DeepSeek-V4.1-Flash 从 64.4%（Noise）→82.9%（EGS）→87.3%（TGS）；GLM-5.3-Flash 从 58.3%→63.6%→81.6%。
- **学习式准备显著提升下游性能**：9 个模型平均通过率从 57.6%（Full）与 59.4%（Qwen3.8-27B）提升至 **72.7%（Env-Rethink）**，相对未适配模型平均 +13.3 个百分点，各模型增益 3.4–17.8 个百分点。
- **文件验证能力提升**：训练源环境划分准确率 74.0%→90.0%；留出环境 56.2%→76.5%，联合准确率 19.4%→32.4%。
- **准备质量改善**：Env-Rethink 保留 160/192 标准文件（召回 83.3%），仅引入 271 个噪声文件；对比 Qwen3.8-27B 保留 136、引入 606。
- **环境演化可制造更难任务**：55 个配对任务中 **32 个（58.2%）在至少 3 个模型上成功率下降**，其中 21 个在全部 4 个模型上下降；覆盖 10 个类别（13 个软件工程任务中的 10 个、5 个调试任务中的 4 个、全部 3 个模型训练任务）。
- **组件贡献**：去掉 Collection Map 使 TGS 通过率下降 12.2 个百分点，去掉 Event Log 下降 2.4 个百分点，说明 Collection Map 是主要贡献者。
- **总体结论**：环境组织与学习式准备帮助智能体恢复有效证据，环境演化则创造新的测试情境；三者共同构成"环境驱动的递归自我改进"闭环。

## 7. 优点

- **问题定位精准**：把"环境非就绪"拆解为可操作的三个子问题（跨文件上下文、可靠环境判断、可验证的更难环境），并给出对应的三个模块。
- **方法体系完整**：从静态组织（Collection Map / Event Log）到学习式准备（验证器 SFT）再到动态演化（事件驱动生成），形成闭环，且明确区分"准备"与"演化"两种干预语义。
- **证据严谨性设计**：Event Log 强制引用证据与生成器推断分离、独立 Evidence Reviewer 审核；演化要求参考解通过、旧答案失败、任务指令逐字节不变，并设捷径审计。
- **训练数据构造精细**：按攻击场景/版本家族/重定向组/填充文件构造子环境，教师轨迹经读保真与多项资格门槛筛选，失败提示由独立 agent 修订。
- **评估覆盖面广**：下游评估跨 9 个模型、6 个家族；演化评估跨 14 个类别、55 个配对任务，并给出任务级案例（如 log-summary-date-ranges 从全对降至 0/3）。
- **可复用性**：同一 Env-Rethink 模型为全部 9 个下游模型准备环境，说明准备步骤可在环境层复用与版本化。

- **算力报告不完整**：仅报告 SFT 训练算力（8×H20，约 9.7 小时），未报告数据合成、教师轨迹生成、环境演化与验证的推理成本。
- **实验覆盖有限**：
  - 环境组织实验仅 5 个模型，消融仅 1 个模型；
