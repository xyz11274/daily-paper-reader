## 摘要
最近的LLM智能体能够处理越来越长程、开放式的任务，而外部技能（即提供给智能体的可重用过程知识）进一步扩展了这种能力。然而，固定的手工编写的技能很少是最优的，也无法适应智能体遇到的任务的多样性。自我改进的智能体通过从执行轨迹中重写自己的技能文件来解决这个问题，从而在具有挑战性的基准测试中取得了有意义的收益。然而，这种自我进化仍然是非递归的：它只改进了任务技能（智能体做什么），而改进过程（如何改进）只编写一次并保持固定。我们引入了MetaSkill-Evolve，一个双时间尺度框架，使得智能体技能的改进成为递归的：每个分支都携带一个任务技能$s$和一个分支局部的元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件参数化了改进流程的分析器、检索器、分配器、提议器和进化器智能体。任务技能在快速循环中进化，而元技能在较慢的循环中进化，在相同的流程应用于自身的情况下，无需额外的模型或目标。由于所有五个流程智能体共享一个冻结的主干网络，MetaSkill-Evolve在三个智能体基准测试（OfficeQA、SealQA、ALFWorld）上优于无技能、静态技能和单级进化基线，分别在保留的测试准确率上比原始主干网络提高了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将改进管线（analyze→propose→evolve）视为由五个组件参数化的过程，每个组件本身是Markdown格式的技能文件。通过双时间尺度分离任务技能演化（快速）和元技能演化（慢速），并使用相同的五智能体管线递归地应用于元技能自身，实现无需额外模型或目标的递归自改进。

- **关键技术细节**：
  - **分支状态**：每个分支$b = (s, m, h)$，其中$s$为任务技能，$m = (\psi, \sigma, \alpha, \pi, \varepsilon)$为元技能，$h$为迭代历史。
    - $\psi$：诊断策略（Analyzer），将失败映射为标签$\phi$和自由形式分析$a$。
    - $\sigma$：共享策略（Retriever），选择同分支和跨分支的灵感节点。
    - $\alpha$：分配策略（Allocator），决定每次的子技能预算$K \in [1, K_{\max}]$。
    - $\pi$：编辑提议策略（Proposer），生成具体编辑$\delta$。
    - $\varepsilon$：编辑执行策略（Evolver），写入磁盘并验证。
  - **图结构**：整个搜索历史作为有向无环图（DAG）持久化在SQLite中，每个节点存储分支状态、效用$U_v$、生产率$\Delta U_v$、标签$\phi_v$和选择次数。
  - **前沿选择**：采用多目标评分$\eta_1 U_v + \eta_2 \hat{P}_v + \eta_3 N_v$，其中$U_v$是任务效用（利用），$\hat{P}_v$是元生产率估计（轨迹质量），$N_v=1/(1+\text{times\_selected}_v)$是访问冷却（多样性）。
  - **快速循环（算法1）**：
    1. 恢复选定父节点的任务和元快照。
    2. 通过训练集评估，选取最差失败样例。
    3. Analyze → Retrieve → Allocate → Propose → Evolve，生成$K$个子技能。
    4. 每个子技能在验证集上评估$\Delta U_k$，只有严格改进（$\Delta U > 0$）的节点进入档案。
    5. 每$H$次迭代触发慢速循环。
  - **慢速循环（算法2）**：
    1. 基于最近$H$个后代的改进率$\hat{P}$构建元失败踪迹$f_m$。
    2. 对$f_m$运行相同五智能体管线，目标从任务技能文件切换为元技能文件。
    3. 分析器识别最应改进的元组件，检索器匹配相似元失败，分配器设定$K_m$，提议器和进化器协作重写全部五个元文件。
    4. 累积式子代：子代$k+1$基于子代$k$写入的文件进行增量改进。

## 7. 优点

- **方法创新**：提出双时间尺度递归自改进框架，将改进过程本身作为可学习对象，突破了现有自改进系统的非递归局限。元技能采用与任务技能相同格式的Markdown文件，使得递归应用同一管线自然且简单。
- **设计完整性**：元技能五组件覆盖了改进管线的所有环节（分析、检索、分配、提议、执行），且每个组件均可通过慢循环独立演化，适应不同失败模式。
- **持久化图结构**：使用SQLite持久化DAG，支持跨分支检索、完整的溯源记录、以及非递增或失败节点的保留（用作灵感），避免固定大小波束的局限性。
- **多目标前沿选择**：同时考虑效用、元生产率和访问次数，平衡利用、探索和多样性，防止搜索陷入停滞或垄断。
- **实验公平性**：所有对比方法共享同一冻结主干模型，增益完全归因于技能演化策略；测试集从未在演化中露面，评估泛化能力。
- **消融分析深入**：逐组件消融揭示了不同领域对元技能组件的依赖差异，为未来设计提供指导。

## 8. 不足与局限

- **实验覆盖有限**：仅在三个经过筛选的基准上评估，未测试更开放、长程、噪声更大的真实世界任务（如复杂软件工程、多轮对话等），泛化性待验证。
- **管线结构固定**：五个智能体及其角色、连接方式（analyze→retrieve→allocate→propose→evolve）是预先固定的，只演化各组件的技能内容，而不演化管线本身的结构或组件数量。真正的递归自改进可能需要更灵活的结构进化。
- **元更新间隔固定**：$H$是超参数而非自适应调节，不同任务或不同演化阶段最优$H$可能不同，固定间隔可能不是最优。
- **计算开销**：使用31B参数模型进行多次推理（每次迭代对每个子技能评估），虽然未训练但推理成本高，论文未报告具体GPU时间、能耗等，影响可复现性评估。
- **高基线任务增益小**：在ALFWorld上改进幅度仅+1.92，且静态技能甚至导致下降，表明方法在已近饱和的任务上实用性有限。
- **分支间元技能共享受限**：元技能仅通过元级别检索的单一渠道传递，没有全局共享机制，可能影响优秀改进策略的快速扩散。
- **标签维护**：分析器$\psi$维护自己的标签词汇表，细粒度标签的效果主要依赖慢循环更新，可能引入收敛延迟或不一致。
