## 摘要
在长周期LLM系统中，智能体自我进化在很大程度上是程序性的：有用的经验不仅仅是存储的信息，而是用于搜索、调试和验证的可重用程序。然而，当前的评估并未隔离这种形式的迁移。智能体基准测试测试单轮任务解决；记忆基准测试则针对信息保留而非程序性重用。我们引入了EvoAgentBench，这是一个通过能力引导迁移实现智能体自我进化的基准测试，涵盖四个智能体领域：网络研究、算法推理、软件工程和知识工作。EvoAgentBench从智能体执行中提取轨迹基础的能力，将其规范化操作单元，并构建特定领域的能力图，连接具有程序重叠的任务。通过设计，每个测试任务都有经过验证的训练侧能力支持。在528/267的训练/测试划分、两种框架和三种骨干模型上，精心策划的能力内容在不同模型家族间可靠地迁移，但当前没有自动方法能在所有设置中保持正向收益。EvoAgentBench将自我进化评估从总体精度比较转变为对经验编码、路由和吸收的细粒度诊断。该基准测试可在https://huggingface.co/datasets/EverMind-AI/EvoAgentBench公开获取。

## Abstract
Agent self-evolution in long-horizon LLM systems is largely procedural: useful experience is not merely stored information, but reusable procedures for searching, debugging, and verification. Yet current evaluations do not isolate this form of transfer. Agent benchmarks test single-episode task solving; memory benchmarks target information retention rather than procedural reuse. We introduce EvoAgentBench, a benchmark for agent self-evolution via Ability-guided transfer across four agentic domains: web research, algorithmic reasoning, software engineering, and knowledge work. EvoAgentBench extracts trace-grounded Abilities from agent executions, canonicalizes them into operational units, and builds domain-specific Ability Graphs linking tasks that share procedural overlap. By design, every test task is backed by verified training-side Ability support. Across a 528/267 train/test split, two scaffolds, and three backbones, curated Ability content transfers reliably across model families, but no current automatic method sustains positive gain in all settings. EvoAgentBench shifts self-evolution evaluation from aggregate accuracy comparison to fine-grained diagnosis of experience encoding, routing, and uptake. The benchmark is publicly available at https://huggingface.co/datasets/EverMind-AI/EvoAgentBench.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：构建一个**“能力支持（Ability-supported）但实例不重叠（Instance-disjoint）”** 的基准。即，测试任务必须与训练任务共享可迁移的“能力”（Ability），但确保不是同一问题的重复或近亲繁殖，以纯净地测量程序性知识的迁移。
- **关键技术细节**：EvoAgentBench的构建遵循一个三阶段流程：
    1.  **多骨干模型轨迹收集（Multi-Backbone Trace Collection）**：
        - 使用多个不同的构建骨干模型（Kimi-K2.5, GLM-5.1, DeepSeek-V3.2）对每个任务进行无技能（no-skill）的执行，收集成功和失败的轨迹（Trajectories）。通过对比不同模型的执行过程，提取通用的、可重复的操作模式。
    2.  **轨迹赋能的能力提取与规范化（Trace-Grounded Ability Extraction & Canonicalization）**：
        - **能力提取**：从每个任务的轨迹中，由提取模型（如Claude Sonnet 4.6）提取“原始能力卡”（raw Ability cards）。每张卡是一个元组，包含触发条件（Trigger）、可重用程序（Procedure）、证据（Evidence）、边界（Boundary）和角色（Role：方法Method、防护Guard、工作流Workflow）。
        - **能力规范化**：不同任务提取的原始能力卡可能描述同一操作。通过嵌入相似度分块（Embedding Blocking）和LLM调解（LLM Adjudication）+ 领域专家审查的方式，将任务局部的原始能力卡**合并成标准的、具备操作等价性的规范能力单元**（Canonical Ability Units）。这构成了共享的“能力词汇表”。
    3.  **能力图构建与能力感知的迁移划分（Ability Graph & Ability-Aware Transfer Split）**：
        - **构建能力图**：在每个领域内，如果两个任务共享了至少一个规范能力单元，它们之间就存在一条边。从而构建出领域的能力图（Ability Graph），图中的社区（Communities）代表了程序性重叠的局部区域。
        - **能力感知的迁移划分**：基于能力图的社区结构，进行受约束的采样。确保**每个被分配到测试集的任务，都至少与一个训练集中的任务共享一个规范能力单元**。这样就保证了测试任务在能力层面有训练侧的支持。实验最终得到528个训练任务和267个测试任务，且所有测试任务的支持度均为零。

### 3. 实验设计：数据集、基准与对比方法

- **数据集与场景**：涵盖四个长期周期的智能体任务领域：
    - **网络研究（Web Research）**：使用**BrowseComp-Plus**基准。
    - **算法推理（Algorithmic Reasoning）**：使用**LiveCodeBench**基准。
    - **软件工程（Software Engineering）**：使用**SWE-Bench Verified**基准。
    - **知识工作（Knowledge Work）**：使用**GDPVal**基准。
- **基准（EvoAgentBench）**：整个框架本身就是评估基准。它提供了训练轨迹和测试任务，所有方法都基于此进行自我进化对比。
- **对比方法**：在两种智能体框架（**OpenClaw**和**Nanobot**）和三种骨干模型（**Qwen3.5-27B**、**Qwen3.5-397B**、**Gemma-4-31B**）上进行评估。对比了四种进化状态/方法：
    - **Vanilla（基线）**：没有任何进化状态。
    - **Memento**：通过嵌入相似度检索并重用最相似的训练案例。
    - **ReasoningBank**：从训练中蒸馏推理记忆，并按策略相似度检索。
    - **GEPA**：在训练集上演化一个单一提示（Prompt），并在所有测试任务上广播使用（无检索）。
    - **Anchor Skill（诊断参考）**：使用由提取管道产生、并由策展方（Curator）提供能力标签进行路由的技能。**这是一个不可部署的诊断参考，用于衡量其技能内容本身在原则上是否可迁移**。其技能内容完全来自训练侧。

### 6. 论文的主要结论与发现

1.  **能力内容是跨模型可迁移的**：诊断参考“Anchor Skill”在所有6个基础设置、24个方法-领域-设置单元格中都产生了正向的平均迁移增益。这表明，从轨迹中提取的高质量、结构化的过程性知识（能力）可以被不同模型家族（如Qwen与Gemma）理解并有效利用。
2.  **自动方法仍然脆弱**：所有三种自动自我进化方法都存在至少一个设置（骨干-领域组合）中出现负迁移的情况，即注入的经验反而损害了性能。它们的表现也随骨干模型、领域和框架的不同而变化。
3.  **瓶颈在于方法端的提取与路由**：由于人工精心制作的“Anchor Skill”表现优异，而自动方法在同等条件下却表现不稳定，论文得出结论：当前自动方法的瓶颈不在于训练数据中缺乏能力，而在于它们自身**从轨迹中提取可重用内容、索引和路由到正确测试任务**的机制存在缺陷。
4.  **成本与准确性并非线性相关**：提供准确匹配的进化技能可以节省步骤，但许多自动方法（如Memento、GEPA）即使解决了任务也增加了交互成本。降低成本和提升性能不可兼得，需要联合报告。
5.  **多设置评估至关重要**：因为迁移增益会因领域、框架和骨干模型的不同而共同变化，因此在单一设置上的评估是不可靠的。EvoAgentBench提出的多域、多框架、多骨干模型评估框架是必要的。

### 7. 优点

- **方法创新性**：提出了“能力支持但实例不重叠”的结构化原则来设计自我进化基准，从概念上区分了信息记忆和程序性知识迁移。**能力图（Ability Graph）** 的构建是核心创新，它将任务间的共享操作作为迁移的依据，而非简单的标签或主题。
- **诊断能力**：EvoAgentBench不仅仅是一个评估平台，更是一个诊断工具。通过比较自动方法和“Anchor Skill”的表现，可以精准定位问题发生在经验编码、路由还是吸收环节，对方法开发有直接指导意义。
- **公平性与泛化性**：实验设计严谨，在多个模型系列、规模和框架上进行，增强了结论的稳健性和泛化能力。Anchor的技能内容由独立的骨干模型构建，排除了数据泄露或模型自适应偏差。
- **成本透明**：不仅报告准确率，还详细分析了交互成本的变化，揭示了成本与性能的复杂关系，为实际应用提供了有价值的参考。

### 8. 不足与局限

- **实验覆盖有限**：仅评估了四个基于文本的长期周期智能体领域和三个开源骨干模型。扩展到多模态或具身智能体，以及更大或专有的模型家族超出了本文范围。每个测试集的大小（56-86个任务）相对有限，进行更细粒度的领域内分析时力度可能稍显不足。
- **能力提取的依赖**：能力提取步骤（Eϕ）使用了单个模型（Claude Sonnet 4.6），其选择会影响最终的能力词汇表。虽然后续的规范化过程（三LLM调解+专家审查）能减轻一些特定偏差，但替代提取器的影响尚未被研究。
- **数据污染风险**：评估用的骨干模型可能在预训练阶段遇到过源基准（如SWE-Bench、LiveCodeBench）的数据。作者指出，因为所有条件共享同一骨干，这只会影响绝对分数，而不会影响条件间的比较结果，但这仍是一个潜在的干扰因素。
- **评估偏差**：测试集偏向于对部分构建骨干模型有提升空间的任务，这使得报告的绝对增益（Δ）并非对随机任务样本的期望估计，而更像是“最佳情况”下的结果。虽然这不影响方法间的排序，但可能无法完全反映在实际应用中的平均收益。
