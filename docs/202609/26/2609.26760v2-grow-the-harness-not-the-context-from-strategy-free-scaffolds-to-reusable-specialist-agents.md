## 摘要
大型语言模型（LLM）智能体经常处理一系列相关任务，然而标准执行框架会反复要求模型在每个任务的上下文中重建相同的控制决策。我们研究任务反馈是否能够转而将反复出现的控制转化为可复用的可执行代码，同时将 LLM 调用保留用于任务特定的语义推理。我们提出 Growing Harness，一种失败引导的训练范式，它从一个无策略脚手架中学习智能体执行框架本身；该脚手架暴露固定的模型与工具接口，但不编码任何任务求解控制器。函数级执行轨迹将每次失败定位到一个有界代码面上，优化器联合修复一个失败窗口，而成功优先的留出集门控会回滚那些损害先前能力的修复序列。被接受的编辑会累积在一个共享执行框架中，使其控制结构能够从任务反馈中涌现。在 BrowseComp-Plus 和 WebArena-Verified 上，使用从 4B 到 120B 参数的三类部署模型，Growing Harness 在六个基准-模型设置中的五个取得最高平均成功率，在第六个中比最佳均值低 0.7 个百分点。相对于 Tool-Calling 智能体，它将 LLM 调用减少 76.0-91.8%，并将部署智能体的推理成本降低 74.4-98.6%。在 WebArena-Verified 上，其成功率在不同模型规模下保持在 44.7-45.3%，而 Tool-Calling 在使用 4B 模型时降至 6.7%。消融实验表明，轨迹局部编辑、联合修复和基于门控的回滚均能提升最终成功率。这些结果表明，持续的程序增长可以将反复出现的控制从模型上下文中移出并转入低成本代码，从而产生可复用的专家智能体，使其在较小部署模型上仍然有效。

## Abstract
Large language model (LLM) agents often handle streams of related tasks, yet standard harnesses repeatedly ask the model to reconstruct the same control decisions inside each task's context. We study whether task feedback can instead turn recurring control into reusable executable code, while reserving LLM calls for task-specific semantic reasoning. We introduce Growing Harness, a failure-guided training paradigm that learns the agent harness itself from a strategy-free scaffold that exposes fixed model and tool interfaces but encodes no task-solving controller. Function-level execution traces localize each failure to a bounded code surface, an optimizer repairs a window of failures jointly, and a success-first held-out gate rolls back repair sequences that harm prior capability. Accepted edits accumulate in one shared harness, allowing its control structure to emerge from task feedback. Across BrowseComp-Plus and WebArena-Verified with three deployment models from 4B to 120B parameters, Growing Harness achieves the highest mean success in five of six benchmark-model settings and trails the best mean by 0.7 pp. in the sixth. Relative to a Tool-Calling agent, it reduces LLM calls by 76.0-91.8% and deployed-agent inference cost by 74.4-98.6%. On WebArena-Verified, its success remains 44.7-45.3% across model scales, whereas Tool-Calling falls to 6.7% with the 4B model. Ablations show that trace-local edits, joint repair, and gate-based rollback each improve final success. These results show that persistent program growth can move recurring control out of model context and into low-cost code, yielding reusable specialist agents that remain effective with smaller deployment models.

# 论文总结：Grow the Harness, Not the Context

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体常面向同一任务族反复执行任务，但标准 harness 会在每个任务的上下文中重复要求模型重建相同控制决策，如查询改写、观察过滤、进度验证、错误恢复和停止判断。
- **核心痛点**：重复委托给 LLM 虽然灵活，但会增加推理调用、上下文长度和成本；小模型在资源受限设备上尤其难以稳定完成这些控制决策。
- **核心问题**：能否用任务反馈把“反复出现的控制”固化为可复用可执行代码，而把 LLM 调用保留给任务特定的语义推理？
- **整体含义**：论文主张“让 harness 成长，而不是让上下文膨胀”。智能体程序本身应成为持久学习产物，控制结构从任务反馈中涌现，而不是预先手写或每次在线重建。
- **目标场景**：同一任务族内的重复部署，尤其是移动端、资源受限设备和较小部署模型。

## 2. 方法论

- **核心思想**：从 **strategy-free scaffold** 出发，只暴露任务入口、固定 LLM 接口和工具接口，不编码任何任务求解控制器；harness 是唯一可学习对象，模型与工具固定。
- **问题形式化**：部署智能体为 \(h(x;M,T)\)，其中 \(M\) 为固定 LLM，\(T\) 为固定工具，\(h\) 为可执行 harness 代码。训练集、门控集、最终评测集分离，优化器不接触最终评测集。
- **函数级执行轨迹**：每个任务记录执行图 \(G_i=(V_i,E_i)\)，节点表示函数调用、LLM 调用、工具调用、返回或错误；轨迹包含任务、图、输出、结果和 token/成本/时间。
- **失败定位**：从轨迹中提取参与执行的 harness 函数集合 \(F(\tau_i)\)，用于限定优化器可修改的代码面。
- **失败窗口课程**：维护有界失败窗口 \(W_t\)，容量为 \(K\)。窗口内任务保留最新轨迹和修复尝试次数；已解决任务离开，未解决任务保留并增加尝试次数，达到 \(R_{\max}\) 后退休。
- **轨迹引导的函数级优化**：
  - 优化器接收当前 harness、失败轨迹和离线诊断材料。
  - 只允许修改入口函数 `main` 及失败轨迹中出现的函数。
  - 可新增可复用 helper，但不得删除已有函数、不得改接口签名、不得硬编码任务 ID、答案或固定解。
  - 编辑预算为 \(L\)，即修改或新增函数数量受限。
  - 引导原则：确定性、可复用控制写入代码；语义解释、综合、模糊比较和答案生成保留给 LLM。
- **候选评估与窗口更新**：
  - 候选 harness 必须在整个活动失败窗口上重新执行。
  - 若解决任务数 \(P_t\) 低于修复阈值 \(Q\)，则丢弃候选。
  - 未解决任务进入下一窗口，并更新轨迹与尝试计数。
- **成功优先的留出集门控与回滚**：
  - 使用门控集 \(G\) 评估候选，只有 \(SR_G(\hat h_t) \ge SR_G(h_{\text{gate}})\) 才接受。
  - 否则回滚整个修复序列，包括代码、任务游标、失败窗口、计数器和训练记录。
  - 规则是“成功优先”：在线成本更低不能补偿门控成功率下降。
- **算法流程概述**：
  1. 初始化空脚手架 \(h_0\) 和空失败窗口。
  2. 在当前 harness 上运行未见任务，收集失败直到窗口满或训练流结束。
  3. 优化器基于失败轨迹生成 trace-scoped 候选。
  4. 候选在窗口上重执行，检查修复数量。
  5. 通过门控后接受并更新 harness；否则回滚。
  6. 重复直至任务流和窗口耗尽，最后再做一次门控检查，输出 \(h^\star\)。

## 6. 主要结论与发现

- **成功率**：Growing Harness 在 6 个 benchmark–model 设置中的 5 个取得最高平均成功率，在第 6 个仅比最佳均值低 0.7 个百分点。
- **效率**：相对 Tool-Calling，LLM 调用减少 **76.0–91.8%**，部署智能体在线推理成本降低 **74.4–98.6%**。
- **小模型鲁棒性**：WebArena-Verified 上，Growing Harness 在 4B 到 120B 模型间成功率保持 **44.7–45.3%**；Tool-Calling 在 4B 模型下降至 **6.7%**。
- **控制结构从反馈涌现**：
  - BrowseComp-Plus 学到共享检索与证据验证流水线。
  - WebArena-Verified 学到确定性 resolver、专门控制例程、通用浏览器循环和完成状态验证器的分层程序。
- **消融结论**：
  - 去除函数级指导：成功率从 36% 降至 18%。
  - 去除门控验证：从 36% 降至 22%，且门控成功率会先升后降，说明回滚必要。
  - 去除失败窗口：从 36% 降至 28%，说明多失败联合修复有助于识别可复用行为。
- **总体发现**：持续程序增长能把反复控制从模型上下文移入低成本代码，形成可复用专家智能体，并在小模型上保持较好效果。

## 7. 优点

- **问题定位清晰**：把“上下文膨胀”转化为“harness 程序增长”问题，视角新颖，强调结构性管理上下文。
- **低先验承诺**：从无策略脚手架开始，不预设 ReAct 式控制器，让控制结构由任务反馈涌现。
- **局部化优化**：函数级执行轨迹把失败定位到有界代码面，避免每步优化整个程序，降低搜索空间和代码上下文。
- **防退化机制**：成功优先门控与事务回滚能保护已获得能力，针对持续优化中“局部改进不累积”的风险。
- **成本优势显著**：在保持或提升成功率的同时大幅减少 LLM 调用和在线成本，尤其适合小模型和资源受限部署。
- **实验覆盖较广**：两个不同任务族、三个模型规模、多个基线、3 次独立运行，并提供效率与收敛分析。
- **可解释性较好**：最终 harness 可后验抽象为控制路径，展示不同任务族诱导不同程序结构。
