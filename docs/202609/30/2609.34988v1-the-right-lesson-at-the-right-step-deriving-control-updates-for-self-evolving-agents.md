## 摘要
自进化智能体通过复用过往经验来改进未来行为，通常以全局提示、记忆或反思的形式实现。然而，这些机制很少控制经验在何处生效。在长工具使用工作流中，同一经验可能纠正一个决策却干扰另一个决策，使得经验复用成为局部控制问题，而不仅仅是记忆问题。我们提出 EvoCUE（通过证据控制更新实现进化），一个从已完成的智能体执行中学习可复用控制程序更新的框架。EvoCUE 将智能体表示为一个显式的状态机控制器，其节点执行模型或工具调用，边定义控制下一步传递的位置。这使得工作流可在精确位置进行编辑，因此每个学习到的更新都能指定添加什么、在何处作用以及何时适用。从已完成的轨迹中，EvoCUE 利用残余目标和观察到的执行轨迹来提出局部化的指令或技能编辑。每个候选更新在其将作用的位置进行评估：从同一检查点恢复父控制器和编辑后的控制器，并比较它们的最终结果。被接受的编辑会与适用性规则一起编译，在留出任务上确认，并由后续执行继承。我们在长工具使用环境中评估 EvoCUE，其中学习到的约定必须到达正确的执行步骤。从一个没有基准特定引导指令的最小 AppWorld 控制器出发，EvoCUE 学习到缺失的任务完成约定，并在 Test-Normal 和 Test-Challenge 上大幅提高成功率。在 PAST-Bench 办公工作流中，EvoCUE 将先前回合中的组织要求迁移到后续任务，提高了任务执行质量。这些结果表明，自进化智能体应将经验置于控制流内部，而非仅将其存储为文本。

## Abstract
Self-evolving agents improve future behavior by reusing past experience, typically as global prompts, memories, or reflections. Yet these mechanisms rarely control where experience takes effect. In long tool-use workflows, the same lesson may correct one decision but distract another, making experience reuse a problem of localized control rather than memory alone. We introduce EvoCUE (Evolution through Control Updates from Evidence), a framework for learning reusable control-program updates from completed agent executions. EvoCUE represents the agent as an explicit state-machine controller, whose nodes perform model or tool calls and whose edges define where control passes next. This makes the workflow editable at precise locations, so each learned update can specify what to add, where it acts, and when it applies. From completed trajectories, EvoCUE uses residual goals and observed execution traces to propose localized instruction or skill edits. Each candidate is evaluated at the point where it would act by resuming the parent and edited controllers from the same checkpoint and comparing their final outcomes. Accepted edits are compiled with applicability rules, confirmed on held-out tasks, and inherited by later executions. We evaluate EvoCUE on long tool-use environments where learned conventions must reach the right execution step. From a minimal AppWorld controller without benchmark-specific onboarding instructions, EvoCUE learns the missing task-completion convention and substantially improves success on Test-Normal and Test-Challenge. On PAST-Bench office workflows, EvoCUE transfers organizational requirements from prior episodes to later tasks, improving task-execution quality. These results show that self-evolving agents should place experience inside the control flow, rather than only store it as text.

# 论文总结：The Right Lesson at the Right Step: Deriving Control Updates for Self-Evolving Agents

## 1. 核心问题与整体含义

- **研究动机**：自进化智能体（self-evolving agents）通常通过全局提示、记忆或反思来复用过往经验，但这些机制**很少控制经验在何处生效**。在长工具使用工作流中，同一经验可能纠正一个决策却干扰另一个决策。
- **核心问题**：经验复用本质上是一个**局部化控制问题**，而不仅仅是记忆存储问题。具体表现为两个耦合难题：
  - **定位问题**：如何识别一条经验应该影响控制流中的哪个位置？
  - **验证问题**：如何测量某个局部编辑是否真正改善了最终结果？从任务起点重跑会混入编辑作用前的无关变化。
- **整体含义**：论文主张自进化智能体应将经验**置于控制流内部**，而非仅作为文本存储。作者提出 EvoCUE 框架，将智能体表示为显式状态机控制器，使每条学习到的更新都能明确指定"添加什么、在何处作用、何时适用"。

## 2. 方法论

### 核心思想
- 将智能体建模为**显式状态机控制器** C = (G, π, Ω)：图 G 的节点执行模型或工具调用，边定义控制传递；路由策略 π 选择下一条边；库 Ω 存放可执行技能。
- 经验被转化为**局部化的控制器编辑**（指令或技能），而非全局文本。

### 关键技术细节

- **残余目标（Residual Goals）**：从已完成轨迹中估计任务指令里"公开历史尚未显示为已满足"的需求，将失败定位到可编辑位置。例如"导出前需获得批准"若历史中无批准记录，则为残余目标。
- **候选编辑 δ 的规格**：包含内容、位置（作用的边）、作用域（当前调用/技能调用/下一步动作）和预期效果。指令编辑添加文本；结构编辑插入 1–6 个原语操作的技能。
- **配对试验（Paired Trials）**：从编辑作用前的检查点 j 恢复环境状态、公开历史、控制器状态和剩余预算，然后分别执行父程序 C 和编辑程序 C⊕δ 至任务结束。效果定义为：
  - **d_tj(δ; C) = Y_tj(C⊕δ) − Y_tj(C)**，其中 Y 为最终任务得分。
  - 由于两次运行共享前缀，比较排除了编辑作用前的一切变化。
- **适用性规则拟合**：枚举至多两个等式测试的规则 q，选择使 **p̂_Sδ(q)·d_δ,q − λ|q|** 最大化的规则。编辑通过条件：至少覆盖 2 个任务、d_δ,q̂ > 0、且 p̂·d − λ(|q̂|+|δ|) > 0。
- **编译、确认与继承**：通过的编辑编译为候选程序 C′，在与提案/试验任务不相交的确认批次上从任务起点比较 C′ 与 C，满足预设接受标准后由后续任务继承。
- **试验记忆**：所有试验记录（接受与拒绝）均保留，供后续提案参考，避免重复失败方向。

### 算法流程（Algorithm 1 一轮学习）
1. 选择提案/试验任务与不相交的确认集 V；
2. 索引公开轨迹、残余目标和先前试验；
3. 提出带内容、位置、作用域和证据的编辑；
4. 对每个候选采样检查点、运行配对试验、存储记录、拟合适用性规则；
5. 若有通过的编辑，编译为 C′ 并在 V 上从任务起点比较；
6. 满足接受标准则 C ← C′，存储确认记录。

## 3. 实验设计

### 数据集 / 场景
- **AppWorld**：9 个模拟应用、457 个 API 的多步任务。90 个训练任务、57 个开发任务、168 个 Test-Normal、417 个 Test-Challenge。学习使用 32 个训练子集。
- **PAST-Bench**：模拟办公任务序列（工单处理、数据共享请求等），要求通过早期回合揭示。收集 16 个历史回合，8 个后续回合作训练，16 个后续试点任务评估。
- **六个额外领域**：τ²-bench、EvoClawBench、MBPP、HumanEval、MATH、HotpotQA。

### 对比方法
- **GEPA**（反思式提示进化）、**AFlow**（工作流代码搜索）、**AWM**（智能体工作流记忆）、**MaAS**（多智能体架构搜索）。
- 所有基线使用相同模型、工具、观察接口和预算，从相同的最小智能体提示出发（不含官方引导指令）。

### 模型与预算
- 所有模型调用使用 **deepseek-v4-flash** 自托管端点，温度 0，top-p 1，低推理努力，4096 token 思考预算，32768 token 输出限制。
- AppWorld：每任务 40 个环境动作、400 个控制器步骤；PAST 试点 900 个控制器步骤。

## 6. 主要结论与发现

- **AppWorld**：从最小控制器出发，EvoCUE 学到缺失的任务完成约定（非问题任务应将答案留为 None），Test-Normal 成功率从 13.7% 升至 79.2%（110 个改进、0 个退步），Test-Challenge 从 6.7% 升至 70.0%（270 个改进、6 个退步）。场景成功率分别从 5.4%→57.1% 和 2.2%→44.6%。
- **位置至关重要**：同一指令在首步仅解决 5/16 开发任务，在重复步解决 14/16；每步都提供也解决 14/16。关键在于指令是否在完成决策时可用。
- **基线表现**：在相同最小提示下，GEPA、AFlow、AWM、MaAS 在 Test-Normal 上最多提升 4.8 个百分点，Test-Challenge 上无一提升。
- **PAST-Bench**：EvoCUE 将任务执行分数从 0.608 提升至 0.772（11 改进、1 退步、4 持平），基线最大变化不超过 0.06。未见家族上从 0.35 升至 0.73（全部蒸馏知识），基线最多提升 0.14。
- **六个额外领域**：初始程序已高分或任务较短，EvoCUE 均未接受更新，基线变化也很小（最大为 GEPA 在 MATH 上 +3.1 分）。
- **核心发现**：经验驱动的适应不仅应学习复用**什么**经验，还应学习经验应进入控制流的**何处**。

## 7. 优点

- **问题定位精准**：将经验复用重新定义为局部控制问题，而非记忆问题，视角新颖且有实际意义。
- **方法论严谨**：
  - 配对试验从匹配检查点恢复，有效隔离编辑的下游因果效应，避免全任务重跑的混淆。
  - 适用性规则拟合借鉴因果推断中异质性处理效应的思想（Athey & Imbens, 2016）。
  - 确认步骤使用不相交任务，防止过拟合；试验记忆保留拒绝记录，避免重复失败方向。
- **实验设计公平**：所有方法共享模型、工具、观察接口和预算；冻结评估与学习严格分离；测试集信息不参与任何学习决策。
- **结果显著且可复现**：AppWorld 上 65.5/63.3 个百分点的提升幅度大；多次独立运行（不同种子、无历史假设）均重新发现同一约定；提供了实现哈希和配置标识。
- **诚实报告**：明确说明基线非复现、PAST 评判模型差异、小样本确认的保守性、以及学习成本记录不完整。

## 8. 不足与局限

- **适用性规则的泛化有限**：规则从有限观测任务推断，更广泛的迁移和异常的系统处理仍是开放问题。
- **配对试验依赖可恢复状态**：并非所有环境都支持检查点恢复，限制了方法的适用范围。
- **当前评估为冻结程序**：未涉及长任务流上的在线学习，而在线场景中不断增长的指令集在每个步骤重复注入会越来越昂贵。
- **确认步骤在小样本下偏保守**：未见家族研究中仅 2 个可改进确认任务，导致所有编辑被拒绝，牺牲了召回率。
- **实验覆盖不均衡**：六个额外领域中 EvoCUE 均未接受更新，无法验证方法在这些领域的有效性；部分领域（如 EvoClawBench）存在执行错误和超时限制未强制执行的问题。
- **基线对比的解释限制**：基线使用最小提示而非官方提示，与已发表结果不可直接比较；作者也声明不对原始方法做超出本协议的声明。
- **算力信息缺失**：未披露 GPU 型号、数量或训练时长，难以评估实际资源需求。
- **潜在偏差风险**：PAST-Bench 使用自选后端模型作为 LLM 评判，可能与基准默认评判存在系统性差异；AppWorld 学习仅用 32 个任务，虽然结果领先，但任务选择的代表性未充分讨论。
- **应用限制**：学习到的更新可能导致退步（如 PAST 中一个远迁移任务从 0.796 降至 0.510），受限的编辑语法和记录干预支持检查，但不足以确立评估环境之外的部署安全性。
