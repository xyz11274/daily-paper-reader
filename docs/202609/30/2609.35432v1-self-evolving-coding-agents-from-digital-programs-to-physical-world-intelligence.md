## 摘要
视觉-语言-动作（VLA）和世界-动作（WAM）模型将观测和指令直接映射为机器人动作。这种直接性将策略与训练绑定：布局或视角的微小变化就会导致失败，且指令泛化能力差。根本原因在于表示：任务需求、条件、进度和故障恢复被隐式编码在动作序列中，使其难以检查或修改。数字编码智能体提供了一个先例：LLM调用工具、验证结果，并基于反馈以可执行代码的形式进行修改。显式状态、可管理执行和可修改流程这一相同的工作模式，构成了物理世界中泛化和长时程执行的基础，使物理经验能够作为可重用程序、记忆或证据返回。我们提出物理编码（Physical Coding），将任务状态和执行表示为代码。作为世界的代码（Code as World）记录对象、关系、约束和进度；作为策略的代码（Code as Policy）组织规划、验证、恢复和执行。我们构建了HexaAnything，它调用感知、规划和控制工具（包括VLA/WAM策略），并根据外部反馈进行在环决策。经过验证的轨迹成为数据和记忆，从而支持从工具和Harness到模型权重、架构，最终到硬件和任务设计的进化。在RoboCasa365上，HexaAnything在Composite-Unseen和整体成功率上优于XR-1 VLA，并且其经Harness训练的HexaModel在每个划分上都优于基座模型，表明代码轨迹内化了物理执行。在PhyBench和双臂AgileX机器人上，该智能体自主完成物理实验和大多数桌面任务，通常比已发表结果更快。我们观察到数据、模型和工具的自我进化；未来工作旨在权重内化、架构、语言、表示和任务的自主重新设计，以及在制造和科学中的部署。

## Abstract
Vision-language-action (VLA) and world-action (WAM) models map observations and instructions directly to robot actions. This directness ties a policy to training: minor layout or viewpoint changes cause failure, and instructions generalize poorly. The root cause lies in representation: task requirements, conditions, progress, and failure recovery are implicitly encoded in action sequences, making them difficult to inspect or revise. Digital coding agents offer a precedent: LLMs call tools, verify results, and revise from feedback as executable code. The same working pattern of explicit state, manageable execution, and revisable procedures underlies generalization and long-horizon execution in the physical world, letting physical experience return as reusable programs, memory, or evidence. We propose Physical Coding, representing task state and execution as code. Code as World records objects, relations, constraints, and progress; Code as Policy organizes planning, verification, recovery, and execution. We build HexaAnything, which calls perception, planning, and control tools, including VLA/WAM policies, and makes in-the-loop decisions from external feedback. Verified traces become data and memory, enabling evolution from tools and Harness to model weights, architectures, and ultimately hardware and task design. On RoboCasa365, HexaAnything improves Composite-Unseen and overall success over XR-1 VLA, and its Harness-trained HexaModel beats the base on every split, indicating code traces internalize physical execution. On PhyBench and a dual-arm AgileX robot, the agent autonomously completes physics experiments and most tabletop tasks, often faster than published results. We observe data, model, and tool self-evolution; future work targets weight internalization, autonomous redesign of architectures, languages, representations, and tasks, and deployment in manufacturing and science.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：Physical Coding

- **Code as World**：可执行的世界程序，记录任务相关对象、关系、观测、状态变量、约束和进度谓词（如 `inside(bread, oven) = False`）。
- **Code as Policy**：可执行的策略程序，组织规划、工具调用、动作执行、验证、恢复和重规划。
- **核心原则**：物理世界编码智能体维护一对可执行工件（世界程序 W 和策略程序 P），由独立验证器检查其是否被证据支持。代码是可组合、可执行、可验证、可版本化、可修订的，因此成为表示、执行和反馈之间的自然接口。

### 2.2 关键技术细节

- **从感知到 Code as World**：
  - 场景结构（对象、区域、关系）以 VCode 方式从图像写成代码，不读取模拟器状态。
  - 测量值来自工具（检测器、深度、位姿、仪器读数），每条记录携带来源（provenance）。
  - 执行状态来自机器人本体感受和 Harness。
  - 任务需求写成谓词，证据不足时返回“insufficient evidence”而非猜测。
- **从物理能力到 Code as Policy**：
  - 能力以类型化工具暴露：感知、运动规划、抓取、放置、接触控制，以及终端、文件、Python 工具和学习的 VLA/WAM 策略。
  - 策略程序节点类型化（观察、动作、VLA 调用、判断、验证、恢复、分支、序列、循环），可在执行前静态检查。
- **闭环执行**：每次工具调用后重新观察、更新世界程序、评估谓词；由验证器的类型化裁决（PASS / FAIL / INSUFFICIENT EVIDENCE / BLOCKED / SAFETY STOP）决定继续、重观察、恢复或停止，而非模型自报完成。
- **持久化产物**：验证通过的轨迹成为训练数据、记忆条目、工具/工作流修订，支持持续改进。

### 2.3 自进化框架

- **四个耦合进化目标**：Harness（工具、工作流、验证器、恢复）、数据与环境、模型与算法、具身与计算基座；表示与接口进化贯穿所有四个目标。
- **版本化工件包**：$a_v = (W_v, P_v, H_v, D_v, M_v, E_v)$，候选更新需在独立评估协议下与冻结父版本比较。
- **七步循环**：Specify（冻结任务分布与协议）→ Execute（记录类型化轨迹）→ Verify（独立验证器）→ Diagnose（定位瓶颈）→ Propose（有界编辑）→ Evaluate（回归测试、金丝雀、留出评估）→ Select & Commit（接受或回滚）。
- **形式化**：$\xi_v \sim \text{Execute}(P_v; W_v, H_v, e, z)$，$o_v = V_v(\xi_v, z, e)$，$a_{v+1} = \text{Select}(\text{Evaluate}(\text{Propose}(a_v, o_v)), \text{Tholdout})$。
- **证据阶梯**：E0（可运行）→ E1（oracle 可完成）→ E2（可区分策略）→ E3（训练可改进新检查点）→ E4（迁移到真实机器人）。

### 2.4 HexaAnything 系统

- **形式化定义**：$H_t = (O_t, T_t, V_t, R_t, M_t, \Gamma_t)$，其中 O 为观察接口、T 为工具注册表、V 为验证器、R 为恢复算子、M 为来源感知记忆、Γ 为执行契约与安全门。
- **执行契约**：GoalContract（目标不可变）、类型化策略表示、ObservationEnvelope（观察来源）、语义裁决、TrialOutcome、ExperimentSpec。
- **五接口分离**：工具、工作流、验证器、恢复、记忆。
- **Vibe as Policy**：编程智能体在回合间编写、验证并冻结工具，冻结的执行智能体在运行时组合它们。

## 6. 主要结论与发现

1. **Harness 效果**：在动作模型固定为 XR-1 的情况下，HexaAnything 将 Composite-Unseen 成功率从 34.3% 提升至 38.3%（+4.0），Composite-Seen 从 54.8% 提升至 61.5%（+6.7），整体从 56.6% 提升至 61.1%。
2. **模型进化**：HexaModel v0.1 在相同 Harness 下每个划分均优于基座 Qwen3.8-27B，Composite-Unseen 从 37.3% 提升至 39.5%，整体从 60.5% 提升至 61.7%，且优于 GPT-5.6-Sol（61.1%）。
3. **工具进化**：RoboDojo 三个任务经两轮修订，成功率从 0%/40%/0% 提升至 80%/100%/100%，权重全程不变。
4. **科学实验**：HexaAnything 在 PhyBench 上自主设计并执行物理实验，GPT-6-Astra 和 Opus 5.5 在全部 30 次试验中均获有效结果，平均相对误差低于 5%。
5. **真实机器人**：7 个桌面任务中 5 个三次全部成功；在可比任务上比 GPT-Policy 快 2.7–3.5 倍，比 Robocurve 快 2.4 倍且 token 消耗少 4.7 倍。
6. **总体结论**：验证轨迹可转化为数据与记忆，实现工具、模型与数据的自进化；但完全自主的模型架构搜索、无限制自改写和非约束物理环境部署尚未实现。

## 7. 优点

- **表示创新**：将物理任务状态和执行统一为可执行代码，使中间进度可检查、失败可定位、修改可测试，从根本上区别于端到端动作映射。
- **验证器独立性**：验证器独立于提出动作的模型，返回类型化裁决而非二元自报，防止模型自我确认错误。
- **版本化与回滚**：所有更新经过静态检查、回归测试、独立评估和回滚保护，保证可归因性和安全性。
- **跨域通用性**：同一接口在操作任务、科学实验和真实机器人上均有效，展示了范式的广泛适用性。
- **证据阶梯**：E0–E4 的分级证据框架清晰区分了“能运行”“能完成”“能区分”“能训练”“能迁移”等不同强度的结论。
- **失败案例透明**：报告了工具修订中的非单调改进（Pour vase 先降后升）和真实机器人上的失败模式（感知和可达性问题）。
- **工程细节丰富**：提供了完整的执行契约、类型化节点、来源追踪和上下文管理（190K → 30–35K token）等可复现细节。

## 8. 不足与局限

- **实验覆盖有限**：
  - Harness 效果仅一个动作模型、一个基准；长时程任务仅内置复合任务，论文自设计的更长任务未评估。
  - 真实机器人每个任务仅 3 次试验，统计效力不足。
  - PhyBench 每模型每任务仅 10 次试验，且全部在仿真中。
- **偏差风险**：
  - Fold cloth 中操作员选择像素，且操作员曾查阅评估器源码，存在特权信息泄漏风险（虽最终版本重新评估，但开发过程受影响）。
  - 已发表参考结果来自不同硬件和操作限制，非严格同条件对比。
  - 验证器与模型可能共适应，论文承认这是未解决问题。
- **应用限制**：
  - 部署需要针对不安全机器人动作、破坏性命令、提示注入和秘密泄露的安全测试。
  - 长期记忆的隐私保护、稀疏轨迹中的物理因果学习、专家修正与仿真轨迹的融合等均未解决。
  - 计算和硬件进化是长期目标，当前实验未涉及。
- **自进化范围有限**：当前仅展示 Harness、工具和首次数据到模型的更新；四个目标的协同进化、架构自主搜索、无限制自改写均未实现。
- **算力信息缺失**：未报告 GPU 型号、数量、训练时长，影响可复现性和成本评估。
