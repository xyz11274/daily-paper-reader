## 摘要
智能体技能封装了可复用的程序性知识，使LLM智能体能够执行任务，并且可以利用与环境交互的轨迹自动改进。这是经典的技能演化问题。现有方法主要遵循线性演化范式，即按顺序将更新应用于最新的技能库版本。因此，它们不可避免地陷入局部最优，留下许多有前景的演化路径未被探索。我们提出SkillVine，一种自动技能演化框架，将技能演化形式化为图搜索问题，并采用分支探索策略。借助主干-分支协同搜索机制、智能父节点选择器和自适应粒度更新规则，SkillVine在探索与利用之间实现了平衡。我们在5个基准上使用两个LLM评估SkillVine。结果表明，SkillVine沿分支发现的技能库版本优于沿线性主干的版本，并在十个基准-模型组合中的九个上取得了最佳测试性能。

## Abstract
Agent skills encapsulate reusable procedural knowledge that enables LLM agents to perform tasks, and they can be improved automatically using trajectories from interactions with the environment. This is the classic problem of skill evolution. Existing approaches predominately follow a linear evolution paradigm, in which updates are sequentially applied to the latest skill-library version. As a result, they inevitably fall into local optima, leaving many promising evolution paths unexplored. We propose SkillVine, an automatic skill-evolution framework that formulates skill evolution as a graph search problem and employs a branching exploration strategy. Equipped with a trunk-branch collaborative searching mechanism, an intelligent parent-node selector, and an adaptive-granularity update rule, SkillVine achieves a balance between exploration and exploitation. We evaluate SkillVine on 5 benchmarks with two LLMs. Results show that SkillVine discovers better skill-library versions along branches than along the linear trunk and achieves the best test performance in nine of ten benchmark-model combinations.

- **现有范式的三大局限**：主流方法采用**线性演化范式**，即每次更新顺序作用于最新技能库版本：
  1. 早期版本中的有用内容可能被覆盖，尤其当新任务与旧任务差异较大时；
  2. 每次更新都建立在此前所有更新之上，一旦陷入局部最优便无法回退探索替代路径；
  3. 强制技能库沿单一轨迹演化，无法并行探索与系统比较不同技能变体。
- **整体含义**：论文将技能演化重新形式化为**图搜索问题**，通过分支探索突破线性演化的局部最优困境，为智能体自演化提供了新范式。

## 2. 方法论

### 2.1 核心思想
- 将技能库的所有历史版本组织为**可恢复的版本图**（version graph），每个节点是一个完整技能库快照，每条边表示父子派生关系，从而支持回退到任意历史版本并从该点开辟新路径。
- 采用**主干-分支协同搜索**：主干在每个训练批次上做增量更新以累积长程信息；分支从历史检查点出发，探索主干所缺乏的能力路径。

### 2.2 问题形式化
- 技能库记为 $S_v$，更新算子 $U: S \times T \rightarrow S$ 将选定版本与交互轨迹映射为候选子版本。
- 目标是在预算 $B$ 约束下最大化验证分布上的期望准确率：$S^* = \arg\max_{S \in V_B} \text{Acc}(\pi, S; D_{val})$。

### 2.3 三大关键机制

**（1）主干-分支演化策略**
- 主干在每个训练步都更新，能"看到"每个批次，累积长时程信息；分支仅使用部分批次。
- 每个训练步执行三步：更新主干 → 用节点选择器挑选历史节点 → 优化被选节点（粒度由主干是否接受决定）。
- 主干更新规则：从当前批次轨迹生成若干编辑，全部应用后若验证准确率高于父节点则接受，否则拒绝（式 2）。

**（2）互补性感知节点选择器**
- 节点评分公式（式 3）：`Select_t(v) = q(v) + λ_exp · sqrt(log(N_exp+1)/(n_exp(v)+1)) + λ_comp · C_t(v)`
  - $q(v)$：节点验证准确率；
  - 第二项：对产生子节点较少的节点给予探索奖励；
  - 第三项 $C_t(v)$（式 4）：与当前主干父节点比较，奖励"解决主干失败样本"的能力，惩罚"丢失主干已解决样本"。
- 系数 $\lambda_{exp}$、$\lambda_{comp}$ 控制探索与互补性权重，$\beta$ 惩罚丢失主干已解样本。
- 实践中混合使用**发现选择器**（强调探索与互补，$\lambda_{exp}=0.08, \lambda_{comp}=0.5$）与**精炼选择器**（两者均为 0，强调验证准确率）。

**（3）自适应粒度分支更新（AGBU）**
- 以主干更新的接受/拒绝结果作为该批次信息质量的信号：
  - 主干**接受** → 批次信息较有益 → 分支采用**粗粒度**更新（一次性应用全部编辑，仅一次评估，成本低）；
  - 主干**拒绝** → 批次可能含有害编辑 → 分支采用**细粒度**更新（逐条应用并评估，可回退到最近接受版本，能过滤有害编辑）。
- 该机制在评估成本与更新可靠性之间取得权衡。

**（4）最优技能输出**
- 训练结束后，从图中所有主干与分支节点中选取验证准确率最高者作为最终输出。

- SkillVine 在 **10 个基准-模型组合中的 9 个**取得最佳测试性能；DeepSeek-V4-flash 上全部 5 个基准领先。

- 优于 Best-of-3（全部 10 个组合），说明并非简单增加更新尝试次数即可奏效；优于 Random，说明引导式分支比随机分支更有效。
- 10 条最优路径中：2 条仅用发现选择器、2 条仅用精炼选择器、6 条两者兼用；8 条路径中 AGBU 至少拒绝一个有害编辑。
- 参数分析：分支尝试次数先增后平；更短的分支更新间隔更好；更小批次 + 更多训练步通常更优。
