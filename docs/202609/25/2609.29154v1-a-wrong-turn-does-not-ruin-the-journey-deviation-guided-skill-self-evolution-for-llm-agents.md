## 摘要
大型语言模型智能体日益依赖自然语言技能来解决复杂的工具使用任务。然而，此类任务通常允许多条有效求解路径，因此通过强迫失败轨迹匹配某条固定成功轨迹来改进技能并不合适。此外，失败轨迹很少完全错误：智能体可能先收集到有用证据并取得有意义进展，但随后偏离到错误的后续片段。因此，我们认为，技能自演化应识别富有成效的问题求解从何处开始崩溃，而非对整个失败进行粗粒度反思。基于这一洞见，我们提出 SkillPivot，一种由偏差点引导的技能自演化框架。SkillPivot 利用执行有效性、目标进展和动作多样性来检测从有用前缀到错误后缀的转折。随后，一个更强的教师模型从相同前缀继续，并在相同交互历史下生成成功的替代方案。通过对比学生的失败后缀与教师的成功后缀，SkillPivot 生成局部化的技能更新，同时保留已经有效的指导。在 ToolQA、LogicBench 和 WildClawBench 上的实验表明，SkillPivot 持续优于竞争性的技能演化方法，可改进多种智能体模型，并产生紧凑、可迁移的技能更新。

## Abstract
Large language model agents increasingly rely on natural-language skills to solve complex tool-use tasks. However, such tasks often admit multiple valid solution paths, making it inappropriate to improve skills by forcing failed trajectories to match a fixed successful trajectory. Moreover, failed trajectories are rarely entirely wrong: an agent may first collect useful evidence and make meaningful progress, but later deviate into an erroneous suffix. We therefore argue that skill self-evolution should identify where productive problem solving begins to break down, rather than reflect coarsely over the entire failure. Based on this insight, we propose SkillPivot, a deviation-point-guided framework for skill self-evolution. SkillPivot detects the transition from a useful prefix to an erroneous suffix using execution validity, goal progress, and action diversity. A stronger teacher then continues from the same prefix and produces a successful alternative under the same interaction history. By contrasting the student's failed suffix with the teacher's successful suffix, SkillPivot generates localized skill updates while preserving already effective guidance. Experiments on ToolQA, LogicBench, and WildClawBench show that SkillPivot consistently outperforms competing skill-evolution methods, improves multiple agent models, and produces compact, transferable skill updates.

## 1. 核心问题与整体含义
- **研究背景**：LLM 智能体日益依赖自然语言“技能库”完成复杂工具调用任务，但现有技能往往不完整，缺少边界条件、恢复策略和工具约束。
- **核心问题**：如何从智能体自身的失败交互中演化技能库，同时避免破坏原本有效的技能指导。
- **关键洞见**：失败轨迹通常不是“全程错误”，而是先有有效探索前缀，随后在某个偏差点后进入错误后缀。整条轨迹反思或强行对齐固定成功轨迹，会把有用前缀与有害后缀混在一起，导致技能更新噪声大、过宽或过拟合。
- **整体含义**：技能自演化应定位“问题求解从何处开始崩溃”，只针对偏差点之后的错误后缀生成局部、条件化、可审计的技能更新，而不是重写整个技能。

## 2. 方法论：SkillPivot
### 核心思想
- 使用**偏差点检测**找到学生轨迹由有效前缀转向错误后缀的位置 \(t^*\)。
- 让更强教师从同一前缀继续，生成同一交互历史下的成功后缀。
- 对比学生失败后缀与教师成功后缀，生成局部技能增量。
- 通过回归门控验证，确保更新不破坏原有有效规则且具备可泛化性。

### 形式化设定
- 技能库：\(S^r=\{s^r_1,\dots,s^r_M\}\)。
- 任务集：\(D^r=\{x_i\}_{i=1}^N\)。
- 学生轨迹：\(\tau_i=(x_i,h_{i,1},a_{i,1},o_{i,1},\dots,y_i)\)，评估器 \(E(\tau_i,x_i)\in\{0,1\}\)。
- 目标：学习更新算子 \(\Phi\)，生成技能增量 \(\Delta S^r=\Phi(S^r,T^+,T^-)\)，得到 \(S^{r+1}=\text{Update}(S^r,\Delta S^r)\)。
- 优化目标：提升未来任务成功率，同时约束已可解任务上的回归。

### 关键流程
1. **学生 Rollout**  
   - 学生智能体使用当前技能库执行任务，产生 ReAct 风格轨迹。
   - 成功轨迹进入成功池，用于后续回归测试；失败轨迹进入失败池，用于诊断技能缺口。

2. **偏差点检测**  
   - 对每一步计算进度潜力分数：  
     \(\hat V_t=0.4 Exec_t+0.3 Prog_t+0.3 Div_t\)。
   - \(Exec_t\)：工具调用是否成功执行、观察是否可用。
   - \(Prog_t\)：当前观察与任务目标/ground-truth 的语义相关性增量，使用 all-MiniLM-L6-v2 编码并计算余弦相似度，只保留相对历史最大值的正增量，避免重复证据被多次计分。
   - \(Div_t\)：当前动作与历史动作的多样性，\(Div_t=1-\max_{j<t}\text{sim}(a_t,a_j)\)，低值表示重复策略。
   - 先选最低分步骤为候选偏差点，再检查其后是否持续低分、形成清晰低谷，确认后才作为 \(t^*\)。

3. **教师 Rollout**  
   - 教师接收任务、当前技能库、学生偏差点前缀和完整失败轨迹。
   - 从 \(t^*\) 继续 ReAct 循环，保持相同步骤编号。
   - 使用 inline reflector 在每步后生成简短提示，但提示不写入最终保存轨迹，避免污染后续后缀对比。
   - 教师成功才接受；失败则丢弃或从同一偏差点重试，最多预设次数。

4. **配对后缀对比与技能生成**  
   - 构造配对案例：共享前缀 + 学生失败后缀 + 教师成功后缀。
   - 单案例轨迹摘要器分析：学生错误、教师纠正、当前技能缺失指导、演化方向。
   - 技能增量生成器聚合分析，选择 `improve_skill`、`optimize_description` 或 `skip`，避免证据不足时强行编辑。

5. **回归门控技能更新**  
   - LLM 编辑器先将候选增量应用到原技能，得到暂定技能 \(s'\)。
   - LLM 验证器按两个标准打分：
     - **No regression**：是否保留原有有效规则，不删除、削弱、覆盖或矛盾。
     - **Generalizable rule**：新增指导是否为可复用流程原则，而非一次性补丁。
   - 仅当两项分数均 \(\ge \theta=0.5\) 时接受更新，否则保留原技能。
