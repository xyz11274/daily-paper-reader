## 摘要
许多现实世界任务（例如办公工作流、科学实验）要求LLM智能体反复与环境交互，以执行依赖上下文的操作。然而，此类环境往往并非智能体就绪。首先，信息常常分散且碎片化于整个环境中。其次，环境中的相关证据常常与误导性信息和相互冲突的版本混杂在一起。第三，环境会随时间演化，引入新的噪声和更具挑战性的任务。这些挑战会显著降低最先进AI智能体的性能（例如从83.9%降至57.6%）。为应对这些挑战，我们提出Env-Rethink（一个采用27B后训练模型的系统），其支持三项主要能力：（1）自适应构建Collection Maps（用于组织相关文件）和Event Logs（用于情境化跨数据关系），以补充必要上下文；（2）进一步利用后训练模型（通过离线轨迹学习）识别环境中潜在的噪声问题；（3）最终通过虚拟事件历史来演化环境，这些历史会改变环境状态和证据关系，从而产生更棘手的环境以促进智能体进一步改进。实验表明，Env-Rethink能有效提升下游任务性能（在30个任务上，九个模型的rubric通过率提升超过15.1%）。

## Abstract
Many real-world tasks (e.g., office workflows, scientific experimentation) require LLM agents to interact repeatedly with their environments for context-dependent operations. However, such environments are often not agent-ready. First, information is often scattered and fragmented across the environment. Second, relevant evidence in the environment is often mixed with misleading information and conflicting versions. Third, environments evolve over time, introducing new noise and more challenging tasks. These challenges can substantially degrade performance for state-of-the-art AI agents (e.g., from 83.9% to 57.6%). To address these challenges, we propose Env-Rethink (a system with 27B post-trained model) that supports three main capabilities: (1) It adaptively builds Collection Maps (for organizing related files) and Event Logs (for contextualizing cross-data relationships) to supplement necessary context; (2) It further leverages the post-trained model (through offline trajectory learning) to identify underlying noise issues in the environment; (3) It ultimately evolves environments through virtual event histories that alter environmental states and evidence relationships, producing more tricky ones for further agent improvement. Experiments show that Env-Rethink can effectively improve downstream task performance (with over 15.1% rubric pass rate improvement across nine models on 30 tasks).

## 1. 核心问题与研究动机

- **背景**：真实任务（办公工作流、科学实验、代码维护等）要求 LLM Agent 反复与持久化的文件型环境交互。环境由文件与服务实现及其当前状态构成，记为 `E = (F, S)`；任务模型 `Mθ` 与 harness `H` 共同构成下游任务智能体 `A`，输出 `ŷ = A(q, E)`。
- **核心痛点：环境"非 Agent-ready"**，具体表现为三类：
  - 信息分散、碎片化，跨目录散落；
  - 相关证据与误导性信息、冲突版本混杂；

- **三种典型失败模式**：

  - 把文件名当作版本指示（如盲信 `final.bib`，忽略后续撤回通知）；

- **三个研究挑战**：① 跨文件上下文的恢复；② 学习可靠的环境判断（权威性与版本有效性）；③ 生成更难但可验证的环境。
- **整体含义**：把"环境准备"与"环境演化"从被动背景提升为一等公民，使环境成为可学习的组件，并为智能体递归自我改进（recursive self-improvement）提供挑战生成与验证闭环。

## 2. 方法论：Env-Rethink

### 2.1 总体思想

- 统一系统，支持两类请求：**任务执行**（准备已有环境）与**挑战生成**（指定任务、种子文件与生成方向）。
- 三个互补模块：**环境组织**、**学习式准备**（27B 后训练模型）、**事件驱动环境演化**。
- 形式化定义：
  - 准备算子：`Ẽ = C_φ(E; c)`，要求产出可导航内容、显式关系、来源有效性；
  - 演化抽象：`(E_t, y_t, V_t) → (E_{t+1}, y_{t+1}, V_{t+1})`，环境状态变化必须与参考答案、评测器同步更新，且保持任务请求不变。

### 2.2 环境组织（Collection Map + Event Log）

- **Collection Map（集合地图）**：
  - 先按目录结构做确定性分组（受文件数上限约束）；
  - **Collection Summarizer** 为每组写"卡片"（主题、内容、代表性证据、源路径）；
  - **Semantic Coordinator** 基于卡片与成员路径提出拆分/合并/转移/多重归属；
  - 确定性过程校验并施加变更，保证**文件全覆盖**（每个文件至少属于一个集合，集合可重叠）；
  - **Collection Refiner** 重读受影响组并更新卡片，进入下一轮。
- **Event Log（事件日志）**：
  - **History Synthesizer** 阅读文件，提出候选历史（会话 = source review / 修订 / 讨论；事件 = read/write/copy/export，记录 actor、action、time、path、provenance）；
  - 时间戳与工作流明确标注为**合成**；引文证据与生成器推断严格分离，推断内容以临时文档形式出现（创建→使用→删除）；
  - 确定性结构校验 + 独立 **Evidence Reviewer**（校验引文匹配、判断有据、动作与文件一致、与现存文件一致）；
  - 失败进入修复循环，超出预算则丢弃；后续轮次**隐藏已用文件子集**以覆盖其他材料；
  - **Timeline Integrator** 合并已接受历史为单一日志，统一标识与时间戳，保留事件内容、证据与因果顺序。
- **两种准备模式**：
  - **EGS（Environment-Grounded Synthesis）**：仅用环境内文件与元数据；
  - **TGS（Task-Guided Synthesis）**：额外使用任务监督（标注 clean/noise 文件、任务请求与 rubric 引导事件日志合成，但禁止把 rubric 条目抄入公开日志）。

### 2.3 学习式环境准备（文件验证器）

- **动机**：TGS 优于 EGS，但需要任务监督；因此训练一个仅凭文件即可判断的模型。
- **验证任务**：输入文件集合、manifest、读文件工具与指令（**不含下游用户请求**）；对每个文件输出：
  - standard/noise 划分；
  - 类别：`authoritative record`、`false final version`、`fabricated authority`、`misleading redirection`、`superseded version`、`out-of-scope file`；
  - observed stage（文件自称状态）、family 归属、时间线信息、支撑证据。
- **训练数据构造**：
  - 子环境类型：attack scene（权威目标+诱饵链）、version family（版本族及顺序）、redirect group（指针+支撑消息）、filler（密度）；
  - 来源标注池：**1,597 个文件 / 16 个任务**；15 个父任务 → 209 个子环境 → **2,116 条合格教师轨迹（覆盖 139 个环境）**，另加 **288 条 consensus-attack 轨迹**；
  - 教师来自 DeepSeek / GLM / Gemini 家族，经 Claude Code 在隔离沙盒中执行；提示分 L0/L1/L2 三档（学生训练提示**只含验证指令、输出 schema 与阅读要求，不含判别性线索**）；
  - **资格门槛**：read-fidelity 检查通过后，要求 partition F1 ≥ 0.9、权威记录零误拒、所有强诱饵分类正确、版本族顺序正确；失败可由独立 agent 依据失败轨迹与真值修订提示，**最多 2 次重试**，仍失败则排除。
- **训练**：在 Qwen3.8-27B 上做 LoRA SFT，损失只覆盖 assistant token（工具调用、中间叙述、最终 JSON 判断），工具返回的文件内容不计损失：
  `L_SFT(θ) = −(1/Σm_t) Σ_t m_t log pθ(x_t | x_<t)`
- **部署**：模型输出用于**文件筛选**与**证据报告**（类别、阶段、支撑证据、被排除文件）；下游任务智能体先读报告再执行原请求。

### 2.4 事件驱动环境演化

- **Counter-default 决策点**（每个变体至少 3 个，证据链不短于种子）：
  - **temporal**：发布更新是否已在报告日期生效；
  - **exclusion**：记录被撤回/未注册/缺少必要前置事件时必须剔除；
  - **exception-rule**：看似相似但适用不同规则；
  - **numerical**：存在貌似合理的预计算结果，仍需从源输入重算。
- **生成过程**：Evolver 读取任务工件、生成记录与失败样例，输出新文件、对现有文件的 patch、事件历史片段，以及参考解与期望值的修订；历史记录文件创建/修改/重命名/删除，并通过引用先前事件保留依赖：
  `(E_{t+1}, y_{t+1}, V_{t+1}, ΔH_{t+1}) = G_φ(E_t, q, V_t, H_t, D_t; z_t)`
- 确定性 merger 合并历史片段（校验事件 ID、会话边界、序列连续性），Assembly 将变更应用到上一版环境；**仅组装后的文件与不变的请求**交给任务智能体，生成历史不进入执行上下文。
- **实例校验**：结构校验（事件、文件引用、装配、材料放置、评测资产语法、**任务指令逐字节比对**）+ 答案校验（新参考解必须通过、旧期望输出必须失败）+ shortcut audit（检查是否泄露本应推理得出的结论）。
- **难度评估**：种子与变体在匹配的 agent 配置与预算下成对运行；失败摘要可反馈给 Evolver 指导下一代决策点。
