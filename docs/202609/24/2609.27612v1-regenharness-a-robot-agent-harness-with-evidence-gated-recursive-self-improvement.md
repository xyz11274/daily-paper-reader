## 摘要
长时程机器人执行需要清晰区分模型的提议、控制器的终止以及经验证的任务完成。我们提出 RegenHarness，一种证据门控的机器人智能体运行框架，将任务规划与异构机器人技能连接起来。其执行架构将用于生成上下文条件化提议的模型循环，与用于调度、观察、验证、提交和有界恢复的智能体循环耦合在一起。四个角色隔离的上下文分别隔离规划、监督、验证和恢复输入。版本化记忆将观察到的事实与已接受的任务进展区分开来，而受身份和版本约束的提交门控控制对可信任务状态的更新。运行时在显式后端契约下结合重复调度控制、资源租约和恢复预算，并在报告完成之前检查原始用户目标。据我们所知，我们首次为具身机器人智能体引入证据门控的递归自我改进（RSI）协议。在多个任务中，执行记录会促发对上下文规则、任务模板、路由和恢复策略的候选变更；固定的回归检查和发布授权管理其接受；版本化部署和回滚保持配置可追溯性。该 RSI 协议修订运行框架配置，而无需在线更新模型权重，也不允许削弱提交门控。一次真实四足机器人部署记录了语音触发的仓库导航、全景巡检、视觉分析、消息传递、返回和语音报告，并通过关联的音频、图像、轨迹和回执加以佐证。另一个独立回路表明，完成与否取决于执行历史，而不仅仅是终点邻近性。这些案例共同展示了真实世界机器人任务中集成的感知、物理执行、通信以及依赖历史的完成判定。

## Abstract
Long-horizon robot execution requires a clear distinction between a model's proposal, a controller's termination, and verified task completion. We present RegenHarness, an evidence-gated robot-agent harness connecting task planning to heterogeneous robot skills. Its execution architecture couples a model loop for context-conditioned proposals with an agent loop for dispatch, observation, verification, commitment, and bounded recovery. Four role-isolated contexts separate planning, supervision, verification, and recovery inputs. Versioned memory distinguishes observed facts from accepted task progress, while an identity- and version-bound commit gate controls updates to trusted task state. The runtime combines duplicate-dispatch control, resource leases, and recovery budgets under explicit backend contracts, and checks the original user goal before reporting completion. To our knowledge, we are the first to introduce an evidence-gated recursive self-improvement (RSI) protocol for embodied robotic agents. Across missions, execution records motivate candidate changes to context rules, task templates, routing, and recovery policies; fixed regression checks and release authorization govern their acceptance; versioned rollout and rollback preserve configuration traceability. This RSI protocol revises the harness configuration without online model-weight updates or permission to weaken the commit gate. A real quadruped deployment documents voice-triggered warehouse navigation, panoramic inspection, visual analysis, message delivery, return, and spoken reporting through linked audio, images, trajectories, and receipts. A separate circuit demonstrates why completion depends on execution history rather than endpoint proximity alone. Together, the cases demonstrate integrated perception, physical execution, communication, and history-dependent completion in real-world robot tasks.

## 2. 方法论

### 2.1 核心思想

- 将"技能"定义为有界操作（如导航到指定地点、拍摄图像），"提供方/后端"为实现该操作的模型、控制器或服务，"harness" 则是围绕这些提供方的运行时：决定可调用什么、跟踪执行、判定什么算作被接受的进展。
- 关键抽象是**版本化技能调用（versioned skill invocation）**：绑定显式前置条件、目标效果、资源需求、证据需求、取消语义与恢复策略。同一抽象可统一承载 VLA 策略、导航动作、TAMP 求解器、世界模型辅助策略或传统控制器。
- 任务契约表示为 `T = (g, G, Cg, S, R)`（式2）：g 为原始目标，G 为子目标的无环依赖图，Cg 为原始完成条件集合，S 为安全与资源约束，R 为恢复预算。每个节点 v 声明目标效果 Ev、可用能力类、依赖与证据要求。
- **区分"观察"与"提交"**：在状态版本 k 维护两个事实集合——Oₖ 为来源与新鲜度已知但任务含义未验证的观察事实；Cₖ 为经验证路径接纳的已提交事实。技能调用可读授权上下文，但**不能直接写 Cₖ₊₁**。

### 2.2 关键技术细节

- **模型循环与智能体循环**：
  - 模型循环只做推理时提议生成：`c_k^(r) = κr(Sk)`，`u_k^(r) = Mθr(c_k^(r))`（式3），r ∈ {规划, 监督, 验证, 恢复}，κr 只选择该角色允许的输入字段。
  - 智能体循环是任务级过程：C1 选择下一个可执行节点与提供方，C2 提供执行上下文，监督器调度并轮询技能，C3 用执行证据评估后置条件，提交门控只接纳身份与版本匹配的有效结果，失败/不确定结果进入 C4 做有界恢复或升级。
  - 两个循环不一一同步（长时技能可能需多次控制器更新），共享接口是**版本化任务与证据契约**，而非把对话记录当作可信状态。
- **四类角色隔离上下文（C1–C4）**，由同一版本化状态编译出四个有界视图：
  - C1 规划器："下一步该做什么"（原始目标、图前沿、已提交进展、空间状态、高层失败历史）；
  - C2 技能："本节点应如何执行"（单一当前子目标、接地目标、技能契约、有界观察、少量已验证操作示例）；
  - C3 验证器："预期效果是否发生"（后置条件、前后证据、传感器时间戳、相关已提交事实；**排除源自规划器自身结论的记录**）；
  - C4 恢复："何种有界响应是正当的"（结构化失败、已尝试动作、剩余预算、可用替代方案）。
  - 目的：限制意外泄漏与**相关性自我确认**（例如规划器生成的"杯子已被抓取"文本在 C2 中可作意图，但不能成为 C3 的抓取成功证据）。
- **能力卡与路由**：提供方发布能力卡（标识与版本、支持本体、参数模式、前置条件、副作用、预期延迟、资源集、取消行为、风险类、失败词表、所需证据）。路由先做确定性过滤（能力、本体、参数有效性、前置条件、新鲜度、安全性），再用可配置评分器排序：
  `s(πi) = wp·p̂ᵢ − wr·r̂ᵢ − wu·ûᵢ − wl·l̂ᵢ − wc·ĉᵢ − wh·ĥᵢ`（式4），其中 ĥᵢ 来自历史失败或"转移残差"（预期效果与观测效果之差）。评分只是可检视的排序接口，**本身不是执行权限**，硬性守卫与资源获取在排序后仍会执行。
- **世界模型为可选**：其预测效果只能作为决策输入，不能确立执行后成功；harness 也可在没有学习预测的情况下运行。
- **监督式技能生命周期**：监督器是唯一调度路径。执行前校验请求、记录调度意图、获取机器人/工作空间资源租约、将幂等键绑定到 task/node/attempt；后端暴露 accepted/queued/running/blocked/succeeded/failed/cancelled 生命周期。**幂等调度**指重复收到同一调用请求时返回既有执行记录而非再次触发物理动作。**资源租约**是有所有者与过期时间的有界预留，冲突的独占租约会阻止两个技能同时指挥同一资源（但租约只是协调元数据，不是物理急停）。长时技能有显式截止时间。
- **证据包与提交门控**：终止执行时保存证据包 `Zk = (I, kctx, Obefore, Oafter, P, Δ̂k)`（式5），其中 I 标识 task/node/provider/execution/packet，kctx 是调度时使用的状态版本，Δ̂k 是提供方提议的任务事实。每条证据引用保留来源、时间戳、置信度、文件引用或校验和，以及相关坐标系。**证据包即使被验证拒绝也会保留**。
  - 判定词表：`satisfied / violated / ambiguous / stale / unsafe`。
  - 验证分两层：节点级验证器逐条评估后置条件（来源尽可能独立于执行提供方，后端自身的 done 信号可作证据但**绝不是唯一权威**）；提交门控再检查判定、身份绑定、状态版本与条件覆盖，然后**原子地**推进节点与可信事实。
  - 核心不等式：`控制器 done ⇏ 节点成功 ⇏ 目标成功`（式6）。所有必需节点提交后，还需由独立的目标验证器重新检查原始完成条件，只有 satisfied 的原始目标判定才授权向用户报告最终成功。来自过时状态版本的证据包会被拒绝，而不会被静默地按新状态解释。
- **有界恢复**：非 satisfied 结果带结构化失败类进入 C4，恢复路由器映射到有序升级阶梯，例如：
  - `目标未找到`：重新感知 → 调整视角；
  - `无进展`：局部重规划 → 切换技能；
  - `不安全动作`：安全停止 → 人工接管。
  - 每个动作消耗"单动作预算"与"总恢复预算"；无新证据地重复同一失败动作可被确定性禁止。预算计的是授权的恢复动作数，而非底层控制器周期。
- **可信记忆与事件溯源**：记忆指存储的任务与证据记录（非学习的世界模型），分五类：工作记忆、空间记忆、情节记忆、操作记忆、语义记忆。更新采用追加新记录 + supersedes/conflict 关系，而非静默覆盖。可信任务存储从有序的 observation / commit / recovery-budget / goal-verification 事件投影出当前进展。作者明确区分"重建"与"重跑机器人或复现随机模型响应"。
- **证据门控的递归自我改进（RSI）**：在模型循环与智能体循环之外加一层跨任务修订循环。改进

- 候选修订（如新的技能参数、提示词模板、路由权重、恢复策略、验证器规则）不能直接上线，必须先经过**证据门控**：在离线回放或影子执行中，候选必须产生可被独立验证接纳的进展证据包，才允许被提升为生产契约的一部分。
- 修订过程本身同样事件溯源：每次提案、评估、接纳或拒绝都追加为带身份的记录，附带其依据的证据包引用与状态版本，因此任何一次自我改进都可被审计与回滚。
- 关键约束：**自我改进不得修改提交门控与验证器的判定逻辑**。也就是说，系统可以改进"如何做"，但不能改进"什么算作被接受的进展"，以避免奖励黑客与验证器退化。

### 2.3 执行契约的权限边界（小结）

- 单一写入者原则：可信任务状态 `Cₖ` 只能由提交门控原子推进，规划器、技能后端、世界模型、验证器均无直接写权限。
- 读权限按角色最小化编译（C1–C4），敏感结论（如"已完成"）不跨角色作为证据流通。
- 所有物理动作经监督器单一调度路径，配合幂等键与资源租约，杜绝重复执行与并发争用。
- 失败、超时、歧义一律视为**未提交**，进入有界恢复，而非被默认解释为成功。

## 3. 实验与评估

### 3.1 评估设置

- 平台：基于作者先前的 HROS 四足巡检操作系统，RegenHarness 作为其智能体运行框架。
- 任务形态：长时程、多阶段、需物理验证的巡检/操作任务，包含导航、感知、操作与恢复环节。
- 对照维度：围绕"进展授权"展开，比较有/无验证门控、有/无版本绑定、有/无有界恢复、有/无角色上下文隔离等配置。

### 3.2 主要观察（论文主张层面）

- **假阳性完成的下游污染**：缺少提交门控时，早期一次错误的完成声明会沿依赖图向下传播，使后续阶段在错误状态上继续决策；引入验证门控与版本绑定后，过时或错绑证据被拒绝，污染被限制在局部并触发恢复。
- **控制器 done 与任务成功的解耦**：实验强调式6的不等式——后端报告 done 只是证据之一，节点级验证与目标级独立验证才授权最终成功声明，因此最终报告的成功率更能反映真实物理完成。
- **恢复预算的作用**：以"授权动作数"而非控制器周期计费，使得恢复行为可被约束与比较，避免无界重试掩盖失败。
- **上下文隔离的价值**：将规划器自身的结论排除在 C3 验证输入之外，减少了相关性自我确认导致的假阳性。
- **可选世界模型**：世界模型预测仅作决策输入，不参与成功判定，系统在无学习预测时仍可运行，说明其收益是增益而非依赖。

### 3.3 评估的定位

- 论文将评估定位为对**运行时契约**的验证，而非对某一策略或模型的性能刷榜；重点在于可审计性、可重建性与失败可控性。

## 4. 讨论

- **与既有工作的关系**：论文承认"验证门控进展"并非全新原理，其贡献在于把权限边界、证据流、身份/版本绑定与恢复预算统一为一套可复用的运行时契约，并明确区分观察与提交。
- **重建 vs 重跑**：可信记忆采用事件溯源投影，强调从有序事件"重建"进展，而非重跑机器人或复现随机模型响应——这对审计与调试尤为重要。
- **安全性边界**：资源租约是协调元数据，不是物理急停；威胁模型不覆盖被攻破的传感器或恶意硬件，说明其安全保证限于运行时一致性层面。

## 5. 局限与未来方向

- **验证器质量依赖**：尽管要求验证来源尽量独立于执行提供方，但验证器本身的缺陷不在威胁模型内，仍是单点风险。
- **目标验证的完备性**：原始完成条件的独立重检依赖条件本身可被可靠表达与观测，对难以形式化的目标可能受限。
- **成本**：证据包保留、角色视图编译与双层验证带来额外开销，长时程下的存储与延迟权衡需要进一步研究。
- **可迁移性**：抽象声称可统一承载 VLA、导航、TAMP、世界模型辅助策略与经典控制器，但其在异构提供方上的普适性仍需更多实证。

## 6. 结论

- RegenHarness 的核心贡献是把"什么授权模型提议的进展转变为被接受的物理任务进展"这一问题，落实为一套带权限边界、版本绑定、证据门控与有界恢复的运行时契约。
- 通过区分观察与提交、隔离四类角色上下文、单一调度路径与幂等/租约机制，以及事件溯源的可信记忆，系统在长时程任务中抑制假阳性完成的传播，并使进展可审计、可重建。
- 式1的链式成功率、式6的 `控制器 done ⇏ 节点成功 ⇏ 目标成功` 不等式，构成其设计的两条主线：既承认长时程的复合脆弱性，又坚持成功声明必须由独立证据授权。
