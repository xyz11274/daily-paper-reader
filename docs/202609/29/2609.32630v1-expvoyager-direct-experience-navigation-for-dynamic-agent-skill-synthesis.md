## 摘要
在LLM智能体中从经验学习已成为开发能够持续学习并扩展能力的自演化智能体的关键范式。在该范式中，合成智能体技能已成为一种有前景的解决方案，用于将积累的经验转化为可复用的程序性知识，并作为运行时为智能体提供支持的harness系统的重要层。尽管具有潜力，现有方法在很大程度上是在下游需求已知之前，将过去经验抽象为固定的程序性知识，这可能导致后来变得关键的知识被丢弃，同时保留与未来任务无关的实例特定细节。在本文中，我们将智能体技能合成重新表述为对过去经验的动态导航问题，其中智能体根据当前任务的需求主动探索积累的轨迹，并以有针对性且细粒度的方式访问经验知识。为此，我们提出了ExpVoyager，这是一种新颖框架，其中技能策展器在不同视图和分辨率下导航原始经验，持续从所观察内容中识别可复用的程序性知识，同时跟踪剩余知识需求以指导下一步导航方向。大量实验证明了ExpVoyager的有效性和通用性，显示其在下游任务性能上持续提升、随着经验空间扩展而不断获益，并在高效经验访问下与现有技能具有实际兼容性。

## Abstract
Learning from experience in LLM agents has become a key paradigm for developing self-evolving agents that continuously learn and expand their capabilities. Within this paradigm, synthesizing the agent skill has emerged as a promising solution for transforming accumulated experience into reusable procedural knowledge, serving as an important layer for the harness system that supplies agents at runtime. Despite its potential, existing approaches largely abstract past experience into fixed procedural knowledge before downstream demands are known, which risks discarding knowledge that later becomes critical while retaining instance-specific details irrelevant to future tasks. In this paper, we reframe agent skill synthesis as a dynamic navigation problem over past experience, where agents actively explore accumulated trajectories on demand for the current task with targeted and fine-grained access to experience knowledge. To this end, we propose ExpVoyager, a novel framework in which a skill curator navigates raw experience across different views and resolutions, continually identifying reusable procedural knowledge from what it observes while tracking remaining knowledge needs that guide where to navigate next. Extensive experiments demonstrate both the effectiveness and versatility of ExpVoyager, showing consistent improvements in downstream task performance, continual gains as the experience space scales, and practical compatibility with existing skills under efficient experience access.

## 1. 核心问题与整体含义

- **研究背景**：LLM 正从单纯生成回复的系统演变为能够与环境交互、使用工具、执行多步任务的长期智能体。随着任务与环境日益复杂，仅靠基础模型的通用能力已不足以可靠提供跨执行上下文所需的知识，**agent harness**（运行时为智能体提供支持的层）变得愈发重要。
- **核心问题**：现有"从经验学习"的方法（如 AWM、ReasoningBank、Trace2Skill）大多在**下游需求未知之前**，就把过去经验抽象为固定的程序性知识（技能）。这带来两个风险：
  - **丢弃风险**：后来对某任务变得关键的知识在预构建阶段就被丢弃；
  - **冗余风险**：保留了与未来任务无关的实例特定细节。
- **关键追问**：如何让智能体**按需**（on demand）从原始经验中为当前任务动态合成技能？
- **整体含义**：论文将技能合成从"固定抽象"重构为**对过去经验的动态导航问题**，让智能体主动决定"检查哪里、以什么分辨率检查"，从而实现有针对性、细粒度的经验访问。这为构建持续将积累经验转化为可复用能力的自演化智能体提供了新范式。

## 2. 方法论

### 2.1 核心思想
- 由**技能策展器（curator ϕ）** 为**冻结的执行器（executor θ）** 生成任务条件化的技能 `S_{E,x}`，作为执行时的额外上下文。
- 形式化：`S_{E,x} = ϕ(E, x)`，执行动作 `a_t ∼ θ(· | x, h_t, S_{E,x})`，其中 `E = {τ_i}` 为轨迹集合，`x` 为目标任务，`h_t` 为交互历史。
- 动机直觉：目标任务的程序性知识常分散在轨迹的不同侧面（整体执行模式 vs. 局部决策上下文），因此需要多视图、多分辨率的访问。

### 2.2 关键技术细节

**（1）可导航接口（Navigable Interface）**
- 将每条轨迹组织为互补的知识视图，不修改原始经验内容：
  - **轨迹级视图**：有序动作序列、执行结果、任务元数据 → 用于识别整体策略、成败模式、值得深挖的执行阶段。
  - **步骤级视图**：观察、记录的推理、执行动作、即时结果及周边上下文 → 用于识别与动作结果相关的局部条件。
- **导航动作**：
  - `search_exp`：跨轨迹定位新经验记录，参数包括视图层级、字段、正则表达式模式、结果上限；匹配返回完整记录并保留源轨迹引用。
  - `inspect_traj`：在需要更广程序性上下文时，按时间顺序返回完整源轨迹。
- 第 r 轮：策展器选择导航动作 `ν_r`，通过接口 `I` 获得导航观察 `ω_r = I(E, ν_r)`。

**（2）导航状态（Navigation State）**
- 引入状态 `Z_r = (K_r, Q_r)`，每轮更新：`(Z_{r+1}, ν_{r+1}) = ϕ_nav(Z_r, ω_r; x)`。
  - `K_r`：为当前目标积累的知识项，区分"源特定观察""可迁移的程序性关系""执行时仍需验证的条件"，并按执行角色组织。
  - `Q_r`：将知识缺口转化为具体导航目标（开放问题），由目标初始化并随导航演化（已解答的可移除，新缺口可加入）。
- 作用：连接"经验访问"与"对目标相关知识的解释"，使二者相互引导。

**（3）技能合成**
- 从 `Z_0`（由 x 初始化）开始，迭代 R 轮导航，直到进一步调查无益或预算耗尽。
- 最终技能 `S_{E,x} = ϕ_synth(Z_R, x)`：将积累的程序性知识转为定制化执行指导，未解决的目标条件保留为执行时检查，失败教训转为警示或恢复指导。

## 6. 主要结论与发现

- **有效性**：ExpVoyager 在三个基准上一致优于所有基线，同时减少执行步数（如 Qwen3.5-9B 执行器下 ALFWorld SR 从 41.4% 提升至 63.7%，步数从 34.1 降至 25.9）。
- **可迁移性**：跨不同模型家族与规模的策展器-执行器组合均稳定提升；**较小的策展器也能提升更大执行器的性能**，说明"复用哪些知识"的指导与智能体自身能力同等重要。
- **在线自演化**：经验有限时增益有限甚至下降，但随着经验积累，ExpVoyager 持续提升而基线趋于平台期，逐步扩大优势。
- **可扩展性**：源经验越多，基线性能反而下降（噪声技能），而 ExpVoyager 持续改善，优势随规模扩大而更明显。
- **与预构建技能协同**：将预构建技能作为初始知识、再由 ExpVoyager 按需精炼，可同时提升性能并降低任务时成本。
- **预算效率**：在匹配预算下优于 agentic search 扩展；基线增加预算收益甚微甚至有害，ExpVoyager 在约 20 轮内受益，超过后下降。
- **机制分析**：
  - 可导航接口促进知识访问（移除后知识召回下降、无关知识增加）；
  - 导航状态维持持续发现（移除后因重复访问而召回增长变慢）；
  - 策展器按信息需求选择动作（轨迹视图看流程、步骤视图看局部、inspect 看跨步上下文），并跨多个源轨迹整合知识。
- **预分析发现**：预构建技能最多仅保留约 40.9% 的 oracle 知识；现有检索范式知识召回低，增大 k 会因冗余与无关信息导致精度快速下降。

## 7. 优点

- **问题重构有洞察力**：将技能合成从"预构建固定抽象"转为"按需动态导航"，直击现有方法丢弃关键知识、保留无关细节的根本缺陷。
- **接口设计贴合经验结构**：多视图（轨迹级/步骤级）+ 多分辨率 + 源轨迹引用，保留了"上下文-决策-后果"的执行语义，优于通用检索或通用终端操作。
- **状态管理机制精巧**：`(K, Q)` 双结构将"已确立知识"与"待调查问题"分离，并强调区分源特定事实与可迁移规则，避免把源实例值误当目标事实。
- **实验严谨**：预算匹配对比、oracle 知识标注、消融与行为分析、成功/失败案例研究，论证链条完整。
- **实用性强**：与现有预构建技能兼容，可降低 token 成本；支持在线自演化，适合真实 harness 场景。
- **可迁移性好**：跨模型家族与规模验证，小策展器可提升大执行器。

## 8. 不足与局限

- **算力信息不完整**：未报告总训练/推理时长、总 GPU 小时或成本，难以评估实际部署开销。
- **预分析覆盖有限**：oracle 技能与知识标注仅在 ALFWorld 上进行，结论向其他领域的泛化性未验证；标注依赖 LLM，存在偏差风险。
- **导航预算敏感**：性能在约 20–25 轮后下降，说明过度导航会引入冗余/无关经验干扰执行，需要调参。
- **失败案例揭示的局限**：
  - 技能合成时可能**丢失动作顺序约束**（如 ALFWorld 双遥控器任务）；
  - 执行器**未重新检查已满足条件**（如 WebShop 重新打开商品后未重选选项）；
  - **识别出前置条件但未能翻译为可执行动作序列**（如 ScienceWorld 中误用 `mix kitchen` 作为转移动作）。
- **应用限制**：方法依赖原始经验的可访问性与结构化程度；对执行状态变化的适应性不足；技能质量仍受策展器能力与导航预算约束。
- **偏差风险**：案例研究为"cherry-picked / lemon-picked"，可能无法完全代表整体分布；在线实验仅覆盖 ALFWorld 与 ScienceWorld。
