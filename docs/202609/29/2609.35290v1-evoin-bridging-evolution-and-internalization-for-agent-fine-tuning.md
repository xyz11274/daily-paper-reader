## 摘要
近期研究探索了通过联合进化智能体的执行框架与模型来改进智能体，但往往采用一种“大杂烩”式的方法，将新工具、新决策流程以及模型对进化后执行框架的适应，统一归入单一的智能体改进概念之下。本文则转而研究智能体如何改进其决策流程。具体而言，我们提出 EvoIn，一个连接进化与内化的智能体微调框架。EvoIn 首先分析智能体的执行轨迹，通过在执行框架中临时实例化来进化并验证新的决策流程。经过验证的流程引导智能体生成改进的推理轨迹。随后，这些轨迹被改写为自包含的推理轨迹，去除对执行框架指令的显式引用，同时将所归纳的决策逻辑表达为模型自身的推理。最后，EvoIn 在改写后的轨迹上微调模型，将这些流程内化，使得改进后的决策能力在推理时无需进化后的执行框架也能持续存在。我们在多种基准上评估 EvoIn，发现它能够持续使智能体学习到更强的决策流程，在域内将通过率提高 10.9 个百分点，在域外提高 9.2 个百分点。结果进一步表明，内化后的决策流程能够泛化到未见任务。案例研究显示，智能体能够学会在解决任务之前先决定如何解决该任务，例如通过检查文档长度来选择是完整阅读还是搜索。EvoIn 也具有广泛的适用性，在另一模型系列上同样表现出持续改进。

## Abstract
Recent work has explored improving agents by jointly evolving their harnesses and models, but often takes a ''potpourri'' approach that bundles together new tools, new decision-making procedures, and model adaptation to the evolved harness under a single notion of agent improvement. In this paper, we instead investigate how agents can improve their decision-making procedures. In particular, we propose EvoIn, an agent fine-tuning framework that bridges evolution and internalization. EvoIn first analyzes agent execution traces to evolve and validate new decision-making procedures by temporarily instantiating them in the harness. The validated procedures guide the agent to generate improved reasoning traces. These traces are then rewritten into self-contained reasoning traces, removing explicit references to harness instructions while expressing the induced decision logic as the model's own reasoning. Finally, EvoIn fine-tunes the model on the rewritten traces, internalizing these procedures so that the improved decision-making persists without the evolved harness at inference time. We evaluate EvoIn on diverse benchmarks and find that it consistently enables agents to learn stronger decision-making procedures, raising the pass rate by 10.9 points in-domain and by 9.2 points out-of-domain. Results further show that the internalized decision procedures generalize to unseen tasks. Case studies show that agents can learn to decide how to solve a task before solving it, for example by checking a document's length to choose between reading it in full and searching it. EvoIn is also broadly applicable, showing consistent improvements on another model family.

# EvoIn 论文深度总结

## 1. 核心问题与研究动机

- **背景**：语言智能体可被形式化为「模型 M + 执行框架（harness）H」的组合。决策流程（decision-making procedure）决定智能体如何规划、调用工具、验证结果，是智能体推理能力的核心。
- **现有范式的问题**：
  - **模型微调**（M, H₀）→（M*, H₀）：框架固定，改进全部压入权重，缺乏显式提出、测试、验证候选流程的空间。
  - **框架进化**（M, H₀）→（M, H*）：模型固定，改进始终外在于模型，流程只能作为指令/技能/代码被携带，无法沉淀为模型自身推理。
  - **模型–框架协同进化**（M, H₀）→（M*, H*）：在 H* 上训练又在 H* 上评估，混淆了「模型自身推理变强」与「模型对特定框架的适配」，难以判断决策逻辑能否迁移。
- **核心问题**：如何单独改进智能体的决策流程，并让这种改进持久地内化到模型权重中，使其在推理时无需进化后的框架也能生效？
- **整体含义**：EvoIn 提出第四条路径——先通过框架进化发现并验证更好的决策流程，再将其内化进模型，最后回到原始框架 H₀ 评估，从而把「流程学习」与「框架适配」解耦。

## 2. 方法论

### 核心思想
将进化后的框架 H* 作为**临时的流程发现与验证空间**，把其中涌现的决策逻辑改写为模型自身的推理，再通过监督微调内化，最终在原始框架 H₀ 下运行。形式化路径为：

（M_θ, H₀）—进化→（M_θ, H*）—内化→（M_θ*, H₀）

### 五个阶段
1. **流程提案（Procedure Proposal）**：从 H₀ 出发，提案智能体（Claude Opus 4.7）分析当前框架、上一轮反馈与执行轨迹，提出候选框架更新（可修改系统提示、工作流、工具 schema、工具实现、中间件）。每个候选须通过静态校验（编译、符号可导入、配置可加载）与运行时校验（端到端跑通一个样例）。
2. **流程评估（Procedure Evaluation）**：每个候选框架配同一目标模型 M_θ，在留出集 D_dev 上评估；分析智能体总结失败模式与可操作反馈。多轮迭代后保留 D_dev 上得分最高的框架作为 H*。
3. **流程引导采样（Procedure-Guided Sampling）**：用 H* 与 M_θ 在 D_train 上收集轨迹，仅保留任务满分且答案有效的轨迹 {τ*ᵢ}。
4. **改写（Rewriting）**：由 TAILOR 流水线执行三步——(a) 改写阶段去除对 H* 的依赖（重述框架专属推理、将不支持的工具调用映射到 H₀、删除冗余步骤）；(b) 在 H₀ 下重放并做确定性检查（无效工具调用、残留框架依赖等），失败者做一次定向修复后重放；(c) 检查阶段验证最终答案有可见证据支撑且适合训练。仅通过者保留为 {τ̃ᵢ}。
5. **流程内化（Procedure Internalization）**：恢复 H₀，在改写轨迹上做全参数监督微调，损失仅作用于模型生成的轮次，得到 M_θ*。

### 关键设计细节
- **种子框架 H₀**：任务无关，提供六个动作（scan、grep、read_lines、bash、notepad、complete_task），最多 30 轮，长工具输出截断首尾。
- **改写必要性**：原始轨迹常引用 H* 独有的指令/工具（如「按 step 0 的强制结构探测」），直接微调会导致模型在 H₀ 下复现这些不存在的依赖。
- **TAILOR 的严格约束**：禁止捏造工具调用或观测、禁止把截断文本当作可见证据、禁止用 gold 作为证据、保留种子框架下合理的自适应路由（如按文档长度选择读取策略）。

## 3. 实验设计

### 数据集与场景
- **域内（ID）**：23 个任务类别，归为 7 个任务组（多文档键检索、证据接地 QA、结构化数据推理、日志与对话追踪、上下文学习、文档接地生成、复杂指令遵循）。每类 100 条进化测试样例，共 2,300 条。
- **域外（OOD）**：6 个基准共 2,064 条——AA-LCR（100）、BrowseComp-LongContext（295）、LongBench v2（503）、MRCR（800）、Oolong（300）、Table-Longer（66）。均不出现在进化或 SFT 数据来源中。
- **训练数据**：12,035 条演示（去重、去测试重叠、截断超长后）。

### 对比方法与消融
- **Base**：Qwen3.5-35B-A3B 原始模型。
- **Seed-harness SFT**：在种子框架下采集同等数量成功轨迹微调（检验框架进化是否必要）。
- **EvoIn w/o Tailor**：跳过改写，直接用 H* 下原始轨迹微调（检验改写是否必要）。
- **All-Qwen**：用目标模型自身替代 Claude 提案者与 GLM-5.2 改写模型（检验能否自驱动）。
- **Qwen rollout vs GLM-5.3 rollout**：同等 1,752 任务下比较更强 rollout 模型是否提供更好演示。
- **Gemma-4-31B-it**：验证跨模型家族适用性。

### 评估指标
- **Pass**：得分 s=1 的样例百分比。
- **Score**：评分细则分数的均值×100，允许部分得分。

## 4. 资源与算力

- **训练配置**：全参数 SFT，框架 Megatron-Bridge，3 个 epoch，序列长度 24,576 tokens，全局/微批大小 8/1，张量/专家并行 8/8，bfloat16，Adam 优化器，学习率从 5×10⁻⁶ 余弦衰减至 5×10⁻⁷，预热前 3%，主模型每 epoch 1,488 步、共 4,464 步。
- **模型角色**：Qwen3.5-35B-A3B 为目标模型与学生；Claude Opus 4.7 为分析与提案智能体（每类 10 轮进化、每轮 3 个候选）；GLM-5.2 为改写与检查模型；GPT-OSS-120B 与 Qwen3.5-35B-A3B 为评判模型。

## 6. 主要结论与发现

- **主结果**：EvoIn 将 ID Pass 从 35.96% 提升至 46.83%（+10.87，相对提升 30%），OOD Pass 从 18.99% 提升至 28.20%（+9.21，相对提升 48%）；ID Score +11.82，OOD Score +23.47。
- **全面性**：7 个 ID 任务组全部提升，6 个 OOD 基准全部在 Pass 与 Score 上提升；23 个类别中 21 个 Score 上升（Needle QA −6.00、Long-Source Deliverables −1.77 例外）。
- **框架进化必要**：Seed-harness SFT 仅提升 ID Pass 1.87 点，OOD Pass 无提升，说明增益来自进化而非单纯更多数据。
- **改写必要**：w/o Tailor 的 ID 表现接近（45.00 vs 46.83），但 OOD Pass 跌回 19.67（接近 Base 18.99），且在 19.4% 的 OOD 样例上耗尽 30 轮预算（EvoIn 仅 6.1%），模型会引用不存在的指令与工具。
- **自驱动可行但有限**：All-Qwen 达到主系统增益的 56%（ID Pass 42.04），但 OOD 无迁移。
- **更强 rollout 有益**：GLM-5.3 演示将 ID Pass 提至 52.43、OOD Pass 提至 25.68，但 OOD Score 持平。
- **跨家族有效**：Gemma-4-31B-it 的 ID Pass 从 49.61% 升至 53.04%，OOD Pass 从 49.08% 升至 50.10%。
- **行为发现**：在 11/23 类别中，最优框架会先检查文档长度，短文档全文阅读、长文档才用搜索或分块读取；EvoIn 在短文档上先全文阅读的比例（88.3%）显著高于 Base（66.4%）。

## 7. 优点

- **概念清晰**：将「模型微调 / 框架进化 / 协同进化 / 进化–内化」四种范式形式化对比，明确指出协同进化混淆了推理提升与框架适配的问题。
- **方法简洁有效**：五阶段流水线逻辑自洽，改写环节（TAILOR）设计严谨，包含重放、确定性检查、定向修复与独立检查模型，有效防止框架依赖泄漏。
- **评估解耦**：训练与评估均在原始框架 H₀ 下进行，使增益可归因于模型自身决策能力，而非框架适配。
- **泛化验证充分**：域外 6 基准 + 跨模型家族 + 逐类别/逐基准完整结果，证据链完整。
- **案例研究具体**：通过 Table QA、多文档键检索、LongBench v2 等案例直观展示进化、改写与不写改的差异。
- **前瞻性讨论**：提出可内化的其他能力（工具使用知识、经验先验、环境观测模式）与递归自我改进路径。

## 8. 不足与局限
