## 摘要
智能体技能演化旨在通过迭代修订，为大型语言模型（LLM）智能体改进可复用的程序性指导。现有方法主要基于执行轨迹或反馈进行每次修订，这使得跨任务反复出现的行为需求保持隐含，并将修订与当前技能的行为绑定。我们提出 SkillFocus，它将反复出现的任务需求分解为一个在技能演化过程中保持固定的能力空间，从而将任务需要什么与当前技能如何表现分离开来。SkillFocus 将当前任务结果映射到该空间，以识别导致最多任务未解决的能力，然后利用该能力决定修订什么以及使用哪些证据。在涵盖异构任务的四个基准上，SkillFocus 在所有四个基准上均取得了最佳留出准确率，平均比最强竞争结果高出 5.7 个百分点，同时平均比最接近的迭代基线少用 24% 的演化 token。受控研究进一步表明，从反复出现的任务需求中导出的能力优于任务语义和从执行中导出的替代方案，而随机化任务—能力分配会使最终准确率最多降低 20.2 个百分点。在优先修订下，将证据与所选能力匹配可使候选增益提高 4.4 个百分点。

## Abstract
Agent skill evolution seeks to improve reusable procedural guidance for large language model (LLM) agents through iterative revision. Existing methods base each revision mainly on execution trajectories or feedback, leaving recurring behavioral requirements across tasks implicit and tying revision to the behavior of the current skill. We introduce SkillFocus, which decomposes recurring task requirements into a capability space that remains fixed as the skill evolves, separating what tasks require from how the current skill behaves. SkillFocus maps current task outcomes to this space to identify the capability that leaves the most tasks unresolved, then uses that capability to determine what to revise and which evidence to use. Across four benchmarks spanning heterogeneous tasks, SkillFocus achieves the best held-out accuracy on all four, outperforming the strongest competing result by 5.7 points on average while using 24\% fewer evolution tokens on average than the closest iterative baseline. Controlled studies further show that capabilities derived from recurring task requirements outperform task-semantic and execution-derived alternatives, while randomizing task--capability assignments reduces final accuracy by up to 20.2 points. Matching evidence to the selected capability increases candidate gain by 4.4 points under prioritized revision.

# SkillFocus 论文深度总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体可通过"智能体技能"（Agent Skills）——即可复用的程序性指导——来提升推理、工具使用和任务执行能力。由于技能文本可在不更新模型参数的情况下被修订，**技能演化**（skill evolution）成为提升智能体表现的重要途径。
- **核心痛点**：当一个共享技能被复用于异构任务时，其修订必须同时服务多个不同且常重叠的程序性需求。现有方法（Trace2Skill、SkillGrad、SkillOpt、SkillRevise 等）主要基于**执行轨迹或反馈**来驱动修订，存在两个根本问题：
  1. 执行证据只反映"当前技能做了什么"，随技能变化而变化，**无法揭示跨任务反复出现的需求**；
  2. 以任务为修订单位也不合适——一个任务可能包含多个程序，同一程序又可能出现在多个任务中。
- **核心问题**：能否在**执行之前**从任务规格中提取反复出现的需求，并以此同时指导"修订什么"和"用哪些证据修订"？
- **整体含义**：论文提出将"任务需要什么"（固定不变）与"当前技能如何表现"（动态变化）分离，用前者作为稳定的修订锚点。

## 2. 方法论

### 2.1 核心思想
- 引入**能力空间（Capability Space）**：从任务规格、输入结构和环境契约中提取反复出现的程序性需求，定义为"能力"（capability），并构建任务—能力二值矩阵 **Q**。
- 关键性质：**能力集 C 与矩阵 Q 在演化开始前冻结，整个演化过程中保持不变**；任务结果可变，但任务需求不变。

### 2.2 关键技术细节

- **能力归纳（Capability Induction）**：
  - 从每个任务记录中提取需求 R_i；
  - 用三种独立视角（Requirement-centric、Intervention-centric、Boundary-centric）各生成一次能力提案，取共识形成 C₀；
  - 将需求分配到能力或标记为 UNASSIGNED；
  - 支持度过滤（n_min = 3）后冻结 (C, Q)。
  - 该过程**不看当前技能、执行轨迹、成功/失败标签**。

- **能力选择（Capability Selection）**：
  - 每个能力有支持份额 π_d（任务池中需要该能力的比例）和当前得分 q_d（训练集上该能力覆盖任务的平均归一化得分）；
  - 定义**未解决任务质量**：m_d = π_d · (1 − q_d)；
  - 选择 m_d 最大的能力 c*，但仅限**可行动且可检验**的候选集 U_t（训练集中有可诊断失败、选择集中有支持任务）。

- **证据匹配（Evidence Matching）**：
  - 只保留 Q 中标记为需要 c* 的训练任务；
  - 证据包 E_t 包含：这些任务上的失败执行、成功对照执行、与 c* 相关的技能内容、历史中针对 c* 的修订记录；
  - 诊断与编辑均只基于该证据包，避免全量执行轨迹的噪声。

- **候选验证（Whole-Skill Validation）**：
  - 配对变化 Δ_X(S′, S) = 在集合 X 上候选与当前技能得分差的均值；
  - 接受条件：**选择集与训练集上的配对变化均为正**（Δ_sel > 0 ∧ Δ_tr > 0）；
  - 选择集执行轨迹不参与候选生成，起到"未见证据"的检验作用。

- **算法流程**（Algorithm 1）：归纳 (C, Q) → 初始执行 → 构建选择/训练集 → 循环：计算能力得分 → 选 c* → 收集证据 → 诊断与编辑 → 候选验证 → 接受则更新技能与执行记录。

## 6. 主要结论与发现

1. **性能最优**：SkillFocus 在全部 4 个基准上取得最佳留出准确率，平均超出最强竞争结果 **5.7 个百分点**（各基准领先 1.4–15.0 分），在 SpreadsheetBench 上对 SkillOpt 领先最大（77.1 vs 62.1）。
2. **效率更高**：平均比 SkillOpt 少用 **24% 演化 token**，且更早完成最后一次被接受的修订。
3. **能力来源至关重要**：
   - 从反复任务需求导出的能力，比任务语义分组高 8.2–18.8 分，比执行导出分组高 6.6–12.9 分；
   - 随机化任务—能力分配（保持度序列）使准确率下降 **11.1–20.2 分**，说明具体分配关系而非分组数量/大小才是增益来源。
4. **能力匹配证据有效**：在优先修订下，匹配证据使候选训练增益提高 **4.4 分**；Top + Matched 条件取得最高 Δ_tr（+9.37）和最高接受率（40.0%）。
5. **能力空间结构合理**：多数任务需要多个能力（LiveMath 平均 5.11 个），能力间任务集重叠低（中位 Jaccard ≤ 0.17），且三次独立提案的分配一致性高（ARI 0.883–0.973，NMI 0.953–0.989）。
6. **修订具有外溢性**：整体技能编辑会同时影响目标与非目标任务，因此整体验证（而非局部验证）是必要的。

## 7. 优点

- **概念创新**：首次将"任务反复需求"形式化为固定能力空间，明确分离"任务需要什么"与"技能如何表现"，为技能演化提供了稳定锚点。
- **方法闭环完整**：从能力归纳、能力选择、证据匹配到整体验证，形成可复现的完整流程，且能力归纳不依赖执行结果，避免循环依赖。
- **证据匹配机制精细**：只向修订暴露与目标能力相关的失败/成功对照、技能片段和历史，显著降低噪声。
- **验证策略稳健**：选择集 + 训练集双重配对验证，选择集轨迹不参与生成，起到近似"泛化检验"作用。
- **实验设计严谨**：多组受控对照（来源、分配、证据、优先级、选择集构造）系统性地隔离了各组件贡献；稳定性分析（ARI/NMI）增强了结论可信度。
- **效率与效果兼顾**：在提升准确率的同时减少 token 消耗，具有实际部署价值。

## 8. 不足与局限

- **前提假设较强**：假设反复程序性需求可在演化前被识别，且可通过技能修订解决；若任务需求难以预先形式化或无法通过文本技能改善，方法失效。
- **整体修订的副作用**：每次修订改变整个共享技能，改进一个能力可能影响其他能力；论文承认无法将编辑限制在目标能力内，只能靠整体验证兜底（IFBench 上目标/非目标对比甚至为 −8.1 分）。
- **算力信息缺失**：未报告 GPU 型号、数量、训练时长，仅有 token 成本，难以评估实际资源需求。
- **模型与配置单一**：仅使用一种优化器—目标模型组合（GPT-5.4 + DeepSeek-V4-Flash），未验证跨模型家族的泛化性。
- **演化视野有限**：最多 5 轮、每轮 1 个候选，长时程或跨域演化未探索。
- **选择集对照不完美**：用均匀随机采样近似"独立于优先级规则的选择集"，作者自认专门的对照实验仍待开展。
- **能力归纳依赖 LLM 提案**：三次独立提案的共识机制虽提升稳定性，但仍可能受模型偏差影响；无人工标注的真值分类可供验证。
- **部分基准增益有限**：LiveMath 上各条件差异较小，选择集对比不够一致，说明方法在任务池较小或需求高度专业化时优势减弱。
