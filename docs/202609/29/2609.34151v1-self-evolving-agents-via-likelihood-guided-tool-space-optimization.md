## 摘要
自进化智能体能够持续改进其行为，而工具定义了它们与环境交互的可执行动作空间。然而，将完整的工具库暴露给模型会引入大量无关上下文，并可能损害工具使用决策。我们研究工具空间自进化，其中每种重复出现的任务类型维护一个由累积输出经验构建的持久工具空间。我们指出现有方法的三个局限：(1) 输出无感知选择：它们主要依赖工具描述或模型先验，而非观察到的工具输出；(2) 跨请求无状态：它们为每个请求独立选择工具，未将先前的输出经验整合为持久的任务特定状态；(3) 推理成本：它们对同一任务的后续请求反复搜索、排序或推理候选工具。我们通过输出感知的工具评分、持久的任务特定工具空间、摊销式工具选择以及跨模型的可复用配置来解决这些局限。我们提出LOTS（仅似然工具评分），它在保持模型参数固定的同时，从累积输出经验中进化智能体的工具空间。每次请求后，LOTS保留模型生成的答案，并通过测量移除观察到的输出时答案似然的变化来估计每个工具的贡献。这些贡献在每个重复任务内聚合，以对工具进行排序并更新其持久空间。在三个基准测试中，LOTS提升了任务性能，同时大幅减少了工具上下文。更重要的是，序列实验表明任务特定空间持续存在并随时间不断改进，而跨模型实验表明学习到的配置可迁移到不同模型。

## Abstract
Self-evolving agents can continually improve their behavior, while tools define the executable action space through which they interact with the environment. However, exposing the full tool library to model introduces substantial irrelevant context and can impair tool-use decisions. We study tool-space self-evolution, where each recurring task type maintains a persistent tool space which is constructed from accumulated output experience. We identify three limitations of existing methods: (1) output-unaware selection: they rely primarily on tool descriptions or model priors rather than observed tool outputs; (2) statelessness across request: they select tools independently for each request without consolidating prior output experience into persistent task-specific state; (3) inference cost: they repeatedly search, rank, or reason over candidate tools for subsequent requests of the same task. We address these limitations through output-aware tool scoring, persistent task-specific tool spaces, amortized tool selection, and reusable configurations across models. We introduce LOTS (Likelihood-Only Tool Scoring), which evolves an agent's tool space from accumulated output experience while keeping model parameters fixed. After each request, LOTS holds the model's generated answer and estimates each tool's contribution by measuring how much the answer likelihood changes when its observed output is removed. These contributions are aggregated within each recurring task to rank tools and update its persistent space. Across three benchmarks, LOTS improves task performance while substantially reducing tool context. More importantly, sequential experiments demonstrate that task-specific spaces persist and continue to improve over time, while cross-model experiments show that learned configurations transfer across different models.

## 1. 核心问题与整体含义

- **研究背景**：LLM 驱动的自主智能体通过调用外部工具与环境交互，工具空间决定了智能体的可执行动作空间，同时工具描述与 schema 也构成推理上下文的一部分。
- **核心矛盾**：全局工具库不断累积能力，但每个重复出现的任务类型通常只需要一个小的、任务特定的工具子集。将完整工具库暴露给模型会引入大量无关上下文，扩大模型需要选择的备选集合，从而降低工具使用准确率（论文 Figure 1 显示：工具数从 30 增至 240 时，全量暴露准确率降至 34.5%，而任务特定空间保持在 53.8% 以上）。
- **现有方法的三大局限**：
  - **输出无感知**：主要依赖工具描述或模型先验进行选择，未直接衡量工具实际输出是否支持最终答案。
  - **跨请求无状态**：每个请求独立选择工具，先前请求的输出经验未被整合为持久的任务级状态。
  - **推理成本高**：同一任务的后续请求仍需反复搜索、排序或推理候选工具。
- **核心研究问题**：智能体能否从自身输出经验中进化出一个持久的工具空间，使后续请求被更准确、更高效地服务？
- **整体含义**：论文将"工具空间"本身视为智能体可持久化的自适应状态，提出 LOTS 方法，在不修改模型参数的前提下，通过输出经验持续优化任务特定工具空间。

## 2. 方法论

### 核心思想
- **LOTS（Likelihood-Only Tool Scoring）**：固定模型参数，利用模型自身生成答案的似然变化来评估每个工具对答案的贡献，并将请求级贡献聚合为任务级工具排序，进而剪枝得到持久工具空间。

### 关键技术细节

- **问题形式化**：
  - 全局工具库为 S，任务 c_t 的工具空间为 E_t ⊆ S，目标是最大化任务性能 U(c_t; p_θ, E)。
  - 智能体按任务序列 c_1, ..., c_T 到达，每个任务维护自己的持久空间，模型参数 p_θ 保持不变。

- **输出感知工具评分（请求级）**：
  - 对请求 x，记录模型实际输出 y_x 及完整上下文 h_x（含请求、工具文档、工具调用与观察输出）。
  - 对工具 s，构造干预上下文 h_x^{-s}，移除 s 相关的输出证据（TGB 上会重新执行链，下游工具因缺少输入而报错；BFCL 上移除调用该工具的消息及其观察）。
  - 贡献分数定义为：**I_x(s) = L_θ(y_x | h_x) − L_θ(y_x | h_x^{-s})**，其中 L_θ 为答案 token 的平均对数似然。
  - 正值表示移除该工具证据会降低模型对同一答案的支持，说明该工具贡献了有用证据。
  - 两个关键设计：① 冻结同一输出，在两种上下文下 teacher-forcing 评分，无需额外 rollout；② 每个工具在与其他工具共存的情况下被评估，保留组合工具使用中的依赖关系。

- **任务级聚合与空间构建**：
  - 任务级贡献：**Ī_t(s) = (1/|Q_t(s)|) Σ_{x∈Q_t(s)} I_x(s)**，仅在暴露且可评分的请求上取平均。
  - 按 Ī_t(s) 排序，取 Top-K 得到工具空间 **E_t = TopK_{s∈A_t} Ī_t(s)**。
  - **Theorem 1**：在工具交互有界（二阶差分 |Δ_{s,u}F(B)| ≤ β）的假设下，Top-K 选择恰好最大化固定输出似然的加性近似，且选择差距有界：0 ≤ F(A*) − F(E_t) ≤ r(r−1)β，其中 r = m − K。

- **持续演化机制**：
  - 任务空间作为持久部署状态存储，后续同任务请求复用该空间。
  - 新任务到达时独立构建其空间，集合扩展为 E_t = E_{t−1} ∪ {E_t}，不修改 p_θ。
  - 同一任务的新批次经验可通过指数移动平均更新运行分数：**Ĩ_t(s) ← α·Ī_t^{(k)}(s) + (1−α)·Ĩ_t(s)**，实现空间的可修订性。
  - 未暴露的工具不参与该请求的均值计算，也不计为零；证据不足 K 时空间小于 K，不会为凑数添加未评分工具。

- **算法流程（Algorithm 1）**：服务并记录 → 评分（留一似然） → 聚合 → 剪枝 Top-K → 部署复用。

## 3. 实验设计

### 数据集 / 场景与 Benchmark

- **TGB（受控组合基准）**：合成文本基准，4000 个请求，10 个任务族，15 个工具（7 个链式工具 + 8 个干扰工具）。每个任务族 80 请求拟合、320 请求评估。用于研究工具依赖、干扰项与空间更新。
- **BFCL-v4 multi-turn**：多轮函数调用基准，按 API 类分组（GorillaFileSystem、TradingBot、TravelAPI、VehicleControlAPI），每类 10 条拟合、40 条评估（共 160 条）。采用文档降级（documentation demotion）而非工具移除，所有工具仍可调用。
- **GTA-Atomic**：GTA 的原子任务划分，基于图像的 ReAct 执行，使用官方 harness 与可执行工具服务器。使用 read_arith、count_arith、web_fact 三类共 112 条评估请求。

## 6. 主要结论与发现

- **任务性能提升**：TGB 上 LOTS 在全部 8 个模型上优于 Keep all，提升 3.8–25.0 个百分点；BFCL 上 5 个模型中 3 个最优、2 个接近最优；GTA-Atomic 上 7 个模型中 6 个优于 Keep all。
- **工具上下文大幅压缩**：TGB 上平均保留 2.8–6.8/15 个工具，服务 prompt token 减少 33–46%；GTA-Atomic 上 token 消耗比 TTO 少 2.0–4.0 倍、比 Beam Search 少 4.4–9.5 倍。
- **持久任务空间有效**：跨任务流中 LOTS 始终高于 Keep all，最终 credited accuracy 0.87 vs 0.49；任务内后续批次可补充缺失工具、完成工具链，准确率随更新上升。
- **跨模型可迁移**：BFCL 上 18/20 跨模型配对优于 Keep all，说明排序捕获了任务级偏好，可在不同规模与家族模型间复用。
- **排序而非空间大小是关键**：同预算下 Top-K 平均 0.819，Random 0.222，Keep all 0.694；AUROC 在 71/72 个模型–任务族对上完美区分参考链工具。
- **错误输出仍含有用证据**：正确与错误输出的任务级排序 Spearman 相关 0.911，支持频率保留规则在 50% 答案损坏下仍保持空间。

## 7. 优点

- **方法创新性**：
  - 首次系统研究"工具空间自进化"，将工具空间本身作为持久自适应状态，而非仅优化模型参数或提示。
  - 提出输出感知的留一似然评分，无需正确性标签，避免了 TTO/Beam Search 的标签依赖与高昂搜索成本。
  - 摊销式选择：一次拟合、多次复用，显著降低后续请求的推理开销。
- **理论支撑**：Theorem 1 给出了 Top-K 选择作为加性代理最大化的误差界，明确了工具交互有界时的选择差距。
- **实验设计亮点**：
  - 覆盖合成受控、多轮函数调用、真实 ReAct 执行三类场景，外部效度较好。
  - 跨任务流、任务内更新、跨模型迁移三类实验直接验证了"持久性"与"可复用性"两大核心主张。
  - 消融充分，对评分目标、删除操作、聚合规则、更新规则均有细致对照。
  - 成本分析完整，报告了 token 摊销与 break-even 请求数。
- **实用价值**：无需修改模型权重，可与闭源 API 模型配合（拟合用开源模型，服务用闭源模型），部署灵活。

## 8. 不足与局限

- **实验覆盖局限**：
  - TGB 为合成基准，任务族由模板生成，聚类实验对该设置过于有利，真实请求流的任务分离可能更困难。
  - GTA-Atomic 仅使用 3 类任务、112 条评估请求，部分模型（如 Qwen2.5-14B）上 LOTS 未超过 Keep all。
  - BFCL 使用文档降级而非工具移除，与 TGB/GTA 的剪枝设置不完全一致，跨基准可比性受限。
- **方法限制**：
  - 似然评分衡量的是模型对自身输出的依赖程度，**不保证答案正确性**，论文明确声明"likelihood-based scores do not certify correctness or safety"。
  - 需要访问模型似然（log-probabilities），对仅提供 API 输出的闭源模型，拟合阶段需借助开源模型，可能引入分布不匹配。
  - 任务分配在实验中依赖 benchmark 元数据；无元数据时需聚类或路由，论文承认阈值路由在不同编码器间不可迁移。
  - 工具交互有界假设（Theorem 1）在强互补/替代场景下可能不成立，误差界可能变松。
- **偏差与风险**：
  - 预算 K 的选择使用拟合标签，虽非空间构建本身，但仍引入少量标签依赖。
  - 部分实验（如 GTA-Atomic 组合诊断）使用相同 65 条请求进行评分与评估，存在过拟合风险，论文以 95% 区间标注了不确定性。
  - 评分时间随注册表规模增长较快（120 工具时 8158 秒），大规模工具库的扩展性仍需验证。
- **应用限制**：
  - 论文未建立自主执行的安全性，实际部署需要工具权限控制与人工监督。
  - 持续更新会带来额外评分成本，长期运行的总成本需按 Eq. 18 核算。
