## 摘要
智能体技能封装了可复用的程序性知识，使LLM智能体能够执行任务，并且可以利用与环境交互的轨迹自动改进这些技能。这是经典的技能进化问题。现有方法主要遵循线性进化范式，即按顺序将更新应用于最新的技能库版本。因此，它们不可避免地陷入局部最优，留下许多有前景的进化路径未被探索。我们提出SkillVine，一种自动技能进化框架，将技能进化形式化为图搜索问题，并采用分支探索策略。借助主干-分支协同搜索机制、智能父节点选择器和自适应粒度更新规则，SkillVine在探索与利用之间实现了平衡。我们在5个基准测试上使用两个LLM评估了SkillVine。结果表明，SkillVine沿分支发现的技能库版本优于沿线性主干的版本，并在十个基准-模型组合中的九个上取得了最佳测试性能。

## Abstract
Agent skills encapsulate reusable procedural knowledge that enables LLM agents to perform tasks, and they can be improved automatically using trajectories from interactions with the environment. This is the classic problem of skill evolution. Existing approaches predominately follow a linear evolution paradigm, in which updates are sequentially applied to the latest skill-library version. As a result, they inevitably fall into local optima, leaving many promising evolution paths unexplored. We propose SkillVine, an automatic skill-evolution framework that formulates skill evolution as a graph search problem and employs a branching exploration strategy. Equipped with a trunk-branch collaborative searching mechanism, an intelligent parent-node selector, and an adaptive-granularity update rule, SkillVine achieves a balance between exploration and exploitation. We evaluate SkillVine on 5 benchmarks with two LLMs. Results show that SkillVine discovers better skill-library versions along branches than along the linear trunk and achieves the best test performance in nine of ten benchmark-model combinations.

- **背景**：LLM 智能体被广泛用于软件工程、科研自动化、网页交互和具身智能等场景。Agent Skills 将可复用的程序性知识封装为模块化、可动态加载的执行单元，以突破固定上下文窗口的限制。
- **核心问题**：静态技能库无法适应变化的环境与任务，因此需要"技能进化"——利用与环境交互的轨迹自动改进技能库。然而，简单增加技能数量并不总能提升性能：技能库从少量扩展到 202 个技能时性能可下降多达 21%，其中"技能遮蔽"（skill shadowing）贡献了高达 68% 的退化。
- **现有方法的缺陷**：主流方法遵循**线性进化范式**，每次更新顺序作用于最新的技能库版本，导致三个问题：
  - 早期版本中的有用内容可能被覆盖，尤其当新任务与旧任务差异较大时；
  - 更新顺序累积，一旦进入局部最优便无法回退探索其他路径；
  - 强制技能库沿单一路径演化，无法并行探索和系统比较不同技能变体。
- **整体含义**：论文将技能进化重新形式化为**图搜索问题**，提出 SkillVine 框架，通过分支探索突破线性演化的局部最优限制，为智能体自进化提供新范式。

## 2. 方法论

### 2.1 问题形式化
- 技能库 $S_v = \{s_{v,1}, \dots, s_{v,n_v}\}$ 表示版本节点 $v$ 的技能集合；智能体 $\pi$ 在任务流 $D_t$ 上产生轨迹 $T_t$。
- 更新算子 $U: S \times T \rightarrow S$ 将选定版本与轨迹映射为候选子版本。
- 目标：在训练预算 $B$ 约束下，最大化验证分布上的期望准确率：
  $$S^* = \arg\max_{S \in V_B} \text{Acc}(\pi, S; D_{val})$$

### 2.2 核心思想：版本图 + 主干-分支协同
- **版本图表示**：将所有技能库版本组织为有向图 $G=(V,E)$，每个节点保存完整技能内容与元数据，边表示父子派生关系，实现**完全可恢复**的历史检查点。
- **节点元数据**：父指针 $p(v)$、节点状态 $z(v)$、验证准确率 $q(v)$、已解决/失败样本集合 $(D_v^+, D_v^-)$、扩展计数 $n_{exp}(v)$。

### 2.3 三大关键技术

**（1）主干-分支更新策略**
- **主干**：每个训练批次都尝试增量更新，观察全部批次，累积长时程信息。
- **分支**：从历史版本生长，仅使用部分训练批次，探索主干缺失的能力。
- 主干接受/拒绝决策作为该批次信息质量的信号，指导分支更新力度。

**（2）互补性感知节点选择器**
- 节点评分公式：
  $$\text{Select}_t(v) = q(v) + \lambda_{exp}\frac{\sqrt{\log(N_{exp}+1)}}{n_{exp}(v)+1} + \lambda_{comp}C_t(v)$$
- 互补性项 $C_t(v)$ 奖励解决主干失败样本的节点，惩罚丢失主干已解决样本的节点：
  $$C_t(v) = \frac{|D_v^+ \cap D_{u_t^{tr}}^-|}{|D_{u_t^{tr}}^-|} - \beta\frac{|D_{u_t^{tr}}^+ \setminus D_v^+|}{|D_{u_t^{tr}}^+|}$$
- 实验采用"发现选择器"（$\lambda_{exp}=0.08, \lambda_{comp}=0.5$）与"精炼选择器"（均为 0）混合。

**（3）自适应粒度分支更新（AGBU）**
- 若主干更新被接受（$a_t^{tr}=1$），批次信息质量高，分支采用**粗粒度**更新：一次性应用全部编辑。
- 若主干更新被拒绝（$a_t^{tr}=0$），批次可能含有害编辑，分支采用**细粒度**更新：逐个应用编辑并逐一验证，拒绝有害编辑。
- 在评估成本与更新可靠性之间取得权衡。

**（4）最优技能输出**：训练结束后返回图中验证准确率最高的节点 $v^* = \arg\max_{v \in V} q(v)$。

## 6. 主要结论与发现

- **性能领先**：SkillVine 在 10 组模型-基准组合中的 **9 组**取得最佳测试性能；DeepSeek-V4-flash 上全部 5 个 benchmark 领先。
- **显著增益**：SpreadsheetBench + DeepSeek-V4-flash 上测试分从 48.04 提升至 71.53（+23.49）。
- **分支优于主干**：所有 10 组组合的最终最优技能库均通过**分支路径**发现，而非主干。
- **选择器有效性**：10 条最优路径中，2 条仅用发现选择器，2 条仅用精炼选择器，6 条两者兼用。
- **AGBU 有效性**：10 条路径中 8 条至少拒绝了一个有害编辑，保护了有前景的演化路径。
- **参数规律**：分支尝试次数先增后平；更短的分支更新间隔、更小批次 + 更多训练步数通常带来更好性能。
- **任务依赖性**：在错误类型集中、主干较弱的任务（OfficeQA、SpreadsheetBench）增益更大；在错误多样、主干已强的任务（SearchQA）增益较小。
