## 摘要
基于 LLM 的智能体日益依赖持久技能，即可复用的过程性提示，以在不更新权重的情况下进行适应。现有技能自演化方法根据执行反馈直接修改技能文本，但每次 Oracle 评估都需要完整的智能体 rollout，造成监督瓶颈，使搜索局限于故障修补式更新。我们的关键洞见是：排序是比绝对结果回归更平滑的监督目标——判断哪个技能更好所需的 Oracle 评估次数少于预测精确分数。基于这一洞见，我们提出 SkillLift，它通过学习一个与 Oracle 对齐的评分准则作为结构化评估空间，将技能搜索与 Oracle 成本解耦。我们将此形式化为一个双层优化问题，并通过交替优化求解：内层循环使用冻结的评分准则作为廉价代理，在零 Oracle 成本下指导技能修改；外层循环则调用少量 Oracle rollout，通过秩相关重新对齐评分准则，从而摊销 Oracle 成本并稳定文本空间中的更新。在复杂智能体任务基准上的实验表明，我们的方法优于现有自动技能方法，并且与前沿演化方法相比，token 成本降低 40--70%。代码见 https://github.com/WalteR-MittY-pro/SkillLift。

## Abstract
LLM-based agents increasingly rely on persistent skills, i.e., reusable procedural prompts, to adapt without weight updates. Existing skill self-evolution methods directly revise skill text based on execution feedback, but each oracle evaluation requires a full agent rollout, creating a supervision bottleneck that confines search to failure-patching updates. Our key insight is that ranking is a smoother supervision target than absolute outcome regression: identifying which skill is better requires fewer oracle evaluations than predicting exact scores. Building on this insight, we propose SkillLift, which decouples skill search from oracle cost by learning an oracle-aligned rubric as a structured evaluation space. We formalize this as a bilevel optimization problem solved via alternating optimization: an inner loop uses the frozen rubric as a cheap surrogate to guide skill revision at no oracle cost, while an outer loop invokes a small number of oracle rollouts to re-align the rubric via rank correlation, amortizing oracle cost and stabilizing text-space updates. Experiments on complex agent task benchmarks show that our method outperforms existing auto-skill methods with 40--70\% less token cost compared to frontier evolving methods. Codes are available at https://github.com/WalteR-MittY-pro/SkillLift.

- **核心瓶颈**：现有技能自演化方法（SkillOpt、CoEvoSkills、MUSE-Autoskill、Trace2Skill 等）直接把技能文本当作优化对象，依据执行反馈逐次修改。但**每次 oracle 评估都需要一次完整的 agent rollout**，监督信号极其稀疏；加之技能文本空间高度不连续（改几个词就可能让 rollout 从成功翻转为崩溃），搜索只能退化为「失败修补式」的保守局部更新。

- **关键洞见**：**排序（ranking）比绝对分数回归是更平滑的监督目标**——判断「哪个技能更好」所需的 oracle 评估次数远少于预测精确分数；同时相对次序在绝对分数噪声大、跨任务不可比时仍保持稳定。

## 2. 方法论

### 核心思想
- 将技能搜索与 oracle 成本**解耦**：先学习一个与 oracle 排序对齐的结构化评估空间（rubric），把稀疏的 oracle 反馈转化为稠密、可解释的准则级信号，供技能生成器廉价使用。

### 双层优化形式化
- 上层（对齐 rubric）：`min_R  E_{t∼T}[ D(σ^R_t, σ^O_t) ]`
- 下层（搜索技能）：`S*(R) = argmax_S  E_{t∼T}[ R(S) ]`
- 其中 `σ^R_t`、`σ^O_t` 分别为 rubric 与 oracle 在任务 t 上对候选技能诱导的排序，`D` 实例化为 `1 − τ`（Kendall 秩相关）。
- 只要求相对次序一致、不要求分数校准，因此每轮少量 oracle 评估即可完成重对齐。

### Rubric 结构与打分
- Rubric 由 M 个**二元准则** `{(c_1,p_1),…,(c_M,p_M)}` 组成：`c_i` 是关于技能行为的 yes/no 问题，`p_i ∈ Z\{0}` 为带符号权重（正=merit，负=flaw）。
- 由 verifier（LLM）依据 `(t, S_k, R)` 判定命中 `h_i ∈ {0,1}`，归一化得分：
  `R(S_k) = (Σ p_i h_i − S_min) / (S_max − S_min)`
  其中 `S_max = Σ_{p_i>0} p_i`，`S_min = Σ_{p_i<0} p_i`。
- 命中向量 `h(S_k)` 与分数一同返回，使生成器知道**「差在哪里」**，从而做定向修订，而非仅得到一个标量。

### 交替优化流程（Algorithm 1）
- **Mode A｜内层：rubric 指导的技能更新（零 oracle 成本）**
  - 每轮维护一个 champion `S*_{ℓ−1}`；verifier 在冻结 rubric `R_ℓ` 下评估 champion 得到命中 `h*_ℓ`。
  - 生成器 `G` 依据 `(t, S*, R, h*, d_{ℓ,k})` 沿 K 个**多样化修订方向** `d_{ℓ,k}`（如策略优化、工具使用策略、错误处理）生成 K 个分支。
  - 每个分支在轮内迭代精修，采用**非降接受准则**：仅当 `R_ℓ(新) ≥ R_ℓ(旧)` 时保留，防止局部精修使分支退化。
  - 终止条件：所有分支满足 `min_k R_ℓ(S_{ℓ,k}) ≥ θ_A`，或内层预算耗尽。
- **Mode B｜外层：oracle 对齐的 rubric 更新**
  - 技能冻结，对 `{S*, S_1,…,S_K}` 调用 oracle 排序得 `σ_O`（champion 旧分数可复用，故仅需 K 次新 rollout）；verifier 用当前 rubric 重打分得 `σ_R`。
  - 对齐度用 Kendall τ 度量：
    `τ(σ_R,σ_O) = 2/((K+1)K) · Σ_{i<j} sgn(σ_Ri − σ_Rj)·sgn(σ_Oi − σ_Oj)`
  - 若 `τ ≥ θ_B` 则已对齐；否则由 **rubricator**（LLM）接收两个排序、双方逐技能分数与命中向量及可选 oracle 反馈，输出**完整替换版** rubric（可新增缺失准则、调整权重、删除与 oracle 持续不一致的准则），迭代直到对齐或预算耗尽；未对齐时保留历史中 τ 最大的版本。
  - champion 始终由 **oracle 分数**选出，因此 rubric 失配只会降低内层指导质量，**不会污染最终输出**。
- **四个 LLM 角色**（附录）：Bootstrapper（从任务描述+参考材料生成 5–15 条二元准则）、Verifier、Generator、Rubricator；verifier/rubricator 温度为 0（确定性打分），generator 温度 0.7（探索）；全部返回固定 JSON schema。

## 6. 主要结论与发现

- **主结果**：SkillLift 在全部 6 个 model–benchmark 组合上优于 Human-written、LLM-written、SkillOpt、CoEvoSkills，说明「先对齐评估空间、再搜索技能」的解耦范式有效。
- **成本–质量优势**：达到相同通过率分位（如 0.9 分位）所需 token 显著更低——相对 SkillOpt 为 2.62×–2.74× 的节省，相对 CoEvoSkills 为 2.13×–2.22×；这来自 O(L) 而非 O(LT) 的 oracle 调用复杂度，以及内层更新零 oracle 成本的设计。
- **监督信号形态的关键性**：消融中「w/ score regression」（用绝对分数回归替代排序对齐）表现下降，直接验证了论文的核心假设——**相对排序是比绝对分数更平滑、更省 oracle 的监督目标**。
- **组件必要性**：去掉 rubricator（即固定 rubric、不做外层重对齐）与去掉 seed skills 均带来性能下降，前者说明 rubric 会随搜索漂移而失配、必须周期性重对齐，后者说明合理起点仍是搜索效率的重要来源。
- **超参稳健性**：K×L 网格显示性能随二者增大先升后饱和，θ_A=0.85、θ_B=0.9 附近的默认配置处于稳定区间，说明方法对配置不敏感。
- **可解释性副产品**：命中向量 `h(S_k)` 使每轮修订可归因到具体准则（如「工具调用未做失败重试」），案例研究中的轨迹显示技能修订方向与 rubric 命中变化高度对应，提供了纯标量优化方法不具备的可审计性。

## 7. 局限性与未来工作

- **oracle 仍是必要条件**：Mode B 对齐依赖真实 rollout 提供的排序信号，因此方法无法在完全无环境交互的场景下使用；对 rollout 极贵或不可重复的任务（如真实生产副作用）适用性受限。
- **排序信号的粒度上限**：Kendall τ 只刻画候选集合内的相对次序，若候选技能质量接近（分数区间压缩），τ 对微小改进不敏感，可能导致 rubric 提前「假对齐」。
- **rubric 全量替换的稳定性**：rubricator 输出的是完整替换版 rubric，可能引入准则集合的剧烈跳变，论文以「保留历史 τ 最大版本」缓解，但未分析 rubric 随轮次的演化稳定性。
- **任务族假设**：上层目标对任务分布 T 求期望，隐含「同一 rubric 可服务整个任务族」的假设；对高度异质、单任务特化的场景，共享 rubric 的表达力可能成为瓶颈。
- **未探索方向**：多 rubric / 分层 rubric、将命中向量反馈给 oracle 以做主动查询（active ranking）、把排序监督扩展到跨任务迁移的技能库构建等。

## 8. 总体评价与启示

- **贡献定位**：论文的核心贡献不是又一个技能优化器，而是**把「评估器学习」与「技能搜索」解耦**，并用排序一致性这一弱监督形式把昂贵的 oracle 反馈蒸馏成廉价的准则级稠密信号；Table 1 的复杂度对比（O(L) vs O(LT)）是该定位最凝练的表达。
- **工程价值**：命中向量 + 带符号二元准则的设计使技能演化过程可解释、可定向修订、可人工审计，这对需要信任与合规的智能体部署场景有直接价值。
- **方法论启示**：当监督信号昂贵且目标空间不连续时，**先学习一个与真实目标排序一致的低成本代理，再在代理上做稠密搜索**，是一种可迁移的通用策略，不限于技能演化。
- **潜在风险**：rubric 由 LLM 生成与更新，可能继承 backbone 的偏见或对任务描述的过度拟合；论文通过「champion 始终由 oracle 分数决定」切断了 rubric 误差向最终产物的传播路径，这一防护设计值得其他代理评估器工作借鉴。
