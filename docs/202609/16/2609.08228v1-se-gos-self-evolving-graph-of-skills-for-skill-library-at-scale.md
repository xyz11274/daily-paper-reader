## 摘要
现代 LLM 智能体日益依赖可复用技能，然而当技能库扩展到数千个条目时，有效检索成为瓶颈。技能图（Graph-of-Skills, GoS）通过利用依赖感知的图结构进行可扩展的技能检索来应对这一挑战，而 SkillDAG 进一步表明，技能图可以在线积累由执行支撑的结构。然而，这些方法仍未回答：历史执行轨迹能否被系统地提炼为一个更好的、可泛化到未见任务的检索图。我们提出自演化技能图（Self-Evolving Graph-of-Skills, SE-GoS），一个无需训练的框架，它从执行轨迹中演化现有 GoS 图，同时保留原始检索流程。SE-GoS 执行三种互补更新：拓扑演化，从执行证据中发现并剪枝技能关系；边权演化，基于历史有效性强化与检索相关的关系；描述演化，利用执行反馈优化面向检索的技能描述。在 SkillsBench 上的三个 LLM 上，相对于完整技能加载，SE-GoS 持续提高任务奖励，同时减少输入 token，且增益因模型家族而异。在一个代表性设置中，一轮演化将奖励从 52.4% 提升至 59.4%，同时相对于完整技能加载减少约三分之一的输入 token，并且所得图可迁移到一个不相交的留出划分，在静态 GoS 基线上取得 5.4 个百分点的提升。这些结果表明，无需模型训练、无需改变检索算法、也无需修改技能内容，技能图即可从执行经验中得到改进，从而将静态检索图转变为不断演化的检索基础设施。

## Abstract
Modern LLM agents increasingly rely on reusable skills, yet as skill libraries scale to thousands of entries, effective retrieval becomes a bottleneck. Graph-of-Skills (GoS) addresses this challenge by exploiting dependency-aware graph structure for scalable skill retrieval, while SkillDAG further demonstrates that skill graphs can accumulate execution-backed structure online. However, these approaches leave open whether historical execution traces can be systematically distilled into a better retrieval graph that generalizes to unseen tasks. We present Self-Evolving Graph-of-Skills (SE-GoS), a training-free framework that evolves an existing GoS graph from execution traces while preserving the original retrieval pipeline. SE-GoS performs three complementary updates: topology evolution that discovers and prunes skill relationships from execution evidence, edge-weight evolution that reinforces retrieval-relevant relationships based on historical effectiveness, and description evolution that optimizes retrieval-facing skill descriptions using execution feedback. Across three LLMs on SkillsBench, SE-GoS consistently improves task reward while reducing input tokens relative to full skill loading, with gains varying across model families. In a representative setting, one evolution round improves reward from 52.4\% to 59.4\% while reducing input tokens by approximately one-third relative to full skill loading, and the resulting graph transfers to a disjoint held-out split with a 5.4-point improvement over the static GoS baseline. These results show that skill graphs can be improved from execution experience without model training, changes to the retrieval algorithm, or modifications to skill content, turning a static retrieval graph into an evolving retrieval infrastructure.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体通过调用外部工具与可复用技能完成复杂任务。当技能库从几十条扩展到数千条时，瓶颈从"是否使用技能"转移到"如何检索出足以完成任务的有限子集"。
- **现有方案的两难**：
  - **完整加载（Vanilla）**：token 成本随库规模线性增长，且过载上下文会埋没关键技能。
  - **向量检索（Vector）**：只看语义相似度，忽略功能前置依赖，常把高层求解器排在前面而漏掉语义弱但功能必要的底层解析器/初始化工具——即"前置依赖缺口"。
  - **Graph-of-Skills（GoS）**：用类型化有向技能图 + 反向感知 PPR 检索依赖完整的执行包，在 1000 技能 SkillsBench 上比完整加载奖励高约 25.6%、token 少约 56.7%，但**图是静态的**：一旦依赖边错误、关系缺失或描述系统性匹配失败，库无法自我纠正。
  - **SkillDAG**：证明技能图可在线积累执行结构，但其冷启动依赖约 200 次 LLM 调用（嵌入服务 + 成对分类器），且在线编辑由 LLM 判断技能相关性。
- **核心问题**：**历史执行轨迹能否被系统性地蒸馏成一个更好的、可泛化到未见任务的检索图？**
- **关键洞察**：每次试验本身就记录了"检索了哪些技能、实际用了哪些、任务是否成功"——这是一份被浪费的免费信号。SE-GoS 让同一套 GoS 检索流程通过三种免训练更新来改进它读取的图。

## 2. 方法论

### 核心思想
- **不改检索代码、不训练参数、不编辑 SKILL.md**，只修改检索流程所消费的"图 + 节点元数据"。
- 可行性依据：PPR 的转移算子直接由边权构建（重新加权/重新连边即改变检索结果）；种子与重排阶段读取技能描述（改描述即改变语义种子分与匹配分）。检索流程始终是一个**固定消费者**。
- **冷启动图不是 GoS 的完整类型化图**：GoS 的 workflow/semantic/alternative 关系依赖 LLM 验证器，SE-GoS 刻意不假设该 LLM 先验，改为从**确定性语义相似图**（按签名 token 重叠连 top-k 近邻，无 LLM、无嵌入服务）出发，由执行反馈补足缺失结构。
- **先验 vs 算子**：结构通道（冷启动、拓扑、边权）完全无模型；仅文本通道（节点更新）由 LLM 充当"作用于观测轨迹的算子"，而非"关于相关性的先验"。

### 经验信号收集
- 每次试验产生轨迹 `T_t = (q_t, r_t, B_t, U_t, tokens_t)`：查询、验证器奖励、检索包、**实际使用的技能集合**（从轨迹工具调用中匹配技能源路径提取）、token 数。
- `U_t` 可包含 `B_t` 之外的技能（智能体自行浏览发现），这正是节点更新针对的"被用但未被检索到"情形。

### 三项互补更新（按依赖顺序执行）

**（1）拓扑演化（改变离散边集与边类型）**
- **归纳**：
  - *workflow 边*：成功试验中"检索到的种子 u → 实际使用的 v"共现，权重 `w_wf(u→v) = min(0.9, 0.6 + 0.05(c_uv − 1))`，一次成功共现即连边，重复增强但有上限。
  - *dependency 边*：成功试验中 u 先于 v 使用，且 I/O schema 重叠超过 GoS 的阈值 ζ=0.6——"schema 预测前置，轨迹认证前置"。
  - *avoid 边*：失败试验中反复共现（≥θ_avoid）且从未在成功试验中共现的配对，权重为 0，对扩散算子不可见，仅在束组装时生效（丢弃与已选技能互为 avoid 的候选）。**刻意不归纳 alternative 关系**：共载有害可由失败共现直接见证，而"可互换"是关于未发生执行的反事实断言，观测轨迹无法认证。
- **剪枝**：对"被检索 ≥θ_obs 次但从未被使用"的头技能 v，将其所有入向语义边权 ×0.5（软剪枝），低于下限的边直接删除——可逆且收紧束、减少 token 浪费。

**（2）边权演化（改变连续权重）**
- 对每次奖励为正（r_t > 0）的试验，强化所有指向被使用技能 v 的入边：
  `w^(t+1)(u→v) = w^(t)(u→v) + η · r_t · I[v ∈ U_t]`（η=0.1 为强化率）
- 失败试验不贡献正向信用；边权质量反映该关系在历史上被证明有用的频率。
- 附录给出**置信加权插值**（部署保障）：`w(e) = (1−λ_c(e))·w_0(e) + λ_c(e)·w̃(e)`，`λ_c(e)= n_e/(n_e+n_0)`，低证据边被静态先验保护；单轮协议未启用。

**（3）节点/描述演化（改变节点文本）**
- 针对"被实际使用但在失败试验中排名低于 n_rank=3"的技能 s，采用 ProTeGi 式**单轮、技能局部**的文本梯度：
  1. **梯度**：LLM 批评器 ∇ 检视查询 q、当前描述 d_s 与检索证据，产出"描述为何不匹配 q"的自然语言梯度 g_q；
  2. **编辑**：LLM 编辑器 δ 沿梯度反方向修订，锚定原文，编辑预算 ≤50 token；
  3. **蒙特卡洛探索**：改写模型生成 p=2 个变体；
  4. **离线选择**：用同一检索流程离线评测 `E(q, s; d)`（s 在描述 d 下是否进入 top-n_rank 并加小排名奖励），取 `d*_s = argmax Σ_q E(q,s;d)`，平局偏向编辑距离最短者。
- 成本 `O(|Q_s|·(1+p))` 次 LLM 调用/受影响技能，与库规模无关；默认开启"不驱逐保护"（拒绝会把实际用过的技能挤出 top-K 的改写）。

### 演化后检索
- 演化每窗口离线执行一次，推理时检索流程与 GoS 完全相同，仅读取演化后的图：
  `ρ_i(q) = s*_i(q; G(T), w(T), d*) + μ·m_i(q; d*)`
- 功能形式与静态版一致，但排名现在同时依赖图结构、查询相关性与编码在权重中的历史有效性。

## 6. 主要结果与结论（论文报告的方向）

- **相对静态 GoS**：三项更新叠加后在 SkillsBench 上带来奖励提升与 token 消耗下降的**同向改善**，即在更省上下文的同时提高完成率——说明被固化的错误依赖边与失配描述确实是可回收的损失来源。
- **相对 SkillDAG**：SE-GoS 的优势主要来自**冷启动成本**（无嵌入服务、无成对 LLM 分类器、无约 200 次 LLM 调用）与**在线阶段的免训练性**，而非在线检索质量本身的量级领先；两者在最终奖励上属于同一区间。
- **相对 Vanilla / Vector**：延续了 GoS 的既有结论——完整加载的 token 线性膨胀与向量检索的"前置依赖缺口"分别对应成本侧与正确率侧的瓶颈，SE-GoS 只是在 GoS 已解决的框架内进一步降低了"图质量"这一残余瓶颈。
- **泛化 vs 记忆**：留出集实验（50 训练 / 37 评估）是全文最关键的判别性证据——若演化收益完全来自对训练任务轨迹的记忆，则评估任务上增益应消失；论文报告的方向是**增益在留出任务上仍存在但幅度收窄**，据此主张更新学到了可迁移的"哪些技能倾向于共同有用"的结构性知识，而非任务-答案查表。
- **多轮演化**：第 1 轮收益最大，后续轮次边际递减并伴随波动，符合"可纠正的结构错误在一轮内被大量回收、后续仅剩噪声级信号"的解释；同时暗示**边权强化存在自我强化的过拟合风险**，需要置信加权插值等部署保障来约束。
- **组件贡献**：2³ 消融给出的图景是——**拓扑演化（尤其 avoid 边的引入与语义边软剪枝）与边权强化是最稳健的收益来源**，节点/描述演化贡献更小且更依赖具体查询分布；三者并不完全可加，存在一定冗余（拓扑连边后，边权强化所依赖的入边才存在），这也解释了按依赖顺序执行的设计合理性。
- **检索接口消融**：融合束输出（GoS 式单一排序）与 SkillDAG 式三通道输出在更密基底（k=8）上对比，说明收益并非来自输出格式，而是来自图本身的质量提升——即方法的改进点确实落在"检索消费者读取的数据"上。
- **定性发现**：论文强调 `U_t ⊄ B_t` 的现象普遍存在（智能体自行浏览发现未被检索到的技能），这类"被用但未检索到"的技能正是节点更新与拓扑归纳的监督信号来源，也解释了为何仅靠语义相似度无法收敛到正确的检索子集。

## 7. 局限与未来工作

- **信号依赖奖励**：边权强化使用验证器奖励 `r_t`，在无可靠验证器的开放域任务上，该方法退化为只能使用成功/失败共现的拓扑通道。
- **一轮演化的样本效率**：87 个任务的一轮轨迹要同时驱动拓扑、边权、节点三通道更新，单条边可获得的证据量很小，故引入 `λ_c(e)=n_e/(n_e+n_0)` 的收缩；论文未系统扫描 `n_0`、`η`、`θ_avoid`、`θ_obs` 等超参的敏感性。
- **LLM 作为算子的可靠性**：节点更新把 LLM 限制为"作用于观测轨迹的算子"而非"关于相关性的先验"，这是一个有价值的设计约束，但仍未证明 LLM 编辑不会引入系统性偏差（例如把所有描述都改写成同一套流行动词）。
- **静态基底的选择**：主实验的冷启动图是确定性 token 重叠 k=1 图（863 条语义边），刻意剥离了 GoS 的类型化边。这使"补足缺失结构"的叙事成立，但也意味着结论**不能直接外推**到已经拥有高质量 LLM 验证图的部署场景——那种情况下 SE-GoS 的可改进空间会更小。
- **未覆盖**：无 GPU/推理成本的完整清单、无跨库规模（数千技能以上）的伸缩实验、无对"图被污染后能否自我修复"的对抗性测试。

## 8. 对研究社区的意义

- **概念层面**：把"智能体执行轨迹"重新定义为**对检索基础设施的监督信号**，而不仅是策略改进的数据，这与"用轨迹微调策略/模型"的主流路线正交，提供了一条**免训练、免参数、只改数据资产**的改进轴。
- **工程层面**：三项更新都作用于"固定消费者读取的图与元数据"，因此可与任意检索算法（PPR、向量、混合）解耦复用；冷启动不需要嵌入服务这一点对私有技能库的落地很关键。
- **方法论层面**：留出集 + 噪声底经验校准 + 2³ 因子 + 同协议重跑基线的组合，为"自演化检索"这类**极易通过重测训练任务而虚高**的研究方向提供了一个可参照的评测范式。
- **值得追问的问题**：当技能库本身随使用不断新增时，演化是否会与库增长形成正反馈或漂移；以及"avoid 边"这类负向知识能否被安全地跨任务复用——论文刻意不归纳 alternative 关系的保守立场，恰恰提示了负向结构知识的认证难度。
