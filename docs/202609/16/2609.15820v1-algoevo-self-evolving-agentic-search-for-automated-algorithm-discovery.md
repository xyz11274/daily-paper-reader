## 摘要
大型语言模型通过合成可执行代码推动了自动化算法发现，但现有框架将它们困在具有预定义控制流的刚性搜索流程中。这一局限限制了自适应推理，阻碍了跨范式迁移，并丢弃了宝贵的执行反馈。我们提出 AlgoEvo，一个统一的智能体框架，将自动化算法发现转变为交互式、知识积累的过程。自主智能体基于运行时反馈动态检查、诊断和编辑代码。设计技能中心将特定范式的知识与核心发现引擎解耦，使单一工作流能够无缝处理单目标、多目标和多组件设计。同时，分层经验机制将搜索轨迹组织为任务级树以指导探索，并将跨任务模式整合为可复用技能。在六个代表性基准任务上，AlgoEvo 以显著更少的评估次数和更低的 token 消耗，达到或超越专用方法，展现出强大的任务内积累、跨任务迁移，以及通过灵活激活技能来复现或超越现有最先进性能的能力。

## Abstract
Large language models have advanced automated algorithm discovery by synthesizing executable code, but existing frameworks trap them in rigid search pipelines with pre-defined control flows. This limitation restricts adaptive reasoning, blocks cross-paradigm transfer, and discards valuable execution feedback. We propose AlgoEvo, a unified agentic framework that transforms automated algorithm discovery into an interactive, knowledge-accumulating process. An autonomous agent dynamically inspects, diagnoses, and edits code based on runtime feedback. A design skill hub decouples paradigm-specific knowledge from the core discovery engine, allowing a single workflow to seamlessly handle single-objective, multi-objective, and multi-component design. Meanwhile, a hierarchical experience mechanism organizes search trajectories into a task-level tree to guide exploration and consolidates cross-task patterns into reusable skills. Across six representative benchmark tasks, AlgoEvo matches or surpasses specialized methods with substantially fewer evaluations and reduced token consumption, demonstrating strong intra-task accumulation, cross-task transfer, and the ability to reproduce or exceed existing state-of-the-art performance through flexible skill activation.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **研究领域**：自动化算法发现（Automated Algorithm Discovery, AAD），即无需人工算法工程即可生成优化启发式算法，是运筹优化与人工智能交叉的重要方向。
- **技术背景**：将大语言模型引入自动化启发式设计（LLM-AHD）后，可直接合成可执行代码。已有工作沿用了多种成熟的进化范式：
  - 基于种群的全局搜索（如 EoH）
  - 岛屿模型维持多样性（如 FunSearch）
  - 蒙特卡洛树搜索（如 MCTS-AHD）
  - 局部代码编辑迭代搜索
  - 并进一步扩展到多目标（MEoH）与多组件协同设计（E2OC、MOTIF）。
- **核心痛点**（论文指出三大局限）：
  1. **控制流刚性**：LLM 被嵌入专家预定义的进化管线中，仅作为被静态提示模板驱动的“被动代码采样器”，无法进行交互式调试、诊断分析与深度结构重构。
  2. **范式耦合严重**：不同设计任务（单目标、多目标、多组件）需要各自独立的代码库，框架碎片化。
  3. **记忆管理缺失**：现有方法主要依赖标量性能反馈，丢弃了结构化的执行细节，导致搜索沦为孤立的“试错”，难以累积与迁移可复用的算法经验。
- **整体含义**：论文主张将算法发现从“预定义管线的被动采样”转变为“交互式、知识累积的科学过程”，使 LLM 从被动采样器升级为主动的搜索编排者（搜索控制器）。

## 2. 论文提出的方法论

### 2.1 核心思想
- 提出 **AlgoEvo**：一个统一的智能体框架，将算法发现建模为算法空间 S 上的**智能体搜索过程**。
- 用两个互补组件替代刚性管线：
  - **设计技能中心（Design Skill Hub）**：提供范式相关的执行契约，使同一搜索循环可覆盖单目标、多目标、多组件任务。
  - **分层经验库（Hierarchical Experience Bank）**：存储提炼后的轨迹，并按情境检索相关经验指导探索。

### 2.2 问题形式化
- **领域与实例**：领域 D 由实例空间 X_d、解空间 Y_d 和目标函数 f_d 定义，优化目标为 y* = arg min f_d(x, y)。
- **求解器与算法**：求解器由可设计的策略集合 Π = (π₁, …, π_K) 构成，K=1 为单启发式设计，K>1 为多组件联合设计。
- **算法优化**：性能 F_d(x | Π) = φ_d(f_d(x, s(x | Π)))，目标是 Π* = arg min E_{x∼X_d}[F_d(x | Π)]，受计算预算 B 约束。

### 2.3 智能体搜索循环（Agentic Search Loop）
- 发现状态 s_t = (Π_t, C_t, E_t, F_d(x | Π_t))，包含当前算法、工作上下文、经验库与性能反馈。
- 智能体在每步选择动作 a_t：**检查代码、修改策略、运行诊断或评估候选**，执行后得到转移 τ_t = (s_{t-1}, a_t, r_t, s_t)。
- 即时奖励定义为性能改进：r_t = F_d(x | Π_{t-1}) − F_d(x | Π_t)，累计奖励最大化可推导回全局目标最小化。
- 与固定周期不同，智能体**交错执行诊断、修改与评估**，在瓶颈出现时调用针对性分析，在有证据支持时进行结构编辑。

### 2.4 设计技能中心（Design Skill Hub）
- 将范式差异外化为可插拔的“设计技能”S_hub，新增范式只需增加技能而非修改引擎。
- 每个技能声明：(i) 可设计策略的角色；(ii) 代码接口；(iii) 有效修改的指导原则；(iv) 任务相关的评估约定。
- **生命周期**：
  - **选择与激活（t=0）**：任务初始化时匹配并激活对应技能。
  - **演化（t=T）**：任务完成后将证据固化到经验库；技能不在单任务内更新，仅跨任务演化——当某设计模式在至少两个不同任务中被一致验证有效时，被抽象回技能中心。

### 2.5 分层经验库（Hierarchical Experience Bank）
- **Level 1：经验卡片**：在每次评估事件时生成，记录设计上下文、修改内容、奖励与理由。
- **Level 2：任务级经验树**：同一任务的卡片构成树，节点为卡片，边表示“派生自”关系，按 MCTS 四阶段操作：
  - **选择**：按情境 UCB 公式选择节点，UCB(v|q) = r̄(v|q) + c·√(2 ln N / n(v,q))，其中情境 q 可包含 stagnation、bottleneck、coupling、sparse front 四类条件。
  - **扩展**：验证后的候选卡片挂为其父节点的子节点。
  - **评估**：计算奖励 r_t。
  - **回传**：奖励向上传播，维护子树评估次数 m(v) 与累计奖励 S(v)，子树价值 R̄(v) = S(v)/m(v) 估计该设计方向的平均奖励。
- **Level 3：跨任务整合**：当某设计模式在至少两个任务中有效时，抽象为对应设计技能。

### 2.6 经验积累与自演化流程（Algorithm 1 要点）
1. 匹配任务与技能，初始化经验树，加载相关卡片。
2. 检测当前搜索情境 q。
3. 按 UCB 选择经验节点。
4. 智能体在经验指导下执行动作。
5. 若为评估动作：提炼经验卡片、加入经验库、挂为子节点、计算奖励、回传祖先节点。
6. 重复直至预算耗尽或智能体终止。
7. 选择最优算法，并将有效的跨任务模式固化到技能中心。

## 6. 论文的主要结论与发现

- **性能结论**：单一智能体引擎在仅更换激活技能的情况下，在六个任务上**匹配或超越**范式专用基线。
  - TSP 训练/测试分别达 5.986 / 7.007，比最强 LLM-AHD 基线领先 4–7%，比 NN 领先 12.3%，且仅用约 39 次评估（预算的 1/13）。
  - CVRP 达 12.698 / 24.150，约 35 次评估。
  - Bi-TSP HV 0.827（MEoH 为 0.760），IGD 0.036（MEoH 为 0.077），约 36 次评估。
  - Bi-FJSP HV 0.911（最佳），但 IGD 0.162 略逊于 MEoH 的 0.143。
  - CVRP-DR 训练/测试 8.860 / 8.999，优于 MOTIF、E2OC、Synergy、Rotating-EoH。
  - FJSP 4-Ops 测试 1927.5，优于所有基线与专家算子（2137.9）。
- **样本效率**：AlgoEvo 在数十次评估内达到最终质量并保持平稳，基线耗尽全部 500 次预算仍未追上。
- **经验机制有效**：
  - 热启动（代码迁移）优于冷启动，且降低种子间方差。
  - 多轮渐进累积在 TSP 与 Bi-FJSP 上均呈单调改进（TSP −1.91%，Bi-FJSP HV +20.21%）。
  - 跨任务迁移（CVRP→CVRP-DR）将成本从 10.314 降至 9.816（−4.8%）。
- **诊断驱动设计**：诊断密集型种子在 CVRP-DR 上取得最佳结果，支持“先归因后编辑”的设计原则。
- **方法技能可迁移**：将 EoH、ReEvo、FunSearch、MEoH、NSGA-II、MOEA/D 的方法论抽象为技能后，可在不引入其原生搜索流程的情况下达到或超越原生表现。
