## 摘要
开放式强化学习通常依赖基于评分细则的奖励来应对没有可直接验证答案的任务。然而，策略与奖励系统构成一个动态反馈回路：随着策略优化当前奖励，最初有用的奖励系统可能因奖励黑客或响应区分度下降而变得不可靠。因此，奖励系统应在训练过程中进化，而非保持固定。现有的动态评分细则方法会调整评估标准，但奖励失效也可能源于评分机制或信号组成。我们提出 EvoRS，一种自进化的强化学习框架，它从同策略经验中进化奖励系统，并将其表示为一个可执行的 Reward-DAG。具体而言，一个智能体式设计器根据同策略 rollout 和奖励轨迹更新该系统，以维持训练时的可靠性。在写作和角色扮演任务上，EvoRS 在三个评判器下均取得最佳质量，分别比策略高出 2.107 和 4.767 分，同时减少奖励黑客和覆盖失效，并保持奖励信息量。消融实验证实，一个全面的固定奖励系统无法在开放式任务中保持可靠，必须在整个训练过程中进化。

## Abstract
Open-ended reinforcement learning often relies on rubric-based rewards for tasks without directly verifiable answers. Yet the policy and reward system form a dynamic feedback loop: as the policy optimizes the current reward, an initially useful reward system may become unreliable due to reward hacking or reduced response discriminability. The reward system should therefore evolve rather than remain fixed during training. Existing dynamic-rubric methods adapt evaluation criteria, but reward failures can also arise from scoring mechanisms or signal composition. We introduce EvoRS, a self-evolving RL framework that evolves the reward system from on-policy experience, representing it as an executable Reward-DAG. Specifically, an agentic designer updates this system from on-policy rollouts and reward traces to maintain train-time reliability. Across writing and roleplay, EvoRS achieves the best quality under all three judges, outperforming the policy by \(2.107\) and \(4.767\) points, respectively, while reducing reward hacking and coverage failures and preserving reward informativeness. Ablations confirm that a comprehensive fixed reward system cannot remain reliable in open-ended tasks and must evolve throughout training.

## 1. 核心问题与整体含义

- **背景**：强化学习（RL）被越来越多地用于训练 LLM 处理开放式任务（写作、角色扮演、多步办公工作流等）。这些任务缺乏可直接验证的答案，因此主流做法依赖基于评分细则（rubric）的奖励系统，通过 LLM 评判器或生成式奖励模型（GRM）将多维判断转化为可扩展的训练信号。
- **核心问题**：策略与奖励系统构成一个动态反馈回路。随着策略不断优化当前奖励，一个对初始策略可靠的奖励系统可能在训练后期变得不可靠。作者将这类失败归纳为三个维度：
  - **有效性失效（Validity）**：奖励黑客（reward hacking）使策略在不产生预期行为的情况下获得高分；
  - **覆盖不足（Coverage）**：新出现的同策略响应无法被当前奖励系统表示；
  - **信息量衰减（Informativeness）**：奖励逐渐饱和或同查询组内区分度下降，对优化不再有用。
- **关键洞察**：奖励可靠性是**训练时属性**，不能一次性确定。现有动态 rubric 方法只调整"评估什么"（criteria），而"如何评分"（scoring mechanism）和"多信号如何组合"（signal composition）通常保持固定。同一评估内容用连续打分、清单核验、扣分惩罚等不同机制会产生完全不同的奖励分布。因此需要演化的是**完整的奖励系统**。
- **整体含义**：论文提出 EvoRS，把奖励设计视为学习过程的一部分，让奖励系统随策略共同演化，为开放式 RL 提供了一种可执行、可更新的奖励范式。

## 2. 方法论

### 2.1 核心思想
- 将当前奖励系统抽象为一个**可执行的 Reward-DAG**，使准则、评分机制、信号组合都能在统一结构中修改。
- 用**智能体式设计器（agentic designer）** 从同策略 rollout 与奖励痕迹中诊断失效、生成候选状态，并通过**匹配回放（matched replay）** 比较后选择下一状态。
- 关键分离：奖励执行（GRM 打分）与奖励演化（设计器）解耦——演化步之间 Dt 保持固定，保证同一训练阶段内奖励计算一致、候选状态之间可比。

### 2.2 Reward-DAG 表示
- 状态定义为：**Dt = (Vt, Et, Θt)**
  - Vt：可执行奖励节点；
  - Et：节点依赖与执行顺序；
  - Θt：各节点的准则与评分机制，以及节点输出的组合规则。
- 节点类型包括：全局 Rubric 节点、查询级 Rubric 节点、清单/验证器节点、扣分/缺陷惩罚节点、门控（gate）、聚合器（aggregator）等。
- 节点级信号：**hv = M_mv(x, y; ρv, θv, Jϕ)**，其中 ρv 为准则，mv 为评分机制，Jϕ 为评判器。
- 组合算子将上游节点输出映射为 RL 使用的标量奖励：**rD(x, y) = F_out({hv : v ∈ Pa(out)}; θout)**，负责聚合、归一化、门控或路由。
- GRPO 使用组相对优势：**Âi = (ri − mean(r)) / (Std(r) + ε)**，因此 DAG 不仅要行为有效，还要保持同查询内的奖励信息量。

### 2.3 从同策略经验到候选状态
- 设计器联合分析采样响应与奖励痕迹，将反复出现的响应模式与 Dt 的奖励产生方式关联，识别主要奖励失效及其在 Reward-DAG 中的可能来源。
- 若证据不支持针对性更新，则 Dt 保持不变。
- 在允许的更新空间 A(Dt) 内探索多个修复方向，实例化为类型化编辑 e(j)t 及候选状态：**D̃(j)t+1 = e(j)t(Dt)**，e(j)t ∈ A(Dt)。
- 类型化编辑操作包括：add_node、update_node、remove_node、set_entry，均为事务性操作，先克隆、校验、成功才提交。

### 2.4 自验证与演化状态转移
- 当前状态 Dt 与所有候选状态在**相同回放案例 Bt**（取自近期同策略经验）上执行，使差异可归因于候选状态本身。
- 候选需通过多重检查：执行有效性（成功率 τsucc = 1.0）、守卫维度不退化（Δq > −τguard，τguard = 0.05）、健康度下降不超过 τhealth = 0.15、信息量 std/range 下限（0.02 / 0.05）、模型审查支持度 ≥ 0.55。
- 选择最能修复目标失效且保留干净案例与同查询区分的候选；若无候选有支持性改进，则保留 Dt。
- 所有被选中、被拒绝、no-op 的轨迹存入 run-local memory，并蒸馏为动态技能 Kt+1，供后续诊断使用。
- 算法流程（Algorithm 1）：初始化 → 采样查询与分组响应 → 若激活查询级节点则实例化查询准则 → 用 Dt 打分并记录痕迹 → GRPO 更新 → 若到达演化步则诊断、生成候选、匹配回放比较、选择或保留 → 更新记忆与技能。

## 3. 实验设计

### 3.1 任务与数据
- **写作（Writing）**：944 条过滤后的合成开放式写作指令，覆盖六个写作领域及受众、格式、长度、风格、语言、交际意图等约束。
- **角色扮演（Roleplay）**：来自 MiniMax Role-Play Bench 的 5,000 条查询，保留具有明确人设、关系、上下文与对话状态的样本，覆盖中英文场景。

### 3.2 Benchmark 与评判
- 写作质量：**WritingBench**（整体分）。
- 角色扮演质量：**CoSER**（Overall 及 SC、AN、CF、SQ 四个维度）。
- 评判模型：**GPT-5.6-Terra、DeepSeek-V4-Pro、GLM-5.2** 三个强评判器取等权平均，报告 common-success 交集（写作 994 条、角色扮演 194 条模拟）。
- 奖励可靠性指标：
  - **HR（Hack Rate）**：预定义奖励黑客模式出现率，分类在方法比较前由 base 模型校准池冻结；
  - **CFR（Coverage Failure Rate）**：预定义硬覆盖失败率；
  - **R-Var**：同查询内奖励方差；
  - **Zero**：同查询组奖励范围不可区分的比例。

### 3.3 对比方法
- **RLAIF**：固定任务级 rubric。
- **RaR**：固定查询级 rubric。
- **RLER**：基于当前策略响应动态增补准则（动态 rubric）。
- **OpenRS**：基于响应比较构建成对自适应 rubric（成对偏好机制）。
- 所有方法共用相同 GRPO 流水线、训练数据、rollout 预算与评估协议，均使用本地 Qwen3.5-27B 作为 GRM。
- EvoRS 从与 RLAIF 相同的单节点连续奖励系统出发，每 5 个 RL 步演化一次。

### 3.4 消融与泛化实验
- **演化策略消融**：仅准则级适配、固定最终 Reward-DAG。
- **自演化组件消融**：去除候选选择、去除更新拒绝、去除演化记忆/技能。
- **泛化性实验**：策略从 Qwen3-4B 扩展到 Qwen3-8B；GRM 从 Qwen3.5-27B 换为 RewardAnything-8B。

- **消融实验**：5 个变体（Table 4、Table 20），覆盖演化范围与自演化组件。

- **HR 审计独立性验证**：用 Qwen3.5-27B、DeepSeek-V4-Flash、Kimi-K2.5 在两种策略规模上重审 50 个 CoSER 场景，三种审计器给出相同排序；另做 60 个样本的盲人工标注（三方一致率 85.0%，Fleiss κ = 0.705）。

**充分性评价**：实验设计较为充分且客观——多评判器取平均、common-success 交集、盲审计、预冻结分类、配对 bootstrap 置信区间、跨策略与跨 GRM 泛化验证，均有助于减少单一评判器偏差与方法标签泄漏。消融覆盖了方法的关键组件。总体上是公平且可重复性较好的对比。

## 6. 主要结论与发现

- **质量提升**：EvoRS 在 WritingBench 上比 base 策略高 **2.107 分**，是唯一将 HR 降至 base 以下的方法；在 CoSER Overall 上比 base 高 **4.767 分**，且四个维度全部排名第一。
- **基线失效模式**：固定或部分自适应的奖励系统（RLAIF、RaR、RLER、OpenRS）在 CoSER 上未能整体超过 base，HR 反而更高，且维度提升不均匀（如 RaR 提升 SC、CF 但降低 AN、SQ），符合"对日益可被利用的奖励信号过优化"的模式。
- **可靠性改善**：EvoRS 降低写作 HR 与角色扮演 CFR，且在标注的奖励系统转移后进一步下降；Zero-distinction 率保持较低，与盲偏好排序的一致性更强。
- **固定奖励系统不可靠**：即使是一个全面的固定 Reward-DAG（从训练一开始就用 EvoRS 发现的完整系统），也显著低于全程演化的版本（CoSER 上 −5.103）；仅准则级适配也不足（CoSER 上 −4.521）。
- **自演化组件有效**：去除候选选择、更新拒绝或演化记忆/技能均导致质量下降，多轮角色扮演上影响更大。
- **泛化性**：EvoRS 在 Qwen3-8B 策略、Qwen3.5-27B 与 RewardAnything-8B 两种 GRM 下均优于 RaR。
- **行为层面**：基线方法产生更长对话、更高重复率与截断率；EvoRS 响应长度接近 base，重复大幅减少，说明质量提升来自更连贯的推进而非冗长堆砌。

## 7. 优点

- **问题框定清晰**：将奖励可靠性明确定义为训练时属性，并从有效性、覆盖、信息量三个维度系统刻画失效模式，动机分析（Figure 2、3，Table 1）扎实。
- **表示能力强**：用可执行 Reward-DAG 统一表示准则、评分机制与信号组合，突破了动态 rubric 方法只改准则的局限。
- **搜索空间受约束**：类型化编辑 + 合法性校验（无环、可达性、pointwise 语义、节点数 ≤ 10、路径上评分节点 ≤ 3）避免了无限制的 prompt 式修改，保证 RL 奖励接口稳定。
- **验证机制严谨**：匹配回放保证候选比较可归因；多重硬性检查（执行、守卫、健康、信息量、审查）防止奖励坍缩；无支持改进时保留原状态，避免强制转移。
- **执行与演化解耦**：设计器不参与奖励计算，保证同一训练阶段奖励一致、候选之间可比。
- **实验客观性**：多评判器平均、common-success 交集、盲审计、预冻结 HR/CFR 分类、配对 bootstrap、跨策略/GRM 泛化、人工校验，显著降低了评估偏差风险。
- **记忆与技能机制**：run-local memory 与动态技能使设计器能从被拒绝的候选中学习，避免重复失败方向。

## 8. 不足与局限

- **领域覆盖有限**：实验仅限写作与角色扮演，尚未在工具使用、多步智能体环境、延迟反馈等场景验证；Reward-DAG 虽原则上可纳入工具状态与交互历史，但仍需实证。
- **演化调度固定**：每 N 步（N=5）演化一次，是简化设计；

- **演化调度固定**：每 5 步触发一次，属于启发式设定，未探索由奖励健康度下降、分布偏移或方差坍塌等信号驱动的自适应触发。固定周期可能带来两种代价：失效累积较快时响应滞后，奖励已稳定时产生不必要开销（每次演化步平均额外 242.8s）。
- **设计器依赖闭源强模型**：候选生成与诊断由 Codex SDK + GPT-5.4 承担，成本、可复现性与长期可用性受外部模型服务约束；论文未报告用开源模型替代设计器时的表现，因此"设计器能力下限"这一关键变量未受控。
- **超参数未做敏感性分析**：τsucc = 1.0、τguard = 0.05、τhealth = 0.15、std/range 下限 0.02/0.05、审查支持度 ≥ 0.55、节点数 ≤ 10、路径评分节点 ≤ 3 等阈值均为固定常数，缺乏对这些门限松紧程度的消融，无法判断方法对阈值选择的稳健性。
- **评估指标含人工先验**：HR 与 CFR 依赖预先定义的失效模式分类，虽在校准池上冻结以保证方法比较公平，但该分类本身可能遗漏未被预见的新颖奖励黑客形态，使可靠性改善被高估。
- **GRM 质量仍是隐含瓶颈**：EvoRS 只在 Qwen3.5-27B 与 RewardAnything-8B 两个奖励模型家族上验证，规模更小、指令跟随更弱或存在系统性偏差的 GRM 下，Reward-DAG 的诊断与修复是否仍有效未知。
- **缺少理论刻画**：论文未给出演化过程的收敛性、单调改进性或最优性保证，也未量化 Reward-DAG 搜索空间规模与覆盖程度，方法有效性主要由实证支撑。
- **对比范围偏窄**：基线集中在 rubric 类在线 RL 方法，未与偏好优化类（DPO/RLHF 变体）、过程奖励模型或课程学习式奖励调度方法比较，难以判断 EvoRS 相对更广义奖励学习范式的增益。
- **数据分布真实性有限**：写作任务为合成指令（944 条过滤后），角色扮演来自单一 bench（5,000 条），与真实部署中的长尾、多轮、工具耦合场景仍有差距；作者亦承认工具使用与延迟反馈场景未验证。

## 9. 对实践者的启示与开放方向

- **可迁移的工程范式**：把奖励系统当作"可执行程序"而非"一段提示词"，并用类型化编辑 + 回放验证来管理其变更，这一思路可直接移植到任意需要在线奖励的开放式 RL 流水线，即使不采用 LLM 设计器，也可用规则化诊断替代。
- **三个可靠性维度可作为监控指标**：有效性、覆盖、信息量（对应 HR/CFR/Var-Zero）构成了训练期奖励健康的轻量看板，独立于 EvoRS 本身即可用于检测固定奖励系统的退化。
- **开放问题**：
  - 能否用开源模型或小模型承担设计器角色，并量化设计器能力与最终质量的关系？
  - 演化触发能否由信号驱动，从而在失效出现时即时响应、在稳定期零开销？
  - Reward-DAG 能否扩展到带工具调用状态、多轮交互历史与环境反馈的智能体场景？
  - 是否存在对奖励系统演化过程的收敛性或"无退化"性质的理论保证？
  - 如何在奖励演化中同时约束成本（评判器调用次数）与信息量，形成显式的预算—可靠性权衡？
