## 摘要
随着 LLM 智能体处理涉及多样化信息需求的复杂任务，信息检索变得日益重要。由于检索依赖于通过索引键表示每个文档的索引，检索质量在很大程度上取决于这些键能多有效地揭示每个文档所包含的知识。然而，有效的索引表示因检索环境而异，使得任何固定的优化策略都难以始终表现一致。然而，让索引演化以适应其检索环境在很大程度上仍由人工驱动，需要人工诊断检索失败、改进优化策略并据此重新处理索引。我们提出 SELF-INDEX，一个使索引无需人工干预即可自进化的框架。其优化器自主诊断检索不足，选择性地修订相关的索引键，并在更新索引前验证每次修订。除了对观察到的检索需求做出反应，SELF-INDEX 还通过查询模拟器主动探索额外需求，使索引能够超越已可用于优化的查询而演化。在不同的语料库和检索器上，SELF-INDEX 持续提升检索性能，同时优于现有索引优化方法。我们进一步表明，这些收益可扩展到下游应用，提高搜索智能体的有效性和效率，并帮助智能体记忆系统检索有用的过往交互。

## Abstract
Information retrieval is increasingly important as LLM agents tackle complex tasks involving diverse information needs. Because retrieval relies on an index that represents each document through index keys, retrieval quality depends heavily on how effectively these keys expose the knowledge contained in each document. However, effective index representations vary across retrieval environments, making it difficult for any fixed optimization strategy to perform consistently. Yet evolving an index to its retrieval environment remains largely human-driven, requiring humans to diagnose retrieval failures, refine the optimization strategy, and reprocess the index accordingly. We propose SELF-INDEX, a framework that enables an index to self-evolve without human intervention. Its Optimizer autonomously diagnoses retrieval shortfalls, selectively revises the responsible index keys, and validates each revision before updating the index. Beyond reacting to observed retrieval demands, SELF-INDEX proactively explores additional demands through a Query Simulator, allowing the index to evolve beyond the queries already available for optimization. Across diverse corpora and retrievers, SELF-INDEX consistently improves retrieval performance while outperforming existing index optimization methods. We further show that these benefits extend to downstream applications, improving the effectiveness and efficiency of search agents and helping agent memory systems retrieve useful past interactions.

# SELF-INDEX（自进化搜索索引）论文总结

## 一、核心问题与研究动机

- **背景**：LLM 智能体需要处理日益复杂、信息需求多样的任务，信息检索（IR）成为其关键基础设施。检索依赖"索引"，而索引通过 **索引键（index keys）** 表示每个文档，检索质量高度取决于这些键能否充分"暴露"文档内部的知识。
- **核心矛盾**：有效的索引表示**随检索环境而变**——语料类型（自然语言、代码、数学、表格）与检索器类型（稀疏 BM25 / 稠密向量）不同，偏好的键表示也不同。因此**不存在一种固定优化策略能在所有环境中稳定奏效**。
- **现有做法的瓶颈**：索引需要"演化"以适应环境，但该过程仍**高度依赖人工**：
  - 人工诊断哪些索引键导致检索失败、决定策略如何改进；
  - 要么手工改写策略，要么补充标注数据重新训练；
  - 策略更新后需**全量重处理索引**，计算开销大；
  - 新的失败不断出现，需反复循环 → 人力与算力双重瓶颈。
- **研究空白**：自演化（self-evolving）范式已在推理模型与智能体上取得成效，但**将自演化应用于索引优化仍基本未被探索**。本文提出 SELF-INDEX，让索引自身完成"诊断—修订—验证"的演化闭环。

## 二、方法论

### 2.1 问题形式化

- 语料 $D=\{d_1,\dots,d_N\}$，每个文档 $d$ 关联键集 $K(d)$，索引 $K=\bigcup_{d\in D}K(d)$；只改键、不改原文语料。
- 文档打分：$s(q,d)=\max_{k\in K(d)}\mathrm{rel}(q,k)$，即**取文档全部键中的最大相关度**（max 聚合），无需人工设定/调参原始文本与生成键的融合权重。
- 初始状态 $K_0(d)=\{d\}$，**原始文档文本作为固定键**保留，不参与修订与验证。

### 2.2 总体框架

- **Optimizer（优化器）**：在每轮迭代中对查询集 $Q$ 执行三阶段闭环——**Self-Diagnosis → Self-Revision → Self-Validation**，仅接受通过验证的修订，更新后的索引作为下一轮起点，改进逐步累积。
- **Query Simulator（查询模拟器）**：Optimizer 只能对"收到的查询"做反应（被动式演化），模拟器通过 **Self-Exploration** 主动挖掘尚未覆盖的检索需求并供给 Optimizer，使演化由被动转为主动。
- 循环伪代码见 Algorithm 1（Optimizer 单轮迭代）与 Algorithm 3（Query Simulator 单次调用）。

### 2.3 Optimizer 三阶段

- **① Self-Diagnosis（自诊断）**
  - 受伪相关反馈（Rocchio、Lavrenova & Croft）启发，**不使用任何相关性标注**，以检索结果作为反馈。
  - 对每个查询取 top-$K$ 键，为每个被检索到的键 $k$ 构建**共检索画像 $C_k$**：记录哪些其他文档的键与它同时被检索及频次，反映键之间的跨文档关系。
  - 把原文、当前键、$C_k$、查询文本与得分组装成"检索反馈记录"，由 LLM 判断是否存在表示缺陷、指出责任键（或标注为"key set"整体缺陷）、给出**修订指导**（只描述"应改什么"，不直接写新键）；无缺陷则跳过该文档。

- **② Self-Revision（自修订）**
  - 目标：**选择性修订**被诊断出缺陷的文档键集，而非全量重处理。
  - 由于同一 $K(d)$ 内的键共同表示 $d$，独立修订易产生冗余，故**每轮对每个目标 $K(d)$ 整体修订一次**，联合考虑其中各键的诊断结果。
  - 构造**竞争键集** $C_d=\bigcup_{k\in F_d}\mathrm{supp}(C_k)$（$F_d$ 为被诊断涉及的键；若诊断为"key set"级缺陷则含全部键），既作为修订参照，也用于后续 Separation 验证。
  - 不预设修订策略，由 LLM 自行决定键的形式与长度，输出 `keep`（保留键编号）与 `revised`（新写/改写键），满足 $|K'(d)|\le m_{\max}=10$。

- **③ Self-Validation（自验证）**：对 $K'(d)\setminus\{d\}$ 中每个生成键（含保留键）逐条校验，原始文本键豁免；任一失败即剔除，**至少有一个新键通过全部三项**才更新 $K(d)$，否则维持原状。
  - **Faithfulness（忠实性）**：LLM 评委按 0–3 打分，≥2 视为通过，检查键所表达的信息需求是否被源文档真实支持（不虚构、不歪曲）。
  - **Specificity（特异性）**：以该键为查询检索全库，要求其源文档进入 top-$K$，即 $\bigl|\{d'\in D\setminus\{d\}:\mathrm{rel}(k',d')\ge \mathrm{rel}(k',d)\}\bigr|<K$，确保键指向本文档而非全库通用内容。
  - **Separation（区分性）**：计算当前键集与竞争键集的最大两两相关度 $P_d$ 与候选键的最大相关度 $P'_{k'}$，要求 $P'_{k'}<P_d$（取最大值以聚焦最相似键对，避免平均稀释）。

### 2.4 Query Simulator

- **两阶段查询生成**：先对采样文档做"问题抽象"（用非专业语言描述该文档能解决什么困惑/需求，不出现文档术语），再在**不提供原文**的情况下以"普通提问者"身份写出 $m$ 个问题，降低直接抄写原文的可能。
- **查询验证（双过滤）**：
  - **Answerability**：LLM 评委按 0–3 打分，≥2 才接受（文档确能解决该需求）。
  - **Dissimilarity**：与已用查询 $Q_{\text{used}}$ 及本轮已接受查询 $Q_{\text{sim}}$ 做 Jaccard 词集相似度，要求 $< \tau = 0.8$（沿用数据去重经验值）。
- 通过双重过滤的查询送入 Optimizer，驱动索引继续演化。
